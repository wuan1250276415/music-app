状态：0.145.0 源码接通；未运行备份、界面、SQL 或进程，不是 FR13 验收。

侧栏新增“曲库备份”，提供原生保存位置选择、生成／复核进度、取消、后台继续、完成文件名／曲目及资料文件计数／快照时间／内容摘要。文件后缀为 `.auralbackup`。内容仍遵循 ADR-148：schema68 曲库、数据库中的封面／波形、设置与设备档案、歌单、歌词、统计历史、Renderer 原待核对操作、Main 剩余历史及标签写回恢复工件。外部音源与系统凭据不包含；写回恢复仍要求原音乐源。

## Renderer 原资料冻结

在 App 挂载前先安装全局备份监听及 Storage 保护，并读取可信 Main 维护状态。读取失败保持界面不可修改并提供明确退出；重载期间不能先挂载组件再补冻结。事件优先于旧状态回读，后台隐藏弹窗后进度不强制再次打开。

只有当前 localStorage 的五类已知 pending、policy 隔离副本及 clear 被暂时禁止；其他窗口／sessionStorage 不受这组已知键保护。现有应用使用直接 `localStorage.setItem/removeItem`，没有保存旧原生函数或通过属性写入这些键。保护不是针对任意恶意 Renderer 的沙箱，插件权限隔离仍另行完成。

Main 为当次操作发送随机 challenge。Renderer 同步冻结，捕获原字符串及隔离副本，再次读取确认，回报同 UUID／challenge 的原快照或明确失败。同挑战重发使用最初回执，不能重新取 capturedAt 或改变原资料。

Main 将开始请求绑定主窗口 main frame 与 document epoch；冻结回复还需匹配原 challenge，并核对最初文档授权。重载、Renderer 退出和窗口关闭使旧请求失效。Library 的私有租约和暂存路径不会作为 Renderer 操作参数。

晚到的成功保存回调如果尝试删除冻结的 pending 会被拒绝，原身份保留。捕获可能同时包含已提交 DB 回执和未清理原请求；后续只能以原身份对账，不能生成新命令重复提交。关闭弹窗、显示层 inert 或超时本身都不证明资料已经静止。

## 联合维护与释放

固定的 Main 控制接口只有 state／start／frozen／cancel／quit，经同一可信主 frame 校验；普通接口继续经 ADR-150 登记，不允许新资料操作。调用方只提供 UUID，文件位置来自原生对话框。

顺序为 Renderer 确认 → Main 原生及资料资源停止／历史落盘 → Library 私有维护 frozen → 一致快照捕获 → Library 明确 released → Main 明确释放 → Renderer 解冻／曲库刷新 → 独立快照文件生成。快照复制后恢复源操作，文件生成不再读取 live 曲库，用户可关闭进度弹窗在后台继续。

四种私有维护 RPC 的 waiter 仅在真实响应或实际服务 exit 时解除，没有响应观察超时清理。全操作 45 分钟计时只发出取消意图；若原 Library 捕获仍在工作，必须等待原响应／退出，不能借 deadline 释放维护或发布文件。Renderer 挑战 10 秒无回执则不开始快照。

Main 或 Library 停止失败保留占用、显示退出后重新打开提示，不能擅自释放不确定资源。取消先等原维护／捕获结束并明确释放；睡眠时不重启通知／系统媒体或播放。发布阶段不接受普通取消，以保持最后文件动作的明确结果；生命周期变化仍使检查失效并停止独立复核。既有退出最多等待 1.5 秒后终止服务，不能将这个等待视为已完成备份。

释放前读取当前 Library 私有状态，核对原 UUID／token；已明确 idle／released 不重发固定恢复意图。这可处理消息交付失败而原释放已完成的情况，不能用旧缓存 frozen 回执强行重新释放另一操作。

## 独立生成及复核

固定 `catalog-backup-worker` 以独立 Electron utilityProcess、256 MiB JS heap 启动，只接受 Main 私有来源／输出／manifest／操作 UUID。使用已有 1 MiB 块、文件及清单预算和同步落盘；不从 Renderer 获得路径，不执行迁移或运行音乐组件。

pack 先核对快照目录和独立 SQLite 计数／完整性；逐项摘要、规范清单及完成 footer 写入并 sync，返回创建时实际 inode 身份／完整观察。随后重新读完整容器，核对逐项内容、规范清单、完成前缀 SHA256 与原工件观察。报告的 SHA 是容器完成记录所定义的前缀摘要，不是把末尾自身摘要再次计入的整文件摘要。

消息有当次 UUID／严格序号／2 MiB 清单加 16 KiB 帧预算。Main 核对完成清单与原快照完全相同，再 ACK；只有实际进程 exit0、完整结果及无取消／故障才可接收输出证明。worker 退出后的迟到消息不能改写下一次操作。停止反复请求 kill，但 owner 只在 exit 清除。

输出磁盘检查按规范容器长度加 64 MiB 余量观察；不是空间预留。源快照空间检查仍由 Library 做。独立 heap 和块预算不是 Windows Job／内核 I/O 的硬资源隔离证明，相关门槛仍待完成及运行验收。

## 目标发布

原生选定目标的父目录逐级拒绝链接／junction，保存目录身份及已有普通单链接目标完整观察。worker 只创建随机临时路径的 wx 文件。Main 在实际退出后核对创建证明、大小和观察，并在最后动作前复核原目标及目录；观察不能消除其他进程更换父目录的全部 OS 竞态。

已有目标仅在仍与原观察一致时 rename；新目标优先 link 后移除自有临时名称，不覆盖后来出现的文件。文件系统不支持 link 时使用 COPYFILE_EXCL、sync，并以第二个独立 worker 全量验证目标与原清单／摘要，再等待实际 exit0 和目标观察复核。复制发布不是原子操作，失败可能在保存位置留下未确认文件；不删除该目标，保留原完整临时工件。选择已有目标的确认来自原生保存对话框。

本轮保留私有快照与失败临时工件，不做不确定递归删除。持久操作／发布回执、目录工件登记／保留期／配额及重启后的核对仍未实现；重启不能仅凭随机文件名自动当作已完成操作。
