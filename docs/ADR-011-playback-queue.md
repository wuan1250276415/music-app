# ADR-011：持久化播放队列与控制入口

状态：原型 0.3 已实施。

## 决策

播放队列由主进程的 `PlaybackCoordinator` 协调；Library Service 仍是 SQLite 唯一写入者。队列的期望状态以 JSON 保存到 v2 `app_setting`，包含独立 entry ID、曲目 ID、当前 entry、显示顺序、随机本轮顺序、上一首历史、循环模式和 revision。独立 entry ID 允许同一曲目重复入队。队列操作串行化，保存成功后才发布新队列状态；音频宿主只负责实际输出和结束事件，不读曲库数据库。

从曲目列表点击歌曲时，以当前已加载列表创建队列。音频宿主发出 `ended` 后，由主进程推进队列并启动下一项；显式停止不触发推进。上一首在播放超过 3 秒时重播当前项，否则沿已记录的历史返回。随机和循环互相独立；单曲循环只作用于自然播放结束，用户按“下一首”仍前进。

重启时恢复队列意图和模式，实际音频状态保持停止，用户自行按播放继续。这样避免重启后意外发声。当前播放项暂不能移出队列；其他队列项可重排和移除。

## 未完成

- 当前列表分页限制了初次入队范围；还需“加入队列”、跨页面批量入队和独立歌单。
- 自动切歌会重建音频进程，不能作为无缝播放证据。
- V1 需用独立队列表和 `baseRevision` 替换单一 JSON 状态，并补齐多窗口冲突、媒体键、崩溃对账和播放历史。
