# ADR-194：启动窗口与真实升级阶段

日期：2026-10-12。源码0.188.0；schema73／音频IPC1.23／媒体14保持。完整V1和性能门槛未验收；最新已验证试用安装包仍0.187.0，本轮没有生成0.188安装器。

## 原因与实现

原流程在曲库、设置、输出、队列、桌面偏好全部初始化之后才创建窗口。大库安全升级期间用户看不到应用状态。现于普通初始化开始前创建独立启动窗口，显示真实阶段和累计等待秒数，不显示估计百分比或虚构剩余时间。

Library普通初始化通过单独的进程消息报告读取音乐库、保存升级快照、核对快照、更新索引、核对更新结果、创建运行服务。schema73升级仍保留原快照／结构／13类计数／完整性／外键检查与事务；没有删除或降低检查来缩短时间。Main继续显示设置、输出、队列、桌面和主界面阶段。

阶段仅作显示提示。Main只接收当前普通初始化实例的白名单阶段，恢复只读／暂停／释放实例不会报告普通启动进度；阶段不能满足init响应、实例身份、恢复链或服务就绪证明。普通服务仍须实际init回执，45分钟初始化期限、普通请求期限及退出独立1.5秒收尾期限保持。

启动窗口使用本地静态页面、独立沙箱preload、上下文隔离和禁用Node集成。无外部字体／资源或通用music桥，仅有状态及退出两条IPC，核对窗口及主frame发送者；动态文字使用textContent。先订阅再读取状态，并拒绝被新事件超越的旧状态响应；禁用页面导航和弹出窗口。第二实例可以聚焦等待窗口。正常主窗口创建后才销毁启动窗口；恢复启动被阻止时仍交给既有核对界面。主动退出期间不弹出初始化失败对话框。

旧AURAL_TEST客户端不创建该额外窗口，以保持既有首窗口定位；新启动MVP显式使用AURAL_STARTUP_TEST=1，运行真实启动窗口和完整窗口交接，没有延时或模拟进度。测试专用AURAL_STARTUP_TRACE保存最多64项Main阶段／耗时，不记录请求参数、音乐路径或凭据；生产不写此追踪文件。

## 真实MVP证据与范围

- `v0.188-startup-upgrade.json`：严格只读原schema72十万合成快照，校验SHA后复制到D盘独立测试目录，真实Main／Library完成升级。升级期间启动计时持续更新，窗口不开放music桥，主窗口尚未出现；实际启动画面已检查。最终13类原计数、十万首屏和精确查询、唯一schema72原快照、schema73及再次打开不重复迁移通过，原SHA不变，成功只清理本次新建副本。
- 本次升级到可查询约228.4秒，超过原180秒期限；此次是完整应用验证，不能仅当作数据库单连接实验。再次启动到查询约10.7秒，两次均非OS冷缓存测试。报告字段startupVisibleMs约3020ms包含等待计时跳变的响应检查，**不是首次画面时间，也不证明冷启动三秒**。
- Main阶段追踪显示热重开约0.584秒到ready-to-show，升级Main约216.1秒到此事件；追踪从Main模块创建监视器时开始，不含进程加载，也不代表React完整渲染、查询结果可用或首屏端到端。快照核对约70.5秒、升级结果核对到运行服务约135.5秒只是本次阶段间隔，不是独立SQL基准。仍须补充Renderer可操作确认及RPC耗时，定位Main与可查询之间的差距。
- `v0.188-startup-exit.json`：另一个隔离schema72十万副本，在实际snapshot-save阶段点击退出，约2.1秒退出应用；提前观察到的Library实际PID已退出。中断副本仍schema72、13类计数一致、integrity_check为ok、无外键问题，原SHA不变。该新建副本保留用于后续恢复验证；没有验证继续迁移和完整中断矩阵。
- 首次退出测试实际进程已退出，但独立完整性检查漏注册真实CUE路径函数，exit1保留。补齐实际函数后另一个副本复测exit0；没有把首次失败报告改成成功，也没有修改生产数据库检查。
- schema73快照／重复歌单／生产备份接口／迁移DDL失败回滚聚焦MVP与1100组独立语义查询对照通过；源码实际MP3/WAV图片像素、详情、歌词滚动／定位、模式／队列／实体检索回归通过。输出日志仍hardwareVerified=false，不新增ASIO／DSD／独占认证。

普通启动源构建／类型／原生构建通过，最初preload缺少DOM类型声明的构建失败记录保留；补齐声明后通过。最终版本／分发清单和各阶段来源指纹见validation/v0.188-checkpoint.json。未重跑正式20轮十万性能采样；0.187的正式报告保留为历史证据，不能把其中数据库源码SHA替换成0.188。
