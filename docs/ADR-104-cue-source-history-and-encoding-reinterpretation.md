# ADR-104：CUE 原文历史与显式编码重解释

- 状态：源码、类型与编译检查通过；SQL、迁移、真实文件和桌面交互待 MVP
- 日期：2026-10-02
- 源码：0.98.0；schema v42；媒体协议 7；音频 IPC 1.19／系统媒体协议 1
- 关联：架构 §9、§15.1、FR02／FR04／FR13、WP03／WP04／WP05／WP06

## 问题与操作入口

旧源码保存当前 CUE 的来源摘要、检测编码和部分解析字段，但没有原始字节历史，也不能为乱码选择其他编码。扫描覆盖当前资料之后，摘要不能代替旧原文，解析失败也缺少可查阅的原始来源。

本批将外部 CUE 原文历史接入持久扫描，在播放详情的“播放与音频信息 → CUE 编排信息”和扫描任务的“CUE 原文与编码”提供入口。全库来源每页 50 项，支持路径子串检索；每个来源的解析版本每页 20 项。旧曲目与隐藏／历史编排仍可通过保留的编排 ID 找到来源；首次读取失败、没有产生可播放曲目的 CUE 可从全库入口查阅。旧数据库不会凭摘要伪造原文，下次成功完成字节读取后补建。

历史记录展示字节数、SHA-256、检测／指定编码、解析版本、音轨数和解析诊断。用户可将保存的原始字节按自动检测、UTF-8、UTF-16 LE、UTF-16 BE 或 GB18030 预览，界面最多显示前 131072 个 UTF-16 代码单元，完整字节仍保存。预览只解码文本，不重新验证轨道与媒体引用；历史版本仅供查阅，不能借此覆盖音乐或 CUE 文件。

## 原文观察与监督契约

1. 保留原扫描的稳定窗口、同句柄及路径完整属性摘要核对。只有授权读取及读取后核对完成的原始字节才提交历史；正在变化、越界、无法打开或超过读取限额的文件不作为可信原文保存。
2. `ParsedCueSource` 增加完整 Base64 字节、原字节数、请求编码和解析错误。解码／解析异常返回无效编排及诊断，保留已读取字节；扫描保存它们后保护原可用编排，不将无效新位置发布给播放器。
3. 媒体协议升为 7，CUE 请求明确编码；CUE 专用回执上限 6 MiB。验证原字节长度／规范 Base64／SHA-256／请求编码／当前解析版本及有界结构。原文不超过 2 MiB，解析 JSON 不超过 2 MiB；标签、封面、歌词的原响应限额保持。
4. 正式编排解析继续在既有 Windows Job 监督的可丢弃 adapter 中执行，沿用 22 秒墙钟／CPU／内存和退出确认约束。服务中的编码预览只对有界已保存字节执行 TextDecoder，不做媒体 I/O 或完整编排解析。
5. 采用 fatal 解码，UTF-16 BOM 自动选择字节序，没有 BOM 时先验证 UTF-8，再尝试 GB18030。不能由“解码成功”推断汉字一定正确；用户仍需检查预览与重扫结果。机制依据 [Node TextDecoder 官方文档](https://nodejs.org/api/util.html#class-utiltextdecoder)，当前 Electron 的 ICU 和实际语料仍需 MVP 验证。
6. 请求、回执验证与 worker 使用共享 `MEDIA_PROTOCOL_VERSION`；分发清单从该声明生成版本，并记录协议／client／entry 的源码摘要。修正此前分发元数据仍写 5 的漂移；不能将清单核对解释为运行契约验收。

## 持久化与容量

schema v42 增加：按内容摘要去重的不可变字节资产、按根目录／规范路径定位的来源、不可变解析版本、当前来源指针／属性观察、明确编码选择／独立修订、待重扫意图、不可改写原回执及事务容量计数。版本绑定文件来源、字节摘要、实际／请求编码、解析版本、解析结果摘要、诊断和首次路径快照；重复读取相同内容／解释复用版本。

原字节与解析快照各限制 512 MiB；字节资产最多 32768，解析版本最多 65536，每个来源最多 128 个版本，操作回执最多 65536。容量在原事务中预留，失败回滚；原历史不会作为封面缓存被隐式删除。达到限额时拒绝新增并保留旧编排，完整历史容量管理／导出／清理仍待实施。逻辑内容上限不是数据库、WAL、备份和快照字符串的物理磁盘上限。

现有数据库在结构事务前生成 `.pre-v42-时间.bak`，超过 v42 的应用版本边界仍拒绝打开。维护既有 schema 断言与历史 fixture，未执行它们。

## 编码命令、重扫与播放边界

1. 编码选择针对最近观察的版本，包含原 UUID、来源 ID、基础修订、最近版本 ID 和编码白名单。状态及原回执同事务；相同 UUID 只能重放原请求。传输／提交未知时界面保留原请求并明确核对，不生成新的操作替代未知结果。
2. Main 在播放协调器中串行操作，先核对当前／预备 CUE 与恢复／输出书签，停止受影响编排再提交。原成功回执重放不再次停止。CAS 拒绝或传输失败可能发生在停止之后，不能声明数据库与音频停止跨进程原子完成。
3. 保存选择同时持久化原 UUID 扫描意图；启动和每 5 秒检查，与文件恢复共用至多 64 个根目录预算，等已有任务结束后用原意图提交整根扫描。已经提交／失败的旧回执不自动重新启动，失败、取消或中断保留提示，用户明确处理任务或再次提交。
4. 待解释来源对应的 CUE 条目暂不可播放，队列保留引用并提示等待编码核对；整曲及其他编排按原规则。新扫描重新读当前磁盘字节，绝不把保存的历史文本直接应用成播放位置。
5. worker 读取前捕获解释修订，读取后保存历史时核对；媒体引用核对中允许用户改变选择，因此编排安全检查点内再次核对来源修订及最近版本。过期结果拒绝提交，保留旧编排和新意图。
6. 完整安全编排提交及待解释标记清除同检查点事务。无效编排、缺失媒体或有保护性诊断时保持等待状态。历史原文保存与编排提交是两次事务：失败原文可以保存，旧编排继续保留；崩溃后扫描检查点重新处理，不能把历史提交误当成编排提交。
7. 文件管理中已忽略的音频仍按 ADR-102 保留历史绑定，不重新打开；该文件状态继续禁止播放。此路径不证明被忽略源存在或其时长已验证。

根目录与路径键沿用 Windows 首发的 NFKC／Unicode 小写规则。新增版本化 `aural_cue_path_key_v1` 和编排表达式索引，用于查找同路径的历史大小写编排记录、停止相关播放及应用等待状态；同路径编排查询最多 1000 个，超限明确失败。函数在迁移和所有应用写入前注册，相关编排写入必须通过 LibraryDatabase；当前固定运行时升级时仍需核对规范化算法并按需迁移／重建索引。区分大小写目录、跨平台路径规则和原生文件身份继续实现，规范键不是永久文件身份。

索引和 deterministic 注册依据 [SQLite 表达式索引文档](https://www.sqlite.org/expridx.html)及 [Node SQLite function 文档](https://nodejs.org/api/sqlite.html#databasefunctionname-options-function)。本批只静态核对这些约束，没有执行 SQL 或查询计划证明。
