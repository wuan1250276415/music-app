# ADR-097：拼音、首字母与可恢复检索投影

日期：2026-10-02。状态：0.92.0 源码实现；迁移、检索与性能运行验收待 MVP。

## 需求与边界

架构 FR05／WP05 要求中文原文、拼音与首字母检索。此前只有原文子串、FTS5 trigram、中文一／二字辅助索引及分类筛选；不能把这描述为完整模糊搜索。

本批次增加歌曲及歌手／专辑／专辑概念分类的完整拼音、拼音首字母匹配。词库只在曲库服务中运行，Renderer 不载入词库，不发送标签到外部转换服务。原文搜索、实体 ID、角色、风格组合、文件版本折叠、收藏和重复歌单语义保留；检索扩展不改写音乐标签、艺人身份或播放队列。

FR05 的英文错拼、完整繁简／重音映射、自然排序、组合字段语法、相关度排名、外部引用全局检索，以及一万／十万库基准仍未完成，此 ADR 不关闭工作包或发布门槛。

## 转写规则与依赖

固定 `pinyin-pro` 3.29.4，保留 npm 完整性与 MIT 声明，加入运行依赖清单及完整许可 notices。版本变更须重新评估读音、性能、许可和索引算法版本；安装本依赖跳过生命周期脚本，没有运行样例或测试。

`SEARCH_ALGORITHM` 记录库版本、NFKC、最长 256 汉字的词组上下文和艺人姓氏策略。汉字连续段使用无声调数组输出，完整拼音由音节连接，首字母取每个音节第一字符；长段分块完整转换，不截断检索文本。块边界可能影响少数多音词的读音，读音准确率和极长标签处理仍需语料验证。未知汉字保留库的回退输出，不猜测罗马字。

非汉字片段保留字母／数字词到完整形式；首字母形式保留数字词，其余取词首字母。只有含汉字的字段生成派生形式，纯英文仍走现有原文匹配。NFKC／小写处理后，拼音中的 ü 统一为 v。查询中的空格、连字符和单引号可在拼音分支忽略；原文分支保持输入的字面语义。查询最长 256 字符，拼音分支只接受明确的拉丁字母／数字及允许分隔符，不把 SQL `%`、`_` 或反斜杠作为拼音通配符。

歌曲按题名、有效署名、专辑／专辑概念／录音资料和有效风格四个现有检索字段生成投影，各字段之间用换行隔开；同一字段内连接词与空白可在派生形式中消除，因此这不是基于实体的语义匹配或成员身份合并。艺人字段额外建立段首姓氏读音形式，同时保留普通词组读音。分类中艺人名称／已绑定来源别名及专辑艺人亦保留姓氏备选，专辑名称使用普通词组读音。没有枚举所有多音字组合，也不承诺全部读音／方言／繁体字覆盖。后续人工读音别名／词典规则需要独立修订和重建。

转换缓存按最近使用淘汰，单实例最多 256 条且字符串预算 8 MiB；超过单条缓存预算的结果转换后不常驻缓存。歌曲投影和分类各有自己的缓存，这不是曲库服务的总内存上限。单条转换及 SQL 仍同步，极端标签的展开内存／CPU 与词库冷启动必须在 MVP 测量，不能由分块／缓存推断满足全部资源门槛。

## schema v39 与持久状态

迁移先按既有规则为旧库生成 `pre-v39` 一致备份，然后事务创建：

- `search_latin`：条目外键、算法标识、有效字段 SHA-256；记录已建立的当前版本投影。
- `search_latin_fts`：条目 ID、完整拼音、首字母的 trigram 派生表。
- `search_index_state`：单一任务的算法、键集游标、已检查条数、building／ready／error、错误文字、状态修订及独立的投影内容修订。
- 标记删除触发器：删除标记／条目外键级联时清除其派生 FTS 内容。

没有在 v39 迁移事务中遍历全库转换拼音。备份和结构迁移本身仍是既有同步流程，完整迁移空间预算、校验和／恢复门槛未因此完成。v38 应用按自己的最高版本拒绝新库；二进制降级不等于数据回滚，恢复备份的时间边界仍需明确。

原文 FTS／中文短字和拼音的实时更新／删除由拥有事务的曲库操作耦合；内部刷新也建立 SAVEPOINT，失败不留下半套索引。拼音标记只有在派生内容成功写入后更新；相同算法与有效字段摘要跳过重复转换。有效字段读取由实时编辑与后台补建共用，覆盖现有扫描／CUE／元数据／身份和集合修订回调。原始音乐文件不被写回。

## 后台补建与失败恢复

初始化后只在 Library Service 调度一个补建定时器。每批以 `playable_item.id > cursor` 的键集读取最多 64 项，批量投影其有效字段；已处于当前算法的条目不重复转换。包括不可见版本，以便后续可见性变化仍能检索。

批内使用约 25 ms 的协作时间预算：至少检查一项，在条目之间判断是否让出；约 50 ms 后再调度。单次 SQL、批量资料读取或一个拼音转换不可抢占，预算不是硬超时。实际处理多少项，就把最后处理 ID 和条数与该批派生写入一起提交；失败整批回滚，再单独保存 error。应用／进程中断后保留已提交游标，重新进入从检查点继续；新导入和编辑的条目由实时回调建立投影，即使 ID 位于游标之前也不会等后台再次经过。

当前没有单独停止／销毁派生索引的 UI。error 只在用户点击“继续准备”后改回 building，不重置游标或重放元数据编辑；相同恢复请求在任务已运行或完成时不重新开始。意外调度错误单独暂停并报告，允许明确恢复。算法变更在初始化中清除检查点，旧算法投影被查询过滤，并逐项更新，不把旧算法当作完整新索引。

每约 2 秒或终态发送准备事件，Renderer 单在途回读当前状态并拒绝较旧修订；完成发送一次曲库刷新。界面显示“已检查”而不是伪造完成百分比，并明确在准备完成前拼音结果可能不完整；原文检索仍保留。读取失败和补建错误区分“重新读取状态”与“继续准备”。组件卸载清理监听和轮询，迟到回执不更新新页面。

## 查询、分页与播放一致性

字面匹配与当前算法的拼音／首字母命中并集，再应用原有视图、实体、风格、收藏、版本和歌单范围；不绕过原有过滤。拼音查询只绑定值，完整与首字母分支用 UNION，避免同一条目重复出现；重复歌单仍按外层 entry 表返回。服务端排序和普通浏览的独立 500 项播放范围保留。

原文不含 `%`／`_`／反斜杠时不附 ESCAPE，保留 trigram LIKE 使用索引的可能；含特殊字符时仍转义且逐字匹配。拼音值经过受限归一化后没有 SQL 通配字符，使用绑定 LIKE，无需 ESCAPE。少于三个字符的 LIKE 可能线性扫描；实际执行计划与速度未测，不能声称 SQL 优化已达标。

原领域 TEMP 计数不包含派生拼音表或其内部 FTS 表；仅可能使用拼音分支的曲目查询，把 `search_index_state.content_revision` 加入浏览／播放快照。后台投影改变时旧拼音页不能与新结果混用；纯进度／状态更新不改变内容修订，无拼音分支的浏览不因这些派生批次反复失效。纯英文字段仍有已检查标记，但不保存空的拼音 FTS 行。分类转写针对当前卡片资料实时匹配，不依赖歌曲补建进度，仍以既有领域／连接快照隔离。

索引持续改变时既有分页失效预算仍适用；用户可继续原文检索或等准备完成刷新。缓存不是冻结结果，索引构建期间拒绝过期播放请求；完成后的曲库事件重新读取当前查询。服务重启和外部提交继续通过既有 epoch／data_version 保护。
