# ADR-164 冻结状态下准备普通曲库服务

状态：源码实现，运行验收待 MVP。日期：2026-10-10。版本：0.158.0。

## 目的与决定

ADR-163 已确认新界面及 Main 使用状态，但暂停连接还没有完成普通启动所需的中断任务整理和搜索算法初始化。在恢复完成终态之前，单独执行这些准备操作，再保存完整的新曲库清单。不能仅将 dormant 服务的 ready 标志设为 true。

此阶段保留同一实际 Library 进程、实例 UUID、PID、构建、随机租约与目录身份；服务仍处于 dormant 模式，普通 RPC 和 Library/Main/Renderer 三方维护占用仍关闭。

## 持久记录与三方绑定

新增严格版本1的 RestoreNormalRequest/Proof 及 normal-intent、normal-prepared 全局阶段。Main 必须持有当前新文档的实际准备结果，原 activation、hydration、renderer-ready 均已持久确认，才保存新意图。意图绑定三个证明摘要、原角色、实例、租约、目录、激活、随机挑战和事务。

Library 不仅信任 RPC 参数：它独立读取自己的全局事务链，要求 normal-intent 是当前最后阶段，并与本进程原 activation/hydration 结果及新界面证明一致。完全相同的原请求可返回同一工作；不能以新挑战重试或改变原内容。

## 数据库与运行对象准备

准备前核对原可写暂停证明中的全部 library 文件摘要、当前十组使用状态、权限策略、网络停止，以及搜索/文件恢复计时器和实际在途工作为空。

关闭原连接，在 schema68/DELETE/FULL 的暂停连接中明确执行一次普通启动准备：搜索算法版本初始化、标签中断状态整理、扫描检查点恢复和波形中断标记。构造连接时禁止迁移和隐式任务恢复；准备只改变检查点与派生索引状态，不执行扫描、标签写回、媒体读取、网络或波形任务。候选库旧任务、凭据、来源和目录策略仍受 ADR-160 限制。

核对曲库来源、11表数量、十组使用状态及实际权限策略不变后关闭连接，重新计算所有 library 文件摘要并检查现有完整结构及八类领域。随后重新构造暂停连接与服务对象，使用同一 token 再次冻结全部资源；重算完整内容及状态，要求与刚保存的新清单一致。

回执绑定完整新 manifest、兼容报告、使用状态和权限摘要、原进程与构建。Main 独立核对实际固定 library 目录及全部文件后，才能写 normal-prepared。回执的 normalPrepared 仅表示准备结束，backgroundStarted 必须为 false；Main 不设置 serviceReady，不改变生命周期模式，不释放后台资源。

## 中断与边界

任一整理、关闭、重建、内容或持久记录核对失败，保留原意图、备份、候选、留档和三方占用。部分准备可能已经修改曲库；禁止按旧 activation 清单移动或回滚，也不以失败消息猜测任务能恢复。45分钟监督和生命周期中断继续由原进程所有者管理。

最长全局链增加两条，当前33/48；帧与累计边界不变。此阶段保留 DELETE 模式以便完整文件核对。后续终态与正式服务转换需要明确处理 WAL、普通服务就绪和分阶段释放。
