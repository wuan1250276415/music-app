# ADR-229：结构化标签来源与版本化审核依据

日期：2026-10-16；源码 0.223.0。对应 FR06／FR12、WP08／WP09、AC11／AC12，完整架构目标继续。

## 当前曲库值与来源

标签上下文接通歌曲名称、专辑、歌手、专辑歌手、发行日期和风格六类字段的当前值及来源检查。歌手读取结构化署名，按当前顺序输出多个 ARTIST，只取 performer；专辑歌手只取 album_artist。优先保留当次署名名称，不把规范名称覆盖到已审核的别名，也不把作曲、指挥等其他角色或连接词拼进 ARTIST。

风格合并当前歌曲与发行的成员，按身份去重。所有实际写入的值都必须有当前来源依据；混入未许可值时整字段拒绝，不悄悄删掉该值或借用另一个成员的权限。日期读取所属发行的当前选择并保留年／月／日精度，不能借用其他发行的日期。

新增 `tag-library-fields.ts` 集中核对实体／字段归属、当前投影、集合选择、原始观察、来源权利、期限和保存模式。派生人工署名记录可沿已有 providerObservation 引用找到同实体、同字段、同来源地址的原始记录；仅原始获许可记录中完全匹配的身份与名称可写回。人工新增名称、后来更名、角色注释和连接词不会因此取得权限。依据摘要覆盖全部相关观察与选择；权限撤回、来源或成员变化会使预览失效。

本地私用来源的 writeback:false 保持，不能因为存在于曲库就自动采用。尚无可核对曲库来源的曲序、碟序、备注、版权声明和 ISRC 仍可通过既有明确确认的手工输入处理，不虚构其来源或写回许可。新模块也不表示真实在线风格数据源已接通：当前正例中的风格观察是明确标注的受控输入。

## 已保存任务兼容

新冻结快照记录 basisVersion:2。此前缺少版本的快照按版本 1 原样读取，保留原上下文计算、原字段权限与不可变计划；不把旧审核自动升级成新字段授权。所有准备、暂存、提交前复核与持有租约后的复核都按该快照版本读取。新预览始终使用版本 2，普通 Renderer 请求不能指定旧版本。

MVP 从固定提交 526e4e1 重建真正的 0.222 代码，在独立目录用旧运行时生成待写任务，再由当前运行时重新打开并实际暂存。核对旧完整指纹相同、旧快照字节不变、原文件不变。没有只给当前数据库改版本号来冒充历史任务。

`npm run test:tag-library-fields-mvp` 会构建当前程序，归档本地已有的上述旧提交，在专属 D 盘目录核对旧检查点摘要后重建旧 Main；需要包含该历史的 Git checkout。也可通过 AURAL_TAG_PREVIOUS_COMPILED 提供已捕获的真实旧编译根。旧目录和失败材料保留，不修改旧归档或正式认证目录。

## 整库恢复后的来源隔离

新恢复激活策略版本 2 分别记录 metadata_observation 和 metadata_collection_observation 的最高 rowid。两类表不能混用计数。来自备份的旧集合及其原始父观察不获得当前文件写回权限；重新取得并审核的新观察可以形成新的字段依据，但音乐目录仍须重新确认。重放原激活请求返回原策略，不推进基准。

版本 1 激活记录继续按原格式读取，不捏造缺失的集合基准，其新集合写回授权保持关闭。该限制不阻止明确确认的手工输入或继续查看历史。数据库仍为 schema 80，无结构迁移；原生协议和音频引擎不变。策略域的验证不代表本轮已经重做完整目录切换或安装恢复验收。

## 验证范围

集中验证使用生成 FLAC、真实监督解析、SQLite 来源仓储及原生备份／暂存；受控候选和风格观察只替代来源输入，不替代文件读取、任务提交或原生成功。六字段逐值回读、音频载荷、原文件与备份摘要分别核对。

正式 Main／preload／Service／Renderer 在自有、已保存审核资料的曲库中启动，通过实际按钮选择四类曲库值、预览、确认保存及进入原生暂存；没有把它们转换成手工输入来绕过权限。网络检索与匹配真值不在这项证明之内。批量准备和候选写回／进程中断恢复另作集中回归。

初轮测试先审核旧发行的专辑署名，再修改歌曲专辑，误把当前已切换发行仍当成旧发行；已按当前发行重新审核。旧源码重建首次漏归档主题文件，保留失败日志后补齐；测试库新增子目录时也补齐真实目录创建。失败不改写为通过，最终结果以当前报告为准。

生产写回／恢复认证保持为空。本轮不新增原生编译、安装包、真实网络匹配或硬件认证。完整后台批次、更多格式、保留清理、完整失败矩阵、性能及全部 FR01–14／WP01–11／G1–5／AC01–19 继续，仅 ASIO 实机验证暂停。
