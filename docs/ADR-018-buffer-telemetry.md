# ADR-018：实时缓冲诊断与界面压力证据

状态：0.14.0 本机原型通过；G1 仍未验收。

## 决策

音频回调只用原子计数记录回调总次数、因生产线程未及时提供 PCM 而补零的回调次数和帧数，不在回调中写日志、分配内存或发送 IPC。已到文件/轨道末尾以及用户取消预排第二段造成的预期补零不计为缓冲欠载。计数在同一播放宿主内累积，seek 不重置；新建宿主从零开始。

协议 1.6 的 `playback.position` 事件每 250 ms 携带三个十进制字符串计数。Main 要求握手具有 `buffer-telemetry` 能力，校验计数可安全表示、欠载回调不超过总回调数、计数不倒退，并把结果作为 `PlaybackState.diagnostics` 暴露给诊断与测试。损坏的遥测事件按协议错误终止会话。常规界面不把计数当作音质认证。

## 本机验证

2026-09-29，在 Windows 测试机以 44.1 kHz、双声道、16-bit、15 秒 WAV 播放，通过 Electron Renderer 连续 3 秒修改 DOM 并强制布局；0.14.0 源码构建的宿主回调增加 288 次，缓冲补零回调和帧数增量均为 0，曲目时间从 0.32 秒推进到 3.20 秒。0.14.0 安装目录中的同一测试回调增加 289 次、补零增量仍为 0；安装宿主与源码构建宿主 SHA-256 一致。单元测试验证遥测传递与倒退拒绝，原生宿主测试验证事件字段。压力脚本已纳入源码 `tests/electron-ui-pressure.smoke.cjs`，通过 `npm run test:ui-pressure` 显式运行；它会调用本机音频设备，不列入无声卡 CI 的常规契约测试。

这个计数只观测应用生产线程到 WASAPI 回调的缓冲供应。它不能检测 WASAPI/驱动/DAC 之后的故障，也不能证明无旧样本、位完美或所有机器在界面压力下零欠载。G1 仍需跨设备、长时间、故障注入和数字输出捕获；G4 仍需硬件输出证据。
