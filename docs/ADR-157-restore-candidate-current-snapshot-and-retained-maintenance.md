# ADR-157 恢复候选库、当前一致快照与保留维护租约

日期：2026-10-10；源码批次：0.151.0；状态：私有准备流程已接入源码，未开放用户准备／应用恢复入口，运行验收待 MVP。

## 背景

ADR-156 的单次目录移动不能直接组成整库恢复。替换前需要独立候选副本、当前库的一致回滚快照，以及覆盖 Renderer、Main、Library 的保留维护租约。普通备份协调器会在打包之前释放源，不能用它的完成状态证明恢复时仍冻结。本批增加独立的 Main 私有恢复准备所有者；尚不调用目录移动，也不停止或重开 Library 服务。

## 固定事务与记录

事务位于 userData/backups/restore-transactions/transactionUUID。独占创建 transaction、data、data/candidate、records；不收养或覆盖旧目录。intent.json 绑定当前 userData／事务根／事务／data／candidate／原 live 目录的 dev:ino:birthtimeNs 身份，以及原恢复预览操作 UUID、prepared 完整文件摘要和原暂存身份。

最多 64 个保留事务，每链 32 条记录、单记录 3MiB、总读取 64MiB。已知记录仅 candidate、rollback、aborted，顺序分别为候选已核对、当前库一致快照已核对、替换前明确终止。原 intent 和记录使用普通单链接文件、句柄与路径观察、wx、sync，规范固定字段字节、连续序号及前条完整文件 SHA256 链。拒绝重复键、未知字段、链缺口、终态后的记录和未知资料；记录摘要是本机一致性证据，不是身份签名。

每次读取重开原 prepared 及当前记录，拒绝原来源／暂存目录身份变化。candidate 记录绑定整份原 manifest 的文件数量、载荷字节数、原 candidate 和新 library 身份及当前构建的部分领域兼容性报告。rollback 记录绑定本事务 UUID、一致快照路径与身份、原 live 身份、完整 manifest 及独立核对报告。

## 候选准备

Main 独立准备进程重新读取原恢复准备回执，仅接受应用内已登记的 offline stage。固定目标为本事务空的 data/candidate。来源与目标不得相同，目标存在任何内容即拒绝；仅复制 manifest 白名单内的资料，逐文件 wx、1MiB 分块、句柄／路径变化检查及 sync。没有复制活动 library.db／WAL、原文件移动、覆盖或自动删除行为。

复制前核对来源完整文件清单和 SHA256；复制后再次核对来源与候选完整清单和摘要。随后只读核对候选数据库结构、完整性／外键／来源／计数及现有八项领域范围，解析原文 Renderer pending，最后再次计算候选全部摘要。报告含 candidate 根及 library 身份。失败的自有部分副本保留，不用于下次复制；重新开始需新的事务 UUID。

准备 worker 与旧预览 worker 分离，256MiB V8 heap、顺序消息、3MiB 单帧、16KiB stderr、15 秒完成 ACK、实际进程退出及反复 kill 等待。整次准备期限 45 分钟；done 或 kill 返回不代替真实正常退出。Main 等实际 exit0 后重新核对候选目录身份，才保存 candidate 回执。

## 当前库一致快照与保留租约

候选回执完成后，独立 CatalogRestoreMaintenance 发送原操作／随机挑战的 Renderer 冻结请求，核对固定原回复及原界面文档。它复用现有 pending Storage 冻结与维护边界通道，Main 的状态查询在恢复维护期间返回该 owner 的 held 状态，防止重载把未结束恢复当作普通空闲备份。此通道目前属于私有准备底座，正式恢复入口及专用界面仍待接通。

随后冻结 Main 资源组，等待播放／输出、查询、面板、设备通知、媒体快捷键、系统媒体、封面、外部文件、设置及历史等真实所有者停止；再用同一事务 UUID 获得 Library 随机 frozen 租约。使用既有 catalogMaintenanceCapture／SQLite Backup API 捕获一致数据库、用户资料、写回恢复文件和两类 pending 原文，验证返回位置及 manifest 的本事务身份，并重新读取 Library 当前 frozen 状态和原 token。

捕获后不释放 Main、Library 或 Renderer。第二个独立准备 worker 核对固定 backups/catalog/.aural-backup-transactionUUID-* 快照、当前构建 manifest、数据库结构及部分领域、pending 原文、完整文件摘要和目录身份。Main 在实际 exit0 后保存 rollback 回执，返回仍持有冻结资源的私有准备对象。

该对象没有公开 prepare/apply IPC，Main 生命周期中断、互斥与退出等待已登记。新备份或旧恢复预览不能与准备／保留租约并行。中断或失败保留资料；能证明没有任何原生移动登记且原 live 身份仍相同时，先持久记录 aborted，再明确释放原 Library 租约、Main 资源并 thaw。停止／记录／释放未确认则保持占用，不能用超时解除。明确取消准备同样只能在目录切换前执行。

## 原库的启动判断

在 ADR-156 的启动只读观察上增加全局准备记录。只有有效 intent／已知完整准备链、没有任何原生移动操作目录、原 live 实际身份仍与 intent 一致，而且前后观察稳定，才允许普通打开原曲库。它不表示恢复已应用，也不允许复用旧的当前库快照；下一次替换仍必须重新准备并捕获当前库。

有任何移动登记、槽位冲突、损坏或未知记录均停止打开曲库，保留原库和候选资料。单个 exit.json 不证明全局恢复成功。该规则替代 0.150 对所有事务一律阻止启动的保守规则；全局切换／回滚终态和受控新库启动证明尚未实现。

## 尚需完成

仍需受控 Library 正常退出与实际 exit 证明、全局切换意图／阶段／终态记录、目录切换与失败回滚、新 Library 在后台任务和外部写回关闭状态下的启动核对，以及跨进程崩溃恢复界面。还需隔离／审核旧与新 pending、来源权利／凭据范围／外部路径授权、完整领域及迁移校验和、物理配额与受控保留清理。当前计数上限和磁盘空间观察不是实际文件系统配额。

整库应用入口必须在这些流程完整接通后开放。FR13／WP11／AC17及完整架构目标尚未验收，不能把候选准备或快照成功当作整库恢复完成。

## 验证边界

仅进行类型、源码、构建和发行静态检查，不运行应用、worker、SQL／内存库／迁移、复制／快照／恢复、媒体、驱动或测试。真实文件／数据库真值、进程交错、取消／重启、盘满、快照保留、UI 与全部故障验收集中到 MVP。schema68、音频 IPC1.22、媒体协议10保持，无新安装包；仅 ASIO 实机验证搁置。
