# ADR-112：ASIO 厂商控制面板的独立会话和释放确认

- 状态：源码、类型与编译检查通过；运行留到 MVP
- 版本：0.106.0
- 日期：2026-10-03
- 关联：架构 FR09／§14.2，WP06；延续 ADR-108–111；用户封面与播放详情反馈继续保留

## 控制面板与输出持有

在应用已经停止且播放／能力查询进程已经释放时，用户明确点击所选驱动的厂商控制面板入口。Main 通过播放协调器序列化打开检查，创建独立的 `audio-host --asio-panel` 子进程；注册名、CLSID、随机 nonce、父 PID 和操作 UUID 绑定这一次会话。初始化与 `controlPanel()` 在拥有驱动的 STA 和窗口线程执行，不要求先完成能力查询，也没有在此入口创建音频缓冲、设置采样率或启动播放。回执中的这些声明只描述宿主操作，不能证明厂商 DLL 内部行为。

厂商函数可能阻塞，返回也不作为窗口已经关闭的证据。调用返回后，STA 继续泵消息并保留驱动，由用户点击“完成设置并释放驱动”触发带 nonce／操作 UUID 的私有完成命令。只在 Engine 清理成功后报告驱动引用释放；Main 还必须观察原子进程实际退出，才能重新允许播放和初始化能力读取。不能从 JSON 回执、UI 关闭或强制退出请求推断已经退出。关闭应用内输出设置页不会关闭厂商面板。

Main 校验固定 build／nonce／x64、严格字段、递增序号、驱动身份和状态转移；无合法完成请求的 closed 回执被拒绝。标准输出和诊断各限64 KiB，单回执16 KiB，完成命令512字节。每次操作原 UUID 存储至多128个内存回执；重复操作返回原会话最新结果，同 UUID 改换驱动被拒绝。缓存与面板进程都不跨应用重启恢复，不自动重新打开厂商窗口。

初始化25秒，单次会话15分钟；原生进程还有905秒退出后备预算和父进程观察。完成命令给5秒清理预算；退出观察先等待2.5秒，再请求强制结束并观察2.5秒。取消、通道错误、休眠和应用退出主动请求结束；若仍没有观察到退出，保留未知状态和播放闸门。取消不表示厂商设置已经保存，也不证明驱动完成正常清理。阻塞在厂商方法内部时无需等待调用返回即可从 UI 发起取消。输入线程清理反复取消同步读取直到线程完成，避免一次取消发生在读取开始前而遗漏。

## 信息与设置交互

面板开始和实际进程结束后均使 ASIO 初始化观察失效；界面清除旧声道／缓冲结果及 WASAPI 能力显示，设备选择标记需要重新读取。只有观察到当前会话正常释放的 ASIO 设置页面才自动重新读取选中驱动；取消或失败不自动再次初始化驱动，重新打开页面时也不会仅因为历史会话已结束便再次初始化驱动。配置保存仍走独立 CAS 原回执，不把厂商面板操作当作应用配置保存。

播放详情关闭时恢复进入详情前的封面或播放列表按钮焦点，入口已消失则退回封面按钮。点击歌手、专辑、风格和其他参与者继续关闭详情并检索对应曲库分类；大封面、滚动歌词、模式和可编辑队列保留。内嵌正面／其他图片优先、完整内嵌读取无可用图片后才读取目录图片的路径见 ADR-105。尚未取得用户实际缺图文件，不把源码检查当作原因已定位或问题已实测修复。
