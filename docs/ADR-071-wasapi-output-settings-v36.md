# ADR-071：Windows 输出设备选择与持久设置

日期：2026-10-02。源码版本 0.66.0；schema 36；音频 IPC 1.9；内部媒体协议 5。状态：源码与编译完成，运行验证待 MVP。关联 FR08、WP01/WP02/WP03/WP06；不代表 G1–G5 或任何硬件门禁通过。

## 用户入口与行为

播放栏新增“输出设备与播放设置”，选择 WASAPI 播放端点、共享／原始格式独占／允许转换独占模式及 DSD 停止／转 PCM 策略。首次默认共享、系统默认设备、DSD 停止。设备名称用于显示，端点 ID 用于打开，缺失的已保存设备保留并提示；不按名称匹配另一设备，不静默回退。

系统默认选项在每次打开时解析并固定到本次端点。关闭 miniaudio 自动流路由；设备重路由、输出中断或意外停止将导致会话错误，不跳到下一首。完整 Windows 默认设备变更订阅和设备能力目录尚未实现。

设置页分别显示用户设置与最近／当前会话宿主报告的实际设备、格式、采样率和声道。宿主打开结果不证明数字输出一致性、设备时钟或硬件 bit-perfect。ASIO 实机验证继续暂停，本轮没有增加 ASIO 音乐输出、Native DSD 或 DoP 输出。

## 枚举与打开边界

Main 启动固定音频宿主的独立枚举模式，核对协议／构建身份、随机 nonce 和原始父进程 PID；最多 128 个端点、256 KiB 单帧回执、16 KiB 诊断，10 秒期限，超时后最多等待 2.5 秒退出确认。只在子进程 close 且完整回执有效后交付列表；未确认退出时阻止下一次枚举。原生父进程守护覆盖 Main 退出时枚举阻塞，不是 OS 沙箱，也没有 Job 的 CPU／内存配额。

每次播放重新枚举并明确指定端点 ID，随后核对打开结果中的 ID。不把界面列表视为可用性或格式能力保证；打开时设备可能已断开。相同设备在原有允许转换策略下可尝试浮点路径，不更换端点；原始格式独占仍拒绝隐式转换。

IPC 1.9 增加 wasapi-endpoint-v1、initial-position-v1 能力、deviceId、十进制微秒初始位置及 initialPaused。宿主在解码定位、端点打开及缓冲准备完成后发送初始 playing／paused 事件，Main 必须同时获得命令确认和有效初始输出事件，不能把 accepted 当作播放已开始。暂停恢复只初始化设备，不先短暂启动播放。

## 切换、持久性与不确定结果

设置操作与队列操作串行。先校验设置修订，撤销或对账已预排的 CUE 边界，再保存当前曲目、回调消费位置和暂停状态；确认旧宿主退出后才提交设置并重新打开。恢复位置是回调位置书签，包含 CUE 范围内偏移，可能领先于设备实际呈现，不声称无缝切换。用户“停止”优先取消恢复，设置仍可保存；音源消失、所选端点不可用或策略拒绝时报告失败。书签仅在进程内保留，重启不自动播放。

schema 36 新增 singleton audio_output_setting 和不可变 audio_output_change。提交携带 UUID、baseRevision 和固定意图，事务内先查回执再 CAS；同 ID 不同内容拒绝。迁移前生成一致备份，迁移尚未实际执行验证。选择来源必须是 Main 校验的设备目录，Renderer 不能直接指定宿主命令或可执行文件。

保存回复丢失时查持久回执；无法核对时暂停播放并阻止其他设置提交，界面保留原操作供再次核对。核对成功不重复切换、不自动恢复；确认未保存后才能重新提交。进程内最多 512 个操作缓存，持久回执不自动删除；完整审计保留策略／磁盘管理尚待实现。

## 本轮检查与 MVP 验收

已通过原生音频／凭据／媒体组件编译、Main 和 Renderer（66 模块）编译、TypeScript 检查、发行与分发清单及相关脚本语法检查。只编译既有原生金样程序，没有运行它们。没有执行应用、设备枚举、SQL、迁移、单元测试、声卡播放、界面测试或新安装包制作。

MVP 必须覆盖：默认与指定设备、断开／重连、同名不同 ID、驱动枚举阻塞、无设备、截断目录、暂停／播放／CUE 边界切换、切换时用户停止、旧进程无法退出、保存前后崩溃／丢回执／CAS 冲突／多窗口、重启保留设置但不播放、DSD 策略冲突以及格式拒绝。另需按用户反馈检查内嵌封面优先／损坏回退、播放栏封面详情、身份检索、滚动歌词、播放模式与队列操作。设备时钟／数字输出／长时间播放和完整授权生命周期继续按架构实施。
