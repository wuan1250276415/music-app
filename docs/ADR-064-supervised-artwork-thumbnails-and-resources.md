# ADR-064：封面监督读取、原生缩略图与受控资源

状态：0.59.0 源码实现；2026-10-01。schema v30、音频 IPC 1.8 不变，内部媒体协议升级为 version 3。FR01–FR14／WP01–WP11 全范围继续保留，ASIO 实机验证仍暂停。

## 当前读取路径

曲库服务中的直接图片解析已移除。歌曲封面经共享 MediaParser 调度，在 ADR-062 的受监督 Node 适配进程中从同一个只读音乐句柄读取；适配器再启动固定的 media-worker.exe --artwork-convert 模式，用 Windows WIC 校验、缩放并编码。转换组件只收二进制 stdin 并写 stdout，没有图片路径、输出路径、shell 或网络参数。转换组件与适配器属于同一个 Windows Job，不能逃逸为无监督的后台图片任务。

候选顺序继续为内嵌正面图片、其他内嵌图片、歌曲同名图片、目录常规图片；CUE 使用引用音频的图片。后续标签错误仍保留已提取的图片，目录属性／枚举失败不阻断内嵌封面。metadata tokenizer 沿用 32 MiB／20 秒合作预算与 Job 硬监督。最多考察前 64 张内嵌图片、转换 16 个候选，无法解码或超预算的候选可继续回退；本批没有把失败或缺图永久缓存。

本地图片先检查类型、大小和真实路径位于授权根内，再用自己的只读句柄读取，长度、句柄属性、当前路径与真实路径在读取后复核。父曲库服务另持音乐句柄，在任务完成后复核文件与根范围。来源 token 改为原图片字节 SHA-256，缩略图尺寸改变不改变同一候选身份。当前文件属性／目录观察、30 秒候选缓存与主动重读保留；同名 sidecar 的原地改写可能依赖 TTL 或主动重读，完整来源文件身份、租约与 watcher 仍待实现。

## 原生转换与限制

WIC 读取首个图片帧，在拷贝像素前核对尺寸；保持宽高比、不放大，生成最大边 256 或 1024 的 JPEG，质量参数 0.9。列表默认 256，播放栏与详情默认 1024。GIF 使用首帧静态封面。本批没有完成 EXIF 方向、完整颜色管理或透明背景合成策略。

| 项目 | 当前上限 |
|---|---|
| 单候选压缩体 | 16 MiB |
| 原图片单边 | 8192 像素 |
| 原图片总像素 | 32 × 1024 × 1024 |
| 规范缩略图压缩体 | 2 MiB |
| 图片任务结果 JSON | 3 MiB |
| 标签／CUE 任务结果 | 2 MiB |
| 请求帧 | 64 KiB |
| Job 活动进程 | 2：适配器＋固定转换组件 |
| Job 时间／提交内存 | 用户 CPU 20 秒／墙钟 22 秒；单进程 384 MiB、全 Job 512 MiB |

JPEG／PNG／GIF／BMP 使用 WIC 解码；WebP 继续识别 RIFF/WEBP，实际解码依赖系统注册的 WIC WebP codec。没有安装对应 codec 时可能回退到其他图片，尚不能声称保留了所有系统上的 WebP 支持。独立受控 WebP 解码、格式能力清单与实机兼容校准继续在目标内，不能以系统可选 codec 替代完整验收。

Job 活动进程上限由 1 调为 2。监督组件在适配器结束后终止剩余 Job 进程，并查询活动进程归零；仅确认适配器结束不足以释放槽。查询／退出确认异常仍返回不确定状态并阻止后续解析，沿用原任务真实性保护。原子 Job 关联、父结束清理和取消时的输入管道控制继续保留。本批没有实现低权限令牌或 OS 沙箱；WIC 元数据／codec 在像素核对前也可能执行工作，因此提交内存、CPU 与墙钟监督仍必需，已编译不代表已证明攻击语料表现。

参考 [Microsoft WIC 编码流程](https://learn.microsoft.com/en-us/windows/win32/wic/-wic-creating-encoder)与 [GetSize](https://learn.microsoft.com/en-us/windows/win32/api/wincodec/nf-wincodec-iwicbitmapsource-getsize)核对 API 使用；预算是应用策略，不是这些 API 自带的安全保证。

## 调度与资源地址

标签、CUE、封面共享一个执行槽及最多 16 个等待项；封面优先，连续最多三个封面任务后让已等待扫描任务进入。封面等待最多 25 秒；扫描等待由取消信号控制，不消耗其单文件执行预算。槽只在监督 close 与 Job 退出确认后复用。等待项取消／超时从队列移除；未知生命周期会拒绝全部等待项，并传递同一不确定状态。原生整曲波形仍有独立单槽，因此目前最多两个解析／分析任务并行；整体播放优先级和统一持久媒体任务中心仍待完善。

仅内部 worker→Library→Main 回执包含规范缩略图的有界编码字节。Main 检查 JPEG 形式、编码预算和尺寸，按缩略图 SHA-256 注册 aural-artwork://image/<hash>.jpg，Renderer 只得到不含本地路径的资源地址与来源摘要，不接收原图 Base64。受控协议只接受 GET、精确小写摘要地址和已注册资源，不根据 URL 拼接文件路径。响应为 image/jpeg、nosniff、私有不可变缓存；CSP 仅增加此图片 scheme，去掉 data: 图片许可，不开启 bypassCSP、远程网页、任意 fetch 或导航。

Main 保留最多 512 个资源描述、64 MiB JPEG 字节及最多 16 个在途重读；字节逐出后可用原对象 ID／尺寸／候选条件重读，必须与原 token 和缩略图摘要一致，变化后拒绝把另一张图套入旧地址。候选共享缓存仍在 Library 中，Renderer 保留共享地址缓存和当前项优先加载。此缓存目前是进程内缓存，不是持久磁盘缩略图库，也没有完成资源 pin、跨重启恢复和离线封面保留。

使用 [Electron protocol 文档](https://www.electronjs.org/docs/latest/api/protocol)核对 ready 前 scheme 注册、ready 后 handler 和会话范围。当前只使用应用默认会话；将来增加多窗口或独立 partition 必须重新核对注册与访问边界。系统图片解码和 Chromium 资源显示尚需运行证据。

## 构建与 MVP 验证

转换代码编入现有媒体监督 exe，新增 WIC／COM 系统库链接；没有新增 npm 或随包第三方二进制。分发清单新增转换源摘要、媒体协议 3、图片预算与双进程 Job 信息；解包验证器增加图片适配及资源模块哈希核对，但本批没有执行安装包验证。

类型检查、Main、Renderer（64 模块）、音频／凭据／媒体监督与 WIC 转换编译通过；发行／分发清单及现有封面、详情、解包检查脚本仅静态核对。既有封面用例改为调用受监督读取并核对内嵌／本地来源摘要；详情脚本改为核对资源地址及实际显示的红／蓝封面像素，避免把原文件 Base64 相等当作显示证明。以上用例本批均未运行；MVP 前需先构建原生组件。没有运行图片解析、桌面、资源协议、SQL、迁移、音频或安装包。

MVP 需覆盖真实内嵌 FLAC／MP3／WAV／DSF/DFF 图片、损坏正面候选回退、编码与超大／解压尺寸、WIC WebP 可用与不可用、色彩／透明／方向、两种尺寸、CUE 共用来源、歌曲与 sidecar 改写／越界／离线、刷新与候选拒绝、并发扫描／封面／波形、排队取消／超时、转换卡死／异常／适配器先退出／父强退、Job 归零、截断或多帧结果、资源缓存逐出重读／未知地址、CSP 与真实界面，以及打包 ASAR 与系统 DLL 依赖。最新已验证安装包仍为 0.29.0，0.59.0 只交付源码。

剩余目标仍包含持久多尺寸缓存及离线显示、资源租约与恢复、完整格式与色彩／方向处理、Provider 封面／授权生命周期、硬隔离父端全部文件 I/O、播放中后台负载校准、故障重试及跨平台转换适配。WP04、FR04 和完整封面门槛均未验收。
