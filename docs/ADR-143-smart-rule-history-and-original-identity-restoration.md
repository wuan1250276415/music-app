# ADR-143：智能规则历史与原身份恢复

日期：2026-10-06。状态：0.137.0 源码实现；SQL／迁移、历史真值、故障恢复和界面运行验收待 MVP。对应 FR04／FR05／FR07、WP05／WP06。音频IPC1.22、媒体及写回协议保持。

## 用户流程与完整规则

智能歌单目录增加全局“规则历史与恢复”，包含已经删除的歌单；具体智能歌单也有按其身份限定的入口。历史按稳定序号倒序每页20项，显示名称、创建／修改／删除前规则／恢复类型和当次保存时间。更早页替换当前20项，可刷新回到最新。打开历史不会改变歌单、音乐文件或播放队列。

选择记录后读取其完整定义与当前状态，包括范围、检索词、排序、折叠状态、额外风格分类范围和全部组合条件。组合条件复用原编辑窗口的只读模式，完整显示艺人／风格、源音频、个人状态、统计与滚动日期字段；不能应用、保存预设或编辑历史。支持按历史完整查询预览当前曲库的总数和前8项。历史存的是规则，预览不是当时音乐条目的历史快照。

恢复前需要明确勾选确认。当前歌单仍在时，用历史名称及规则生成新修订；已删除时，按原UUID和最初创建时间重新建立smart歌单，并生成超过全部已有历史的新修订。删除记录保存删除前的名称和定义，也可作为恢复来源。已经应用到队列的条目、顺序、用户状态和音乐文件继续保留；恢复规则不物化固定音乐条目。

每次恢复新增 `restore` 历史，引用所选来源修订及其摘要。后续可查看这次恢复的来源；来源是另一次恢复也可查看，修订引用只能向更早版本，禁止自引用或未来版本。原创建、修改、删除和恢复记录不被改写。

## schema66 与原历史保留

schema66在原 `playlist_smart_history` 基础上增加稳定 `ordinal INTEGER PRIMARY KEY AUTOINCREMENT`、restore动作、source_revision／source_fingerprint，以及按歌单和序号的索引。原 playlist_id＋revision 保持唯一领域身份，command_id保持唯一。原七个字段与原始 definition_json直接复制，来源指纹不要求改写旧规则格式。

迁移序号取原表当前rowid，随后成为显式整数主键，作为稳定分页顺序；它不是墙钟准确性或旧物理记录顺序的认证。已有可见时间字段保留原值，时钟回退不会改变新序号分页。新增恢复来源以同表组合外键约束，source_revision必须小于新revision，来源与摘要只在restore动作中存在。恢复来源只能来自保留的同一歌单历史。

升级前做既有一致性备份，在事务中建立并复制新表、替换旧表、恢复禁止UPDATE／DELETE的触发器、核对外键后设置user_version66。普通创建／修改／删除改为显式列名INSERT，兼容新增默认空来源字段。当前smart/static歌单、原静态entry身份／顺序、曲库、播放历史、队列及共享原操作回执不改内容。旧程序拒绝新schema；生产库降级不支持。

现有旧schema夹具辅助函数只在智能规则历史为空时重建旧结构，现有四处最终schema断言更新为66；这些SQL和辅助函数未执行。迁移前后原字段、删除歌单历史、连续新序号、外键与触发器完整性仍需MVP验证。

## 有界分页与来源核验

第一页捕获全局最大ordinal水位。后续按同一水位、当前最后序号和可选playlistId做keyset读取，查询21项以决定是否有下一页，只返回20项；不计算全历史COUNT或物化全历史ID。新加入的记录在刷新后出现，不在正在翻阅的固定水位中插入而造成重复／漏页。

游标绑定范围、进程epoch、水位和before，由私有随机密钥HMAC签名。请求长度／格式严格校验，服务核对签名与规范化编码，拒绝换歌单使用、篡改、跨服务重启和历史回退的旧游标。Shared／Renderer验证范围、排序递减、数量、来源字段和样本身份。目录没有保存全局历史总数，也没有宣称历史存储配额或清理政策已经完成。

来源指纹是独立域SHA256，包含原歌单身份、修订、动作、原commandId、名称、原definition_json字节、保存时间和已有恢复来源字段，不包含迁移序号。读取所选记录时核验当前末尾和当前smart定义／名称／修订一致性；读取restore记录也核验它记录的直接来源摘要。普通不可变触发器和保存的恢复引用共同约束历史，指纹用于绑定所选载荷，不是恶意修改整个数据库后的外部签名证明。

## 恢复事务和结果未明

Main只接受可信桌面文档，按白名单转发history／history-detail／restore；Library再次严格校验。恢复请求只提供commandId、playlistId、sourceRevision／sourceFingerprint、headRevision和baseRevision（已删除时为null）；不接受Renderer自造名称、规则、SQL、音乐条目或文件路径。

一次FULL-sync事务先查共享原UUID回执，再读取原来源和当前状态。来源摘要必须匹配；历史末尾必须仍为headRevision，当前修订或不存在状态必须仍为baseRevision。静态歌单占用原身份、当前定义与历史末尾不一致、来源缺失／摘要变化或状态变化都会拒绝。已删除歌单还需要原revision0的create记录，保留其最初创建时间。

新revision始终为headRevision+1；恢复当前或重建删除身份、追加带来源的不可变恢复历史及写入原命令回执同事务提交。相同UUID／同载荷返回原已保存结果，不再次恢复；相同UUID／不同载荷拒绝。提交异常后在数据库不处于未决事务且原回执可读时核对原结果，无法读取时向Main保留异常，不猜测结果。只有实际新恢复提交才发布libraryChanged；重复回执不再通知新变更。

Renderer在IPC前将完整规范化原请求写入固定待核对记录，读取上限16384个UTF-16单位。持久化失败不发送；连击单飞；关闭、超时或重启后保留原请求，重试不生成新UUID或重新绑定当前修订。回执必须匹配commandId、歌单身份、新修订和已读取的原定义，清除时再确认本地记录仍是同一载荷。明确已保存或已拒绝才清除，未知结果保持待核对。

已保存回执证明原操作曾提交，不保证目标后来没有再次修改或删除。成功后的界面要求重新读取当前状态，不能把重放回执的旧结果当作最新规则。规则目录更新会取消未确认的勾选、使相关当前状态失效，读取中的旧响应按代际退场；后端CAS仍是最终判据。只读历史来源不随曲库资料改写，预览则使用ADR-142的当前曲库快照规则。

单组件待核对记录有原载荷覆盖检查，没有宣称跨窗口原子锁、多进程协调或完整备份恢复能力。无效本地记录需明确清除。共享回执／智能历史保留与清理、导入导出和多窗口协调继续属于后续范围。
