# 0.228.0 原生备份核对与清理组件开发记录

日期：2026-10-17。接续 [0.227 备份空间与保留设置](development-0.227-backup-storage.md)，当前仍是开发快照，完整空间管理 MVP 尚未验收。

## 本次代码

新增独立 Windows 原生组件 `tag-backup-cleaner.exe`。它只构造由任务 UUID 与备份工件 UUID 确定的 `.bak` 名称，不接受任意文件列表，不递归清理目录。普通原生构建、安装包资源和解包后的文件摘要核对均已接入该组件。

核对与删除均要求本机固定 NTFS，固定全部目录祖先并验证实际路径；备份以独占句柄打开，拒绝重解析点、硬链接、额外数据流和不支持的文件属性。独立计算完整文件、FLAC 元数据和音频有效载荷摘要，与后端传入的原始备份证据比较。删除请求还必须匹配之前核对的文件物理身份与目录身份。

原生删除按已打开的文件句柄设置删除属性，关闭后再次核对原路径缺失；不会按一个稍后可能指向其他文件的路径重新发起删除。核对阶段与最终结果均有严格的身份、顺序、大小及字段检查。

监督通道沿用单进程 Job、父进程身份与存活检查、内存／时间／输出预算以及实际进程退出确认。客户端在等待持久化阶段回执时停止消费后续阶段，只有回调完成持久保存并返回摘要后才发 ACK；收到终结消息不等于进程已退出，也不等于任务已经成功。

## 日志与阶段

每个操作使用独立的只追加日志目录，初始绑定包括曲库来源、原暂存执行、任务与保留策略修订、暂存日志摘要及实际原生请求。每个阶段单独写入不可覆盖文件并同步，再重读校验摘要链；日志有缺口、额外文件、物理身份变化或不一致时保留原证据并拒绝继续。

| 阶段 | 文件状态和后续约束 |
|---|---|
| checked | 备份已在独占句柄下核对；只读核对请求在此阶段确认后结束 |
| delete_ready | 原文件证据仍被句柄持有；后端必须先保存清理意图和匹配的数据库回执，才能 ACK |
| deleted | 句柄删除与关闭已经执行，原路径在该时点核对为缺失；该阶段仍须持久保存 |
| done + 实际退出 | 仅在全部阶段、ACK、完整终结及正常退出均核对后，才可接纳完整原生成功结果 |

删除前的意图与删除后的结果不是同一事实。原进程中断、缺失终结或只保存了 `delete_ready` 时，不能凭备份缺失伪造完整删除回执；接续的协调层必须重新核对实际文件，并保留“结果未完整确认”等独立状态。

## 尚待接通

当前组件和日志没有公共删除入口。数据库清理意图、固定清理范围、逐文件操作记录、后台调度、界面确认与停止、重启后的原操作核对仍需接通。原生组件只证明备份物理内容及删除阶段，不自行决定保留期、批次依赖或任务是否仍需恢复；这些条件必须在后端创建意图与实际发出删除 ACK 前重新检查。

目前空间清单的 `cleanupReady` 保持 false，应用不会自动调用组件删除现有备份。生产标签写入／恢复认证目录保持为空；备份清理组件也没有开启原歌曲替换能力。
