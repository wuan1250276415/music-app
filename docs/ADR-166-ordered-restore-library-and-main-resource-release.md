# ADR-166 恢复曲库和主程序资源的有序释放

状态：源码实现，运行验收待 MVP。日期：2026-10-10。版本：0.160.0。

## 决定

ADR-165 的封存决策和 WAL 就绪证明仍然保留全部维护占用。本批在私有恢复准备主流程中接通曲库释放、实际普通服务转换和主程序资源释放，但保留主程序请求门禁、播放维护、播放历史维护和 Renderer 维护视图。四项新记录不能代表应用恢复完成，正常 App 尚未挂载，尚无公开整库应用入口。

## 曲库释放

Main 确认原事务、实际 dormant 进程、原封存决策和 service-ready-held 的实际规范记录摘要。library-release-intent 包含原完成 UUID、实例、租约、目录身份、新挑战、决策摘要、服务证明及实际记录摘要。持久意图并读回后才发出私有 catalogRestoreRelease；普通 catalogMaintenanceRelease 在恢复 dormant 状态继续拒绝。

Library 独立读取全局链，要求最后一项正是原 library-release-intent，校验本地服务证明、同一实际 PID 和构建、租约和目录身份。释放前确认该连接实际已经完成 WAL 准备，schema68、WAL、外键及 FULL 设置保持；来源、计数、十组使用状态和导入策略仍与冻结证明一致，后台定时器及网络占用仍停止。随后调用原维护资源释放，要求相同租约进入 released 并实际不再 held，核对目录后才返回证明。

backgroundReleased 表示后台管理器的维护占用已经释放，不声称任务已经执行，也不把 resumeWatch 解释为所有后台任务的统一开关。候选导入的旧路径、来源与任务隔离策略保持。释放后后台可以改变数据和索引，禁止再将旧 DELETE 清单或冻结计数作为当前内容证明。

Main 仍以原实际进程的独立待回复所有者处理结果；严格核对实例、PID、构建、请求摘要和结果预算。先持久 library-released 并完整读回，随后再次确认当前原实际进程，才切换 owner.mode 为 original、设置 ready 并允许普通 Library RPC 和事件发布。超时、持久失败、退出或取消终止该恢复实例，不能把迟到结果移交给其他进程。

## 新界面所有权交接

曲库释放前，当前已经准备的新文档进行一次所有权交接。固定本地 URL、实际 webContents、文档代次、主 frame 跨文档加载及原准备回执的校验全部保留；只将旧的冻结曲库及 Main 缓存断言替换为当前恢复操作和外层维护门禁断言。否则释放以后继续引用旧的 dormant/frozen 断言会拒绝所有后续回执。未知导航和刷新仍中断恢复。

## 主程序资源释放

曲库证明实际持久并且当前实例已转换之后，保存 main-release-intent，绑定曲库释放证明、相同完成 UUID、新挑战、全部资源名称和封存恢复意图。当前资源共 13 组，包含快捷键、系统媒体、设备查询和通知、历史导出、外观、窗口、外部文件、封面和托盘。

MainCatalogResources 使用独立恢复释放方法，逐项启动释放并等待所有结果；任意失败都等待其他释放结束、报告具体资源并保留外层占用。普通备份资源释放共用等待所有结果的实现。恢复分阶段释放一旦开始，普通 release 不能绕过流程开放交互，assertFrozen 也不能再把这些已恢复资源视为冻结。

所有组成功后，实际核对播放输出仍释放、播放队列命令停止、历史记录原请求停止、播放和历史维护仍属于原操作，以及 Main 外层请求门禁仍 held，才保存 main-resources-released。该证明明确 resourcesReleased/playbackHeld/historyHeld/userGateHeld，不宣称正常应用已经可交互。快捷键和系统媒体控制仍经过 Main 门禁，普通 Renderer IPC 继续拒绝。

独立资源结束维护后，系统入口也必须继续遵守外层门禁。外部文件打开纳入 Main 请求登记；托盘设置和窗口关闭策略、键盘缩放、窗口位置设置及自动保存检查外层 inputBlocked。托盘菜单显示同一阻塞状态，点击时再次校验。普通维护释放在实际外层门禁结束后刷新托盘和窗口观察，避免菜单永久显示维护状态；恢复分阶段释放期间不调用该开放回调。

## 中断与剩余工作

资源部分释放不可伪造成全部冻结或释放成功；保留意图和已经持久的结果，中断恢复实际实例。中断针对原 bootOperationId，覆盖已经转换为 original 的同一恢复进程，避免服务模式变化后遗漏进程终止。

完整正常 App 挂载及实际读取回执、播放/历史与最终交互释放、应用 completed 证书、完成后的启动准入和未决重启处理仍待接通。现有启动门禁仍拒绝所有已移动但未完成的恢复事务。未来至少需要新界面回执和最终资源释放证据，不能仅凭本批四项记录准入。

最长已有链 40/48 条，3 MiB 单帧、64 MiB 累计、保留事务数量及 schema68/音频 IPC1.22/媒体协议10不变。所有架构功能与验收项保持，不缩减目标。

## 验证边界

本批只进行类型、源码构建、原生组件编译、脚本语法和发行来源清单静态核对。未运行应用、SQL/迁移、恢复流程、worker、真实媒体、驱动或测试。实际释放时序、失联/取消/晚回执、部分失败、导入策略和界面行为均需在 MVP 集中运行验收。ASIO 实机验证继续按用户要求搁置，实际封面缺失问题仍待复现；没有新安装包。
