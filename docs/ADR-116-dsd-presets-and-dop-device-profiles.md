# ADR-116：DSD 输出预设与 DoP 设备档案

日期：2026-10-03。状态：源码、类型与编译检查通过；运行与迁移集中到 MVP，ASIO 实机验证仍搁置。

承接 [ADR-115](ADR-115-asio-dsd-private-session-and-bit-tick-bookmarks.md)，对应架构 FR03／FR09 和 WP02／WP06／WP07。原始私有会话需要明确的档案授权对象，驱动枚举或能力观察不能代替设备支持证据。

## 独立设置与授权身份

新增 `dsd_output_setting` 和不可变 `dsd_output_change`，schema46 升级前备份。DSD 预设包括 inherit／stop／pcm／native-dsd／dop，默认 inherit；旧 schema45 播放后端的 DSD 转 PCM／停止设置保留。profile 阶段不消费新预设，不重启现有 PCM 播放。主进程缓存及 UI 明示 `playbackIntegration: profiles`；后续接入原始路由时才启用播放影响判断。

DoP 档案保存 UUID、独立修订、注册驱动身份、驱动报告的整数版本、DAC 名称、已确认的 DSD64／128／256 速率、1–16 个有序且不重复的输出声道和文档依据。档案对象始终标记 userConfigured／hardwareVerified:false。文档支持与硬件音量确认必须显式勾选，新增或编辑不预先勾选。UI 的声道编号从 1 起，传输和存储按 0 起。

保存档案仅查询注册目录，不初始化驱动。界面可使用上方用户显式读取且未过期的能力观察填写版本；版本、声道或速率观察不构成 DoP 认证。选择 DoP 预设时，档案驱动与声道顺序必须匹配保存的 ASIO 配置；原始预设要求关闭软件增益，转 PCM 需要明确允许精度转换。真正播放仍须重新验证当前驱动版本、源格式、速率和样本容器，禁止把保存成功当作播放批准。

## 修订、归档与不确定结果

整个设置按 baseRevision 做 CAS，档案编辑和归档另外检查档案修订。请求严格校验字段并规范 UUID 和授权对象字段顺序。事务内记录原请求、旧设置和结果；同命令 ID 重试只核对原回执，不重新应用旧设置。回执读取重新计算状态转换并核对保存结果。

最多保留 32 个档案，归档不物理删除，不复用身份。归档选用档案会撤销选择；若预设为 DoP，同时改为 stop。恢复不自动重新选用。回执数限制 65536，总 JSON 历史预算 256 MiB，达到上限时保留已有历史并拒绝新增操作。

主进程通过播放协调器串行处理可信 IPC。保存与回执读取都不能确认结果时，保留原请求并阻止新的 ASIO 播放；WASAPI 不受该设置不确定性影响。原操作核对在已停止、已确认输出释放后读取实际保存值，不自动恢复播放。UI 保留原请求，重试沿用同一 ID；过期配置必须刷新，不把旧响应回退成新配置。

## 接入与验证边界

新增共享 DSD 设置契约、单写入存储、Main 管理器、preload API、设置事件和 ASIO 设置内的档案界面。现有歌曲内嵌封面优先及播放详情功能保留（[ADR-114](ADR-114-embedded-cache-priority-and-detail-queue-search.md)）。

Main／Renderer 类型检查和构建通过（118模块，主块383.16 kB／gzip120.39 kB，输出设置块47.94 kB／gzip14.68 kB）。audio-host／waveform-worker／credential-vault／media-worker／system-media 及既有金样程序编译、41个 CommonJS 语法检查通过；发行生成文件和分发清单（18个 npm运行依赖／5个 vendored组件）核对，源码另做 ZIP CRC核对。上述不构成运行、迁移或架构门禁证据；不执行数据库迁移、应用、驱动、真实音乐、数值金样或测试。MVP 需要核对空库及 schema45 升级、事务回滚／重复 UUID／未知保存恢复、归档选用行为、版本观察过期、UI 原操作重试及焦点交互。

后续仍需 Main 原始会话路由、每次播放冻结档案与位数书签、宿主真正退出后重建、DSP 变化的停止／显式转 PCM 重新规划、独立 PCM 分析副本、DSD／DoP 金样和设备验收。全架构 G1–G5／AC01–AC19 未完成，不能标记目标完成或发行认证。
