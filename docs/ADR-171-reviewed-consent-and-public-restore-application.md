# ADR-171 审核决定持久化与公开恢复应用

状态：源码实现，运行验收待 MVP。日期：2026-10-10。版本：0.165.0。

## 决定与界面

恢复审核之后提供“恢复此备份”。用户明确确认三项处理方式：以所选备份替换当前曲库并保留原曲库；恢复后保持停止并重新确认目录/在线设置；待处理资料和旧任务保留审核，不自动继续。

Renderer 对严格解析后的完整审核计算 SHA256，提交固定版本、事务 UUID、来源 UUID、审核摘要和三项 true。Main 在实际主窗口主 frame、原文档 epoch、现有普通曲库和无其他备份恢复操作的边界内再次读取原审核，比较完整规范摘要。Renderer 不提供路径、时间、凭据范围、目录许可或执行计划。请求最多4096字节。

短 IPC 只返回已接受的 Main 状态。单一 Main 工作负责候选准备、原库一致快照、维护/实际关闭退出、目录切换、只读启动、可写暂停、pending/使用状态准备、受控新文档、普通服务转换、实际读取与资源完成证明，以及持久 completed/独立启动准入和最终交接。原 sender 收到回执、超时或消失均不代表恢复完成。

准备、收尾、已恢复候选、已返回原库、未确认完成的状态分别展示。正常窗口的维护面板订阅同一 Main 状态，并在新文档初始化时重新读取；当前操作 UUID 与真正维护状态关联，不展示旧备份结果。原库返回使用真实完成角色，保留原候选失败原因，不能展示成候选恢复成功。

## 持久确认与历史兼容

新增严格 version1 consent，记录事务/来源 UUID、prepared SHA、stage identity、具体 check SHA、完整审核 SHA、原核对时间、Main 接受时间、来源 origin、备份内容 SHA、接受时构建、固定导入策略和三项明确选择。

公开工作向内部 preparation/cutover 传入 consent。`intent.json` 使用事务版本2，并在复制候选、维护快照、关闭服务和目录移动之前 wx+sync 保存及独立加载；其规范 SHA 成为原全局链根。建立新事务时要求最新 check、当前构建及原准备/来源与确认一致。读取历史事务时绑定所选不可变 check，而不是不断变化的最新 check；之后明确重新核对来源不能使已完成旧事务失去启动准入。版本1私有历史保持原字段和规范字节，不能伪造用户确认；公开入口始终要求版本2确认。

确认只是原审核决定的记录，未扩大目录权限。复制时完整内容/数据库重新核对，原库快照在实际资源冻结后建立。导入继续采用现有新凭据范围/目录授权基线、关闭网络和自动更新、隔离旧扫描/写回/凭据任务、先归档再处理 pending 的策略。原音乐文件和系统凭据不因该确认成为允许操作的目标。

## 工作与文档所有权

相同事务 UUID 必须保持原来源、审核和确认；重复请求只查询同一工作/结果。已经开始的真实工作由 Main 持有，不因短 IPC 结束重跑。准备和切换也保留确认身份，禁止原操作改换决定。

修正 cutover 返回 Promise 的收尾顺序：先保存结果并清除原 work，再让调用方进入完整准备，避免旧 `.then().finally()` 的第二次微任务尚未执行时误判原切换仍在运行。

原文档授权保持到内部 `prepareCompletion` 完成已登记的新文档准备。之后沿用原有独立新文档/PID/token/构建/资源证明，不用已经失效的原 frame 授权收尾。completed 的实际 operationId 和角色核对后才能发布候选成功或原库返回；三方真实持久证明与资源释放仍由原完整主流程决定，播放不自动恢复。

整项工作保留3小时中断边界。停止、未知导航、主窗口关闭、休眠和退出沿用原 coordinator/abort/实际进程退出及维护屏障；没有真实完成证明时不恢复业务入口、不猜测目录状态、不移动已激活 WAL 的旧快照。退出登记等待公开 accepted/work 以及原各资源工作。中断记录与资料保留。

## 限制与验证

本批接通公开确认到完整内部流程的源码，不代表正式恢复已经经过运行验收。未决重启的操作界面和重新取得实际所有权、原文导出复审/权限重提、完整领域及迁移校验和、物理工件配额和清理继续开发。部分领域报告的实际范围仍明确呈现，不宣称全域认证。

仅进行类型、Main/Renderer 构建、生产原生及既有金样编译、脚本语法和发行生成文件/清单静态核对。没有运行应用、SQL/迁移、worker、复制、切换、恢复、媒体、驱动或测试。MVP 集中验证确认/重复提交/旧审核/取消、跨文档回执、真实候选与原库返回、数据保留及故障/重启交错，完整 FR/WP/G/AC 目标不缩减。
