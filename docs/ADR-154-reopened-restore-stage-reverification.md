# ADR-154 恢复暂存重启读取与重新校验

状态：源码已接入，MVP运行验收待完成。日期：2026-10-09。版本：0.148.0。

## 决定

恢复弹窗列出此前保留的操作，Main从私有登记读取来源、prepared回执与后续核对回执。历史记录表示当次完成校验，不能当成当前文件仍有效的证据。用户选择原操作UUID后，独立进程重新校验当前暂存并显示预览；不重新提取、不要求原外部备份文件仍可访问、不应用到活动曲库。

## 原证明读取

最多64操作，opendir有界目录列举；每次列表总读取预算128MiB，达到后说明只展示已读取部分，不删除剩余资料。来源JSON以严格9字段、规范UTF-8字节、固定操作目录和数据父目录、原物理身份、文件路径/名称及有界证据读取。prepared回执核对固定格式与版本、规范时间、规范完整字节及body SHA256、操作与原来源证明、manifest及preview所有数量/版本/摘要关系。

操作/数据父目录须保持原物理身份，暂存须是登记的唯一子目录且身份相同。不能按目录名前缀采用其它暂存、链接、未知或部分工件。检查记录损坏、来源登记不完整或未完成prepared则保留原资料，显示invalid/interrupted，不给出可使用预览。来源登记的文件证据是捕获时证据；重启读取不访问原外部文件，以便使用已完整准备的独立副本。文件证明和规范SHA是损坏检测，不是抵抗本机账户重写全部登记的签名。

## 当前暂存重新校验

新增固定可信Main frame的history/recheck接口，只接收UUID，不接受Renderer路径。recheck占用同一恢复owner，与备份/维护互斥，清除当前公开预览，保持原资料不变。仍使用固定独立恢复worker；stage模式执行新提取，check模式只读取原prepared证明所指的暂存。

check模式核对父目录和已登记暂存身份，离线检查schema68 SQLite头部/DELETE模式/integrity/FK/页面/来源及11表计数，再完整列举并重新计算所有文件SHA，要求与原manifest一一相同。Renderer待核对原文按检查句柄、大小及原SHA再次读取，只计算条数、不执行命令。只读过程不构造仓储或迁移，不读取原音源/备份容器，也不替换活动曲库。

Main仍要求严格顺序/预算消息、ACK及实际exit0。随后重新读取原source/prepared和核对链，要求原prepared原始文件SHA、原清单/目录身份和先前链未变化，pending条数相同，再独占写入并sync新的核对回执。`checks/0000.json`至`0015.json`仅记录规范checkedAt、原prepared字节SHA、暂存身份、pending条数、序号/前条SHA及自身body SHA；不改写原prepared。达到16条则拒绝再次核对并保留工件。缺口、部分记录或未知内容不能绕过。

历史显示此前准备/核对的日期；只有当前独立核对成功后重新进入ready预览。ready仍是暂存校验完成，不能证明原音源仍授权、插件权利适用、完整schema/领域约束通过或整库已恢复。取消、重载、休眠、服务退出和应用退出沿用实际进程所有权，失败不得发布成功预览。

## 后续与验证

本轮仅类型、源码静态和构建；未运行应用、SQL、worker、暂存核对、媒体、驱动或测试。MVP须验证真实重启、外部备份已移走而暂存独立可核对、记录字段/字节/链损坏、文件变更/缺失/未知目录、数据库故障、预算与取消交错、真实进程退出及界面。目录观察不提供OS排他锁，重算结果代表读取当时，活动恢复前仍须在维护边界再次核对。
