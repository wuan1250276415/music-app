# ADR-137 自然排序与发行日期精度

日期：2026-10-06。状态：0.131.0 源码实施，SQL／迁移、排序真值、性能和界面运行验收留到 MVP。对应架构 §10.1／10.2、FR05、WP05 与 AC09，完整检索功能尚未验收。

## 用户选择与执行顺序

曲目浏览增加 LibrarySort，提供默认、歌曲名称、艺人名称、专辑名称、发行日期和加入时间，支持明确升／降序。Shared 拒绝未知字段、无效枚举和无意义的默认降序；排序字段和方向经白名单生成 SQL，不拼入 Renderer 任意表达式。分类浏览原有名称／文件数量／发行日期增加方向选择。

默认曲目顺序保留专辑实体、碟号和轨号；人工发行使用逻辑轨 position，其余沿用源轨号。同专辑仍连续，名称自然序用于专辑名称和最终曲名。最近添加默认新到旧。自选名称／艺人／专辑／发行日期／加入时间应用于曲目列表；非主排序字段仍以稳定专辑、碟轨和 ID 解开同值，不把碟轨次序一并倒转。

歌单始终使用原 pj.position 和 entry_id，不允许替代排列，重复条目保留。文字查询的直接命中／精确匹配层级及近似距离仍先于用户排序；用户排序作用于同等级结果，近似结果不能挤掉明显精确结果。总数、版本折叠、分页及按查询播放仍共用 Library.list。

## 自然键

自然键先做 NFKC、Unicode 小写及首尾空白移除，再按完整文本编码为 BLOB。普通字符按 Unicode code point 的大端整数编码；连续 ASCII 数字保存去前导零后的有效位数、实际数字字节和原数字段长度。比较不把长整数转为 Number，因此超过安全整数范围也不丢精度；数值相同时较少前导零先排。全角数字经 NFKC 转为普通数字。未对标签文本做写回、截断或改名。

这是一致的数字自然序，不是操作系统区域排序：未增加中文拼音排序、全部语言校对、重音折叠、罗马数字或带符号／小数数值解析。数字段与字符段分别排序，标点继续保留，字符大小写／兼容写法同键时以既有实体和条目 ID 稳定解开。

schema61新增 item_sort_key，条目外键级联删除，保存算法／源指纹、title／artist／album／release四个 BLOB 键和发行日期区间／精度。提供标题、艺人、专辑和日期普通索引。艺人键取与当前界面一致的有效署名，包括人工身份／已确认署名；专辑键取有效发行标题。艺人分类优先用户 sort_name，空排序名称回退 name；分类键当前通过确定性 SQL 函数计算，独立分类后台投影仍未实施。

SQL 函数的自然键 LRU 最多2048项，文本和键有效载荷预算8MiB；大于预算的单值只计算不缓存，不为了缓存截断文本。缓存预算不代表全部 JavaScript 堆占用。所有键构造是完整文本的线性计算；超长字段、全库首次回退、SQLite CASE 排序及查询计划的真实成本必须在 MVP 验证，索引存在不代表每个组合查询必然使用。

## 日期范围与未知值

日期沿用严格公历校验，接受 YYYY、YYYY-MM、YYYY-MM-DD，保存原文本和精度，拒绝不存在的月份／日期。年、月对应可能日期的完整区间，日为单点：2024为2024-01-01至2024-12-31，2024-02为闰年2月的完整范围。端点用于排序，不作为真实发行日期写入或呈现。

升序按最早可能端点，降序按最晚可能端点；相同端点先列精度较高者，之后按自然名称／碟轨／ID稳定解开。区间重叠不证明某发行实际上早于另一发行。空、非法和未知日期两种方向都在已知日期后。界面注明“发行日期（保留精度）”，排序不代替录音日期或加入时间。

## 补建与修订

SEARCH_ALGORITHM 纳入 SORT_ALGORITHM，升级使用现有 building／ready／error、64条读取、25ms合作预算和持久 cursor。迁移建立空投影并重置构建检查点；构建逐行同时检查搜索与排序算法，防止已有搜索版本正确但新排序表为空时误判准备完成。缺少排序源抛错而非跳过。

SearchIndex.put 在判断原文搜索指纹之前检查实际排序源，所以只修改发行日期或排序显示来源时也更新键和 content_revision，不因搜索字段未变而漏更新。扫描、有效资料编辑、人工覆盖／撤销沿用原事务同步；删除清理投影。补建时未准备条目使用当前文本和日期的 SQL 回退键；艺人回退使用曲目文本，准备完成后切为完整有效署名。界面准备提示包含排序，补建期间顺序可能变化。

item_sort_key 纳入现有 item_* BrowseClock 触发修订；自然排序算法标识也加入分类快照，排序条件纳入列表／分类请求快照。补建、条件／方向变更或资料变化使旧分页和按旧位置播放请求失效。不会在 Renderer 收集全库后排序，也不会在翻页时使用未绑定旧快照。
