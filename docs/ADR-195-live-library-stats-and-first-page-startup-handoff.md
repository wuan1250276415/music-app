# ADR-195：实时曲库统计与首屏启动交接

日期：2026-10-12。源码0.189.0；完整目标未完成。

## 依据与实现

带诊断的0.188实际应用重复打开，搜索输入约一秒出现，但首屏等待11–12秒。Main／Library各最多64项、前30秒的方法耗时追踪定位到stats约9.6–10.2秒串行占用Library，后续browse／目录／歌单等排队。追踪仅显式AURAL_TEST和AURAL_STARTUP_PROFILE双开关启用，不记录参数、结果、路径、凭据或错误正文，生产不写日志。

统计仍基于当前事务可见资料：收集active可见项的署名与专辑轨引用，集合选择已确认或带artists来源状态的录音署名，按独立performer歌手存在性核对后合并规范身份；曲目须对应online文件，专辑／歌手仍包括有效但离线条目，不可用仍按missing文件计数。隐藏／removed／ignored项、非performer、身份绑定、确认／锁定／manual／automatic和功能开关在语义对照中覆盖。覆盖索引和顺序扫描调整不改变schema，不添加缓存总数，不更改SQLite缓存预算。

主界面ready-to-show仅表示原生画面条件。新回执由React实际首屏snapshot及初始播放／队列／统计／目录／歌单状态提交后的effect发送，不依赖隐藏窗口的动画帧。票据属于当前Main窗口／主frame／documentEpoch，导航时更新，关闭时清除；恢复链仍须原有实际证明，启动回执不能释放恢复。接口经现有受控维护入口，新增明确白名单及普通就绪／恢复／退出检查。

界面加载失败展示实际错误；首屏崩溃事件可更新失败状态，同时120秒交接期限覆盖未收到事件或回执的情况。超时回执不能揭示过期文档；计时器随文档加载重置，交接或窗口关闭取消，仅限数据库初始化完成之后的界面准备，不限制大库迁移。失败启动窗口继续保留独立退出按钮。

## MVP范围与证据

**0.189.0 曲库统计与首屏交接 MVP**：定位到十万合成曲库的统计查询串行阻塞首屏。统计改为先收集有效署名和独立歌手，再核对有效曲目／专辑，继续读取当前数据库，不缓存旧总数。13项原查询语义／独立真值、4种功能开关和十万只读对照通过；根1／曲目100000／歌手508／专辑5009／不可用0保持。

实际应用3次重复打开，首屏从带诊断的0.188约10.92–11.95秒降到3.34–3.90秒，Library统计约2.19–2.23秒；实际输入《夜曲》至唯一结果约331.8–344.3ms。不是OS冷启动、正式20轮检索或完整性能验收，三秒门槛未达。

主窗口须实际完成首屏和播放／队列／统计／目录／歌单读取后才交接；当前文档票据与epoch校验，外来票据／未知状态／完成后重复回执实际被拒绝。界面交接另设120秒上限，始于数据库初始化完成后，不缩短迁移／普通请求／退出期限。实际终止本次应用的独立主界面PID后，约121.5秒观察到失败状态并由启动窗口退出；生产崩溃事件即时通知路径及完整故障矩阵仍未认证。

真实schema72十万隔离副本升级／13类计数／唯一快照／精确查询／幂等重开通过，升级至查询约139.2秒、重开约3.55秒，原SHA保持。该升级运行在最后增加界面等待上限之前；最终Main另由正常启动及真实界面进程终止MVP验证，SQL／迁移不变。1100组分页对照、聚焦迁移／DDL回滚、实际MP3/WAV封面／详情／歌词／队列回归通过。构建／类型／原生／版本与分发清单通过，早期失败均保留。

schema73／音频IPC1.23／媒体14保持；0.189为源码，无新安装器，最新已验证内部试用包仍0.187.0，已验证安装流程仍0.29.0。完整FR01–14／WP01–11／G1–5／AC01–19继续，仅ASIO实机暂停。详见[ADR-195](ADR-195-live-library-stats-and-first-page-startup-handoff.md)。

报告：validation/v0.189-startup-profile.json、v0.189-stats.json、v0.189-startup-failure.json、v0.189-startup-upgrade.json及v0.189-checkpoint.json。baseline报告明确来自0.188版本加测试专用诊断的源码，不是未改动0.188发布归档的正式基准。报告保留原指纹，不重写历史0.187正式20轮结果。

## 失败和限制

第一版统计优化仍约5.7–7.8秒；进一步SQL计划诊断才采用目前的集合／存在性查询。早期四次统计夹具准备／断言错误记录保留；最终13项对照及4种开关、十万原SHA验证通过。第一次原生完整流水线被统一IPC入口检查拒绝，改回受控入口并更新明确白名单；额外启动票据守卫检查曾误放在注释同行，最终已拆行并置于输出前，最终清单检查通过。

最初把统计前已出现的《夜曲》误当成新搜索完成的诊断报告保留；最终必须等待精确“搜索结果 · 1 首”及唯一行。故障实验依次调用crash API、终止进程、CDP crash都未取得预期即时事件；只读观察证明原主界面PID已经不存在，而Main仍未收到相应通知。实际120秒兜底路径已验证，不能据此认证全部崩溃事件／恢复行为；故障报告和保留副本继续用于后续调查，没有改标旧失败为成功。

仍需十万物理扫描、现实完整语料、宽短词与端到端／OS冷启动／全进程内存／8小时，完整来源／封面／歌词／写回、复杂CUE／DSD、可视化／任务、恢复继续／回滚／重启／历史候选及故障矩阵、跨平台和Windows安装／升级／卸载／签名更新。所有原架构门槛保持。
