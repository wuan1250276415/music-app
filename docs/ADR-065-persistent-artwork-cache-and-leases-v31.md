# ADR-065：持久封面缓存、离线回读与资源租约

状态：0.60.0 源码实现；2026-10-01。schema v31；音频 IPC 1.8、内部媒体协议 3 不变。完整 FR01–FR14／WP01–WP11 范围继续保留，ASIO 实机验证仍暂停。

## 数据与来源

此前规范缩略图仅在进程内存在，重启或源文件离线后不能恢复。本次由 Library Service 的单写入 SQLite 管理 artwork_asset、artwork_claim 与 artwork_reference：分别存放按 JPEG 内容 SHA-256 去重的有界 BLOB、媒体文件与资源归属、每个文件／256 或 1024 尺寸的当前主候选。保存资产、归属和主候选在同一事务中完成，失败回滚；没有另写缩略图目录与外部索引，因此没有两个文件提交的崩溃窗口。

资产记录算法 wic-jpeg-v1、尺寸、字节数及创建／访问时间；来源记录原图片 token、内嵌／本地类型、标签、文件／目录观察摘要和确认时间。只保存 ADR-064 中受监督转换出的 JPEG，不把原音乐文件图片或在线 Provider 图片存入此模型。读取前核对算法、长度、JPEG 头和内容摘要，损坏条目删除并级联失效归属／候选；源文件可读取时重新生成。摘要校验是损坏发现机制，不是任意恶意 SQLite 重写的完整安全证明。

Renderer 收到资源地址、来源／尺寸／缓存状态；规范 JPEG 字节通过内部资源请求按曲目 ID 与资产 ID 获取，检查归属后才返回。Main 再核对长度、JPEG 头与 URI 摘要。未知资源地址没有任意文件读取能力，资源 API 不接收本地路径。原有源文件路径、同句柄复核、候选优先级和转换监督继续由 ADR-064 负责。

## 生效与离线显示

在线且观察未变化时可直接读取已确认缓存；本地 sidecar 候选仍每 30 秒过期重读，内嵌候选在观察一致时可复用。当前观察包含音乐文件与目录属性，不等于完整 Windows File ID 或 sidecar 内容身份；网络挂载改写、稳定等待、监听与更精细来源检查仍待实现。

曲目离线或文件属性暂不可读取时，显示该文件已保存的主候选，并标明离线缓存。仅保存了另一尺寸时可回退到该尺寸，提示较小／较大封面；这不假装已经生成请求尺寸。普通重读失败时可显示旧主候选，明确标为旧缓存；授权边界异常与未确认监督退出继续抛出错误，不降级成正常新来源。

成功读取且确无可用图片时清除该尺寸的主候选，避免永久显示已经移除的封面。Renderer 为加载失败拒绝某 token 后取得的回退资源可以缓存，但不覆盖主候选选择。主动刷新只在第一轮强制读取，不再先读一次 URI、随后用另一请求把旧缓存误报为刷新成功；提示区分新读取、离线回读和失败保留。

缓存按媒体文件 ID 关联，CUE 共用引用音频资产；它不把封面绑定到整个 Recording 或所有同名专辑。复杂替换／改名、录音复用和人工封面来源选择仍在完整范围内。

## 容量与租约

当前逻辑容量上限为 512 MiB 规范 JPEG、16384 资产、32768 文件／资产归属，每张 2 MiB；主候选最多两种尺寸。访问更新 LRU，新增事务内逐出最旧的未使用资源或归属，级联清理失效主候选，保护当次新资源。空间全部被有效租约占用时拒绝新增并回滚，不突破声明容量。

此处限制活动 BLOB 的逻辑总量，不能据此声称整个 library.db、空闲页、WAL、迁移备份或瞬时写入峰值只占 512 MiB。完整磁盘配额、保留期限、压缩整理和用户缓存设置仍待实现。删除／保留边界和真实十万曲负载需单独验证。

可见 Artwork 消费者用独立 UUID 持有资源；卸载在 retain 完成后再 release，提前卸载的等待消费者不新建租约。Library 与 Main 各限 256 租约，保护对应资产及文件归属；Main 描述 LRU 也保留已确认租约。Main 仍只保留 64 MiB 图片字节，逐出后可从已授权持久资产重读，不要求源音乐在线。

页面加载／重载、Renderer 退出和窗口关闭清除当前单窗口所有服务租约，包括可能丢回执的 retain。Main 为文档生成 owner UUID，旧文档不能重新 retain；等待 retain 在文档代次改变后补偿 release，IPC 同时核对当前主 frame。租约不写入数据库，服务重启自然释放。当前只有一个 UI owner；多窗口时必须按 owner 分区清理，不能沿用全局清理。丢回执、页面竞态、租约上限与进程崩溃行为仍需 MVP 故障验证。

## 迁移与验证

v31 迁移先建一致备份，再事务创建三张表并更新版本；旧记录从空缓存开始，不猜测过去图片。原 v30 CUE 迁移加入版本分支，旧版上限拒绝 v31。既有历史 schema 辅助脚本与四处最新版本断言同步到 v31；本批未执行 SQL 或迁移。新缓存可派生重建，不更改歌曲来源／收藏／评分／队列／歌单。缓存 BLOB 会进入曲库备份，后续备份容量与清理需按完整保留计划处理。

类型检查、Main、Renderer（64 模块）、音频／凭据／媒体监督及图片组件编译通过；发行与分发清单一致性、历史 schema 辅助脚本及解包验证器语法仅静态核对。解包验证器增加持久缓存模块哈希，本批没有实际打包。没有运行封面、资源协议、SQLite、迁移、重启／离线、桌面、音频或安装包验证；按用户要求集中到 MVP，最新已验证安装包仍为 0.29.0。

MVP 必须覆盖两种尺寸持久回读、共享图片去重、多文件归属、重启与真实离线／重连、仅有另一尺寸回退、内嵌优先与主动刷新、成功缺图清除、失败保留提示、候选拒绝不覆盖主选择、算法变化、内容／长度损坏重建、未知与错误归属资源、LRU 及全部被租约占用、事务失败／崩溃、页面 owner 竞态／丢回执、服务重启、v30 备份迁移／回滚／旧应用拒绝，以及 BLOB、WAL 与备份的真实磁盘／查询负载。

FR04 封面与 WP04 仍未验收。独立 WebP codec、完整方向／颜色处理、Provider 封面授权及清理、磁盘管理 UI、完整文件身份／授权撤销、统一任务与故障恢复、跨平台及多窗口能力继续开发。
