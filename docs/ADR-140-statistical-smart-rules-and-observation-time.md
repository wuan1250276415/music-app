# ADR-140：统计条件、滚动日期与播放观察时间

日期：2026-10-06。状态：0.134.0 源码实现；SQL／迁移、规则真值、性能和界面运行验收待 MVP。对应 FR04／FR05／FR07、WP05／WP06、架构白名单智能歌单及 §16.2。

## 可保存的规则

MusicFilters 新增以下白名单条件，沿用现有组间 AND、来源范围、资料／风格／源音频／收藏评分规则及 BrowseQuery 智能歌单 DSL。

| 条件 | 严格含义 |
| --- | --- |
| playCount: min/max | 已达标的 session+entry 次数，闭区间；缺少统计视为 0。估算时长和点击播放不增加次数。 |
| lastPlayed: never | 没有任何已保存的、有正进度的播放记录；与“达标次数为 0”不同。 |
| lastPlayed: within-days | 最近 N×24 小时内有保存的进度观察，不要求达标；按分钟精度取窗口。 |
| lastPlayed: outside-days | 最后一次进度早于窗口起点；必须明确 includeNever 是否包含无记录歌曲。 |
| addedWithinDays | 最近 N×24 小时加入曲库，依据已有 added_at，不把重新扫描当新加入。 |

次数限制为 0–Number.MAX_SAFE_INTEGER，min≤max；天数为 1–36500。各模式只能使用其指定字段，unknown key、数组／文本数字、缺失天数、无意义 includeNever、负数和倒置范围均拒绝。所有 SQL 数值与时间通过参数绑定，列名和模式来自白名单。旧版无统计条件的 version1 规则保留原规范化方式；新增字段需要支持 schema64 的应用，旧软件不能打开新库。

条件同时用于歌曲列表、分类成员／总数／代表封面、保存的智能成员查询及额外交互条件。只在需要统计的计划中 JOIN playback_item_stats，不物化全库条目 ID；已有 CUE 条目、离线可用性、同发行版本折叠和模糊召回范围规则继续共用原计划。复制当前条件为智能歌单或编辑规则即可保存次数与相对天数；规则持久保存天数，不保存某次界面计算得到的绝对截止时间。

组合筛选增加次数上下限、无记录／近期播放／长期未播、包含无记录选择、近期加入和常用30天按钮。这些按钮只调整对应时间条件，保留其他组。统计刷新通常受既有15秒检查点频率影响；已提交的播放队列不会随成员变化自动重写。

## 播放时间与存储时间分离

上一批 last_played_at 使用数据库提交时间。旧的待保存检查点在重启／故障后重试时会被错误地视为最近播放。本批新增可选 observedAt：Main 只在记录正的源进度区间时捕获 UTC 墙钟标签，沿待保存文件和同一检查点送到 Service。听歌微秒仍完全来自已校验的源帧／DSD 位时钟差值，墙钟不参与时长、seek 和达标计算。

同一历史和每曲最后观察时间取已知最大值，晚到的旧检查点不覆盖更晚播放，墙钟回退不使既有时间倒退。观察时间不属于不可变曲目身份 JSON，也不改变 startedAt；新的检查点摘要包含 observedAt。再次提交同一检查点仍核验原载荷摘要。

旧13字段检查点继续被严格读取，不追加默认字段到其规范化载荷，保留已存回执的 SHA256，旧 version1 待保存文件可以继续核对。缺少观察时间时只使用原 startedAt 并明确 legacy-start 证据；禁止拿新的提交时间补造观察。新历史页返回 observation／legacy-start 来源并展示最后进度时间。旧记录只有首次观察标签，不能恢复当时最后一个播放采样的时间。

schema64 在升级前一致性备份并事务增加 history.last_observed_at／observed_basis 与 stats.last_played_basis。历史时间回填 created_at，每曲回填其历史中最大首次观察标签，保留累计时长、次数、原曲目身份、检查点和不可变摘要回执。新增播放次数／最近播放索引。生产库降级不支持；现有迁移测试辅助函数只允许空历史／统计夹具降级，拒绝丢失真实时间数据。未执行这些 SQL 或辅助函数。

## 查询时间基准和快照

服务端为一次列表／分类／播放上下文请求捕获 UTC 分钟起点；共用起点计算成员条件、额外条件、COUNT、分页及最多5页播放范围。窗口下界为该分钟起点减 N×86400000，包含下界；近期窗口上界为下一分钟起点，不包含上界。采用 UTC 连续时长，不采用本地日历日或夏令时日。系统时钟错时仍会影响日期标签与相对窗口，不影响源进度累计。

只有包含相对条件的查询快照加入分钟基准；跨分钟、跨查询、统计／库修订变化均拒绝旧页或旧播放范围。不会允许 Renderer 任意提供过去的锚点伪装成当前结果。智能歌单的保存条件和外部附加条件用同一个锚点，不出现内外规则跨分钟取值不同的情况。

PlaybackStatsClock 使用连接本地 TEMP 表和 insert/update/delete 触发器，在同一数据库事务里分别跟随次数和最近播放修订；回滚也回滚修订。只在依赖统计的快照中加入对应修订。普通无统计查询和智能歌单的名称目录不因15秒进度写入失效。“无记录”目前保守依赖最近播放修订，可能随正在播放的记录再次刷新，后续性能验证可单独拆分存在性修订。

Service 在检查点提交完成后按实际变化发布 playbackStatisticsChanged(counts,recency)，重复回执不再次发布。Main 原有三字段保存回执保持。Renderer 用当前可见外部条件和所选智能规则判断依赖，只更新对应浏览修订；不会因此重新读取歌词、封面、曲目资料或持久队列。相对视图按分钟以及窗口回焦／可见恢复检查时间基准。SQLite 触发器是快照正确性的依据，UI 通知用于刷新体验；没有通知时后续分页和播放仍核对快照。
