# ADR-227：标签写回、真实界面与进程中断恢复 MVP

日期：2026-10-16；源码0.221.0。完整FR01–14／WP01–11／G1–5／AC01–19继续，FR12／AC12未完成。

## 用户流程与实现

在标签差异已保存并生成备份／临时文件后，增加独立确认及“写入已确认的标签”。Main接收封闭UUID／修订／证书请求，先核对原回执；新请求先复核已暂存任务与实际来源，由现有播放协调器停止读取同一文件的当前／循环／预载播放，再调用原Library协调器。Library继续执行实际权限、当前元数据、目录、完整文件、租约和阶段日志核对，不信任界面判断。新增停止请求有独立不可变回执，等待真实原生退出并保留工件，后续按实际文件恢复。

四文件核对后可选择从保留旧文件或来源备份恢复；重启后的续办沿用0.220的有界不可变尝试链。Main／preload／Service与Renderer现已贯通，普通页面不能提交任意路径或代码。写入／恢复仍需静态目录中的独立证书，能力标志也从目录派生；未认证时显示预览与暂存能力并拒绝执行，不通过环境变量或普通IPC放行。

确认框固定16×16、同排显示。新操作错误使用既有userError去除内部调用前缀。视觉检查发现恢复完成后仍展开旧“尚需恢复”说明，已改为当前状态与历史分开：完成后默认收起旧核对和执行说明，保留用户主动查看原记录的能力，明确显示原标签与曲库已恢复及歌曲可用。

## 候选组合与真实9项验证

`npm run test:tag-writeback-mvp` 创建专属D盘测试根、编译固定根限定的候选原生事务；复制生产Main／Library编译文件和Renderer源代码，除两个生成认证目录外逐字核对。Renderer使用同一Vite配置重新构建，依赖及生产只读原生组件通过专属目录映射。Main由原入口执行，Service包装器仅在真实日志advance完成、已同步之后加入受控确认屏障；不伪造文件阶段或进程成功。

1. 通过正常目录选择、Main／Service监督扫描导入四个生成FLAC，打开独立任务中心，能力标志与候选静态目录一致。
2. 点击明确确认和写入按钮，经Main／preload／Service／原生实际写入；同文件静音循环播放被停止并释放。音频完整摘要和备份不变，更新曲库前歌曲不可读，确认框实际尺寸通过。
3. 点击四文件核对和重新解析，更新同一曲目标识；正常Main退出重启后标题与可用状态保留，原写入请求通过Main重放不重复执行。
4. 点击备份恢复；真实恢复在displaced文件日志已同步、数据库阶段ACK前等待。强制终止实际自有Main／Utility／原生进程树，原路径明确缺失，原备份保留。
5. 重新启动并点击六文件核对，独立读到fs-ahead与target-displaced；旧恢复副本、被移走目标及原证据均保留。
6. 点击“使用备份继续恢复”，创建新尝试并恢复原文件字节，保留旧副本／目标，界面展示两次尝试。
7. 点击原来源重新解析，恢复原标签、曲库和读取可用状态；重放原恢复请求不创建第三次尝试。当前状态正确，旧核对说明默认收起，截图已目视检查。
8. 在真实commit intent日志同步后暂停阶段确认，点击停止写入，再释放受控屏障；等待实际原生退出，原文件不变，备份／临时文件保留，独立四文件核对为unchanged-staged，停止原回执可重放。
9. 暂存后物理修改生成来源，真实Main目标复核拒绝写入，不创建提交操作、不改备份或新来源；界面错误没有内部IPC方法前缀。

首轮在写入已经成功后因测试误把释放后的idle预期为stopped而失败，报告保留；修正断言后继续完整验证。最终9项与早先0.220预备运行的版本范围明确区分。
