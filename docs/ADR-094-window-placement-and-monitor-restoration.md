# ADR-094：窗口位置、最大化与显示器恢复

日期：2026-10-02。状态：0.89.0 源码实现；运行验收待 MVP。

## 范围与选择

落实架构桌面体验工作包中的窗口状态恢复。歌曲内嵌封面优先、播放栏封面进入详情、信息检索、滚动歌词、模式与队列保留。本批次只增加桌面窗口行为，音频 IPC 1.19、schema v38、媒体协议 6、独立系统媒体协议 1 不变。

Main 的 `WindowPlacementManager` 独占窗口几何管理；`Appearance` 继续观察主题、缩放和显示器密度，不再移动窗口。Renderer 只有打开原生设置的接口，不能提交任意坐标或直接操作窗口。

## 持久数据与恢复

使用已有 `app_setting` 的独立 `window_placement` 键，无新表或 schema 迁移。版本 1 保存修订、是否记住位置，以及可空的普通窗口边界、最大化状态、显示器 ID／名称、旧工作区和密度证据。严格限制字段、整数坐标／尺寸、字符串和有限密度值；读取失败或损坏时使用默认窗口并暂停写入，不能把默认值覆盖到未确认的数据。

坐标和尺寸采用 Electron DIP。根据相同 ID 和名称匹配当前显示器；在工作区原点或尺寸变化时映射原有相对位置，保持 DIP 尺寸并裁剪到当前工作区。没有匹配显示器时在主显示器居中。允许负原点，不按保存和当前密度再次乘除。启动时先建立普通窗口，再在 ready-to-show 应用最大化。最小化、全屏和托盘隐藏不作为下次启动的状态，重启不恢复播放。

Main 从 `getNormalBounds()` 采集恢复边界，使用实际窗口所在的显示器作为锚点；最小化和临时全屏期间不采集。普通窗口的标题区域不可达，或窗口尺寸大于当前工作区时，进行工作区裁剪。显示器变化合并 150 ms；最大化、最小化、全屏时不主动争夺系统窗口管理，恢复普通状态时再核对可达性。

## 保存和退出

移动／调整尺寸／最大化／隐藏采用 450 ms 合并周期，最多一个正在保存的请求与一个最新待保存位置，不为每个拖动事件建立队列。严格修订 CAS，成功保存后才更新已确认偏好；保存报错先回读，只有完整下一修订匹配才认定成功。无法回读或修订不一致时暂停自动保存，通过设置入口重新读取。RPC 每次有 1.2 秒期限；超时不表示数据库一定没有提交，下次读取是结果依据。

侧栏和托盘均提供“窗口位置与显示器”：记住当前位置、下次使用默认位置、重置当前窗口、取消。禁用清空保存位置；重置先确认保存，再取消最大化并回主屏默认尺寸，随后可保存新的默认位置。全屏下重置需要先退出全屏。原生窗口设置不修改关闭／后台运行的独立偏好。

普通退出先采集最后位置，同时立即停止音频并清理媒体会话、通知和桌面控制。几何保存最多等待 1.5 秒，再关闭几何管理和曲库进程；重复退出事件不会启动重复保存。每个资源清理独立保护，一个清理异常不能阻止其余资源释放。这个期限可能放弃尚未确认的最新位置。Windows 关机／注销未必触发 before-quit，因此日常自动保存是主要保障；不能承诺硬退出的最后一次移动一定保存。

## 证据与待验收

本批次仅做类型／构建、原生编译、发行／分发清单和脚本语法静态核对。没有运行 Electron、实际歌曲、音频、SQL／迁移、Provider、安装器或 gold EXE；没有生成新的安装包。

MVP 集中核对：普通与最大化重启、负原点双屏、拔除原屏、任务栏／工作区变化、不同 DPI 跨屏、最大化后移动屏幕、最小化／全屏／托盘退出、禁用和重置、曲库繁忙／提交丢回执／损坏偏好、重复退出和 Windows 注销。macOS／Linux，特别是 Wayland 的移动和尺寸限制，需要目标平台验证；完整多显示器身份和窗口管理兼容性尚未验收。
