# ADR-031：发行实体合并与拆分（schema v9）

日期：2026-09-30。状态：开发原型采用；WP03 与发布门槛仍未验收。

## 问题与行为

相同专辑可能分散在多个音乐目录，或一次扫描候选包含多种实际发行。仅关联 ReleaseGroup 无法纠正发行成员；把同名文件直接合并会误认录音和文件版本。

从曲目或播放详情的“整理关联”进入“整理发行版”，可将两个完整发行版合并，逐碟确认目标碟号；也可按逻辑发行曲目选择部分成员，填写名称、日期、国家／地区和版本说明，拆成新发行。预览显示实际来源目录、曲目及文件数，按页加载曲目。人工操作不移动文件、不写标签，不改变 PlayableItem、MediaFile、收藏、评分、歌单重复 entry 或播放队列的身份。

## 领域与存储

- 合并与拆分创建新的 `manual-release:` Release。原发行、介质和发行曲目保留，供审计与撤销使用。
- 合并使用目标发行信息，复制不可变专辑署名，保留概念组及发行字段。拆分使用原发行的其他字段及概念组，应用用户填写的四个字段。
- 按旧 ReleaseTrack 复制到新 Medium，并通过现有 `item_catalog_binding` 原子地更新每个 PlayableItem。同一旧 ReleaseTrack 的所有当前文件版本共享同一个新 ReleaseTrack；Recording ID 保持不变。
- 保留曲目标题、印刷轨号和署名快照。同碟冲突保留为不同曲目，按目标发行、来源发行和各自原有轨序生成唯一存储 position；同名、同印刷号不代表相同录音。用户可以另行确认版本关联。
- 介质映射保留每个目标碟首个来源介质的名称及格式；合并到同一个目标碟时目标发行优先。需要分别保留介质身份时应映射到不同碟号。
- 人工发行列表按 Medium 碟号与 ReleaseTrack position 排序，原始本地候选继续使用标签轨号。播放详情显示有效发行碟号与印刷轨号，兼容原始标签仍独立保留。
- `release_change` 记录动作、标题、前后成员绑定与修订、发行指纹、时间和撤销状态，与已有曲库/艺人修订统一查询及撤销。人工发行无需新的绑定表。

## 并发、恢复与迁移

发行预览包含 revision 和 SHA-256 指纹。指纹覆盖发行信息、来源根路径及所有当前成员（包括隐藏 CUE、缺失文件、离线根）的 ID、有效曲目／录音、碟号、position、介质／曲目信息和成员曲库修订。扫描添加成员、后续版本关联或整理均会使旧预览失效。每次操作在单写入 Library Service 的 `BEGIN IMMEDIATE` 内重新检查。

命令采用 UUID 与规范化参数摘要，成功回执与实体、搜索、修订在同一事务提交，跨重启可重放。撤销检查全部后置成员与发行指纹，防止吞掉后续添加的文件，即使已有目标项修订未增加也会拒绝。撤销恢复原绑定或当前本地候选，修订继续递增，人工快照不删除；存在后续修改时需刷新并重新整理。

已有 v8 库先 `VACUUM INTO` 留下 `.pre-v9-*.bak`，再事务创建审计表、更新投影指纹及搜索、升为 v9。仅因投影增加发行轨序字段而变化的指纹不增加已有修订，以保持 v7/v8 修订的撤销兼容。DDL 失败回滚到 v8。支持旧版本的既有迁移链，但真实用户库恢复验收仍待补充。

## 验证与限制

单元测试覆盖完整发行合并、共享文件版本拆分、同碟印刷轨号碰撞、介质字段、录音身份／用户引用／队列保留、重扫／重启／命令重放、成员冲突、无效输入、后段故障全事务回滚及 v8 迁移备份／DDL 回滚。桌面 smoke 使用真实 ID3 MP3 及内嵌图片，通过实际界面确认、播放、详情检索、修订撤销、强制重读标签和重启检查。

每次最多整理 5000 个当前文件；API 支持 2–100 个发行合并，首版 UI 每次合并两个。发行候选、曲目预览每页最多 100（UI 50）。扫描未引用的旧轨目不被搬移或删除。错误折叠为同一逻辑轨的文件，应先恢复或更正版本关联，再拆发行。

尚未提供发行字段全量编辑、来源／锁定、艺人创建、外部实体引用、任意 CUE 改写对账、合并后轨序拖拽或审计垃圾回收。成员指纹和人工命令仍需十万库／长时性能验收；Windows 最小窗口下主页面已有横向溢出仍待 WP05 处理。ASIO 实机验证继续依用户要求暂停。
