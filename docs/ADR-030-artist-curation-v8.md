# ADR-030：人工艺人身份与逐曲署名（schema v8）

状态：已实现开发版，2026-09-30。对应 WP03/05 的艺人身份、署名顺序、角色和连接词；WP03 整体仍未验收。

## 数据与身份

文件标签生成的 artist 候选继续按授权根隔离，保留原始名称和稳定 ID。姓名相同不自动认定同一个人，`AC/DC` 等名称也不按斜杠拆分。

`artist_identity_binding` 将来源候选关联到不可变的人工确认 artist 快照。第一次关联复制目标候选；目标已有确认身份则复用该身份。一个候选只能关联一个确认身份；确认身份不能成为来源，因此没有别名链或循环。显式 FK、唯一键、CHECK 和插入/更新触发器共同约束关系。不会删除来源或确认身份，也不会改音乐文件。

艺人分类、详情链接、按角色/身份 ID 检索、搜索索引和统计使用生效身份；原始标签名称继续可检索。关联适用于所有使用这些候选的有效曲目署名及发行版专辑艺人，离线/隐藏曲目也保留引用。解除一个来源关联可以把该候选恢复独立身份，其他候选仍保留确认结果。

复合标签的原始呈现文字继续保留，例如 `甲 feat. 乙`。不会从多值 Artists 标签反推连接文本。单艺人候选的确认名称可以作为显示名；多艺人文字仅在用户主动编辑署名时重建。

## 逐曲署名

`item_credit_binding` 把 PlayableItem 绑定到不可变的人工 artist_credit，独立于可重扫的本地 credit 候选和文件版本/录音绑定。编辑支持现有艺人选择、顺序、曲目歌手/作曲/指挥/乐团角色，以及每位歌手之后的连接词。至少保留一位曲目歌手，最后一位歌手的连接词必须为空；同一艺人同一角色不重复。重排保留用户已输入的连接词，不静默清空。

新 credit 保留全部成员和顺序；显示文字按歌手顺序与显式连接词组成。参与角色用于对应分类筛选。逐曲编辑不改变发行版的专辑艺人；恢复本地署名会使用最新扫描候选，全局身份关联继续生效。重新扫描更新原始候选，随后重新应用人工绑定。

编辑入口：曲目旁的“整理关联”→“整理艺人与署名”，播放详情的“整理关联”也进入同一入口。界面提供“此曲署名”和“跨目录艺人身份”两个操作；身份确认前展示来源、目标和目录。所有操作进入统一曲库修订记录。

## 事务、回执与撤销

候选身份有单调 revision，逐曲署名复用 item_catalog_state revision。来源及目标的基础修订都需匹配；署名编辑的每个所选艺人也需携带身份修订，避免确认前身份变化使结果与预览不同。编辑过的曲目需要重新读取后确认。

身份/署名、索引、修订审计和成功命令回执在一个 BEGIN IMMEDIATE 事务内保存。UUID 命令 ID 与规范化参数摘要绑定；相同命令跨重启重放原回执，不再次执行，不同参数不能复用该 ID。前端在结果不确定时保留原命令 ID。

artist_change 保存修改前后来源绑定、曲目人工 credit、修订及曲名。与 v7 catalog_change 以 UNION ALL 分页展示。撤销先检查全部受影响来源和曲目的后置修订，再原子恢复绑定；后来编辑或相关标签改动使撤销拒绝，避免覆盖新工作。后来扫描新增的引用曲目也随身份恢复刷新。撤销自身留记录，确认快照不删除。

## 迁移与验证

已有数据库在 v8 DDL 前执行 VACUUM INTO 一致 pre-v8 备份；DDL、投影指纹和搜索更新在同一事务内完成。仅投影增加字段不改变既有 catalog revision，因此 v7 修订仍可正常撤销。失败回滚新增表、索引及触发器，版本维持 v7；降级应恢复备份而不是让旧应用打开 v8。

新增领域测试覆盖同名隔离、全角色/检索生效、复合文字保留、绑定触发器、解除/撤销冲突、署名顺序与角色、重扫、规范化回执、重启，以及 v7 一致备份、旧修订撤销与 v8 失败回滚。

桌面测试从隔离 v7 库升级，在界面确认两目录艺人、详情链接检索双方、编辑连接词/角色/顺序、恢复并撤销署名、等待实际标签重扫完成，再重启核对人工署名、收藏评分和重复歌单。最终测试与发行证据见 README 的 0.25.0 记录；运行 `npm run test:artists`。

## 未完成范围

目前只选择已有本地/确认艺人，不提供任意创建与重命名、艺人外部引用和别名来源管理。全新人员创建、发行/录音层署名专用编辑、更细演奏角色、权限/字段来源和锁定仍需后续契约。发行实体整体合并/拆分、呈现时钟历史、智能歌单、大库键集分页与十万曲性能、真实用户库恢复也未完成。ASIO 验证仍按用户要求暂停。
