# ADR-193：排名文字缓存与后半段取页

日期：2026-10-12。源码：0.187.0，schema73／音频IPC1.23／媒体14保持。状态：聚焦MVP；完整十万库性能与V1验收仍未完成。

## 问题与实现

0.186组合检索p95约231.7ms，深页约2434.4ms。不同页面重复对同一候选集排序，使标题繁简转换反复执行；深页的正向探查还要保留大量前面的排序位置。

每连接的纯文字转换缓存扩展为标题、艺人、专辑和风格共用，最多16384项、4MiB的UTF-16键值文字；FIFO淘汰。实际文字是键，标签或覆盖资料改变后不会取得旧转换值。不缓存排名、查询结果或歌曲对象，不改变繁简／精确／前缀／包含／错拼的原排名层级。大于256字符的查询继续走无保留的原路径。

第一轮正式复测显示，近全库单字查询触及的文字超过容量，会反复淘汰并增加分配和GC，宽单字p95升至约1996.8ms，组合仍约204.6ms且exit1。增加每个查询的写入额度：最多再写一份缓存容量，之后仍执行完整转换但不再反复写入／淘汰。改变查询后重置额度，已有文字按实际键继续可复用。原失败报告和源码指纹保留，不把第一次诊断结果当验收。

分页在同一次候选快照中取得精确总数N、请求位置O和页长L。请求位于后半段时，按前缀的逆序探查，探查偏移为 `max(0,N-O-L)`，长度为 `min(L,max(0,N-O))`；前半段仍正向取页。探查方向只影响边界定位，随后展开两端完整同分桶，计数原顺序中边界前的条目，按原完整次级顺序及原位置取结果。最终页不会倒序，空页保留精确总数；歌单仍保持重复条目和手动顺序。

## 已有证据

- 1100组与原完整关系排序的有序页对照通过，包括同分边界、旧／缺失派生键、升降序、收藏／目录／版本折叠，以及页长1／7／25／100、半数位置、不足一页的尾页和越界空页。风格／质量／年份／署名／统计仍有独立清单断言。
- 同一保留十万合成目录，与原0.184完整查询的六组顺序和精确总数一致，包括首屏、深页、艺人／标题方向和组合检索尾页。混合参考查询耗时不作为正式性能采样。

## 完整应用升级验证

新增可选 `electron-startup-migration.smoke.cjs`：显式指定受控schema72十万快照，先检查结构／计数和空间，校验SHA后复制到独立临时目录，运行真实Main／Library完成升级。验证实际窗口和IPC返回十万条及精确曲目，关闭后核对schema73与13类原计数、唯一schema72升级快照，再实际重新打开且不重复迁移，最后核对原快照SHA。成功只清理新建的测试目录，失败保留副本。

实际Main／Library测试通过：D盘本地NTFS上的隔离副本升级到可查询约148.2秒；schema73、十万条和精确曲目、13类计数及唯一schema72快照核对通过。第二次热重开到可查询约6.8秒，没有重复迁移；原保留快照SHA不变，成功后只删除这个新建测试目录。生产保留目录和原快照未被删除。

测试不是物理扫描，也不认证原音乐、ASIO或DSD。首次包含升级，第二次包含Electron自动化连接、界面和实际IPC查询，均不是OS冷启动指标。此D盘升级短于旧180秒，并不单独证明C盘超过180秒时的完整应用表现；45分钟初始化期限还有0.186的C盘实际数据库294.6秒升级依据。热重开仍慢，启动3秒／端到端和全进程内存继续，不能把单连接44ms重开当作完整应用启动。完整报告见 `validation/v0.187-startup-upgrade-mvp.json`。

## 大库窗口保存问题

十万应用升级截图发现窗口位置自动保存暂停警告。独立实际应用MVP复现：调整窗口后，初始几何写入实际落库，但仅1.2秒的保存及重读期限先超时，Main把状态视为未知并暂停后续写入，目标大小没有保存。失败exit1及副本保留。

几何操作现在使用普通15秒请求期限，退出仍由既有独立1.5秒收尾截止和原Library实例终止限制，不用加长几何调用期限来延长退出。相同十万语料隔离副本：改尺寸、实际SQLite偏好revision2、没有暂停警告、正常关闭／重新打开及精确恢复1080×720、原目录SHA不变通过。此修正只涉及Main请求期限；此前升级运行的迁移／查询代码与最终SHA一致，最终Main又由十万重开／窗口MVP和最终包运行验证，不把旧Main的升级日志改写为最后修改后重跑。

打包核对从既有关键模块增加到全部编译应用文件（排除配置明确不分发的map），分别校验Main、Library和Renderer各文件的SHA，继续保留依赖、格式、原生二进制和许可检查。首个包的安装器／静态报告保留用于追溯，最终包重新生成，避免只验证版本号而遗漏最后Main修复。

类型／前后端／原生构建、实际文件和界面回归及最终工件记录见 `validation/v0.187-checkpoint.json`。仅ASIO实机暂停，FR01–FR14／WP01–WP11／G1–G5／AC01–AC19全范围保留，继续完整来源／写回、复杂CUE／DSD、可视化／任务、恢复故障、跨平台与发布验证。

最终解包程序详情首测在封面截图时超时，失败exit1保留，不能据此宣称画面验证完成。测试改为显示并聚焦实际窗口后复测exit0，保留图片来源、解码及画面像素断言：MP3/WAV内嵌／旁置／播放栏／详情封面、歌词定位与滚动、队列／模式／歌手专辑检索通过，正常关闭无封面租约IPC失败。原日志中的过期浏览拒绝是预期保护检查。输出日志报告MOONRIVER 3共享模式，但明确hardwareVerified=false；这不新增独占、ASIO或DSD硬件认证。测试辅助代码变化不改变编译应用，但分发清单记录测试文件SHA；最终清单检查发现两个测试来源指纹陈旧，需要刷新清单并重新打包、核对和验证，不能把较早安装器视作清单已同步的最终工件。
