# ADR-126 原生标签提交日志与持久回执

日期：2026-10-04。状态：0.120.0 内部源码；schema51。运行验证集中到 MVP，认证目录为空，无桌面执行入口。

## 目标与现状

落实架构 §12.2 和 WP09 的逐阶段证据与写入协调。ADR-125 的原生提交进程需要可靠调用方：收到 stage 后必须保存文件系统日志和匹配数据库回执，再允许原生进程继续。本批次接上内部协调器，保留实际退出结果，并明确原生文件已核对不等于曲库已提交。FR12/AC12 尚未验收，全架构 FR01–FR14、WP01–WP11、G1–G5、AC01–AC19 范围继续。

## 启动与审核

内部 startCommit 使用严格 UUID 原命令和确认字段。已保存命令先回读；新命令必须存在受控发行认证，当前 certificates=[] 在取得租约和文件访问前拒绝。Main、服务分派、preload、桌面没有执行入口，也没有许可覆盖参数。

提交要求当前 prepared、原暂存执行 staged、任务修订和内容修订一致、无其他活动租约。schema51 事务保存提交操作、新租约/旧文件工件身份、原命令回执，并将标签任务置为运行；先于创建文件日志或启动文件工作进程。保留原计划及暂存日志不变。

按新租约阻止解析、扫描和服务读取，等待解析/分析退出。35 秒内未退出即保留占用进入恢复。检查冻结目录、完整文件观察、曲目文件绑定、标签审核及来源权限；再次运行只读原生核对并等待其实际退出。核对结果必须完整等于原暂存来源/临时文件证据，再冻结单独的认证计划与实际三文件/目录物理身份请求，并链接旧暂存日志 SHA。

原预览审核指纹包含暂存前租约修订。仅在持有新提交租约且内容修订、原执行计划和文件绑定一致的内部路径，使用原暂存租约修订减一重建审核基准；其他元数据、权利、内容、目录字段全部读取当前值。新提交租约不能沿用旧暂存租约身份。过期权利或资料变化拒绝继续。

当前没有 Main 播放停止命令入口。未来开放桌面入口前，必须把当前/计划播放及分析来源释放串入 Main 的序列化协调，沿用已有暂存停止机制；服务读协调不等于证明音频宿主已释放。当前原生核对或独占打开若遇播放占用，会失败并保留恢复占用。

## 文件系统日志和数据库回执

日志保存在 dataDir/tag-commit/operationId/0000.json 至 0005.json。0000 冻结绑定；其后依次为 locked、intent、victim_moved、replaced、verified。canonical JSON SHA 链包含时间、前一摘要及原生严格阶段回执。wx 独占创建、fsync、关闭后重新有界读取，再保存 matching DB receipt。初始最多 512KiB，阶段最多 64KiB，最多六条/1024操作目录；目录/文件重定向、共享硬链接、打开和读取期间身份变化、缺口、不明工件和部分 JSON 均拒绝。失败不覆盖、不删除。

schema51 新增 tag_commit_operation 与 tag_commit_receipt。操作身份和原请求不可变、认证绑定只写一次、最终结果与退出确认一旦保存不可改、阶段不能倒退、每阶段回执不可更新/删除。保存 receipt 的事务检查新租约/当前任务修订/内容修订/原执行身份及所有已有文件日志/数据库回执。SQLite 已配置 WAL + synchronous=FULL。仅事务提交之后返回相应文件日志 SHA 作为原生 ACK。

文件系统和数据库不是单一原子事务。若阶段文件已 fsync 而 DB 提交失败，原生不会收到 ACK；FS-ahead 作为恢复证据保留，不能跳过阶段或自动重试移动。文件日志 SHA 链没有管理者防篡改或掉电持久性运行证明；编译不等于存储认证。

历史日志允许读取已撤销认证的身份以供恢复；新执行、日志创建/推进、客户端和原生程序仍要求当前受控认证。历史读取不能绕过执行许可。

## 原生回执中的审核与退出

每次 ACK 前复核当前数据库租约、任务修订、来源权限及固定目录。原生持续持有排他文件句柄，回执包含实际物理/完整/元数据/音频摘要及权限时间证据。此时不在 JS 中重新打开或 stat 原文件：句柄排他共享会阻止读取，而且 victim_moved 后有明确的原路径缺口。冻结物理身份/实际摘要由原生再次读取证明，不能拿曲库旧观察替代。

客户端返回前必须收到五阶段持久 ACK、匹配 done、确认实际进程退出，且等待所有异步阶段回调退场。随后回读日志、核对 DB 所有 receipt 和最终 proof，事务保存 native_verified + exit_confirmed。标签任务仍 recovery_required；清除旧媒体观察、标记文件不可用，租约转恢复，保持读取协调锁。没有删除备份/临时/旧文件工件，没有清理租约，没有标记标签或曲库 committed。

中断同样持久保存恢复状态和是否能确认全部文件组件退出；组件退出未知时禁止后续文件操作，重启核对。启动时 reserved/running 操作转 recovery_required，旧文件观察失效。已保存 native_verified 最终结果保留，不能变成曲库成功。

进入提交的任务必须核对第四个旧文件工件，现有三文件核对/保留当前文件/取消未变更路径均拒绝。桌面只展示提交结果与退出状态，隐藏旧的三工件处理和暂存停止按钮，避免误释放新租约。
