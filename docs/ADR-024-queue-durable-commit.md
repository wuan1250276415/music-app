# ADR-024：队列持久化成功后才发布状态

状态：0.19.0 故障注入和 SQLite 重开测试通过；真实断电及损坏库恢复尚未验收。

## 决策

Main 在旧队列的副本上计算新状态，将旧修订号和新队列一起交给 Library Service。Library Service 在 SQLite `BEGIN IMMEDIATE` 事务内比较当前修订，再写入完整队列。只有写入确认后，Main 才替换内存队列并发送事件。无状态变化的命令不写库。旧修订写入拒绝；队列 JSON 损坏或结构无效时明确报错，不静默重置或覆盖。

保存请求失败时，Main 重新读取数据库：若数据库恰好保存了目标状态，则把它视为回执丢失并继续；若仍是旧状态，则保留原队列并报告原错误；若数据库出现另一个有效状态，则切换到它、停止播放并要求界面刷新；若无法读取，则将队列标为结果未确认并拒绝后续修改，等待应用重启。这样不能把一次超时误认为一定没有提交。

CUE 预排发生物理跨轨后若边界队列无法保存，停止音频而不继续使用与数据库不一致的轨道标识。手工上一首、下一首和模式/重排操作在取消 CUE 预排后再次检查修订号，避免跨轨时把旧版本命令套到新队列。

## 验证与界限

单元故障注入覆盖保存失败、保存等待期间旧快照仍可见、提交成功但回执丢失、保存结果无法读取时阻断后续修改，以及 CUE 跨轨保存失败时停止音频。SQLite 临时库测试覆盖关闭重开、两个基于同一旧版本的写入竞争，以及损坏 JSON 不被覆盖。0.19.0 的 33 项单元测试及 Electron 队列命令回归通过。

此策略不保存跨进程的命令回执；重启后须以数据库 revision 和队列快照对账。真实用户库迁移、断电与满盘演练、数据库损坏修复入口、Library Service 自动重启及实际多窗口仍是后续验收项。
