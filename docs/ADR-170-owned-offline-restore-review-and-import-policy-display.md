# ADR-170 恢复前的独立快照审核与访问策略展示

状态：源码实现，运行验收待 MVP。日期：2026-10-10。版本：0.164.0。

## 决定

恢复预览在本次独立核对完成后展示审核页面，包括来源 UUID、数据库摘要、核对时间、音乐目录、在线数据源的原开关、旧扫描/标签写回/凭据操作数量、界面待核对类别、历史 pending 大小、标签恢复工件数量，以及实际检查的八类设置范围。读取历史列表不生成新的审核证明；历史资料需要按当前版本重新核对。

页面展示已有导入策略：播放保持停止；目录需重新选择确认，自动更新和在线数据源关闭；新凭据范围不继承系统登录凭据；旧扫描、标签写回及凭据操作不重放。审核页面只读取快照，不授权访问显示的音乐目录，不启动后台任务，不切换当前曲库。本批不开放破坏性 apply 接口。正式恢复确认、持久用户决定和未决事务操作界面继续实施。

## 审核与原内容绑定

审核在原独立恢复 worker 的 stage/check 流程内完成，不在 Main 或 Renderer 打开候选数据库。新只读审核函数先打开并保留普通单链接数据库句柄，按原清单尺寸有界顺序读取完整 SHA256，核对摘要，再调用已有离线数据库检查器取得固定 SQL 的目录/数据源/数量。外层句柄和实际名称的观察在查询前后核对；内层检查继续核对规范路径、DELETE 日志模式、schema68、完整性、FK、来源和原计数，禁止迁移或写入。

审核后重新计算全部暂存文件清单，核对原文件摘要和阶段/父目录身份。最终回执有界、严格原操作/序列/当前构建，审核中的来源/数据库摘要/history pending 大小/类别数量必须与原清单和实际 pending 读取一致。Main 回复原帧 ACK 并等待实际 exit0，持久完成原准备/核对回执，再独立读回原准备证明和本次兼容性报告，才缓存审核。

新 Main-only `catalog-restore:review` 只接受恢复操作 UUID。它要求实际主窗口主 frame、原文档 epoch、应用可用、没有维护或正在处理的预览，以及本次 ready 选择。每次读取再核对规范 prepared SHA、阶段身份、最新 check SHA 和原预览。重新选择、重新核对、导航/休眠/退出中断使缓存失效；异步 UI 回执只应用到仍在显示的原预览。

审核结果是当次快照观察，并不证明未来 apply 时文件未变化；正式确认和应用必须再次核对实际所有权/内容和原审核决定。审核刷新只重读原证明，不谎称进行了新的文件或数据库全量核对。

## 预算与呈现

严格版本1、128KiB完整审核资料；最多4096目录、128数据源、128已知 pending 类别，每项任务计数最多500万。目录路径最多32767字符、ID最多128字符；目录字符串累计预留其他字段预算，重复/非规范顺序/未知字段拒绝。SQL 标识来自固定常量，不拼接备份中的标识或路径。pending 只展示已知类别，不输出其原文或登录凭据。

目录按需展开、50项分页，所有页可查阅；数据源显示原开关及恢复后关闭的状态。实际已检查范围与行数明确展示，不能将部分领域检查当作全部资料或权限认证。新接口/共享类型/离线读取器/页面纳入发行来源清单与未来安装模块核对。

## 验证范围

本批仅进行类型、源码构建、原生编译和发行静态核对，不执行应用、SQL、worker、提取、恢复、音乐、驱动或测试。真实离线资料、篡改/文件竞态、进程 ACK/exit、旧文档回执、目录分页和审核 UI 在 MVP 集中验证。正式确认/应用、未决重启恢复、原文导出复审、完整领域及迁移校验和、工件配额清理与全部 FR/WP/G/AC 目标保持待完成或待验收。
