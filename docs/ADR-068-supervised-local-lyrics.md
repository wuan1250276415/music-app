# ADR-068：受监督的本地与内嵌歌词读取

状态：0.63.0 源码实现；2026-10-02。schema v33、音频 IPC 1.8 不变，内部媒体协议升级为 4。完整架构范围继续保留；ASIO 实机验证暂停。

## 从服务解析改为监督任务

此前 lyrics.ts 在 Library Service 中用 parseFile 读取音乐标签，目录枚举和歌词读取也在服务内完成。标签解析可能长时间占用服务进程；本地 sidecar 没有完整的 root、文件类型和读取期间稳定性核对。

本次 lyrics.ts 只保留纯 LRC 解析、CUE 时间范围换算与最小 LyricsContext 类型；媒体读取移至 lyrics-worker.ts，由固定 Node adapter 在 ADR-062 的 Windows Job 下执行。同音频只读句柄使用 ScanTokenizer，保留 32 MiB／20 秒合作预算，整个进程继续受 22 秒墙钟、20 秒 user CPU、V8 128 MiB、进程提交 384 MiB／Job 512 MiB 限额。服务不再直接调用标签库解析歌词。

每次任务的上下文仅含 kind、title、秒范围和整数 CUE frame 范围，不传数据库、凭据、Provider、动态入口或用户脚本。返回最多 16 个显示来源及有界提示；曲目身份由父端的快照核对负责，worker 不接受任意 item 对象。

标签正常返回时读取 raw／common 两种视图；标签后段失败时保留 observer 已得到的有效歌词，并标明标签未完整读取，不把部分成功描述成完整扫描。保留 LRC offset、重复时间戳、同步歌词以及 CUE 绝对音频时间换算。源 ID 沿用既有 sourceKind、sidecar 路径、语言／描述、offset、kind 与解析行摘要算法，未改动的常规来源仍能匹配已保存的选择／偏移。

LRC 源偏移保留原整数毫秒，不再经“除以 1000 再乘以 1000”的浮点往返生成 sourceOffsetMs。此前若某个整数偏移产生非整数尾差，新结果可能改变该来源摘要；旧选择仍按既有缺失规则保留，不将其偷偷绑定到新来源，需在 MVP 检查这些兼容样本。

## 本地来源与界限

普通文件优先内嵌同步歌词、同名本地来源、内嵌纯文本；CUE 优先以曲目标题命名的 sidecar，再取其音频内嵌歌词对应范围，仍不把专辑同名 sidecar 自动当作某个 CUE 轨的相对歌词。用户明确导入的文档继续优先合并，播放详情的双语、偏移、字号和来源排序不改为新模型。

目录最多枚举 4096 项；精确 lrc／txt 名称及已存在的大小写变体、明确语言后缀最多 14 项。单 sidecar 1 MiB；只接受 regular file，拒绝 symlink 和越过当前 real root 的来源。打开后核对 lstat／fstat，完整读入预期字节并复核同句柄属性、当前路径属性和 real root；属性变化的普通失败提示并尝试其他来源，授权边界错误上抛。

解码采用 UTF-16 BOM 或严格 UTF-8，后者失败时严格 GB18030 回退；不再用替换字符把损坏 UTF-16／GB18030 伪装为有效文本。每文档最多 5000 行、每行 32 KiB、显示内容 1 MiB；集合完整 JSON 最多 1.5 MiB，给 2 MiB 媒体回执留出固定外层余量。NUL／超长行拒绝显示；同步来源丢弃不合理时间或超长行，再验证完整字段与预算。纯 LRC 限额也用于显式导入预览，原文保留由既有导入文档模型负责，不把此显示限额当作完整原文收集能力。

协议 4 新增 lyrics 分支、六字段范围上下文及 documents／notice 回执；父端核对版本、UUID、音乐文件观察、来源类型／路径／字段／字节限额、行数／顺序／时间与稳定摘要 ID。只有嵌入／sidecar 来源可以从 worker 返回，不能伪造 imported 文档。CUE／标签／封面一并使用协议 4，音频 Host 协议仍为 1.8。

## 父端、调度与提示

LocalLyricsLoader 在服务侧最多共享八个未完成请求，同曲目／文件观察／路径／范围／标题的在途请求合并。任务完成后删除，不做无来源观察的长期命中缓存。父端保持自己的只读音乐句柄，结束后复核属性、路径和 root；服务再检查曲目 scope、可用性、title、fileStamp，重扫期间变化时拒绝旧结果。

该父端文件系统操作仍是 Node 异步 I/O，尚无硬隔离或完整 Windows File ID／重解析点／授权租约，因此本批不声称所有媒体 I/O 已有可中断时限。父子进程分别打开自己的只读句柄，属性相等不等于已经实现跨进程同一文件对象证明。sidecar 在其 worker 读取前后核对，未建立持续到用户提交时的文件租约。

封面与歌词共用前台 FIFO，最多连续三个前台任务后让给等待中的标签／CUE；修正原先只计 queued 启动、漏计第一个直接启动的情况。等待最多 16，前台等待 25 秒，后台扫描等待可取消且不占执行预算；执行与未知退出确认仍由原有监督规则处理。Main 歌词及偏好保存等待上限调整为 60 秒以覆盖排队和执行；等待截止不是进程终止证明，MediaParser 仍仅在 close／Job 确认后释放实际槽位。

普通读取失败、资源预算或音乐离线时返回空本地来源和原因，已显式导入歌词继续可用；bundle.notice 与既有来源缺失提示合并，并在歌词设置中显示。边界错误和未确认监督退出抛出，不降级为“没有歌词”。原选择和偏移保留沿用 ADR-059。尚未接入页面切歌取消／统一任务中心；旧 UI 请求仍靠曲目身份隔离迟到显示，后台任务由既有期限结束。

## 验证与完整目标

类型检查、Main／Renderer（64 模块）／原生组件编译、发行／分发清单及解包脚本语法静态核对通过。SBOM 记录协议 4、歌词 worker 摘要和限额；解包验证器加入歌词 worker／loader 模块，本批未实际打包。

没有运行标签／歌词、目录／路径、进程取消／资源、界面、SQL／迁移、音频、设备或安装包测试；按用户要求集中到 MVP，最新已验证安装包仍为 0.29.0。schema 未变化，也未运行用户数据库。

MVP 必须覆盖内嵌 LRC／USLT／SYLT、后段解析失败保留、sidecar 编码和大小写／语言、八种来源组合顺序／去重、CUE 整数范围与 offset、长行／超大／NUL／回执形状、稳定 ID 与旧偏好、重扫／改名／替换／离线／边界拒绝、shared queue 及首个任务计数、在途合并／饱和／截止／未知退出、Renderer 切歌隔离、已导入来源在普通失败时仍可用，以及真实安装包内的 worker 模块和进程预算。

WP04／WP10 尚未验收。本地／内嵌原文及持久观察版本、完整来源文件历史、用户原文复制／导出、呈现时钟／逐字／在线授权歌词、统一任务取消与退避、文件身份／授权生命周期，以及其余 FR01–FR14／WP01–WP11 工作继续实施。
