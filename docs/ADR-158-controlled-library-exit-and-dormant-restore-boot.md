# ADR-158 曲库受控退出与恢复只读启动

日期：2026-10-10；源码批次：0.152.0；状态：私有关闭编排和只读启动接口已接入源码，整库应用入口与运行验收未完成。

## 背景

ADR-157 准备候选曲库、捕获当前一致快照并保留三方维护占用。实际目录切换还需要旧数据库关闭、原进程正常实际退出，以及新曲库在暂停后台任务状态下的启动核对。本批补齐这些私有生命周期契约。整库切换、可写激活、完整回滚和启动恢复界面继续实施；不存在公开的 prepare/apply IPC。

## 服务实例与进程所有权

Main 的 CatalogLibraryLifecycle 统一拥有 Library 创建、请求等待、超时取消、回复和退出。每个 waiter 绑定实际 UtilityProcess 所有者，迟到回复只处理该进程创建的等待者；退出只清理该所有者的等待者和当前相同实例。新服务不能在旧服务实际退出之前创建。普通调用必须处于已就绪的原库模式，私有维护调用没有观察超时释放等待者的行为。

每个 Library 进程生成独立 UUID，普通启动回执含 instanceId、实际 PID 和当前构建 ID。Main 比对实际 child.pid 与严格回执，普通启动完成后才发布 serviceReady。初始化失败先 kill 并反复等待同一原进程的真实 exit，不把 kill 返回或等待超时当作退出。正常原库启动仍先执行已有恢复事务启动门禁。

恢复只读实例保持 serviceReady=false，抑制普通事件发布；不能通过普通调用访问或启动后台任务。正常确认的受控退出与异常退出分开，后者仍触发原有五类维护中断。退出应用的有界清理仅表示退出策略，不生成受控正常退出证明。

## 关闭意图与实际退出链

私有 retireLibrary 从当前已完成 candidate/rollback 的准备对象取得原 frozen token、当前实例 UUID、随机 challenge、原 live 目录身份和一致快照 manifest。Main 先将 Library 维护标记为 closing，再将 service-closing 意图追加到全局规范记录链，然后调用同一个原进程。整个期间保留 Main、Renderer 和 Library 的维护占用。

Library 校验原租约、实例、普通/只读模式、目录身份、来源和十一项计数。原普通数据库完成 WAL TRUNCATE 检查并确认 DELETE 日志模式，实际关闭数据库连接。随后只列举固定 library 子目录，逐文件重新计算完整 SHA256；禁止把整个 userData 当作离线备份树。WAL/SHM、链接、共享链接、未知文件和目录均拒绝。普通关闭允许数据库文件因 checkpoint/header 规范化与 SQLite Backup API 快照字节不同，其他受管理资料必须完全相同；只读关闭要求全部文件相同。

返回的 service-closed 回执绑定原请求、token、challenge、实例、PID、构建、目录和关闭后的完整 manifest。Main 持久追加该回执并取得完整记录文件摘要后，才能发送原关闭回执摘要与持久记录摘要 ACK。Library 等待该原 ACK 才正常 exit0；完成后的 ACK 等待为 30 秒，缺失时异常退出。

Main 校验 actual exit0 后追加 service-exited 证明，随后维护所有者确认原服务实际缺席，将 Library 状态置为 closed。目录切换闸门要求同一 Main frozen owner、Library closed 和实际无服务，不能只凭关闭回执或进程 kill 返回。整次关闭预算 45 分钟；失败或生命周期变化保留已有记录与占用，并等待原进程实际退出。

全局记录严格顺序为 candidate、rollback、service-closing、service-closed、service-exited。关闭意图必须精确绑定 rollback manifest 和原 live 身份；退出证明必须精确引用已持久的同一关闭回执。关闭开始后禁止追加普通 aborted、调用旧服务 release 或 thaw；需要后续恢复/回滚编排解决。记录仍采用原规范字节、连续序号、前条完整文件 SHA256、wx+sync 及原身份重新读取，不是加密身份签名。

## 恢复只读启动

私有 startDormant 只在原服务真实缺席且同一 Main 维护资源冻结时创建新服务，固定目标为 userData/library；接口不接受 Renderer 提供路径。请求绑定事务 UUID、随机挑战、目录身份与 manifest。Main 依据当前请求、实际进程 PID、当前构建和完整 manifest 摘要核对启动证明。

Library 首先在只读兼容性检查中核对可信结构参考、完整性/外键/页面、来源/计数和已有八项领域范围，再重新计算完整 library 文件清单及摘要。可信空库结构参考来自本构建自身迁移；候选数据库没有执行迁移。然后以 DatabaseSync readOnly、query_only、禁止扩展加载打开连接，要求 schema68。

只读构造跳过标签中断状态恢复、波形任务中断标记和搜索算法更新；不执行扫描恢复、不启动目录监听、不调用写回恢复循环或搜索索引计时器。资源组件只构造，不执行媒体或写回操作，随后取得新随机 frozen token。连接构造及冻结完成后重新核对来源/计数、完整文件清单、摘要和目录身份，才能报告 readOnly=true、backgroundStarted=false。

只读实例禁止捕获和释放维护，普通请求由 frozen 闸门拒绝。关闭它仍使用原实例/租约的关闭契约。可写激活、pending 隔离/审核、外部路径及来源权利恢复尚未实现；只读启动证明不能当作恢复完成证明。startDormant 尚未由整库切换协调器调用，未实际启动过该模式。

## 重启判断与剩余范围

启动检查可以读取新增关闭记录。只有规范已知记录链、没有任何原生目录移动登记、原 live 目录身份仍一致且观察稳定时，仍允许重新普通打开原曲库；不复用旧回滚快照。关闭过程不表示目录已切换。未知或损坏资料、移动登记和目录冲突继续阻止打开，保留资料等待完整恢复编排。

仍需全局切换意图/阶段/终态、实际目录移动、新库启动证明持久登记、可写激活和权利审核、完整失败回滚、跨进程崩溃恢复界面、完整领域和迁移校验和、实际工件配额与受控清理。FR13/WP11/AC17 和完整 FR01–FR14 均未验收。
