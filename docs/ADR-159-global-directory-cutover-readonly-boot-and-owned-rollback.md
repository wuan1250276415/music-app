# ADR-159 全局目录切换、只读启动与当前所有者回滚

日期：2026-10-10；源码批次：0.153.0；状态：私有整库切换到只读启动及已确认路径的回滚编排已实现；可写激活、恢复终态、公开应用入口和运行验收尚未完成。

## 背景与边界

ADR-156 提供四种受控原生目录移动，ADR-157 准备候选和当前快照，ADR-158 提供原 Library 受控退出与新 Library 只读启动。本批将它们连接为一个 Main 私有流程。流程仍然保留三方维护占用，不执行 pending、不恢复外部路径或来源写回权限，不把只读启动称为整库恢复完成。

## 全局阶段记录

原 candidate/rollback/service-closing/service-closed/service-exited 记录之后，增加以下规范记录：

| 记录 | 绑定内容 |
|---|---|
| move-intent | 原事务根、操作 UUID、四种固定动作之一、原目录身份 |
| move-completed | 原操作 UUID、原生请求文件摘要、实际退出文件摘要、该库完整逻辑文件清单摘要 |
| boot-intent | candidate/original 角色、随机挑战、固定目录身份、完整 manifest |
| boot-ready | 原角色及独立实例/PID/构建/租约的只读启动证明 |
| boot-failed | 原角色、原启动请求摘要、失败原因 |
| rollback-intent | 当前事务的明确回滚原因 |
| dormant-closing/closed/exited | 候选只读实例的关闭意图、持久数据库关闭回执和实际正常退出 |

纯阶段解析器检查完整顺序及角色，不允许重复动作、重复操作 UUID、跳过未完成移动或在回滚后继续正向安装。候选启动必须在原库保存及候选安装都已完成之后；原库启动必须处于回滚路线，并已放回原库、腾出候选占用。已启动的候选必须取得同一 token/实例的真实正常退出证明，才能回滚移动。

每个 move-completed 重新打开原原生日志，要求完整四阶段和实际正常退出回执，原请求与全局意图完全一致；完整 request.json 和 exit.json 摘要都必须相同。全局目录登记中存在不属于全局 move-intent 的原生操作即拒绝读取。保留原规范字节、连续序号、前条完整文件摘要、wx+sync、单记录3MiB、32条/64MiB链及64事务预算。完整候选启动后再回滚到原库的已实现路径最多使用21条记录，不超过既有预算。

旧 boot-ready 记录按历史构建读取，仍严格绑定原请求、manifest 摘要及报告构建；实时 Main 接收启动证明依然要求当前构建和实际 child.pid。历史证明不代表旧进程还活着，不授权新操作。

## 固定槽位与全量内容检查

槽位固定为 userData/library、transaction/data/candidate/library、transaction/data/original-library 和 transaction/data/retired-candidate。没有任意路径、覆盖、复制移动替代、目录收养或删除行为。

将逻辑 library/ 文件清单检查扩展到固定 original-library/retired-candidate 槽位。每个文件仍经过路径白名单、普通单链接文件、大小预算、句柄/命名路径观察、完整SHA256和原目录身份前后检查。只列举该槽位，不能遍历整个 userData。移动前重新计算完整来源摘要，目标必须实际缺席；原生正常退出后检查来源缺席和目标完整内容，再持久追加全局完成记录。

原库动作使用 ADR-158 实际关闭后的 manifest，不能用 SQLite Backup API 快照的数据库字节替代实际原目录字节。候选动作使用原离线备份 manifest。两类源身份分别绑定最初原 live 和准备完成的候选 library 身份。空的候选容器和来源 state 原文仍保留，待后续权利与 pending 审核。

## 私有正向编排

CatalogRestoreCutover.apply 接收内部事务/来源 UUID 和可信界面授权检查函数。它依次调用候选准备、当前一致快照及原受控退出，再执行 retire-original、install-candidate，持久登记候选 boot-intent，然后调用 startDormant。只读报告通过实时实例核对后更新维护租约并持久写 boot-ready，返回 candidate-readonly。

原生每个阶段仍使用既有持久 ACK、正常实际进程 close 和退出回执。Main 的移动闸门同时要求同一 Main frozen owner、维护方 Library closed 及服务实际缺席。创建新实例不会解除 Main/Renderer 占用，普通服务就绪仍为 false。原库开始关闭后，即使新只读服务已取得新的 frozen token，也禁止普通备份释放路线或 thaw。

整次私有 apply 为3小时外层预算；既有候选/快照/Library关闭和启动检查仍各有45分钟预算，每次原生移动仍45秒。期限或界面/系统生命周期变化会中断实际所有者、保留记录和资料；不把计时结束当作目录或进程已经退出。

## 当前所有者的失败回滚

候选只读启动失败时，生命周期所有者先终止并等待同一启动进程的实际退出，将错误交给切换协调器。尚在私有初始化阶段的失败不提前触发无关全局异常中断，从而允许仍持有 Main 维护资源的当前流程核对后回滚。超期、退出应用和实例不匹配不能发布就绪；过期进程事件不能中断新实例。

只有全局移动都取得完整正常退出和内容证明、移动组件确认空闲且应用授权仍有效时，才自动登记 rollback-intent 并选择回滚路径：

- 尚未保存原库：原目录仍在原槽位，直接核对原库并只读启动。
- 已保存原库但候选未安装：执行 restore-original 后核对和只读启动。
- 候选已安装：执行 retire-candidate 保留失败候选，然后 restore-original，再核对和只读启动。

候选已经成功只读启动后的内部明确 rollback，同样先登记回滚意图，持久保存原候选实例关闭回执并等待 actual exit0，然后再移动。回滚结果为 original-readonly，继续保留维护占用和用户资料；不能宣称已经恢复可写使用。

有未完成移动意图、原生不确定占用、损坏记录、未知目录、内容变化或实例未确认退出时，禁止猜测方向或再覆盖目录，保留现场等待后续重启恢复核对。原生阶段/退出记录已经完成但全局完成记录缺失，也需后续对账；本批没有用文件存在代替未记录的正常退出或内容证明。外部界面重载、进程丢失、休眠和退出均走中断，不在失去授权后继续移动。

## 主窗口集成与重启边界

Main 已创建私有切换所有者，备份与恢复预览互斥包含该所有者；取消按当前事务路由，五类生命周期中断和退出等待已接入。不存在公开 apply/rollback IPC、按钮或本批实际恢复操作。

启动门禁可读取全局新阶段，但有任何原生移动登记仍阻止普通打开 Library。只有没有原生移动登记、有效原记录、原 live 实际身份仍一致且观察稳定时，继续允许普通打开原库，不能复用旧快照进行切换。本批候选只读或有移动的原库只读回滚都不是可写恢复终态，重启仍需后续恢复界面。

## 剩余范围与验证

仍需可写激活、pending/来源权利/外部路径审核及隔离、新配置初始化与 Main/Renderer状态恢复、全局完成和回滚完成终态、目录不确定及记录缺失的重启对账、独立恢复界面、完整schema领域/迁移校验和、物理配额和受控清理。文件记录 sync 和已确认目录观察不是断电持久性认证。FR13/WP11/AC17、全部 FR01–FR14 和 AC01–AC19 继续按完整架构目标实施。

本批仅进行类型、源码、构建及发行静态检查。不运行应用、SQL/内存库/迁移、私有 apply/rollback、目录移动、只读启动、worker、媒体、驱动或测试；真实目录/数据/文件摘要、进程与ACK交错、回滚、满盘及重启恢复验收集中到MVP。schema68、音频IPC1.22、媒体协议10保持。ASIO实机验证继续搁置，实际缺图仍待复现；无新安装包，最新已验证仍为0.29.0。
