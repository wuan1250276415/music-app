# ADR-017：同一镜像相邻 CUE 轨连续播放原型

状态：0.13.0 已接入桌面队列，并通过软件金样、本机宿主和 Electron 集成测试；G1/G4 尚未通过。

## 决策

协议 1.5 的 `playback.play` 可选传入 `nextCueStartFrame`、`nextCueEndFrame`，用于同一媒体文件中紧邻当前 CUE 轨的一段。两项必须同时提供，`nextCueStartFrame` 必须等于当前 `endCueFrame`。Host 以同一采样率把三个 CUE 边界各转换一次为绝对整数 PCM 帧，验证 `[start,boundary)` 与 `[boundary,end)` 均非空。非连续或溢出的计划被拒绝，不自动补静音或删样本。

Host 从第一段起点启动一个解码器、一个 WASAPI 设备和一个有界 PCM 缓冲，持续解码到第二段末尾；跨边界时不 seek、不清空缓冲、不停止或重开设备。音频回调只读缓冲并在消费到边界时设置原子标记；控制线程随后发出 `playback.cueBoundary`，含绝对和相对 PCM 帧、总时间线位置。事件准确标识样本边界，但 IPC 通知可能晚于实际声卡播放，当前控制线程最多每 250 ms 轮询一次。

Main 只在顺序播放、无循环/随机、导航历史已到尾部，且队列下一项为同一可用文件中边界相邻的 CUE 轨时预排第二段。边界事件到达后，Main 按队列 revision、当前 entry 和下一 entry 对账，再提交队列前进；曲目 ID、时长与展示进度切换为第二首，且不重启宿主。计划不一致时停止播放并报错，避免继续播放错误曲目。

用户改变循环、随机或队列顺序前，Main 向 Host 发送 `playback.cancelNext`。若边界尚未被音频回调消费，Host 取消第二段并在第一段末尾结束，队列变更后按新顺序自动前进；若边界已越过，Host 明确拒绝取消，Main 等待边界事件、提交第二首后再应用队列变更。手动切歌或新建队列沿用停止旧宿主再启动新宿主的安全路径。

双段播放支持 seek。Host 报告跳转目标属于第一段还是第二段，并重置边界状态；Main 把第二首的曲内时间映射为总时间线，拒绝跳转结果越过当前曲目。暂停状态下可从第一段 seek 到第二段或反向 seek，恢复后边界事件按新时间线重新发出。桌面 UI 目前只允许当前曲目内跳转；跨轨跳转仍使用队列跳转。

## 验证与范围

软件金样对 44.1 kHz、48 kHz、44,117 Hz 的 WAV，以及 16/24-bit FLAC，用单次 seek 后连续读取的小块解码，与每个绝对 PCM 样本的期望整数值比对；边界样本只出现一次。非连续及零长度计划均被拒绝。本机宿主验证同一 session 的 `playing`→`cueBoundary`→`ended` 顺序、双段 seek、边界前取消及边界后拒绝取消。Electron 集成测试验证队列在边界切换为第二首而没有第二次 `preparing`，第二首曲内 seek，以及重排队列时取消旧计划并播放新下一首。原有桌面曲库、队列、输出策略和播放 seek 回归通过。

当前仅预排一对相邻轨；第二首之后若还有第三首，仍走普通自动前进并重启宿主。其他文件之间、单文件非 CUE 曲目、随机/循环模式均没有无缝保证。没有 DAC 数字输出捕获或跨设备验证，无法证明实际设备无欠载、位完美或满足架构 G1/G4；ASIO/DSD 仍待真实设备验证。
