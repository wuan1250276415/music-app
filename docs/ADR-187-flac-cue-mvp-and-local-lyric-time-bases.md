# ADR-187：FLAC/CUE MVP 与本地歌词时间基

- 日期：2026-10-11
- 版本：0.181.0；schema72／音频 IPC1.23／媒体14
- 对应：FR01、FR02、FR04、FR07、FR08、FR10；WP04、WP05、WP06、WP10
- 状态：本轮限定样本运行通过；完整 MVP、Windows V1 和全部架构验收继续

## 实际问题与实现

FLAC/CUE 的首轮验证成功导入并播放第二轨，但播放详情没有歌词。生产读取器只尝试按 CUE 分轨标题寻找 LRC/TXT，漏掉了整轨音频同名的 image24.lrc。

现在一次有界目录枚举发现两类来源，优先读取分轨标题及其语言后缀，再读取音频文件名及其语言后缀。标题歌词以 INDEX01 为零点：前间隙归本轨时，加上 INDEX01 与实际播放起点的差。整轨歌词以对应音频文件为时间零点，截取本轨播放的左闭右开范围，再减去实际起点。无时间戳的整轨 TXT 无法可靠分轨，予以忽略；分轨标题同名的纯文本仍可显示。标题与音频名重合时保留原标题相对时间约定，不猜测另一时间基。多文件 CUE 的整轨时间指各自 FILE，不是整个专辑累加时间。

目录最多4096项，每类最多两个精确名字和14个语言名字，实际有效来源最多16项。按名字去重，单文件1MiB、实际读取原文总预算16MiB；现有根目录授权、非链接、真实范围、同句柄完整读取、前后属性检查和严格响应校验继续保留。当前加载器只合并正在执行的同曲读取，不保留完成结果缓存；新增语言或歌词文件可在下次读取发现。

## 不可变歌词历史

新保存资料使用 local-sidecar-lrc-v2。在原范围快照中增加可选 localSidecar 配方，明确时间基和 INDEX01 秒数；该配方、原范围和原编码原文一起参与完整性检查。重开时按保存的范围及配方重新解析、转换，再核对原 sourceId，避免仅比较原文时间与转换后的曲内时间。新快照仍限64KiB。

继续接受明确的 v1，版本身份使用该行原 parser_version；不重写旧原文、快照、解析树或 UUID。旧 v1 重开保留原校验规则。本轮未认证所有历史数据库与备份恢复；旧 v1 若保存了带前间隙位移的标题歌词，却没有保存 INDEX01 配方，其重放问题仍需单独处理，不宣称已修复这类旧记录。

## MVP 样本和证据

新增 tests/tagged-flac.cjs 在既有3秒 FLAC 金样中加入 Vorbis 标签和两幅图片。原 STREAMINFO 和完整压缩音频负载逐字节保持，原与新音频 SHA256 一致。图片排列刻意为蓝色背面在前、红色正面在后，目录 cover.png 也为蓝色。块编码依据 [RFC9639](https://www.rfc-editor.org/rfc/rfc9639.html) 的元数据、Vorbis Comment 与 Picture 定义。只写入独立临时样本。

新增 tests/electron-flac-cue.smoke.cjs，入口 npm run test:flac-cue。实际初始化隔离曲库，运行扫描、媒体 worker、React 界面和 WASAPI 宿主。金样波形可能较响，播放前通过真实输出设置静音。脚本仅清理自己的已核对临时目录，应用退出超时只处理自己已记录的进程。

最终脚本退出0，详见 [FLAC/CUE日志](validation/v0.181-flac-cue.log) 与 [播放详情截图](validation/v0.181-flac-cue-detail.png)：

- FLAC16／44100Hz 和 FLAC24／48000Hz 技术属性、3秒长度正确；曲库显示普通文件及两首 CUE，隐藏被分轨引用的整轨文件。
- CUE 标题、歌手、专辑、INDEX00=50／INDEX01=75及1秒／2秒范围正确。
- 列表、播放栏、详情实际图片像素为红色，证明此样本正面优先于背面和目录封面。
- 普通 FLAC 和 CUE 实际进入共享播放，解码器报告16／24有效位；第二轨起点为48000个源采样。
- 默认前间隙归前轨时，第一轨保留0与0.75秒歌词；第二轨只显示第二轨歌词和尾句，时间为0.5／1.5秒。点行定位、当前行高亮、歌手／专辑检索跳转通过。
- 通过真实 CUE 设置命令把前间隙改归本轨，再完成真实扫描；第二轨起点50/75秒，对应32000采样，长度7/3秒。标题歌词0秒定位至曲内1/3秒；整轨0.75秒歌词定位至曲内1/12秒。
- 标题歌词优先、整轨英语后缀发现、整轨纯文本排除、原文完整字节保持，以及前后两种范围共四个第二轨历史版本独立重开通过。

首轮扩展检查出现定位/停止竞争：测试容许0.1秒误差，已有暂停位置恰好在该范围，未等新定位就停止。最终检查要求播放时钟代次增加、暂停状态和0.002秒误差，修正测试后通过，最终日志无该诊断。不以首轮结果证明完成。
