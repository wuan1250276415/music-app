# ADR-078：封面显示恢复与播放详情导航

日期：2026-10-02；源码 0.73.0；schema v36、音频 IPC 1.13、媒体协议 5 不变。

## 问题与范围

用户要求歌曲封面优先读取文件自带元数据，并从播放栏封面进入含可检索资料、封面、滚动歌词、模式和列表的播放详情。现有监督解析、规范缩略图、持久缓存及这些详情入口均已实现，但 Renderer 实际图片加载失败只清缓存并保留占位图。加载检查和正式显示之间没有等待资源租约，资源回收或暂时读取失败时没有恢复路径。此处属于代码路径缺口，尚没有用户文件运行证据，不能据此认定其为用户环境中的唯一原因。

## 决策

1. 保持 worker 的内嵌正面、其他内嵌、同名本地、目录图片顺序。Renderer 首次可见图片失败先清自己的请求缓存并重新请求／注册原候选；再次失败才把源摘要加入排除清单，继续原顺序。使用既有候选 IPC，不变更媒体协议或数据库。
2. 排除摘要在 Renderer 调度与预检候选循环中传递，去重并限制八个；每个歌曲／属性／尺寸请求独立。最多发起九次恢复，首次失败后的九十秒内才允许发起新恢复；既有单次读取的六十秒期限仍适用。这是重试发起窗口，不是全链路九十秒退出保证。
3. 图片候选先等待当前文档资源租约确认，再提供给可见图片。卸载时释放，即便 retain 失败也尝试清理同一 consumer；未知结果的完整恢复和服务生命周期仍属后续可靠性工作。重复 DOM 失败事件按请求键去重，旧请求完成／图片事件不更新新曲目。
4. 提取共用 Artwork 组件，列表、播放栏和详情使用同一恢复逻辑，保留前台优先、后台一个槽、共享在途及成功缓存。列表持续观察可见范围（含 200px 预取），离开范围后移除图片并释放租约，避免不断滚动后所有旧行永久占用 256 个租约额度；播放栏和详情保持前台。没有可用图片时保留占位图与原因，详情可主动重读。
5. 详情歌词／播放列表使用 tablist／tab／tabpanel 和左右方向、Home、End 切换，保留歌词跟随与手动浏览、模式设置、队列跳转／重排／移出。歌手／专辑／风格仍使用实体 ID 检索，未建立实体时回退标签名称。
6. 从全屏详情进入资料检索明确请求退出全屏；关闭详情仍回到播放栏封面焦点。主动重新读取封面与歌词时，歌词立即独立刷新，封面错误不阻断歌词。

## 验证与后续

本轮按用户要求只做类型、构建与清单静态检查，结果记入实施状态；没有运行单元、数据库、音乐文件、桌面 UI、播放、设备或安装包测试。最新已验证安装包仍为 0.29.0，不能用该旧包观察 0.73 的改动。

MVP 需核对：FLAC/WAV/DSF 内嵌封面与本地冲突时的优先级；损坏／不支持图片回退；两个尺寸、CUE 共享文件、多消费者、切歌／卸载、服务错误与租约清理；可见资源被回收时的恢复；歌词与封面一方失败；详情检索、键盘、全屏、滚动跟随及队列模式。ASIO 实机验证继续搁置；完整 FR/WP/AC 与输出计划／增益／ReplayGain 等后续范围不缩减。
