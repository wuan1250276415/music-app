# ADR-231：持久化已认证格式的逐文件写入批次

日期：2026-10-16；源码 0.225.0。对应 FR06／FR12、WP08／WP09、AC11／AC12，完整架构目标继续。

## 行为与授权

已完成备份的批次可以交接到写入确认页。交接按原顺序读取全部明细，只保留当前仍待写入的已暂存任务；已经完成、取消或等待恢复的单曲任务不会再次加入。最多 100 首、每个文件一个计划。用户另行确认“逐首写入已审核差异并更新曲库，保留备份”，保存固定范围后再明确开始。

每首依次完成原文件标签提交、四文件独立核对、重新解析和曲库事务、读取释放确认，才记为成功。Main 在写入前复核实际目标并停止同文件播放；Library 在真实写入前再次核对来源权限、原计划、内容修订及文件身份。只有正常退出、日志匹配的原生结果才能自动进入核对和重新解析；中断后的恢复决策继续由单曲任务明确处理。

批次保存不修改音乐文件。创建和开始都检查当前受信任格式认证；生产认证目录为空时拒绝创建或开始，且不为此停止当前播放。界面保留历史与恢复入口，明确显示当前能力。隔离测试候选认证不能作为生产认证，也不能放宽原生程序的已编译测试目录限制。

## 持久化与调度

schema81 → 82 新增写入批次、不可变成员及命令回执三张表。每首在创建时固定提交、核对及重新解析三个命令身份；提交修订同时冻结，后两步修订在首次进入对应阶段时保存，之后不可重写。操作采用修订比较，已提交请求读原回执；接受结果不确定时保留活动成员，由实际任务记录决定后续，不重新生成写入请求。

Main 沿用同一个后台调度器，Library 在已有活动备份批次、活动写入批次及待运行队列之间选择，避免两个后台执行器各自启动文件操作。单曲文件管理器仍负责最终的全组件空闲检查。已有活动批次先排空；没有活动备份批次时优先调度写入队列。备份和写入各最多 4 个排队或运行批次。

暂停与取消等待当前文件的完整处理结束；未启动的成员保持待处理或标为批次取消。已经成功的标签与曲库结果、原始备份、旧文件均保留。失败按原序号定位；只有原命令仍适用且没有原生执行的失败项可以重新排队。跳过必须明确操作，不解决或删除原单曲恢复任务。

重启使旧会话和 epoch 失效，不自动继续。已经完成且释放确认的本批次结果可以接纳；启动前中断的成员保留原请求并回到待处理；已进入文件操作的中断成员单独阻断。核对后可跳过该项并继续其他文件，随后从原备份批次建立剩余任务的写入批次时，会排除已完成与待恢复项。

## 升级与备份

升级前保存并独立核对 schema81 快照，事务内创建新结构并检查业务计数和领域不变量，失败回滚。旧版 0.224 运行时拒绝 schema82。备份清单与历史导出支持当前 82，旧版本保留原版本信息，需要显式迁移后才能整库应用。

恢复检查沿用十二个领域，原标签批次领域同时包含备份和写入记录。检查创建回执与固定成员的对应、会话与活动成员、原请求修订和认证身份，以及完成成员的原生提交、重新解析和读取释放记录；SQLite 完整性正常但创建回执遭改动时仍拒绝恢复。历史记录可读取，不因此获得当前原文件写入授权。

写入批次最多保存 4096 个父记录、65536 条命令回执及 128 MiB 回执正文。此轮没有新增自动删除或备份清理；不把取消、跳过和撤销库内修改当成删除恢复工件的授权。

## MVP 证据及范围

验证证据归档在同版本检查点及 `docs/validation/v0.225-*.json`。新核心验证使用固定提交重建的真实 0.224 运行时及其实际 schema81，检查升级、回滚、快照、旧批次保留、真实原生提交／独立核对／重新解析、丢回应后的原操作接纳、未认证构建拒绝旧批次继续，以及只读恢复检查。

新桌面验证使用真实 Main／preload／Service／Renderer：生产构建拒绝未认证批次且保持实际循环播放；隔离候选通过正常导入、审核及备份后，实际按钮确认写入、暂停并完成当前文件、正常重启、在旧文件已移走且日志同步后真实强制结束进程树、定位该单曲并独立核对、明确跳过、取消后续处理及仅继续剩余任务。音频 payload、原备份与中断留下的旧文件逐一核对。
