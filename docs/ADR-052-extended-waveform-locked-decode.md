# ADR-052：扩展格式的同句柄整曲分析

日期：2026-10-01；源码 0.47.0；schema v24、音频 IPC 1.7 不变。对应 WP02/WP10/WP11、FR01/FR11/FR13。延续 [ADR-049](ADR-049-whole-waveform-jobs-v23.md) 的任务、范围、缓存与提交确认边界，以及 [ADR-051](ADR-051-controlled-ffmpeg-pcm-decoder.md) 的受控库。

## 实现

整曲波形开放 AAC/M4A、ALAC、Ogg Vorbis、Opus 候选扩展名。格式仍由解码器探测决定，播放与分析均只注册既定四种 FFmpeg codec。waveform-worker 延迟链接已有四库，后续安装资源沿用宿主旁 DLL 与对应完整源码；不增加解码器、网络或 npm 依赖。

`AuralPcmDecoder.initHandle` 先在既有只读 VFS 上尝试 miniaudio，失败后将已经核对目录且计算内容 SHA-256 的句柄借给 FFmpeg custom AVIO。借用不接管关闭责任；原始 File RAII 持有句柄直到分析结果经服务提交并收到确认。FFmpeg 文件播放路径仍自行打开和拥有句柄。重新初始化、格式失败和析构明确分开借用／拥有，禁止先核对旧文件、再按路径重开新文件。

每次未命中缓存的分析先按源采样率与声道分块解码到实际 EOF，统计完整 PCM 帧数；不使用容器 duration、文件大小或估算时长冒充精确长度。包含 libavcodec 自身处理的延迟／padding 后的可读帧。统计期间不保留全曲 PCM，只使用 4096 帧样本缓冲。内嵌损坏标志和 decode_error_flags 被拒绝，FFmpeg 开启 CRC／bitstream／buffer／explode 错误识别；此设置不证明能识别所有损坏或截断，负例仍须金样。

随后从同句柄重新初始化，检查后端、codec、采样率、声道和输出格式不变，从零顺序丢弃到当前曲目起点，再生成该范围的多分辨率 min/max、峰值及 RMS。分析不依赖容器 seek 和 PTS 近似，外部 CUE 继续采用 75 fps 到采样帧转换。范围越界／空源／帧计数溢出／解码不足都失败；范围到真实末尾时再读取一帧核对 EOF，避免将第二遍不同长度保存为完整结果。

这种两遍分析增加未缓存情况下的 CPU/I/O，尤其 CUE 的后部轨道需从源头丢弃；已核对内容的缓存命中仍只做哈希。保持一个后台进程、低优先级、现有 30 分钟任务期限、500 ms 更新及取消后等待 close 的边界。没有以测试绿色证明播放时无额外欠载，MVP 要做成本和负载对照；后续可在已认证精确长度／seek 的格式上优化，但不能用估算结果取代真实范围。

## 进度、缓存与兼容

算法标识改为 `minmax-f32-v2-ma-0.11.25-ff-8.1.3`，纳入范围指纹与缓存键。v1 缓存不复用，旧任务身份与数据不改写；旧完成记录无有效摘要时提示重新分析，旧载荷仍受既有 LRU 管理。结果保存已使用 JSON，数据库表结构不变。

统计阶段属于既有 decoding 阶段，新增私有消息 stage=measuring/positioning/building。前 40% 使用文件读取位置作为估计，MOV 元数据探测等可能使它提前接近上限，不将百分比宣称为准确解码进度；Repository 保持阶段内单调。后 60% 按顺序定位及范围末端帧推进。界面显示统计实际音频帧或读取起点的固定文案，不传出路径。JSON stage 白名单与已有消息预算继续检查。

摘要增加经过验证的 decoder 后端、codec 与 pending 认证值，算法／内容／采样率／声道／范围仍构成主缓存键。Main／Service 拒绝错误来源字段、过大响应和失效范围。这个信息是分析来源，不能替代架构 MediaCapabilityManifest、实际播放或数字输出认证。
