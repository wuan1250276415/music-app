# ADR-175：FLAC 内嵌 CUESHEET 读取与精确可表示分轨

日期：2026-10-10。范围：FR02／WP04 的内嵌编排源码；不是格式播放认证或 MVP 验收。

## 格式依据与行为

依据 [RFC 9639 §8.7](https://www.rfc-editor.org/rfc/rfc9639.html#section-8.7)，FLAC 的类型 5 元数据块使用采样位置，索引偏移相对于本轨起点；末轨为 lead-out，不生成可播放歌曲。CD 标记、保留位、轨号与索引、ASCII 填充、音频总采样数须独立检查，不能把二进制块送入文本 CUE 解释器。

新增 `flac-cuesheet.ts`：在原媒体监督子进程内，使用标签扫描的同一文件句柄、显式定位读取；元数据链最多 1024 块／32 MiB，编排块最多 256 KiB／16384 索引，合作式取消和 20 秒期限。原扫描仍独立确认实际子进程退出、文件身份与前后观察。媒体协议升为 11，接收方重新解析原始 CUESHEET 与 STREAMINFO，逐字段核对结果及文件范围／采样率／时长；不接受仅有摘要的自报解析。

标准 CD 的 588 采样边界可精确换算为每秒 75 帧。其他编排也只有全部采样边界可以精确表示为 75 帧、每轨为音频并有 INDEX 01 时才生成虚拟音轨。lead-out 必须等于已知总采样数；未知总长度、结构不完整或重叠保留原扫描失败行为。非可表示但结构有效的编排记录原始内容和诊断，保留整文件播放，并在扫描结果提示。此批尚未实现任意采样时间基准播放，不能宣称完整非 CD CUESHEET 支持。

## 曲库与用户界面

内嵌文档使用音频自己的相对路径，外部文档继续使用独立 `.cue` 路径。复用现有文档、音轨与 span 表，无 schema 变更；解析器标记 `aural-flac-cuesheet-1`，encoding 为 NULL，字段记录完整原始块／STREAMINFO／SHA／采样索引。一次扫描检查点事务同时更新媒体与内嵌编排，失败不留下半份新编排。保留当前原始块，不冒称已有不可变内嵌编排版本历史或原文导出界面。

沿用既有按文件／轨号／隐藏属性复用身份，保留个人引用；默认 INDEX 00 属于上一轨，文件开头至首轨起点单独保留为隐藏条目。ISRC、PRE 标志和子索引保留，PRE 仍无去加重处理。二进制编排没有名称和歌手文本，音轨用编号命名，专辑、艺人、风格、多碟信息继承文件标签及其来源。

已知外部 CUE 优先，外部解释成功时隐藏内嵌条目；扫描结束确认外部文档消失后可恢复当前内嵌编排。未变化的文件标记连同内嵌文档保持当前代次。旧 FLAC 首次扫描因缺少解析器标记重新探测，之后回到增量扫描。

播放详情区分内嵌和外部编排，只给文本编排显示编码与原文解释按钮。曲目列表读取移除文档中的原始二进制和整块索引，避免每首歌曲重复传递大块数据。封面仍由音频自己的元数据优先读取，歌词与播放继续沿用同一源文件的现有范围链路，真实交互未验证。

## 验证与后续

本批 Main／Renderer 类型与构建、生产原生及既有金样仅编译整体 exit0、4 个发行 CommonJS 脚本语法、发行生成文件和最终分发清单核对通过；不运行 SQL、迁移、媒体进程、应用、真实音乐或测试。MVP 必须覆盖 CD 多轨／INDEX 00／隐藏首轨／lead-out、外部优先与外部移除、重新扫描身份及个人资料、非对齐诊断、损坏与重复块、取消和扫描检查点、封面／歌词／seek／同文件连续播放。

任意采样时间基准、文本 CUESHEET 注释、逐轨命名来源、内嵌原文版本与导出、复杂间隙及去加重、跨文件无缝仍需实现。FR01–FR14／WP01–WP11／G1–G5／AC01–AC19 完整范围保留。仅 ASIO 实机验证暂停；未决恢复继续／回滚与新进程所有权、当前 WAL、标签认证、在线数据源、跨平台和全部验收仍未完成。
