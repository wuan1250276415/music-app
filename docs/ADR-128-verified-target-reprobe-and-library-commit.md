# ADR-128 已核对目标的重新解析与曲库提交

日期：2026-10-04。状态：0.122.0 源码及编译阶段；schema53，运行测试集中到 MVP。受控原生提交认证目录仍空。

## 架构目标与本批次范围

架构 §12.2 / WP09 要求实际替换并校验后更新曲库 revision。ADR-126 保存 native_verified，ADR-127 解释实际四工件；这两个状态没有更新曲库。本批次接通已保存原生 verified/done/实际退出且最新四工件报告 matched/verified/replacement-observed 的重新解析、曲库事务和读取释放。

只完成已确认原生结果这一分支。原生提交中断、FS-ahead、仅观察到目标但未保存 done 的分支仍保留恢复占用，后续需要原生恢复或独立恢复确认，不能伪造原进程 done。完整 ACL/SACL 政策、格式/文件系统认证、备份/旧工件恢复及保留清理、批次/MP3/集合来源映射仍继续；FR12/AC12 尚未验收，完整架构 FR01–FR14 / WP01–WP11 / G1–G5 / AC01–AC19 目标保持。

## 原请求和恢复占用

桌面明确确认重新读取实际目标标签并更新曲库，提交 commandId/jobId/baseRevision/inspectionId/confirmed。Main 信任检查、服务严格解析、原命令回读后，schema53 保存操作/任务/文件/核对/审核修订/新提交租约绑定。要求最新完成核对、原生退出已确认、操作 native_verified、完整五阶段持久回执一致，内容和任务修订未变，曲目为当前 active 独立文件、无共享 CUE、目录 online/scanning。新的四工件核对或其他文件任务不能与重新解析并行。

普通读取保持阻止；仅协调器使用已取得的同一读取占用身份开启内部 parseOwned/flacTagPreviewOwned。FileReadGate 要求精确 owner、无此文件其他未退出读取，再登记操作直到全部子进程 close。没有公开绕过读取门禁的 IPC 参数；它是应用协调，不是操作系统独占写锁。取消/关闭仍等待现有监督程序实际退出，失败保留恢复占用。

## 重新解析证据

先再次进行四工件原生核对，要求与已选报告的实际四文件证据及目录物理身份一致；获取目标 Node BigInt 文件观察和普通文件 stat，拒绝共享链接、符号链接、精确路径变化。目标仍位于冻结授权目录，备份/旧文件保留。

受监督媒体解析程序先对实际目标调用原 FLAC 差异适配器，使用原计划的完整选中值再次生成预览：应 changed=false，每字段原值必须精确等于计划值，元数据摘要/音频偏移/文件字节数等于目标，未知块/图片等保留块摘要和 STREAMINFO 等于原计划。再用普通 tags 解析器读取实际曲库/技术资料。两次媒体进程均等待实际退出；每次前后核对文件观察、租约、任务、来源目录。

完成后再次原生核对四工件，要求两次现存文件完整/元数据/音频摘要、物理身份/时间/字节数和明确缺失状态一致，根/父目录卷、文件ID、创建时间不变。再核对原暂存 SHA 和提交日志完整链/所有 DB 回执，必须仍完整 verified/matched。解析资料通过原媒体回执校验，并与真实目标大小、路径、mtime、采样率、位深和已声明样本数对应时长一致；STREAMINFO 样本数为零时允许保留未知时长。

证明的是实际字节载荷与已核对来源一致、标签及容器元数据符合目标；没有运行音频解码金样，不把摘要或 declared PCM MD5 当作解码证明。格式/文件系统认证和故障运行验证仍是 MVP 门槛。

## 单一曲库事务

tag_commit_reprobe 冻结请求身份，保存进度和最多3MiB证明（包含两次四工件快照、实际标签预览、解析资料、stat/观察及两种日志SHA）。历史4096条/512MiB，活动/成功操作每提交至多一个，最终证明不可修改或删除。请求4096字节、进度1024字节；schema53 迁移前保存 pre-v53 备份，本轮 SQL/迁移未执行。

SQLite FULL-sync 事务再次核对恢复租约/修订/当前报告/日志/权限状态及全部证明，然后复用原扫描的曲库更新实现，仅内部当前重新解析动作可更新指定现有文件：不创建替代 fileId/itemId，刷新 stream/span/catalog/local provenance/search、ReplayGain及新媒体观察。个人收藏/评分/播放列表和既有手工覆盖保持原身份与原规则。按当前根扫描代次保存 seen_generation，曲库和目录变化引起的验证失败会回滚整个事务。

同一事务推进 content revision/lease revision、清除 DB 恢复占用，将原生提交置 committed、标签任务置 completed，并持久保存重新解析证明。备份、旧文件、临时名称均无删除/移动操作。

## 快照与读取释放

原生核对快照在进程退出后不再持有 OS 句柄，媒体读取和 SQLite 不是一个跨资源原子事务。不能宣称此操作阻止所有外部写入：使用解析前后实际摘要和 BigInt 观察缩小并检测变化，提交前复核，提交后在释放应用读取门禁前再次检查；发现路径/目录/观察变化时清除新观察、标记文件不可用，保留已完成事务的历史证据，等待重新扫描。更晚的外部变化交给文件观察/监听及下一读取验证；掉电和外部并发边界仍须 MVP 验证。

读取释放使用独立不可变 tag_commit_reprobe_release 回执，要求当前租约修订恰为原动作+1 且无新占用；仅释放原 owner 的解析/扫描/服务协调。释放前失败不更改 completed 证明，启动及5秒服务协调重试。完成动作没有释放回执时，普通读和新写租约均拒绝；同样补上既有三工件恢复释放的这个等待门禁，避免新操作先取得租约而旧读取协调尚未清理。

原目录变动或观察变更后的释放不代表文件可用；桌面分别显示曲库完成、等待读取释放、当前文件需要重扫、可用。分页列表只读取状态摘要，不加载最多3MiB原始证明。缓存变化事件刷新封面和曲库展示。历史核对报告依然是当时快照。
