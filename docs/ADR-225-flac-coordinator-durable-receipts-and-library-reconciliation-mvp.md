# ADR-225：FLAC协调链持久回执与曲库一致性 MVP

日期：2026-10-16；源码0.219.0。完整FR01–14／WP01–11／G1–5／AC01–19目标继续，FR12／AC12未完成。

## 实际缺陷与修复

1. 原生写入成功后，重新解析证明校验把包含扫描观察的完整worker绑定展开进严格媒体请求，因额外字段触发“无效媒体解析请求”。提交及恢复两条证明校验均改为只显式选择四个路径字段，不放宽媒体协议的封闭字段规则。
2. 从旧文件恢复后，六工件分类将被移走的目标与提交前临时文件的创建时间比较。提交已按原文件策略修改目标创建时间，导致实际恢复成功却被分类为recovery-required。改为核对恢复前实际观察的目标，继续核对完整内容、物理身份、创建／修改时间与目录；不忽略时间差异。
3. 曲库事务已提交、释放回执保存失败后，旧提交释放函数没有在重试时重新检查文件观察，外部改动可能沿用旧可用状态。释放现为可等待的同操作合并任务，维护等待其完成，Service顺序等待并复核当前实例；每次释放先独立核对文件与目录，变化则撤销过期观察并要求重扫，再核对租约修订以避免释放新操作的所有权。

## 组合与验证

新增 `npm run test:tag-coordinator-mvp`，在D盘创建专属测试根，编译固定根限定的候选原生事务。复制当前编译产物，除两个生成认证目录外逐字保持一致；依赖目录仅使用测试组合的模块映射。生产认证头、源文件和产物不被测试改写，正式认证目录保持为空。

用实际监督解析器与扫描器创建生成FLAC的SQLite曲库，通过原TagWriteManager完成预览、暂存、提交、核对、重探测、曲库事务和释放；文件工件与数据库回执均来自真实执行。候选的证书只服务该专属目录，不能作为正式认证证据或通过环境／IPC放行正式写回。

集中13项通过：

- 完整提交的五个原生阶段、六条SQLite回执及原命令重放；曲库更新前的不可读状态。
- 独立目标重新解析、同一曲目标识更新、读取所有权释放与数据库关闭重开。
- 旧文件／备份两种实际恢复，各六个原生阶段和七条SQLite回执，原标签重新解析与数据库重开，保留备份。
- 用实际SQLite触发器拒绝释放回执：保留已完成事务和待释放记录，数据库关闭重开后继续拒绝普通读取；物理追加字节后重试，撤销过期观察并标为不可用待重扫。
- 用实际SQLite触发器拒绝曲目更新：整个曲库事务回滚，旧标题不可用、无新观察、占用保留；移除故障后独立重试成功且仅一条曲目。
- 用实际SQLite触发器分别拒绝五个提交阶段的数据库回执：文件日志已同步、数据库事务实际回滚；独立核对发现fs-ahead。已移动旧文件的三个阶段实际恢复并提交原曲库资料，前两个阶段原文件保持。

另有当前0.219实际Electron暂存／恢复9项回归通过，包含真实Main进程树中断后的恢复任务入口。构建、类型及发行／分发清单检查通过。原生文件操作36项仍为0.218的历史证据，本轮不重复宣称新增36项验证。

证据：[`v0.219-coordinator-final.json`](validation/v0.219-coordinator-final.json)、[`v0.219-tag-staging-final.json`](validation/v0.219-tag-staging-final.json)。修复前的三份实际失败报告也保留；其版本字段为当时的0.218，不能当作最终版本成功记录。原始权限档案及完整工件仅留在隔离测试根，不复制入仓库。

## 范围与后续

此轮证明的是原生产协调器／数据库／原生客户端的隔离组合，未证明正式Main命令、preload、GUI确认与当前生产证书之间的完整提交路径。运行目录和故障注入为明确的测试设置；数据库重开不是Main整进程硬崩溃，也不等于物理断电。

继续完成提交／恢复中断续办、满盘与并发／权限完整矩阵、认证激活后的实际Main／界面链路、更多格式与批次，以及全架构其余验收；不据此关闭FR12／AC12或完整V1。原生本轮未重编译，最新安装包仍0.215.0且未新增实际安装／签名认证。仅ASIO实机单独搁置。
