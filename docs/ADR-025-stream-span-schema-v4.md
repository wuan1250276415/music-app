# ADR-025：曲库 v4 的媒体流与可播放范围

状态：0.20.0 迁移和重扫契约通过；WP03 领域模型尚未冻结。

## 决策

在现有 `media_file`（物理资产）与 `playable_item`（稳定可播放条目）之间增加 `media_stream`，并以 `playable_span` 表达条目使用的流和左闭右开范围。当前每个文件只有探测到的第 0 流；每个条目只有第 0 范围，但 `ordinal` 和独立 `stream_id` 允许后续一个条目按序使用多个文件或流。CUE 范围使用整数 `start_tick/end_tick` 和 `1/75` 时间基；整文件条目从 0 开始，末端未知，暂用 `1/1` 时间基。`end_tick` 非空时必须大于起点，外键和唯一约束阻止悬空范围。

v3→v4 先用 SQLite `VACUUM INTO` 生成 `pre-v4` 一致备份，再在事务中建表、回填和更新 `user_version`。不合法的旧 CUE 范围使整个 v4 事务失败，保留原 v3 数据与备份。新扫描和重扫在现有事务中同步更新文件流和条目范围；删除旧 CUE 条目时范围随外键级联删除。迁移不改变条目 ID、队列 entry ID、元数据确认值或既有播放字段。

旧库没有可靠的声道布局、DSD 位流属性与录音/发行版身份，迁移将 `source_kind` 保守标为 `unknown`，不根据扩展名猜测。当前播放器仍从 v3 兼容字段构建播放计划，v4 表是后续切换的契约基础；不能把新表视为多流、跨文件无缝或 DSD 播放已实现。`Recording`/`Release` 及艺人署名的身份关系须在独立评审后引入，不按同名专辑自动合并。

## 验证与界限

测试在真实扫描所得数据上重建 v3 结构，再升级到 v4，核对备份版本、SQLite 完整性/外键、CUE 整数范围、队列与人工修订不变；重扫更新范围且保持条目 ID。另有非法旧范围触发回滚、v2→v3→v4 连续迁移及跨文件 CUE 流归属测试。尚未在真实用户曲库、断电、满盘和大量损坏标签条件下验收迁移。G1–G5 的音频门禁状态不因本次数据库迁移改变。
