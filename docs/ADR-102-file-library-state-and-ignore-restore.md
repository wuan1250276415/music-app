# ADR-102：文件收录状态、忽略与恢复扫描

- 状态：源码、类型及编译检查完成；SQL、迁移、文件和桌面交互待 MVP
- 版本：0.97.0；schema v41；音频 IPC 1.19／媒体协议 6／系统媒体协议 1
- 日期：2026-10-02
- 关联：架构 §9.3、FR04／FR13、WP03／WP04／WP05／WP06

## 操作范围

歌曲旁的“文件”、播放详情的“文件管理”和扫描任务的管理入口提供文件级移出、忽略和恢复。一项操作覆盖对应音乐文件的整曲及所有 CUE 曲目记录，不支持单独移出一个虚拟轨。原始音乐文件保留，收藏、评分、歌单、歌词和历史引用及稳定曲目 ID 保留。

| 状态 | 普通曲库／分类／搜索／计数 | 个人引用 | 扫描 |
| --- | --- | --- | --- |
| active | 按原可见性展示 | 保留，是否可播放仍取决于文件与目录状态 | 按原扫描规则 |
| removed | 隐藏且不可播放 | 保留并显示不可用 | 继续维护标签与文件存在状态，保持移出状态 |
| ignored | 隐藏且不可播放 | 保留并显示不可用 | 跳过该根目录下已有音乐文件路径的采样、打开及标签读取 |

忽略记录绑定当前曲库文件及路径，替换相同路径文件仍沿用该状态。尚无针对未入库路径的规则编辑、批量操作和物理删除功能；完整架构范围继续。

## 数据库与投影

schema v41 增加文件状态／独立修订、恢复意图和不可修改的命令回执。`playable_item.library_state` 独立于既有 `visible`：后者继续表示 CUE 编排可见性，避免恢复文件时错误打开历史编排。文件状态插入／修改、曲目插入和文件重绑通过 AFTER 触发器同步投影，普通查询额外筛选 active，个人歌单和收藏查询保留不可用条目。

投影使用 AFTER；回执保护使用 BEFORE 加 RAISE，且不在 BEFORE 中修改目标行。UPDATE OF 依照 SET 中出现的字段触发，重绑另有 OLD／NEW 条件。设计依据为 [SQLite CREATE TRIGGER 官方文档](https://www.sqlite.org/lang_createtrigger.html)。这些规则已静态核对，本批没有执行 SQL 或证明运行结果。

既有数据库在 v41 结构事务前写 `.pre-v41-时间.bak`；版本超过 41 拒绝打开。旧 schema 断言和历史 fixture 已适配，未运行它们。个人引用计数含同文件的历史／隐藏 CUE 记录；歌单计数为引用次数，不能理解为独立歌单数。

## 提交、播放与恢复

1. 严格请求包含原命令 UUID、文件 ID、基础修订、动作和文件观察。已保存 UUID 只允许原请求重放；保存状态和原结果回执同事务。传输／提交未知时界面保留原 UUID，显式核对，不生成新意图覆盖未知结果。
2. Main 在播放协调器中串行提交，核对当前曲目、同源 CUE 预备轨与恢复／输出书签。命中时先停止并使旧操作失效，再提交数据库；原成功回执重放不会再次停止播放。CAS 拒绝可能发生在停止之后，需要用户重新播放，不能承诺文件状态与音频停止跨进程原子完成。
3. 恢复事务切回 active，同时清除扫描观察、标记文件缺失并保存原扫描意图。因此恢复点击本身不会让旧资料可播放。首次重新解析该文件并安全提交后清除待恢复标记；不是整个根目录所有阶段成功后才统一开放。
4. 启动和每 5 秒检查至多 64 个根目录，等待已有任务结束，再用原意图提交完整根扫描。同根合并，已提交回执不会重复启动；扫描失败、取消或中断保留待恢复提示，用户处理任务或明确再次恢复。未提交恢复意图不会被已失败的旧命令遮蔽。
5. 扫描读取后再检查忽略状态；扫描中刚被忽略的文件丢弃已读取结果，不能硬取消此前启动的 I/O。恢复期间旧增量跳过结果若观察被清除则拒绝复用，等待新解析。
6. CUE 可以保留已忽略音频的历史文件绑定，不打开该音频；状态投影仍使其不可播放。此路径不证明源文件存在、时长或编排已重新验证。恢复后的音频读取及 CUE 阶段仍需核对。

## 界面与验证边界

管理列表每页最多 50 个文件，按文件 ID 键集分页并绑定曲库快照；变化后明确重读，替换当前页，不无限累积。操作前展示路径、CUE 范围和个人引用数量，未知提交期间保留核对入口。活动状态变化使普通曲库和封面请求失效。
