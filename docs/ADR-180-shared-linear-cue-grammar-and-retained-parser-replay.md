# ADR-180：共用线性 CUE 语法与旧内嵌解析版本读取

- 日期：2026-10-10
- 状态：0.174.0 源码接入；类型／Main与Renderer构建／生产原生和既有金样程序编译／发行静态核对通过，运行验收留至 MVP
- 对应：FR02、FR04、FR13、WP03、WP04；沿用 ADR-175–179

## 问题与决定

扫描、内嵌 Vorbis CUESHEET 和来源备份复审此前使用不同的 FILE 语法入口。普通解析器的引号正则中，转义分支与非引号字符分支都可以消费反斜杠；不完整引号及长反斜杠串存在回溯路径。指令正则的空白与后续正文范围也重叠。只限制输入大小或只保护备份入口不足以统一处理这些来源。

新增 `cue-file-token.ts`，逐字符读取指令、FILE token 与末尾文件类型。所有循环只推进当前位置，指令与 FILE 各自对输入进行有限次线性遍历，不恢复旧回溯正则。这里的线性复杂度是源码结构判断，实际耗时及进程响应仍需 MVP 验证。

当前语法先识别 ASCII 指令名及必需空白，再读取正文；单行限制仍为16384字符。FILE 类型使用原有 ASCII 字母、数字和下划线范围。引号 token 必须在匹配的未转义末尾引号结束；引号内反斜杠消费其后一个字符，不允许孤立的末尾反斜杠。无引号 token 不允许空白或引号。返回原始 token，继续使用既有 `decodeValue`，本次不重新定义文件名解码或路径授权。

普通 CUE、当前内嵌文本和外部来源备份预检查共用该入口。备份预检查按原始行长度核对预算，再使用和扫描相同的指令／FILE 读取；失败仍显示原文和旧快照，保持 `currentParsed=false`，不构造当前解析成功。有效 FILE 后的 TRACK、INDEX、元数据、间隙政策和字段记录逻辑保持。

## 解析版本及不可变历史

| 来源 | 当前版本 | 历史处理 |
|---|---|---|
| 外部 CUE | `aural-cue-4` | 已保存 parser1／2／3 原字节、原解析 JSON、摘要和回执保留；复审显示当前 parser4，不改写旧版本 |
| FLAC 文本 CUESHEET | `aural-flac-text-cuesheet-2` | parser1 用线性兼容入口重建保存时 parser3 FILE 语言，再独立比较原始来源与完整文档 |
| FLAC 二进制／当前文档控制标记 | `aural-flac-cuesheet-4` | 二进制算法保持，历史1／2／3归一至当前标记仅用于核对原字节，返回值恢复原标记 |

旧文本 parser1 的读取不能直接采用新语法后把标记改回1，否则可能改变已经保存的解析树。为其保留 `parseCueLegacy3`。旧 FILE 正则允许反斜杠作为单字符，也允许反斜杠和其后字符组成转义；线性兼容识别因此允许内部引号前有直接相邻反斜杠，并保留旧无空白 token 的回退语言。该宽松入口只用于核对明确的历史文本 parser1，新扫描始终使用严格当前语法。

原始源码对照来自完整0.173源码归档；共享的 TRACK／INDEX／字段／返回对象逻辑及根字段顺序未改。旧坏 UTF-8、错误文档和诊断仍按保存时入口生成并核对。这是实现依据，尚未通过运行证明所有历史输入等价。未来改变共享文档生成逻辑时，必须重新评估 parser1 的固定历史语义，不能只保留旧 FILE token 读取就声明兼容。

## 扫描与进程边界

FLAC 当前控制标记升级至4，使未变文件的旧内嵌观察重新探测。未变、失败保护及完整扫描中的内嵌回退仍明确接纳旧1／2／3；不可变来源历史读取及schema68保留文档登记也接纳已知3，不把历史内容升级成新快照。外部 CUE 的扫描阶段继续读取原来源，新的解释登记为parser4。

媒体协议升级至14，Library接收新扫描结果时要求当前内嵌文本 parser2 和二进制 parser4，继续独立核对原始字节、STREAMINFO、位置和完整解析字段。历史来源读取可接纳已知文本1／2，进程观察不能借该兼容入口返回旧代次结果。

schema69与音频IPC1.23保持。文件身份、虚拟轨身份、原采样范围、人工资料选择与锁、外部 CUE 优先关系及原始历史摘要推导均不因语法升级主动改写。发行清单增加共用词法文件及相关入口的源码摘要，解包核对要求对应编译产物。

## 验证边界

本轮执行类型与Main／Renderer构建、生产原生组件和既有金样程序编译、发行脚本语法及生成文件／分发清单核对；具体终态以实施状态记录为准。没有执行解析器、应用、SQL／内存库／迁移、worker、金样程序、音乐、真实来源保存窗口、音频或驱动，也没有新安装包。

MVP须覆盖：

- 普通及内嵌来源和备份复审的相同 FILE 接受／拒绝规则，转义引号、单双反斜杠、孤立引号、缺失类型、Unicode空白和行分隔符。
- 上限内长反斜杠／引号／空白失败输入的实际CPU与取消响应，以及原始行、总字节、行数和音轨数预算。
- 真实旧文本parser1快照、坏UTF-8、错误文档及原JSON字段顺序与SHA不变；正常和有歧义旧 FILE 语言的运行等价。
- 新worker结果拒绝旧标记，历史读取仍保留旧标记；旧FLAC重新探测、失败时旧分轨保护及外部CUE移除后的内嵌回退。
- 跨版本导出／重开／复审、用户选择与锁、曲目身份／原采样边界／歌词／波形和界面结果。

内嵌备份重开复审、来源与音乐本体映射／权利核对、历史解释重新应用、复杂静音／去加重／跨文件无缝、未决恢复继续／回滚、其他Provider与写回范围、任务中心／多窗口／插件／跨平台以及FR01–FR14／WP01–WP11／G1–G5／AC01–AC19继续保留。仅ASIO实机验证暂停，封面缺失案例尚未复现确认。
