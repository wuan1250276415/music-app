# ADR-236：分析缓存修订与滚动多段 PCM 解码核心

日期：2026-10-17。状态：分析缓存修正与生产者侧多段解码软件 MVP；播放宿主、队列及设备端无缝接入尚未完成。

## 分析结果不能跨解码规则复用

0.231 修正 MP3 逻辑游标、AAC priming／合成状态、部分索引跳转和 AAC/MP4 残余尾部填充，但原波形缓存键只包含波形算法和歌曲范围。文件字节没有变化时，旧结果仍可能通过内容摘要直接复用。持久识别映射的本地来源摘要也没有区分解码规则。

增加独立 `PCM_ANALYSIS_REVISION=pcm-logical-seek-aac-tail-v2`，同时用于新波形引用键、实际缓存对象 ID，以及指纹来源身份。解码时序、裁剪、跳转或 PCM 转换发生变化时必须更新此修订号；它是语义缓存版本，并非自动计算的原生二进制摘要。

不改写原有波形算法名称、历史 DTO 或持久识别记录，不清空数据库。旧波形任务继续读取原缓存字节，新分析生成独立对象，不能因文件摘要和帧范围相同而覆盖旧任务。新指纹审核通过现有 Service 来源摘要核对拒绝旧依据，需要重新识别；历史标识描述仍可读取和备份。数据库 schema86、媒体16及音频 IPC1.24 均不变。

集中验证使用实际扫描、SQLite 和原生波形进程，向隔离数据库写入符合旧格式的、摘要匹配的历史结果。FLAC／MP3／AAC 第一次均重新解码，第二次及实际数据库关闭重开后才复用新缓存；三份历史载荷逐字节保留。这里的旧缓存是构造的有效旧命名空间，并非使用历史可执行程序完成一次旧版本升级。既有指纹17项、持久标识8项回归继续验证当前审核和备份链路。

## 为完整连续播放提供生产者核心

新增 `aural_sequence::PcmSequence`，直接使用生产 `AuralPcmDecoder`，不复制一套简化解码器。它接收1至500项不可变计划，每项具有独立队列 entryId、物理路径、精确源帧起止和可选的已知物理文件绑定；所有累计帧须在安全整数范围内。源路径总长度、单次读取和测试输出均有独立预算。

同路径且前段结束等于后段开始时，连续 CUE 段保留同一个解码器、只读文件对象和解码状态，不重新定位或二次裁剪。跨文件提前打开下一个不同的文件，依次滚动复用两个解码槽；不会只支持首尾两首后重新启动进程。实际输出格式、采样率、声道数及解码声道布局全部相容才允许继续。新增 `pcmChannelMap()` 读取实际解码布局；未知布局、不同整数输出表示、不同采样率或 DSD 必须交给独立的转换／重开计划。

计划必须提供准确的源帧范围。核心不把曲库时长、压缩包数或估算时长转换为无缝裁剪依据；未来文件末帧解析仍需生产适配层提供可靠来源。编码延迟和 padding 只由 `AuralPcmDecoder` 处理，序列层不重复删头尾，也不检测静音或混合样本。

生产者读取可在同一次请求中跨越多个片段，返回帧数与串接内容严格一致；提前 EOF 是失败，不能补静音伪造成功。读取失败或取消保持终止状态。跨文件跳转重新打开曾访问的文件时必须匹配原先物理绑定，不能只因路径相同而接纳替换文件。

全部打开、解析、预读、证据对象分配、跳转及关闭均是非实时操作。最多保留当前与下一份解码对象；每次打开沿用现有只读句柄和取消／I/O时限。滚动预打开仍可能耗时，生产宿主必须以实际 ring 余量和耗时处理欠载，不能据此宣称慢盘或网络盘不会断流。

## 解码进度与已呈现进度分开

每段的全局 begin/end 在计划建立后不再改变。`locate(frame)` 仅对这些不可变范围做有界查找，给出 entry 索引、曲内帧和物理源帧；精确边界属于后一段，总末帧显式标记 atEnd。该标量查询不做 I/O、分配或等待，可在宿主保证设备生命周期的前提下用于实时侧。

`position()`／`segment()` 是生产者解码游标，会领先实际声音。未来宿主必须把已消费／已呈现的权威时钟映射到 `locate`，不能用生产者预读索引提前切换封面、歌词、播放历史或持久队列。`Span.evidence` 仍由生产者填写，其 JSON 对象不能直接供音频回调并发读取。

## 集中软件验证与范围

`test:pcm-sequence-mvp` 构建应用主进程和所需原生组件，再集中执行序列30项和缓存5项，不为每个小改动单独运行测试。固定生成素材沿用0.231的22份清单并核对摘要；不修改用户歌曲。

序列场景包含整数s16／s32、无损浮点、MP3／AAC／Vorbis／Opus多文件、同率混合编解码器、31段非扇区边界、500段短 CUE、CUE→文件→CUE、非连续同镜像片段，以及前后和跨边界跳转。无损串接逐字节对照独立原 PCM；有损对照各物理文件从原点分别完整解码再裁剪串接的基线，不能解释为有损等同原 PCM。

拒绝场景包括空／重复／超量计划、空范围与整数溢出、首份／下一份／更后文件缺失、不同采样率／布局／整数表示、错误物理绑定、打开前／读取前取消及源提前结束。真实只读锁检查覆盖当前与预打开文件，关闭后可重新取得写句柄，但不执行写入。已释放文件被实际替换后，向后跳转拒绝新的文件身份。

这些证据只证明核心的软件序列、精确样本内容、标量时间映射和已测异常行为。尚未把它接入原 `Player` 的 ring、完成尾部、增益、prepared pipeline、Main 与 PlaybackCoordinator。现有用户播放链路仍保留原两段 CUE 实现，不宣称已完成专辑长链或跨文件设备无缝。

## 接续实施顺序

1. 在生产宿主接入序列计划和 ring 生产，按实际输出计划处理不相容格式，保留唯一延迟裁剪责任层。
2. 按已呈现时钟发布每段源证据和边界，逐段重算 ReplayGain／Opus 增益，接通完整链的暂停、跳转、停止及尾部完成。
3. Main 与队列冻结 entry／修订号，协调边界与持久保存；修改队列、移除文件、维护、设备丢失时可靠取消未来片段。
4. 接通封面、歌词、统计和历史逐段身份，再做真实桌面完整链、欠载／中断及数字捕获验收。

本版本只重新构建音频宿主及其分析／软件工具，并重新生成当前二进制绑定的34组格式证明；未生成新安装包，试用安装包仍0.215.0。全部 FR01–14／WP01–11／G1–5／AC01–19继续；只有 ASIO 实机验证暂缓。
