# ADR-162：冻结状态下重建 Main 的队列与设置

日期：2026-10-10；源码批次：0.156.0；状态：私有 Library 状态读取、Main 原状态留档、缓存重建和持久回执已接入源码。没有普通就绪转换，没有开放应用恢复入口；三方维护继续冻结。

## 决定

ADR-161 归档并处理待保存资料之后，Main 不能继续使用原曲库的队列、输出选择、统计策略或未决设置命令。也不能直接调用普通初始化：它会注册快捷键、订阅资源或启动后台任务，且普通服务调用仍受恢复门禁阻止。

增加私有 `prepareHydration`。Main 先捕获并留档自己的原状态和未决设置请求，再要求当前可写暂停 Library 提供一个严格、完整的使用状态快照。Main 在现有资源冻结占用内应用快照，重新捕获结果，只有与 Library 摘要一致、历史文件仍符合原处理结果且输出已经释放时，才持久保存 `hydration-ready`。

## 快照与 Main 原状态

版本1快照包含播放队列、WASAPI 输出、ASIO 输出、音频后端、DSD 输出、外观、窗口位置、窗口/托盘行为、媒体快捷键及播放统计策略。复用各领域的现有校验器，限制规范状态为1MiB，实际 IPC 与全局记录仍遵循3MiB帧预算。没有保存过队列时，在使用状态中提供规范空队列，不写回数据库，也不改变队列修订。

`hydration-intent` 包含原 Main 的上述内存设置与队列，以及尚未确认的四类输出设置请求、外观请求和缩放草稿。候选导入在 ADR-161 已清除历史策略，所以原 Main 留档允许该字段为空；新的 Library 快照必须包含有效统计策略。历史原文及原统计策略的持久证据仍在恢复前快照和两侧 pending 归档中保留。

留档发生在替换任何 Main 缓存之前。旧请求保存供后续明确核对，不自动在新库重提。内存中的已结束命令结果缓存可以清空；未结束的命令会阻止重建。完整的留档查看、导出和经过授权的重提界面仍需后续实现。

## 私有读取与持久顺序

1. Main 重读原全局记录，要求当前激活及 `pending-settled` 已持久保存，且实际同一 Library 实例仍在冻结状态。
2. 生成新的挑战。请求绑定事务、激活、实例、token、角色、目录身份、激活/待保存结果摘要，以及原 Main 留档摘要。先保存 `hydration-intent`。
3. Library 复用同一可写暂停连接，以 `prepareFrozen` 排斥并发维护、捕获和释放。要求原激活已经成功，网络资源仍停止，实例和目录仍符合原证明。
4. Library 在读取前后核对完整 library 文件清单及目录身份；只调用现有只读设置 getter，不迁移、修复、保存队列或启动后台任务。返回当前 PID/构建、原请求及快照摘要和 `backgroundStarted:false`。
5. Main 核对实际进程、构建与请求，再次核对固定 live 槽位完整文件，并重新捕获原 Main 摘要，防止读取期间旧状态变化。
6. 在冻结占用内替换使用状态，重新捕获快照。结果必须等于 Library 规范摘要，历史内存及文件必须等于 `pending-settled` 的结果，输出必须释放。随后保存 `hydration-ready`。

全局历史重读区分旧构建记录与当前进程验证；历史证明的 PID/构建仍必须等于原激活。新增操作只能使用实际当前进程，不能采用旧回执代替当前所有者。本阶段再增加两条记录，当前最长已定义路径为29/32条；Renderer、终态及释放方案需重新核对剩余预算，不能因预算紧张而省略必要证明。

## 重建范围

- 播放队列按保存的身份、顺序、当前条目和修订重建。清空旧命令缓存、无缝计划、输出/恢复书签和历史会话身份。曲目 ID 保留，没有读取源音乐或启动播放。
- 音频控制器要求输出及定位操作已释放，重置旧曲目展示、阻止原因和分析副本状态，再应用四类输出偏好。只应用内存设置，不枚举声卡、不查询驱动、不打开 ASIO/WASAPI/DSD 会话。
- 外观、窗口位置、托盘行为与快捷键只重建缓存，清除旧未决外观操作。主题与缩放的实际应用等待未来释放；不移动窗口，不注册快捷键，不重建托盘或启动系统媒体进程。
- 系统媒体旧曲目、封面、上下文及控制去重缓存在确认原进程和查询退出后清空。原本用户启用的恢复意图继续由既有维护资源保存，当前不启动。
- 播放历史重新核对原处理后的内存与实际文件摘要，再载入新的统计策略。候选的记录仍暂停，计时器不启动；未来明确释放时才启用。original 角色要求原策略完全一致，保留原 pending 记录，不通过本阶段保存到曲库。

Main 组件的普通请求仍受 Main 维护门禁拦截，Library 的普通调用仍未就绪。私有协议不新增 Renderer 可调用的状态读取或任意 Library 调用入口。

## 失败、退出和后续阶段

读取失败、文件变化、实例退出、取消、文档或应用状态变化、Main 原摘要变化、缓存替换中断或最终摘要不一致均保留原意图、留档与维护占用。部分缓存重建不是恢复完成，也不自动恢复旧内存或释放后台。生命周期超时监督保持当前所有者边界；实际退出不能清除其他进程的状态。

下一阶段仍须重置/重新挂载 Renderer 中缓存的旧草稿、查询和 pending 状态，确认新文档与新曲库数据，持久完成终态，然后按顺序转换服务就绪并释放资源。启动前门禁继续拒绝含未完成目录移动事务的普通打开。缺失回执、激活中断、未知目录状态的重启对账及恢复界面尚未完成。

来源与旧任务复审、明确原文导出/重提、完整领域与迁移校验和、物理工件配额和清理，以及 FR01–FR14 的其他余项继续保留。不能把 Main 状态就绪回执解释为整个恢复流程或 WP11/AC17 已验收。
