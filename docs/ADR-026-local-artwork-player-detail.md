# ADR-026：本地封面与播放详情

状态：已实现原型，2026-09-30。对应 WP04/05/06/10 的纵向交互；不改变 schema v4、音频协议或 WP02 门禁。

## 问题与决定

此前扫描器使用 `skipCovers:true`，列表及播放栏只绘制专辑首字色块，无法显示音乐文件已有的封面。扫描仍跳过大图片以保持曲库导入轻量；展示时通过受信任的 Renderer → Main → Library Service IPC 按曲目 ID 读取，解析顺序如下：

1. 用 `music-metadata` 读取音频文件内嵌图片，优先选取最可能的封面。CUE 虚拟轨使用其引用音频文件的图片。
2. 没有可用内嵌图片时，按 `cover`、`folder`、`front` 的 JPG、PNG、WebP 文件名从同目录读取。
3. 都不存在时显示原有的专辑首字色块。

当前源码 0.31.0 接受经文件签名识别的 JPEG、PNG、WebP、GIF、BMP 内嵌图片（目录回退为 JPEG、PNG、WebP），单图上限 16 MiB；侧车文件不跟随符号链接。Library Service 同时最多解码四个文件，按文件 ID 复用请求；成功图片缓存最多 32 项，并以字符串占用估算限制为 64 MiB，扫描完成后失效。缺图和读取失败不会永久缓存；详情页可主动重新读取当前物理文件。缓存预算不包含图片解码、组件正在显示的图片或标签解析峰值。列表图片接近可视区域时才请求；当前播放与详情封面立即请求。图片以 `data:` URL 交给 Renderer，CSP 的 `img-src` 已限制为 `self data:`。没有向网络发送本地封面或路径，也不写回原文件。

播放栏封面成为“打开播放详情”按钮。详情覆盖曲库区域，播放栏继续可用；显示封面、曲名、可点击的歌手/专辑/风格、音质、本地 LRC/TXT、播放模式和播放队列。点击分类返回对应曲库筛选；LRC 按播放时间滚动并可点击行跳转，纯文本只展示；队列可以跳转曲目，模式修改继续使用原有队列命令修订机制。Esc 或关闭按钮退出详情。减少动画设置关闭歌词滚动动画。

## 验证和边界

生成的带内嵌 PNG 的 MP3 与不同颜色的文件夹图片验证了内嵌优先级；无内嵌图片和缺图路径验证了回退。桌面回归覆盖列表/详情/播放栏封面、歌词、随机模式、队列，以及歌手/专辑检索跳转。单元和桌面结果以 README 的 0.21.0 记录为准。

0.24.0 扩展桌面回归为两首真实可解码的测试文件：MP3 验证内嵌封面优先于目录 PNG，WAV 验证目录封面回退；同时检查播放栏图片、歌词点击 seek 到 4 秒、当前歌词自动滚入可视区、详情队列切换并实际播放两个文件，以及随机/列表循环/单曲循环和分类跳转。使用 `npm run test:detail` 运行；当前发行版结果见 README 的 0.24.0 记录。

0.29.0 延续上述完整交互回归，逐字节核对列表、播放栏和详情的内嵌图片以及无内嵌时的目录图片，并保存源码与解包版详情截图。后续发行字段、专辑署名和人工绑定仍使用各实体的精确身份筛选；最新测试结果与已知自动化稳定性问题见 README 的 0.29.0 记录。

尚未提供在线封面源、图片持久磁盘缓存、封面人工选择与著作权来源管理。极大图片可能仍使单次标签解析产生峰值内存；十万曲库的图库性能需按 WP05 验收。图片元数据损坏时显示回退色块，后续可加入明确的“重新选择封面”流程。

0.31.0 补上缓存重试／内存预算、详情主动刷新、切歌读取代次隔离和详情队列编辑；此轮仅编译通过，运行回归集中到 MVP，详见 [ADR-036](ADR-036-artwork-detail-refinement.md)。
