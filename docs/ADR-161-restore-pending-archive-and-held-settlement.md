# ADR-161：恢复待保存资料的原文隔离与冻结处理

日期：2026-10-10；源码批次：0.155.0；状态：私有编排、持久记录、原文归档和冻结处理已接入源码。整库恢复尚未完成，没有开放应用恢复入口。

## 问题与决定

ADR-160 的可写暂停准备不能直接释放普通业务。恢复前的界面有尚未确认结果的原操作，Main 有尚未提交的播放历史；备份中也可能包含这两类资料。把它们直接交给新库重试会跨越曲库身份、来源授权和旧任务隔离边界。删除资料又会丢失追查未决结果的依据。

增加私有 `preparePending`。先将恢复前快照和备份的待保存文件按原始字节复制到事务内的独立 `pending` 目录，并保存完整摘要及来源清单；持久确认归档之后，才允许处理当前会话的受保护存储和 Main 历史文件。归档保留候选和原库两侧，不导入、不执行其中的命令。保持三方维护冻结，下一阶段单独重建使用状态。

## 归档和持久顺序

固定名称为 `candidate-renderer.json`、`original-renderer.json`、`original-history.json`，以及备份包含历史文件时的 `candidate-history.json`。不接收 Renderer 提供的路径。文件规格来自已核对的原快照与备份清单，并绑定事务、激活 UUID、角色和目录身份。

1. 核对当前原记录、可写暂停证明、实际冻结实例，以及两个来源暂存目录身份。
2. 独占创建事务 `pending` 目录，持久保存 `pending-intent`。空间不足或原记录变化时停止。
3. 以 1MiB 分块读取，独占创建副本、同步写入，核对来源与目标的类型、单链接、大小、句柄和具名观察、父目录身份及完整 SHA-256。
4. 核对目录只有计划的三至四个文件。原界面快照以预算内的固定缓冲读取，严格解码并核对规范快照和 values 摘要；复核两个来源根身份，才保存 `pending-archived`。
5. 向当前冻结文档发送不含路径的挑战。收到严格匹配的成功回执后，保存 `pending-renderer`。
6. 在原 Main 历史内存和文件都与原快照摘要一致时执行角色对应处理，再保存 `pending-settled`。

四种记录由全局不可变记录链严格检查顺序、唯一性、激活与原清单绑定。重复、改内容、迟到回执或没有归档证明的处理不能进入成功记录。当前最长已定义回滚路径加上可写准备与本阶段为 27 条记录，仍遵循既有每事务 32 条上限；后续终态设计需重新核对预算。

## candidate 与 original 的不同处理

导入 candidate 时，界面先核对受保护键与原冻结快照。只移除完全相同的原键；新出现或已变化的键会阻止处理。部分清理留下的缺失键仅在导入路径可被识别为已清理，不能推断全局成功。通过预先捕获的原 Storage 方法逐键移除，其余界面写入仍被冻结门禁拦截。最后要求受保护键为空，并返回其规范摘要。

Main 历史采用独占临时文件与同步写入，再复核原文件、替换、核对空历史摘要。成功后清除旧 pending、累计器、时钟基线和统计策略，并保持记录暂停。原历史原文已经独立归档。此时尚未加载新库的统计策略，不启动计时器，不向恢复后的数据库保存旧检查点。

回滚 original 时，界面键必须与原冻结快照完全一致；Main 历史内存和实际文件也必须与原摘要一致。两者都保留，不清空，不改变统计策略。候选侧资料仍单独保留，但不自动重放。

## 所有者、取消与中断

Main 的私有编排核对当前事务、实际 Library 实例及冻结占用。Renderer 只有回复当前挑战的接口，没有启动归档、清空或应用恢复的接口。挑战匹配操作、激活、随机挑战、归档及原快照摘要；所属文档变化、取消、实例变化和 20 秒等待超时均保留资料和维护占用。

事务重读核对归档目录身份和固定文件名。已有 `pending-archived` 必须重新核对完整文件及原快照摘要；只有意图时允许有界、已计划名称的部分副本，但不把它们当作归档完成。无意图的非空目录拒绝采用。没有猜测重试、自动覆盖或清理未知资料的路径。

这是应用层的文件观察、摘要核对与持久确认，不承诺防御任意外部进程在所有观察之间替换目录，也不宣称目录写入具有已认证的断电原子性。Windows 本地普通目录和受监督所有者仍是当前限定范围。

## 仍未完成的恢复流程

本阶段成功仍是可写暂停状态；普通业务、后台任务和维护占用继续冻结，启动前门禁仍阻止含目录移动但没有完成终态的事务直接打开。

下一阶段需要重建 Main 的设置、播放队列和媒体状态，加载新的统计策略，重置或重新挂载 Renderer 中缓存的旧草稿及 pending 状态，核对新状态并持久记录完成终态，再按确定顺序释放资源。还需实现缺失回执和激活中断的重启对账、恢复界面、原文导出、旧来源与任务复审及经过授权的显式重提操作。保留资料不等于这些能力已经完成。

本阶段只有单次事务可用空间检查和既有记录上限；总工件物理配额、登记与清理仍未完成。完整领域和 migration checksum、静态歌单迁移、其他格式标签写回、复杂 CUE 与跨文件无缝、更多 Provider、在线字同步歌词、多窗口、跨平台、签名更新和全架构发布验收继续保留。
