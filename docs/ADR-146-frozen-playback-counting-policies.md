# ADR-146 可配置达标统计与逐次播放规则快照

日期：2026-10-09；源码版本：0.140.0；schema：68。状态：源码实现，运行验收待 MVP。

## 问题与范围

ADR-139 的播放历史仅使用固定 version1 达标条件，用户不能调整统计口径；若直接替换全局算法，正在播放的累计检查点可能在设置变化后按另一个标准计次，既有历史也无法解释当时的计数条件。

本批实现可配置 version2 规则、持久化设置修订、每次逻辑播放／队列条目的冻结快照、历史规则展示及设置操作的持久核对。只调整达标次数，设备回报时长、估算时长和最近播放观察继续保留；关闭达标次数不等于关闭历史记录或清除个人数据。

## 规则语义

规则严格包含 version、countEnabled、percent、seconds、combine、shortSeconds、shortPercent、shortRequireTail；未知字段和版本拒绝。

| 条件 | 范围与含义 |
| --- | --- |
| 曲长比例 | 1–100%的整数；按微秒用 BigInt 有理运算向上取整 |
| 播放时长 | 1–3600秒的整数；未知曲长只使用此条件 |
| 条件关系 | either 取较小阈值；both 取较大阈值 |
| 短曲边界 | 0–300秒；曲长严格小于边界时使用独立短曲规则；0禁用该分支 |
| 短曲比例 | 1–100%的整数；替代一般比例／时长条件 |
| 短曲到达位置 | 启用时除累计设备回报时长外，furthestUs也须达到对应比例 |
| 达标开关 | 关闭后该次播放不增加达标次数，历史与时长仍记录 |

默认条件保持既有行为：50%或240秒，短于30秒需95%累计且到达对应位置。默认值保留的旧语义不是全部文件／时钟边界已验收的证据。both 不强制把阈值截到曲长，可能需要在同一逻辑播放中反复播放片段才能满足；设置页明确解释。一个 session／entry 最多计一次，重复播放片段的进度可以累计，跳转动作本身不计时。不宣称唯一音频区间覆盖或全曲完整播放。

只使用 validated device／driver-reported 源时钟增量判断达标；estimatedUs单列，不参与次数。暂停、跳转、设备代际／宿主改变及倒退时钟仍沿用原基线、最高水位和证据隔离。

## 持久设置与schema68

新增 playback_counting_policy：revision主键、规范完整snapshot JSON、可空首次command_id、created_at；新增 playback_counting_setting：唯一id1与当前规则revision外键。默认revision0在迁移事务内创建，不通过缺失行静默回退默认值。

规则历史禁止UPDATE／DELETE，当前设置禁止DELETE且UPDATE只能old+1。规则JSON最多4096字符，最多65536个修订，达到预算时整次新操作回滚，旧规则和回执不删除。后续受控治理仍待实现。

当前设置请求包含原UUID、baseRevision和完整规则。进入BEGIN IMMEDIATE后先核对全局 user_command_receipt；同UUID／同规范摘要先返回原回执，不受当前设置后续变化影响。新操作核对当前修订后，将父回执、新不可变规则和当前指针在同一事务提交；规则command_id外键阻止移除其成功回执。冲突、预算或写入错误拒绝整次操作，不能留半个新修订。

异常后读取原回执进行提交核对；回执读取或解析失败仍是未决错误，不伪造已知拒绝。真实新提交才发送playbackPolicyChanged。回执重放不代表原修订仍是当前设置；Main与界面均重新读取当前值。

schema68前创建pre-v68一致VACUUM快照，建表／默认规则／外键检查／提高user_version在同事务；旧版根据manifest拒写新库。原播放历史表、统计表和旧JSON不改写，不重新计算历史达标次数。生产迁移及故障回滚待MVP，未执行SQL。

## 播放快照与兼容

Main启动时先读取持久设置，再初始化播放和历史记录。每个新的逻辑session／entry在首个有效来源观察基线时冻结version2完整规则与revision，即使该观察尚未产生可保存的正时长。曲目恢复、暂停、seek或输出重建沿用该累加器快照；配置更新不刷新已有累加器或重启音频。当前规则缓存拒绝同修订不同内容，并忽略迟到的较旧修订。

同文件连续CUE两个entry分别在进入自身观察范围时准备规则，不因预读下一轨提前绑定；跨边界增量仍按整数帧拆分。首次观察不等于鼠标点击的时间，配置若在点击后、首个可用来源时钟前变化，该次记录使用首次观察时的规则。跨重启重新播放会生成新的逻辑session；持久pending检查点继续携带其原规则。

version2检查点必须携带policy和observedAt；完整快照进入identity_json，因此同次播放后续检查点不能更换统计口径。Library在新增检查点事务中核对对应持久规则的revision和完整规范内容；摘要相同的旧检查点先回放原成功结果，不重复计数。

version1检查点仍只使用原固定条件；原13字段／14字段pending载荷的字段顺序和规范SHA路径保持，不能补写新规则改变其回执。旧历史页面显示“旧版固定规则”，新记录显示其冻结的条件；混合页经过严格共享响应验证。pending文件外层version1和512项／16MiB、15秒保存／退出预算保持，既有崩溃／断电时最近尚未持久化进度仍可能丢失。

## 界面与操作核对

“播放历史与统计→统计口径与设置”提供当前规则、编辑、载入默认条件、保存及重新读取。关闭计次仍保留时长，默认条件只载入草稿，必须点击保存。修改只影响下一首开始记录的entry；历史每行可展开当次规则。

保存前将原UUID和完整请求写入localStorage；重试始终使用原请求，不生成新UUID。严格核对返回UUID、保存结果修订和完整规则后才清除待核对请求。响应失去确认、损坏或清除失败保留原记录；已知拒绝要求重新读取后编辑。无法解析的原记录先保存本机副本，再显式解除编辑限制，不直接丢弃。

规则更新使当前编辑失效，用户须重新读取；读取与保存都检查组件代际／活性。设置保存中禁止关闭父窗口或通过歌曲资料检索退场，关闭未决操作窗口仍保留请求。全部能力只来自可信Main文档IPC，不向Renderer开放历史检查点写入或数据库路径。
