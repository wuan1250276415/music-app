# ADR-119：FLAC 标签适配、工件暂存与阶段日志

日期：2026-10-03。状态：源码、Main／Renderer 类型与构建、音频／媒体监督／凭据／系统媒体与既有金样编译、41 个 CommonJS 语法和发行／分发清单静态检查通过；实际文件、进程、目录、工件与恢复验证集中到 MVP。

对应架构 FR12／WP09／AC12。此前只有库内字段修改，本批提供 FLAC 写回底座；不把库内 ChangeSet 当成已经写入音乐文件。完整目标、其他工作包与 ASIO 暂停实机验证的决定保持。

## 标签适配器

使用自有 TypeScript 有界适配器，运行于既有受 Windows Job 监督的可抛弃媒体进程；不新增 TagLib 依赖，也不引入重编码器。格式依据 [RFC 9639 §8](https://www.rfc-editor.org/rfc/rfc9639.html#section-8)：严格独立 `fLaC`、首块唯一 STREAMINFO、元数据 24 位长度、最后块标记、单个 Vorbis comment、长度字段的小端编码、大小写无关的字段名，以及音频帧起点之后的独立载荷。SEEKTABLE 偏移相对音频帧起点，因此只变更元数据前缀而保持载荷字节不要求改写其偏移。

支持 TITLE、ARTIST、ALBUM、ALBUMARTIST、GENRE、DATE、TRACKNUMBER、DISCNUMBER、COMMENT、COPYRIGHT、ISRC。多值使用独立重复项；显式空数组表示清除，不猜测分号／逗号是分隔符。保留原 vendor、未选择注释的原始字节与顺序、STREAMINFO、PICTURE、APPLICATION、SEEKTABLE、CUESHEET、padding 和保留类型块。非目标块内容与顺序保留，元数据 header 的最后块标记按新序列重写。外部未知值保持原字节；选择用于展示和修改的原值必须是可验证 UTF-8。这里不开放图片、歌词、技术声道 mask、任意外部 ID 或未知标签的写回。

重建后重新解析，核对目标值、非目标块聚合、未选字段及 vendor 的字节一致性。预览包含来源／目标元数据 hash、音频 offset、大小、选中字段 before/after、源技术属性、图片数及嵌入 CUE 标志，certification 固定 pending。STREAMINFO 中的 MD5 是原文件声明，不是本次解码验证结果。真正音频复制及载荷 hash 由暂存层验证，预览不伪造音频完整性证据。

## 受监督的只读预览

媒体协议从 9 升为 10，增加 `flac-tag-preview`、`MediaParser.flacTagPreview` 和严格的字段／回执结构；该任务是只读操作，依旧使用授权根、真实根、路径、读取前后文件属性和进程实际退出监督。前台队列有界，并保留每三次前台任务后给扫描一次调度的策略。预览回执限 128 KiB，输入沿用 64 KiB；元数据总量 32 MiB、块数 1024、注释数 32768、vendor 1 MiB，单块不超过容器长度容量。最多 11 个选择字段、每字段 32 个目标值、单值 8192 UTF-8 字节、目标总字节 24 KiB；原值总展示 32 KiB。整个受监督媒体 Job 的既有内存和 20 秒 CPU／22 秒墙钟限制保持。

32 MiB 是支持边界，超过预算或不标准的 FLAC 明确失败，不尝试修复损坏的源文件。源属性检查是现有 Node Stats 与根路径边界，并不是 Windows 独占写租约；后续真正替换仍需原生文件身份与替换语义门槛。

## 备份、临时文件与 hash

`stageFlacTagArtifacts` 是内部 worker 核心，目前没有 Main／Renderer 调用入口。调用前必须给出冻结计划、原文件完整证据、授权根、原始属性、受控备份目录、独立 backup/temp 工件 UUID。它拒绝 CUESHEET 多轨单曲计划、源符号链接和多硬链接，使用固定 UUID 文件名并独占创建，已有工件必须先回读原操作。

原文件、备份、临时文件分别记录全文件 SHA-256、元数据 SHA-256、音频载荷 SHA-256、各段字节数。分块读取／复制为 4 MiB，音频源不整体载入内存；大小上限 64 GiB。先预估备份和完整临时 FLAC 的剩余空间，复制仍单独处理磁盘满错误。创建备份、fsync、重读与完整原文件比较后，才调用持久化 backup_ready；之后在原目录写新元数据前缀及原始音频载荷，fsync、重读标签与各 hash 后，才调用 temp_written。备份和临时文件的具名路径再与打开句柄的属性核对；源句柄、具名源、根和目录在各阶段重新核对，并多次重新 hash 原源。

取消和出错关闭句柄，保留已有工件；没有自动删除、原文件原地修改、原子替换、自动恢复或目录级原子承诺。当前暂存核心尚未部署到独立长任务进程；它不能借用仅用于预览的 22 秒媒体任务预算处理大型复制，也不应在 Main／Library 业务线程直接启动。Windows statfs 行为、空间估计、外部变更和工件句柄绑定仍需 MVP 实测。

## 持久阶段与恢复

共享阶段为 planned → validated → backup_ready → temp_written → replaced → verified → committed，异常为 failed／recovery_required。validated 必须携带源完整 hash 与租约 UUID／修订；备份必须匹配原源；临时文件必须匹配目标元数据、尺寸及源音频 hash；替换必须有同一租约、已批准格式证书及实际被替换文件的副本证据；verified 必须再次匹配临时目标；committed 必须有数据库回执和预期 content revision。

`TagWriteJournal` 将初始计划及每阶段分别保存为独占创建的不可变文件，按修订串联 SHA-256，单记录 64 KiB、单任务最多 32 记录、目录最多 1024 任务；写完 fsync 后回读链，再返回。同 commandId 内容一致回读已保存结果，内容改变、修订冲突、日志缺口、半写记录、符号链接、硬链接或身份变化均拒绝覆盖。哈希链用于一致性检测，不声称能抵御有目录写权限者重写整条链。文件 fsync 也不被包装成 SQLite／目录元信息／硬件断电的跨资源事务。

日志默认认证目录为空；不能创建自称已认证的任务，也不能确认 replaced。历史已认证任务仍允许回读供恢复；未来由受信任的发行认证清单注入当前证书，不能将用户输入的证书字符串当作认证。

恢复分类只使用重新打开并计算出的实际原文件／备份／临时文件／被替换文件证据，区分源未变、已有有效暂存、已替换且完整验证、原文件缺失但可恢复，以及必须人工检查。源未变不意味着可删除不明工件；分类本身从不修改文件。源被外部替换或受害副本不符时保留所有证据，不能以 DB 中的单个阶段字段判断已完成。

## 下一批与 MVP

继续实现 Library 的文件写租约、探测／扫描／播放释放协调、来源 writeback 权利检查、持久任务目录与 SQLite 回执、独立长任务 TagWriter、认证的本机 NTFS 原生替换／实际被替换文件保留、文件后续重探测和库修订更新、差异预览／确认／批次与恢复界面、MP3 适配，以及备份保留与空间策略。WAV／DSF／DFF 仍保持库内编辑；NAS 和云挂载不开放未经认证的替换。外部 CUE 虚拟轨与镜像所有权还需 Library 层拒绝，不能仅凭文件中无 CUESHEET 认为适合单曲写回。
