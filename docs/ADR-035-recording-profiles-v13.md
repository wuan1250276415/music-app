# ADR-035：录音资料与有序署名（schema v13）

状态：0.30.0 开发中，类型检查与 TS／Renderer／C++ 构建通过；按用户要求将运行、迁移与端到端验证留至 MVP 阶段。本文件描述实现，不宣称运行验收完成。

## 领域行为

“整理关联 → 编辑录音资料”编辑 Recording 的名称、版本说明、参考时长，以及演唱／演奏、作曲、指挥、乐团的有序署名与连接词。名称和版本最多 240 字符，署名最多 64 项；同一身份可有不同角色，同一角色不能重复，每种角色最后的连接词为空。来源艺人和解析后的人工身份均须有效、未归档，并校验所选来源修订。

参考时长存为可空的非负整数微秒。界面输入秒，最多六位小数，经整数运算换算并检查安全整数范围；它只是录音参考资料，不改 MediaFile／MediaStream／PlayableSpan、CUE 范围、实际解码或播放时钟。空值表示未指定。

编辑原 Recording UUID，作用于引用该录音的全部当前文件（含隐藏／离线），不改发行曲目名称／署名、物理文件、标签、用户引用或队列身份。录音署名与发行曲目署名独立展示，避免把一个发行版的曲目署名强制套到其他版本。详情显示录音名称、版本、参考时长及可点击的角色署名；名称／版本／人物进入搜索，人物角色分类同时包含已确认录音署名。

保留扫描候选的 local_key；扫描不覆盖已确认的录音字段与不可变人工 credit。对已编辑本地候选确认“同一录音”关联时复用该 UUID，避免丢失其已确认资料及外部引用。恢复候选关联仍沿用既有流程，录音资料有独立撤销入口。

## 事务与修订

`recording_profile_state` 保存独立、单调递增的修订号与确认状态；撤销到未确认状态保留修订号，避免状态回退后的旧预览被重新接受。`recording_profile_change` 保存字段、credit ID、成员和前后完整快照，接入统一历史。

预览指纹覆盖字段、解析后的署名和来源修订、全部当前成员的关联／项修订／指纹／CUE 边界，以及录音外部引用与引用修订。保存校验预览及艺人，事务创建不可变 credit、修改录音和确认状态、更新全部关联项修订／检索、审计和持久命令回执；失败回滚全部操作。每次最多影响 5000 个文件，超限拒绝。重复命令重放原回执，同一命令 ID 改作其他请求则拒绝；已确认资料无变化时不新建修订。

撤销校验后置快照，恢复原字段、原 credit 和确认状态，递增修订并刷新全部成员；后续重扫或绑定导致资料、成员、人物或引用变化时拒绝过期撤销，相同标签的无变化重扫不使预览失效。录音 credit 活动检查阻止恢复已经归档的身份。

艺人更名、身份关联、候选列表和人物成员查询纳入已确认录音 credit；更名和身份变化刷新关联文件。即使录音暂时没有当前文件，已有录音署名也阻止人物归档，人物资料指纹包含该依赖。未确认录音不增加投影字段或人物指纹后缀，以保留未发生后续修改的旧审计兼容性。
