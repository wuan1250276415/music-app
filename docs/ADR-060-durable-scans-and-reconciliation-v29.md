# ADR-060：持久扫描任务、检查点续跑与完成前对账（schema v29）

日期：2026-10-01。状态：0.55.0 源码实现，运行与迁移待 MVP。对应架构 §9、FR01/FR04/FR13、WP01/WP03/WP04/WP11。FR01–FR14 与 WP01–WP11 范围不变，ASIO 实机验证仍暂停。

## 持久任务与控制

schema v29 加入 scan_job、scan_entry 和不可变 scan_command。任务保存授权 root_id／当时路径、首次检查的实际根目标、扫描 generation、检查 pass、阶段、状态、所有者／租约心跳、尝试数、修订、检查／更新／异常计数及剩余清单。条目清单保存目录、音频、CUE 相对路径和安全检查点，异常消息随条目保留；不会把所有文件路径放进 Renderer 状态事件。

状态为 queued、running、cancelling、succeeded、failed、cancelled、interrupted。每个根在排队／运行／取消确认／中断状态最多一个任务，部分唯一索引防重复；最多 64 个待处理根，Library Service 全局一个扫描槽。任务中心可以分页查看、读取任务与异常记录、发起取消或继续。重扫入口和新目录导入走同一管理器；原公开 scanRoot helper 也使用同一持久流程，每个 DB 复用一个管理器。

控制带 UUID，取消／继续再带 baseRevision。Repository 在事务中核对状态、修订、当前根路径及 generation，保存结果回执。新 start 请求遇到已有活动任务时绑定现有任务并保存自己的回执；中断任务可续跑时重新排队，范围已被替代时保留旧任务并创建新的扫描。失败／取消任务只能在原范围仍有效、没有其他活动任务时继续；新 generation 已替代旧任务时拒绝旧续跑。

同 UUID 必须是同一规范请求，重试读取历史结果，不重复排队／取消／恢复。Main 提取固定字段，preload 只暴露任务 ID、分页及控制参数，不接受额外扫描路径。原文和元数据用户修订仍由既有 Repository 处理，扫描控制不承担新的写回或物理删除授权。

取消运行任务先进入 cancelling，AbortSignal 在目录、文件／标签读取及提交边界检查；检查点在写入前再次核对取消标记。真正结束后才进入 cancelled。队列／中断任务可立即取消；已入库内容、用户设置和检查点继续保留。界面区分取消已请求与已确认停止，未知控制结果保留原请求并提供核对入口。

## 清单与安全批次

目录用 opendir 流式枚举，每批最多 256 个相关条目，以 INSERT OR IGNORE 和唯一任务／pass／规范路径键保存；未完成目录在续跑时重新枚举，已有条目不重复计数。规范化冲突明确报错，不能把两条不同路径合并为同一文件。目录、音频和 CUE 分阶段处理，CUE 在本轮音频检查后协调引用。

每 pass 最多 30 万个相关条目，目录路径上限 32768 字符；超过预算进入不完整扫描，不做缺失清理。当前剩余数和清单数在批次／条目提交中维护，不在每个文件或每次 UI 刷新时 COUNT 全库。任务与异常分别每页 20 条，任务按持久递增 seq、异常按条目 ID 键集分页；异常游标绑定任务。

文件入库／markSeen、CUE 应用／保护与对应条目完成、计数、剩余数在同一立即事务中提交。Database 的内部事务在已有事务内使用独立 savepoint，确保 Catalog／搜索等既有写入也属于外层扫描检查点；失败回滚后不提前标记条目完成。目录子清单分批安全提交，只有成功遍历结束才完成目录检查点。

进度最多约 4 Hz 发布；目录／每 20 次音频检查触发观察，控制、开始运行、阶段与最终状态即时发布，短任务最终状态不会被节流掉。首批 Catalog 已提交结果约每两秒通知列表刷新，不必等待整根扫描完成。检查、目录和更新数字是历次检查／入库尝试累计次数，完成前对账或续跑可能再次检查同一路径，不声称是唯一物理文件数。

## 完成前对账与中断恢复

初始遍历／媒体／CUE 阶段完成后，新 pass 与新 generation 重新枚举整个授权根。前一阶段已经正确入库的相同大小／mtime、无 parse_error 且 Catalog 完整的文件走轻量复核与 markSeen；改变的文件重新解析。最后一轮完整清单和实际检查才参与 missing 判定，防止之前已检查文件在暂停期间消失却仍被旧 generation 标记为已见。

进程启动恢复仅在已由 Main 创建的新 Library Service 单写入者中进行：running 转 interrupted，取消已持久请求转 cancelled，清除旧所有者并保留检查点；queued 任务继续执行，interrupted 任务由用户继续或重扫。旧版本只有 root.scanning 没有任务记录时，清掉旧运行旗标而不判缺失。没有根据一个状态文件推断仍有进程存活。

初始 pass 的续跑按剩余检查点继续；已进入对账 pass 的任务再次续跑时，新建对账清单和 generation，避免完成旧的局部观察。每轮根目标一致、当前 generation 匹配、全部清单已完成、finalizing 且没有范围错误时，目录结束与 succeeded 同一事务提交。目录／CUE 范围读取不完整时 failed，保留旧媒体与旧编排，不运行 missing 清理；取消同样不清理。

任务记录所有者和 60 秒租约，运行中约每 10 秒续期，写检查点核对所有者和取消标记。当前恢复依据已知新 Service 进程启动，而非仅靠租约时钟到期抢占；运行中自动租约回收、next_run_at 退避、自动重试和通用任务调度仍待后续。没有把同一任务同时交给多个扫描器。

## 文件稳定性、异常与授权边界

音频通过同一个只读 FileHandle 交给 strtok3 FileTokenizer 子类和锁定 music-metadata 的 parseFromTokenizer；解析前后同句柄 fstat，另核对当前路径 stat 的 size／mtime／ctime／dev／ino。读取目标限定在授权根实际路径内，默认不跟随枚举遇到的符号链接；明确授权的根别名可读取其捕获的目标，但恢复时根目标改变则拒绝并标离线。CUE 相对引用仍用 resolveCueReference，不能越过根目录扩大授权。

标签读取／peek 总预算 32 MiB，合作式时间预算 20 秒，读取／ignore 周期让出事件循环并检查取消；CUE 同句柄最多 2 MiB + 1 字节，前后属性和实际读取长度一致才解析。标签核心文字长度、集合数量、序列化内容预算进一步限制。strtok3 10.3.5 从已锁定的传递依赖改为直接精确依赖，未换版本，许可证／分发库存仍覆盖。

解析失败、文件仍变化或读取失败时，不以文件名和未知艺人等占位值替换既有标签；既有文件只保护 seen_generation，不把原 missing 状态强行改为 online，新异常媒体不加入可播放目录，异常可查阅。正常已知文件才 markSeen 并恢复 online。CUE 仅使用本 pass 成功检查的音频引用；已有 CUE 遇到错误保留原编排，新 CUE 可保留确认有效的子集并显示警告，但本 pass 不完整、不能进行缺失清理。

以上是同句柄及路径属性观察，不是文件系统原子快照、原始字节哈希、Windows CreateFile 最终路径证明或全类重解析点保证。解析预算不约束依赖在调用 tokenizer 前的分配；协作超时／取消不能强行中止阻塞系统 I/O 或不返回的 CPU 代码。独立 Media Worker、可杀死的硬超时／内存预算、完整文件 ID／volume ID 及写租约仍在原架构范围内，不能用本批次代替这些门禁。

## 界面与验证

顶部“任务”打开扫描任务中心，显示排队、阶段、完成前对账、尝试与剩余数；可以查看异常、取消／继续、刷新和核对原操作。控制成功后的刷新失败不会再次提交写操作；请求迟到与关闭按组件状态隔离。实际多窗口、键盘／小窗口和忙碌时取消行为待 MVP。这个入口目前只管理扫描，波形、在线批量等统一任务中心仍待扩展。

升级前 pre-v29 一致备份，任务表／索引／触发器和 user_version 事务提交；v28 设置模型步骤增加条件保护。schema 范围／四处最新断言／逆迁移夹具同步至 v29，音频 IPC 1.8 不变。

本轮类型检查、主进程、Renderer（62 模块）、音频宿主及凭据组件编译通过；发行／分发清单一致性和维护脚本语法静态核对通过。未执行单元、实际扫描／取消／重启／事务／SQL 迁移、目录授权、界面／音频负载或安装验证。没有新安装包，最新已验证安装包仍为 0.29.0。
