# ADR-155：恢复前结构及部分领域兼容性检查

日期：2026-10-09。状态：0.149.0 源码及构建阶段，运行验收留到 MVP。

恢复暂存之前只核对数据库版本、完整性、外键、页面、来源和十一项计数。同一版本号不能证明表、索引、触发器、视图或 JSON 设置与当前代码兼容，因此增加独立的结构和部分领域检查。此阶段仍不替换活动曲库，FR13／WP11／AC17 未验收。

## 结构参考与检查顺序

固定受监督恢复进程只对本构建的空内存数据库调用 `LibraryDatabase.restoreSchemaReference()`，通过既有迁移生成参考，并运行可信 `ANALYZE` 取得可选 SQLite 统计表定义。候选备份永远使用独立只读 `DatabaseSync`，不传入 `LibraryDatabase`、不执行候选 SQL、仓库恢复或迁移。

比较 `main.sqlite_schema` 中全部表、索引、触发器、视图的类型、名称、所属表及完整 SQL，包括 SQLite 自动索引。参考和候选以相同二进制顺序生成固定字段数组，精确比较，不通过忽略空白或 SQL 重写放宽定义。最多 4096 对象、16MiB 结构文字。`sqlite_stat1`／`sqlite_stat4` 可缺失；存在时必须与可信参考中的同名定义一致。派生临时表和临时触发器不属于持久结构。

首先比较完整结构，再执行既有完整性、外键、独立页面、来源及清单计数检查，最后读取部分领域资料。所有检查仍在同一只读事务内，前后复核原文件句柄和具名文件观察。stage 模式在完成备份全量校验和独占提取后执行相同检查；check 模式对原已登记暂存重新执行。随后全暂存文件清单与 SHA256 必须匹配原 manifest，才发送完成报告。

## 当前检查范围

报告明确列出八个范围及检查行数，不表示整库所有领域契约已通过：

| 范围 | 当前检查 |
| --- | --- |
| settings | 已知设置键、现有共享显示／桌面设置读取器、完整队列状态、监听记录及原目录关系、凭据范围 UUID、网络设置；未知设置拒绝 |
| outputs | 当前 WASAPI／ASIO／活动后端／DSD 四类设置的固定单例身份和共享读取器；不初始化驱动，不认证设备支持 |
| providers | 注册 Provider 覆盖、组件契约版本、启用能力、修订、保留策略；不证明所有来源内容的授权仍有效 |
| playlists | 静态／智能类型、身份与修订、智能条件及历史条件、固定条目只属于静态歌单、位置从零连续 |
| filter-presets | 最多 1024 个预设的完整共享详情读取器，包括时间、修订和筛选定义 |
| counting-policy | 最多 65536 个连续不可变规则修订、当前指针、原操作 UUID／请求指纹及保存结果与规则一致 |
| lyrics-preferences | 范围摘要、修订及复用歌词设置读取器；缺失来源的原选择保留，不强行清除 |
| genre-tree | 现有最多 64 层／循环检查、归档风格不能仍有成员或子项 |

固定标识符查询先核对相关文字／JSON 字段的字节长度，避免把超预算值物化到 JavaScript。领域遍历最多 500 万行、累计字符串读取 512MiB，单字段最高 1MiB，具体类型另有更小限制；风格树行数也计入全局行预算。沿用独立进程 256MiB JavaScript heap、Main 的 45 分钟监督、取消后的实际退出等待。SQLite 原生内存、临时 I/O 和操作系统权限仍不是硬隔离。

备份来源版本不能高于当前构建，使用整数版本分段比较。manifest 必须包含来源版本对应的 `aural.core` 以及当前三个 Provider 的确切契约版本，未知或缺失组件拒绝，不自动降级或加载插件。

## 报告、持久记录和旧记录

完成消息新增必需的严格兼容性报告：报告版本、检查应用版本、schema68、结构摘要／对象数、原数据库 SHA256、原组件清单、八个范围和行数。Main 核对消息字段、操作及当前构建版本、数据库摘要及组件与原 manifest 的绑定；完成 ACK 不代替进程退出。

实际 exit0 后，Main 重新读取原来源、prepared 和核对链，追加 version2 核对回执。该回执包含完整报告，仍绑定原 prepared 文件字节摘要、原 stage 身份、前条摘要、序号和 pending 数量，采用独占创建及 sync，不改写原准备文件。新 stage 写完原 version1 prepared 后再追加第一条 version2 回执；追加失败保留 prepared，但不发布本次 ready。

原 version1 核对回执继续按原固定字段和摘要读取，不增加不存在的报告。新旧回执可在同一连续链中出现，仍最多 16 条，单条读取预算扩大到 32KiB。历史报告可来自较早应用版本；独立 worker 本次消息必须来自当前构建。历史列表明确提示旧内容核对须补做当前兼容性检查；新报告也只代表当时检查，应用恢复前仍须在活动维护边界重新核对。

## 后续工作与 MVP 验收

仍须完成全部领域／历史／文件权限和来源权利检查、迁移历史契约及校验和、待保存原请求核对／隔离、凭据与外部路径重新授权、暂存物理配额及清理。结构摘要是当前参考结构的摘要，不是已实现的迁移历史校验和。精确 SQL 比较是否覆盖实际升级路径，需要真实旧库与当前空库对照；目前没有该运行证据。

整库应用还需要 Renderer／Main／Library 维护、当前一致快照、实际关闭原库、受控替换与启动确认、失败回滚和重启核对。目录身份观察及检查回执不能证明进程退出后所有文件一直未改变。

MVP 集中验证包含：空库和实际升级库参考一致性、FTS／影子表和 SQLite 统计表、相同版本伪造结构／未知触发器、缺失组件／高版本、合法空联系信息、已知设置和未知键、队列及监听 JSON、智能规则和静态位置、历史口径请求指纹、歌词缺失来源保留、风格循环、大小及行预算、取消／超时／异常退出、旧 v1 到新 v2 追加及重启读取、旧 prepared 不变、当前暂存全量摘要、失败只保留资料及 UI 提示。

本轮不运行应用、SQL、内存数据库、迁移、worker、提取、媒体、驱动或测试。仅记录类型／构建、原生编译与发行静态检查证据；无新安装包。仅 ASIO 实机验证继续搁置，完整架构目标保留。
