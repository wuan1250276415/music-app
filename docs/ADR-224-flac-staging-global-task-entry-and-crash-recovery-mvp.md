# ADR-224：FLAC暂存、独立任务入口与真实崩溃恢复 MVP

状态：0.217.0源码集中MVP通过，正式替换认证及完整V1未完成。2026-10-16。

对应WP09／FR12、AC12和任务可靠性。证据只覆盖备份／暂存与一次指定断点恢复，不代表全部格式或写回故障矩阵。

**0.217.0 FLAC备份暂存与独立恢复任务 MVP**：任务中心新增“标签与恢复任务”，无需选择或播放歌曲即可查看全库已保存任务，并核对／处理恢复占用。原单曲编辑仍用于创建差异；两种入口共用原任务／命令回执和服务端核验，没有增加任意路径或执行代码入口。

任务可展开查看创建时的原标签和计划值，包括重复多值；关闭或重启后仍可查看。标签字段／确认框改为16×16并与文字同排，已取消的暂存任务明确显示“已取消”，不再以保留的staged记录冒充活动状态。

集中实际桌面9项通过：正常监督导入独立FLAC／CUE；11字段只读预览及明确手工确认；UI保存任务／持久差异；真实原生备份与临时文件；单曲循环播放的实际停止及读取协调；备份逐字一致，临时文件保留音频载荷、STREAMINFO、封面、未知块和未选注释；重启／取消原回执；真实进程树在备份日志fsync后、数据库ACK前强制退出；重启独立核对fs-ahead及从任务中心确认取消／重新扫描并恢复可用。原文件始终未替换。原识别异常／定点重试桌面8项回归通过。

本轮首次复现了恢复任务依赖当前歌曲导致入口不可用，新增独立入口后重新跑通真实界面。只用自有生成金样和受控日志屏障，不修改用户音乐／曲库；没有把文件阶段或进程完成结果替身为成功。正式FLAC替换／备份回滚认证、完整故障矩阵、MP3、批次与保留清理仍继续，认证目录保持空，FR12／AC12未完成。

类型、构建与发行／分发清单通过，schema79／媒体16／音频IPC1.23保持；原生字节与0.216检查点相同。本轮未重新打包或新增硬件认证，试用包仍0.215.0；不重复旧版全元数据81项／105项跨页等回归，其历史范围保留。完整FR01–14／WP01–11／G1–5／AC01–19继续，仅ASIO实机验证暂停。详见[ADR-224](ADR-224-flac-staging-global-task-entry-and-crash-recovery-mvp.md)。

使用正常目录操作导入三项实际逻辑曲目：一首独立FLAC和同镜像的两条CUE。金样含两个图片块、有序多值注释及保留的未知类型42块。没有向数据库植入任务、阶段或成功回执；只读查询执行描述以独立检查实际命名工件。

真实Media Worker预览全部11类字段，包含重复Unicode、空格和清空。正式UI只明确选择标题／多歌手创建待办，再通过Main的stageLibraryFile停止仍在单曲循环的FLAC并释放实际音频读取。真实tag-write-worker监督适配器写备份和临时文件、fsync日志、提交SQLite阶段及ACK，最终真实进程退出。外部独立FLAC遍历比较原文件／备份完整字节、临时音频和STREAMINFO、所有非注释块及未选注释，不能用计划值代替文件结果。

崩溃注入仅包裹隔离Service的TagWriteJournal.advance：真实第二条阶段日志写入并fsync返回后，设置受控等待屏障，尚未交回数据库记录与原生ACK。随后精确识别并终止本测试Main及其实际子进程树。原文件和真实备份保持，临时文件尚不存在；重启无自动重试，保留恢复占用。独立原生核对认出fs-ahead，界面明确确认原文件一致、取消任务并重扫，等待可用状态和摘要再次一致。该屏障是故障注入，不是写入／核对结果替身。

首轮装配错误把标准APPLICATION类型2当作unknown，改为保留类型42；第二轮使用了不存在的stopped播放状态，按公开契约改为idle，并在暂存前确认单曲循环仍为playing。随后实际UI测试发现：当前歌曲不可用时，元数据面板的文件标签入口禁用，恢复只能通过内部API触达。ScanTasksDialog新增独立全库任务分支，TagWriteDialog支持不读取歌曲上下文的任务模式，隐藏创建字段及预览按钮，原任务和服务端保护保持。最终由真实任务中心按钮完成核对、确认、重扫，而非通过API替代用户恢复动作。失败记录保留。

所有已有任务显示保存的差异快照，不将其描述为文件当前值；实际执行仍需读取核对。初次截图复核发现checkbox受通用表单列布局影响，增加作用域样式；另已取消任务不再被旧staged状态覆盖。最终9项与原任务中心识别8项回归、Main／Renderer类型、构建和发行清单通过。原生未改动，逐项核对0.216检查点；本轮是新的原生路径运行证据，不是新编译或硬件认证。

回归入口：npm run test:tag-staging-mvp；已有完整构建可直接运行node tests/electron-tag-staging-mvp.smoke.cjs。自动化需Playwright和Windows原生构建；目录固定在D:/CodexTestData下的独立前缀，成功后确认范围再删除，失败证据留存。历次失败／前置成功及最终报告分别保留，不覆盖历史结果。

尚未覆盖真实断电、磁盘满、所有锁竞争、ACL／SACL及ADS矩阵、真正替换原文件、原始备份放回、MP3、批次和工件保留清理；两个认证目录仍为空，executionReady保持false，没有开放认证执行IPC或绕过许可／来源审核。下一批优先推进独立候选构建上的真实FLAC提交／恢复故障矩阵，证据完成后再接通受限认证和正式确认入口；生产认证不能通过环境或普通IPC临时放行。后续继续认证和完整恢复，不能据9项测试宣称FR12／AC12完成。公开插件、真实规模、长期运行、真实匹配和签名安装等全架构剩余工作亦继续；ASIO实机单独搁置。
