# ADR-160：恢复后的可写暂停准备与导入策略

日期：2026-10-10；源码批次：0.154.0；状态：私有可写准备及持久意图/回执已接入源码。普通请求和后台资源仍冻结，整库恢复尚未完成，没有开放应用恢复入口。

## 决策

在 ADR-159 的候选或回滚原库只读启动后，增加独立的 `prepareWritable` 步骤。Main 先持久保存 `activation-intent`，才向原只读实例发送私有 `catalogRestoreActivate`。请求绑定事务、独立激活 UUID、挑战、实例 UUID、冻结 token、目录身份、完整原 boot-ready 摘要和 candidate/original 角色。候选使用 Main 新生成的凭据范围 UUID；放回原库的角色禁止指定新凭据范围。

准备动作始终属于同一个 utilityProcess。Library 再次检查原清单和目录，关闭只读连接，打开现有 schema68、DELETE 日志模式的可写暂停连接。该连接不迁移、不恢复旧标签任务、不启动派生索引、不修复分析任务。维护对象排斥并发捕获、释放和关闭，普通业务请求一直被维护门禁拦截。

候选策略提交后先关闭连接，对完整文件重新取摘要并执行现有结构及八项部分领域兼容性检查，再重新构建全部仓储、凭据对象和后台管理器，并按原 token 冻结它们。新回执包含实际 PID/构建、原请求和来源清单摘要、结果清单、策略、兼容性报告、`writable:true`、`backgroundStarted:false`。Main 核对当前进程并再次核对固定 live 槽位的全部文件，最后写入 `activation-ready`。

可写准备不能作为恢复完成证明。Main 和 Renderer 的原待保存资料、播放状态、设置对象和恢复终态尚未协调，所以本批不切换为普通就绪，也不释放任何一方维护占用。私有流程没有通过公开 IPC 或界面调用。

## 候选导入策略

策略存于已知 `app_setting` 的 `catalog_restore_activation`，使用严格版本化记录，不新增表或迁移。限制为 4096 个目录、1MiB 规范策略和安全整数检查点；源清单和原策略摘要可追溯至保留的原快照。兼容性检查识别该键，并核对来源身份和当前凭据范围。

在单一数据库事务中：

1. 生成新的凭据范围，禁止继承旧库对 Windows 凭据保管库的访问身份。该步骤不读取、复制或删除系统凭据。
2. 关闭所有已注册 Provider，并保留原审计、追加设置变化；旧凭据命令按导入时的 rowid 水位隔离，不能在新范围下重放旧 UUID。
3. 关闭目录监听，清空旧监听 anchor 和 launch，增加设置修订。原扫描清单、命令回执和进度保留，旧未完成任务转为 interrupted/cancelled 并移除进程租约。导入时的 scan seq 水位禁止它们被调度或续跑。
4. 记录标签任务、凭据命令及元数据观察的水位。旧标签任务、文件租约、原生工件和历史均保留；执行与释放入口拒绝重放旧任务。
5. 写入策略和新的凭据范围。任何检查或写入失败均回滚数据库事务；Main 全局意图继续保留，等待核对。

来自备份的目录必须通过已有的重新选择/确认流程建立新 anchor。直接启用或重试不能建立授权；扫描发起与实际运行、播放来源、歌词/封面原文件读取、波形分析和标签来源共用这一检查。新导入且未在原策略中登记的目录沿用正常的显式添加流程。关闭监听不自动撤销已明确确认的媒体读取授权。

恢复前的来源授权不能单凭备份继续文件写回。旧元数据观察在标签资料中不再标为可直接使用的曲库字段；手工声明仍经过现有确认和来源检查。观察记录按 fingerprint 去重，同值重新匹配可能继续引用旧观察，因此完整的旧来源重新审核/授权回执仍必须另行实现，不能把开启 Provider 当成审核已完成。

本批暂停导入库的自动外部恢复扫描/释放循环。当前新建任务的显式完成路径仍保留；导入的历史恢复任务需要独立审核流程。这个隔离不是删除记录，也不是宣告永久不支持恢复旧任务。

## 放回原库

original 角色不提交导入策略，不改变凭据范围、目录授权或原记录。准备回执要求原全部文件及十一项计数保持一致；策略字段为 null，表示本次不创建新策略，原数据库中可能已有历史导入策略并继续保留。仍需完成 Main/Renderer 状态协调后才能恢复普通使用。

## 失败与重启边界

新全局记录按历史构建可重读，但新增操作必须匹配实际当前实例和构建。重复请求只能复用同一内容；请求变更、角色错配、旧 token、目录/文件变化、预算超限或进程退出不能伪造成功。

激活意图一旦登记，就禁止按旧只读清单继续目录移动、原关闭协议或自动回滚，因为候选数据库可能已经产生策略写入。超时和取消保留目录、原快照及全局记录；启动前门禁继续阻止把未决事务当成普通库打开。后续要实现按新清单/策略核对的激活中断恢复、明确回滚和缺失回执对账，不能靠超时猜测数据库没改过。

全局记录继续使用 32 条、单记录 3MiB 的既有上限；激活证明为持久记录外壳预留 4096 字节。已经启动候选、明确回滚并启动原库、再准备原库可写的已实现最长路径使用 23 条记录。

仅执行类型检查、前后端构建、生产原生与既有金样编译，以及发行生成文件、脚本语法和分发清单的静态核对。未运行应用、SQL/内存库/迁移、私有恢复、worker、目录移动、媒体、凭据保管、硬件或测试。原生金样编译不表示金样运行通过。
