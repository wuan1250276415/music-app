# ADR-041：风格身份、分类层级与组合筛选

状态：0.36.0 源码实现；2026-10-01。对应架构 §7.2、§8 和 WP03/WP05 中的风格分类树、用户分类保持、交集／并集。schema v17，音频协议 v1.6 不变；不代表完整工作包或 MVP 验收。

## 分类身份与升级

- 在既有 `genre` 上增加单调 `revision`、`customized`、`archived`，保留原 ID、关联与 `parent_id`。升级前对已有数据库执行一致备份；事务检查旧树循环及超过 64 层后，再安装新表与约束。错误回滚 v17 这一步，不自动修改原有异常层级。
- `genre_name_alias` 按 NFKC／小写／去前后空格全库唯一，升级时记录现有名称；分类创建或改名时追加名称映射。旧名称不转移给其他身份，不因撤销删除，因此以后扫描到旧标签仍指向同一分类。当前没有身份合并、别名释放和多语言命名操作。
- 扫描与用户集合编辑复用身份解析，保持用户整理后的名称与父级；观察记录仍保存当次文件的实际标签名称，既有不可变来源记录不会因分类改名被改写。展示和检索使用当前分类名称，来源历史可保留旧名称。
- 归档保留身份和全部旧名称，要求没有任何曲目关联、发行风格关联或子分类（包括不可见曲目、空发行版和已归档子分类）。重新分配文件标签或人工风格集合时可恢复同一身份，保持名称／父级并增加修订。撤销创建也采用归档，避免删除历史身份。
- 父级 FK 与 SQL 触发器阻止自指、循环、归档父级、跨身份抢占旧名称、带成员归档及分类身份删除。应用另检查移动后的完整树深度不超过 64 层；旧名称映射不可更新／删除。

## 编辑、审计与撤销

- 提供创建、改名、设为根分类、选择父级、归档与恢复。分类更改只作用于曲库，不写回媒体文件，也不联网。
- 请求提交分类修订与依赖指纹。指纹涵盖名称／父级／归档状态、旧名称、祖先修订、后代修订和结构、直接及后代的曲目关联／曲目修订，以及尚未关联文件的发行风格。选择父级同样提交其修订和指纹；扫描或并发编辑改变依赖时要求重新预览。
- 单一写入事务保存分类、刷新受影响曲目关联修订和搜索索引、写入 `genre_change` 与命令回执。命令 ID 和参数摘要用于持久去重；回执存在时返回原结果，不再套用旧修订。
- 分类树编辑目前最多涉及 5000 首关联曲目，超过时明确拒绝，等待批量任务支持；依赖摘要通过有序游标迭代，不把全库成员传到 Renderer。尚未完成大库延迟预算或后台分批索引更新。
- 修订记录接入现有曲库历史和撤销路由。撤销检查当时修改后的指纹，恢复字段值并增加当前修订；保留历史名称映射。创建后若出现成员、子类或其他依赖变化，则不能直接撤销。撤销本身也保存补偿记录，不反复撤销补偿记录。

## 浏览与筛选

- 新风格列表每页 50 个，用归一名称和 ID 的键集游标，游标绑定查询词、父级范围、归档条件。查询旧名称也能找到当前身份。界面逐层浏览、路径导航与搜索，无须向 Renderer 传完整分类树。
- 节点显示直接分类的曲目数和活动子类数，资料页另显示包含全部后代后的去重曲目数。离线但仍可见的条目保留在分类计数中。
- 风格视图支持最多 16 个选择，明确使用任一（并集）或全部（交集），并可选包含子风格；匹配同时考虑曲目风格与继承的发行风格，同一文件不会因重复成员被重复列出。
- 播放详情的风格链接继续使用稳定 ID，默认包含子风格。兼容按名称传入的请求通过旧名称映射解析，避免改名后旧检索入口失效。
- 分类管理提供父级候选分页、路径、旧名称和影响计数；已整理分类仍可查看来源历史。筛选页面与管理入口共用新列表，不受旧 facets 的 200 个分类上限影响。
