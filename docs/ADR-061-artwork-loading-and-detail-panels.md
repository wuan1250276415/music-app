# ADR-061：封面加载与播放详情面板

状态：0.56.0 源码实现；2026-10-01。schema v29、音频 IPC 1.8 不变。按用户反馈先处理封面和播放详情；ASIO 实机验证保持搁置，完整 FR01–FR14／WP01–WP11 范围不变。

## 内嵌封面优先

仍按内嵌正面、其他内嵌图片、歌曲同名图片、目录 cover/folder/front 的顺序读取。通过固定版本 music-metadata 的 observer 保存已进入 common.picture 的图片；如果后续标签或音频头解析报错，已成功解码的图片仍进入字节签名／大小和 Chromium 解码检查，再决定是否回退。成功返回时使用解析器最终 common.picture，沿用解析器对不同标签优先级的处理，不从任意原始标签强行提取图片。

属性指纹以音乐文件属性为必需项，目录属性不可读时以 unavailable 参与指纹，避免目录检查失败阻断可读文件中的图片。同名本地图片匹配修复两侧小写比较，适用于大写歌曲名或扩展名。CUE 仍使用引用的音乐文件。

Renderer 增加共用加载调度：总计最多两个请求、背景列表最多占一个槽；播放栏和详情使用前台优先级，共用同一文件与修订键的请求。已排队列表项被播放栏复用时会提升优先级。组件卸载撤销尚未开始的请求；已开始的请求继续执行，结果通过原有 alive／key 检查防止显示到另一首歌。缓存仍只保存成功候选，32 项／64 MiB 字符串预算／30 秒有效期。没有实现进程中正在解析图片的硬取消、硬内存限制或文件监听；外部文件修改后可主动重新读取。

曲库列表／单曲／队列投影增加可选 fileStamp，由既有媒体文件 size 和 mtime_ms 组成，不改变数据库结构。Renderer 使用此扫描观察、文件路径／可用性、扫描终态刷新与主动重读版本作为键；中途其他文件入库的 libraryChanged 不再把未变化的歌曲封面请求作废。fileStamp 不是实时属性或内容摘要，目录图片变更仍需扫描终态刷新或主动重读。

这些修改处理代码中的潜在丢图和等待路径；没有取得用户具体问题歌曲，因此不称为已复现或已证明修复所有实际缺图原因。单张 16 MiB、Chromium 最大边长 8192／总像素 32 Mi、最多八候选等原有限制保持；不支持的图片或损坏标签仍可能无图。

## 详情交互

点击播放栏封面打开详情，左侧保留封面、歌名、歌手／专辑／专辑概念／多角色署名／风格和音质等信息。已有身份检索链接沿用实体 ID、角色与风格过滤，关闭详情后进入相应曲库结果。

右侧在歌词和播放列表之间切换；面板保持挂载但隐藏非当前面板，保留歌词手动浏览状态。跟随开启时切回歌词重新定位当前行；切回列表重新确保当前歌曲可见。纯文本仍无虚构同步，逐行歌词可以点击跳转，并保留来源、偏移、双语与字号设置。详情改为两列，并对最小窗口高度压缩页头和封面尺寸。隐藏面板不接受键盘焦点；背景曲库 inert，底部播放控制继续可用。

模式区在两个面板上方保持可用，直接选择顺序／列表循环／单曲循环，随机开关独立。调用既有队列持久化命令和修订校验，编辑／详情跳转期间禁用相应详情操作并用同步 latch 防止双击提交。同一时刻从其他入口发出的命令仍由服务端 revision 冲突机制保护；这里没有替代全局命令对账。列表继续支持跳转、移动和非当前项移出，显示歌曲、歌手、专辑与当前标记。

## 验证边界

本批完成类型检查、Main／Renderer／原生音频和凭据组件编译，以及发行／分发清单静态核对。已有详情 smoke 脚本适配面板切换和模式选择，只做语法检查，不执行。未运行单元、UI、解析器、调度、数据库迁移、实际文件、音频或安装包验证；最新已验证安装包仍为 0.29.0，源码功能不会自动更新用户已经安装的程序。

MVP 需验证：正常 FLAC/WAV/DSF/DFF/MP3/M4A 内嵌封面，已读封面后发生损坏标签、错误 MIME／损坏图片回退；CUE 复用、同名大写文件、目录不可读、多个内嵌封面、没有图片；大量列表请求中立即切歌、前台提升、快速卸载／重挂载、刷新与失败重试；两处面板恢复定位、身份检索、直接模式切换、重复队列项、双击／修订冲突、920×620 窗口、键盘及减少动画。
