# ADR-183：持久 CUE 原文选择与扫描应用

- 日期：2026-10-11
- 状态：0.177.0 源码接入；运行及故障验收留至 MVP
- 对应：FR02、FR04、FR07、FR13、WP03、WP04、WP06、WP10、WP11；承接 ADR-182

## 行为

历史界面在复审当前解释及全部曲库引用后，可以明确选择保存的原文，也可以在预览最近观察版本时选择跟随磁盘。选择历史原文后，后续扫描持续使用它；磁盘 CUE 仍照常读取并保留最新观察。两种来源分别记录，选择操作不覆盖磁盘 CUE 或音乐文件。

提交只表示选择已保存。后台新扫描核对引用和范围后才提交编排；界面显示待扫描状态，并把“当前编排记录匹配”与提交回执区分。原请求 UUID 在提交结果未知时保留，重试不生成另一个命令；成功或明确拒绝的持久回执始终返回原结果，当前状态另行刷新。

本阶段仍需要当前来源路径上的磁盘 CUE 存在。缺失 CUE 的独立历史应用、备份导入后的重新绑定、已忽略或移出引用的保留策略属于后续完整实现，不能据此宣称历史恢复完成。

## 数据与提交

schema70 新增 `cue_source_file.selected_version` 和 `choice_command`，以及不可更新或删除的 `cue_source_selection_command`。原 `latest_version` 保持磁盘观察语义。所选版本外键及同来源触发器、原成功回执与来源／编码／间隙／选择一致性触发器约束选择；旧解释命令及扫描 UUID 不可冒用为新选择命令。命令使用既有总量预算，保存原规范请求和原结果，不更新旧回执。

Main 限定可信主文档，串行占用 CUE 文件入口，核对原文档 epoch。先查询原回执，避免重复停止播放。首次提交经播放协调器处理受影响当前曲目、预备曲目和书签：停止并等待实际音频释放及 DSD 分析停止，确认输出已释放后才调用 Library。未确认退出时不提交选择。

Library 在接受选择的事务中再次核对来源修订和磁盘 latest，以当前原文、解释、完整引用记录、目录状态和授权记录重新计算 ADR-182 的摘要。任何诊断、不可用引用、未知长度或越界范围均拒绝新选择。成功回执先插入，再以来源修订／latest 比较更新选择和待扫描命令，实际来源摘要必须与预测回执一致；事务失败回滚这些记录。明确的复审拒绝保留拒绝回执。

原最新来源解释接口继续可用，但明确改为跟随磁盘并清除历史选择。旧接口回执只在读取结果时补充默认空选择字段，不重写旧保存字节。

## 新扫描与编排

待扫描选择以原选择 UUID 启动独立新扫描。只有对应扫描回执的根目录和任务 ID 都匹配，才可消费待扫描选择。已在运行的旧扫描保存新观察，但保护旧编排并留下待扫描选择；调度器待该目录没有活动任务时再启动新任务。

扫描仍使用现有根目录授权、可信路径、稳定属性观察、监督媒体读取及媒体检查点。读取磁盘 CUE 后，历史选择独立核对原资产、保存解析 JSON 及 v42/v43 摘要，再按当前 parser4 和所选编码／间隙重新解释。派生解释保存为不可变版本，不把磁盘 latest 指向历史字节；版本数加入历史分页标记，使新增派生版本令旧游标失效。

新选择及持续历史选择要求引用有本任务的媒体核对、有效属性观察、已知可用长度、可读状态和 active 文件管理状态；不借旧忽略记录跳过引用核对。75帧起点、INDEX01、子索引和声明终点沿用范围检查。引用属性必须仍匹配媒体核对结果，提交前再检查可信路径及属性；磁盘 CUE 属性也须保持。提交事务同步核对文件身份记录、观察及管理修订、写回占用和原文选择修订。任何诊断均保留原编排，不部分应用。

现有 `applyCue` 保留曲目身份对账、用户资料与人工字段规则；编排附加原来源、所选历史版本、当前解释版本和选择命令的 `cueSelection`。编排及检查点成功提交后才清除待扫描，并增加来源修订；失败、取消、退出不确定时保留待处理状态。这里是此 CUE 的成功提交，不代表整个目录任务或其他文件均成功。失败任务通过任务恢复或明确的新提交继续，原回执查询本身不启动另一次扫描。

## 文件核对的边界

媒体阶段可能使用与当前稳定属性一致的既有解析资料；属性匹配不是独立逐字节重新解码，也不是原历史音乐内容的 SHA 证明。提交前属性观察不构成 OS 文件锁或整个事务期间的文件不变保证。原历史资产能证明保存的 CUE 字节，但尚无当时音乐本体身份记录供当前音频匹配。完整文件身份、权利复审、缺失来源、导入绑定、根目录别名及故障认证继续属于完整目标。

## 升级与旧资料

从旧活动曲库升级前保存 pre-v70 快照，事务添加结构并检查外键后更新版本。保留原 v69 内嵌历史迁移。普通活动库与恢复暂停／WAL释放仅接受当前70；新备份及播放历史导出记录实际70。旧68和69的备份、预览、兼容性报告及导出头仍按其实际版本读取，不改标签。旧整库备份应用仍要求独立候选升级，本阶段不静默升级恢复候选。

## 验证与余项

按用户要求本阶段只做类型、主程序／界面构建、生产原生及既有金样编译、发行脚本语法与生成清单核对、源码归档 CRC。最终类型及构建、生产原生与既有金样编译、4个发行 CommonJS 语法、发行生成文件及分发清单核对均 exit0。没有执行 SQL／迁移、应用、解析器、worker、金样、实际音乐、驱动或运行测试。

MVP 必须覆盖原回执和拒绝回执真值、触发器与迁移／旧备份、历史与磁盘版本分离、旧任务不能消费选择、两轮扫描与重启／恢复、实际文件变化／路径别名／权限／写回占用、身份及人工字段保留、停止与未确认退出交错、分页和 UI。复杂 CUE、静音间隙、去加重、跨文件无缝、备份导入、完整恢复继续／回滚、其他 Provider、歌词、任务中心、多窗口、插件、跨平台及完整 FR01–FR14／WP01–WP11／G1–G5／AC01–AC19仍继续。仅 ASIO 实机验证暂停；真实缺图问题未确认修复；无新安装包。
