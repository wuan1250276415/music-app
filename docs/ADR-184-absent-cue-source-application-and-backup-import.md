# ADR-184：缺失 CUE 的历史应用与来源备份导入

- 日期：2026-10-11
- 状态：0.178.0 源码接入；运行及故障验收留至 MVP
- 对应：FR02、FR04、FR13、WP03、WP04、WP10、WP11；承接 ADR-179、ADR-182、ADR-183

## 目标行为

明确选择过历史原文的 CUE 即使不在磁盘目录清单中，也参加当前根目录的扫描。只有当前音乐引用、范围和管理状态核对通过，才应用其历史原文；不把普通缺失文件自动恢复为旧编排。

来源备份原生打开并核对后，用户明确选择当前曲库已有的目标 CUE 来源，把备份添加到其历史。导入保持磁盘 latest、原文选择、编码／间隙设置、播放编排和目录授权。之后仍须复审导入版本、明确选择原文，再由 ADR-183 的新扫描应用。

本阶段补齐已有来源缺失时的历史应用及已有目标的导入；尚未实现新建来源、另一个目录的新锚点、导入原备份列表／原格式重新导出、内嵌来源备份的持久导入。它们继续属于完整目标。

## 把历史来源纳入扫描

每次枚举阶段结束后，以根目录和 UUID 键集分页读取明确历史选择或待扫描命令的来源，每批128项，间隔让出执行。使用当前任务／pass 清单，已有物理 CUE 条目优先，保留磁盘枚举得到的路径拼写及观察；同路径其他类型冲突即停止，不掩盖路径别名。新条目仍受30万清单容量与原租约／取消条件限制，两轮及重启重新枚举均沿用此流程。

普通磁盘读取仍先尝试可信路径及受监督句柄读取。只在打开路径的 ENOENT 且本条目没有本轮物理观察时，尝试历史原文。已观察文件在扫描中途消失是变化，不直接降级为正常缺失；EACCES、ENOTDIR、链接、类型或根目录问题也不是正常缺失。

缺失核对重新验证现有根目录及授权，再检查当前来源的现存父路径：每一级须是目录且不能为链接，实际位置保持在已绑定根范围。来源锚点可包含缺失父目录，但其音乐引用仍必须在本轮实际枚举／媒体核对范围内。来源记录必须属于当前根与路径键并有明确历史选择；仅有 latest 历史不够。待扫描的跟随磁盘选择也纳入清单，使缺失得到明确任务异常，不能用一个没有 CUE 条目的成功任务冒充应用。

缺失不调用 `observe`，不写造新的磁盘原文、latest、属性或观察时间。历史字节仍独立核对并重新解释，待扫描选择仍要求原选择 UUID 对应本次任务。引用音乐沿用当前媒体检查点、有效且正有限时长、原75帧范围、属性、active 管理状态与写回占用检查。提交前再次核对根／父路径与来源仍缺失；若重新出现，则等待新一轮读取。任意错误保护旧编排。

成功编排记录 `cueSelection.sourcePresence` 为 present 或 absent；这是提交时观察，不是之后持续物理事实。历史应用沿用来源修订比较、曲目身份／人工资料保持、编排与检查点事务和待扫描清除，正常扫描代次对账保留已成功的虚拟编排。

## 原生选择与私有导入

Main 只保留一份经过原生文件选择、同句柄 EOF／属性及规范 JSON 读取的外部来源备份，范围为原主文档 epoch。Renderer 获得有界预览，只提交原操作 UUID、现有目标来源 UUID、基础修订、磁盘 latest 和原备份完整 SHA；不提交备份正文、任意文件名或来自备份的路径权限。

Main 原可信 frame／epoch 与共享 CUE 占用贯穿选择、预览和导入。先查原导入回执，已知操作可返回原结果，不要求重新读取文件；新操作必须匹配私有备份摘要及原文档。读到的备份是一份捕获内容；导入不声称原文件此刻仍相同。刷新或重启后的新操作须重新选择，待确认 UUID 目前由存活界面保留，跨重启未知提交的完整用户恢复仍待补齐。

Library 独立核对19字段原备份、完整规范 UTF-8 字节及 SHA、原字节大小／SHA、旧解析 JSON SHA 和 v42/v43 原版本推导，再用当前 parser4、备份请求编码和间隙解释原文。原位置和身份保留为备份资料，不覆盖目标身份。无效当前解释也可以保存供历史查阅，但后续复审不允许把它应用。

## schema71 与事务

新增不可更新／删除的 `cue_source_import_asset` 保存原完整规范备份字节，单份8MiB，独立512MiB／4096资产预算；`cue_source_import_command` 保存原请求、成功或明确目标拒绝回执、原资产、目标来源和当前派生版本，独立65536命令预算。触发器核对原请求 UUID／目标／摘要及版本所属来源。原备份保留外来 fileId、rootId、位置、保存时间、原编码字节及旧解析 JSON，不把原版本摘要改为当前目标摘要。

目标当前解释按既有 v43 规则登记在目标的不可变来源历史，原字节资产和解析版本仍受既有原文／解析预算及每来源128版本限制。相同内容可复用版本，原导入命令及原备份始终各按原身份保留。

事务内再次比较目标来源修订与 latest，确认目标根仍存在且路径与当前来源一致；允许离线保存历史，但不授予音乐读取权。原备份保存、派生版本登记、目标修订／历史代次更新和成功回执一同提交，错误回滚。重复原 UUID 返回原结果；旧解释、选择和扫描 UUID 不可冒用。导入不启动扫描、不停止播放、不选择版本或调整目录策略。新版本列表显示“导入来源”，界面导入后打开对应版本供复审。

升级前保留 pre-v71 活动库快照，再事务添加结构及核对外键。当前活动库／恢复准备／WAL释放／新捕获要求71。旧68／69／70备份、兼容性报告、预览及导出头继续按原实际版本读取；旧整库应用需独立候选升级，不能只改版本标签或隐式迁移恢复候选。

## 验证与未完成范围

MVP 需覆盖真实缺失／中途消失／重现、链接与权限／目录变化、两轮及恢复扫描、媒体范围和用户资料保留、导入规范字节真值与原格式、跨来源派生摘要、容量／盘满／事务失败、回执重试／进程退出、UI目标选择／焦点／旧预览与旧schema资料。属性观察不证明原历史音乐本体 SHA 或 OS 文件锁；完整身份及权利认证继续。新来源及新锚点、导入资产查阅／原备份重导出、批次与内嵌来源导入、复杂 CUE／静音／去加重／跨文件无缝、旧整库候选升级、恢复继续／回滚与完整领域核对、其他 Provider、歌词、任务中心、多窗口、插件、跨平台及全部 FR01–FR14／WP01–WP11／G1–G5／AC01–AC19仍在完整目标内。真实缺图未确认修复，只有 ASIO 实机暂停；无新安装包，最新运行验证仍0.29.0。
