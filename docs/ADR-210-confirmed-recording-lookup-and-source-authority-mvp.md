# ADR-210：已确认录音查询与候选来源约束

状态：0.203.0 源码；集中MVP证据见本版本checkpoint。Windows优先，仅ASIO实机验证暂停；schema75、媒体15、音频IPC1.23保持。

## 匹配行为

实现架构11.2第一步：读取本地录音实体已明确保存的MusicBrainz引用。只有一个标识时直接查询该录音，不要求本地歌名完整；没有标识时沿用标题／歌手搜索。多个标识不默认采用第一项或改做文本搜索，返回待选择状态，在元数据面板由用户选择本次读取的录音。批次初始匹配遇到多个标识仍待人工审核，不自动接受。

Main采用闭合请求读取器，服务再次核对所选MBID确实属于该歌曲当前录音。文件标签、URL、调用者提供的名称和任意未归属MBID不能直接作为查询身份。前端只传选择标识；来源权威摘要由服务从本地引用和单调修订取得。

录音查询使用既有限流、取消、短期缓存和公开应用标识的ProviderBroker，校验返回录音ID完全一致，标题及署名存在，链接发行版不超过25且标识有效、不重复。缺失或被合并而返回不同ID、失败或不完整响应显式报错，不静默切回文本搜索。按实际来源查询后仍显示歌名、歌手、专辑和时长差异，不编造来源搜索分数或正确概率。

录音与具体发行版保持独立。查询返回的有限发行版仅作为候选，更多版本沿用录音关联发行分页；没有发行关联时保持空值，不能把已确认录音当作已确认专辑。返回数据仍需用户逐字段或整专辑审核，查询本身不改曲库或文件。

协议核对于2026-10-14：[MusicBrainz API](https://musicbrainz.org/doc/MusicBrainz_API)规定录音MBID lookup及`inc=artist-credits+releases`，关联列表上限25，更多资料通过browse取得；保留公共调用不超过每秒一次的调度。

## 候选权威与后续审核

每次匹配捕获本地录音ID、引用状态修订和全部外部引用的摘要，保存在Provider私有候选登记中；响应返回前再次核对。数据库读取失败、实体移除或引用状态变化时旧候选失效。即使引用改回原值，单调修订仍阻止旧候选重新生效。

完整艺人署名读取及发行分页所派生的候选继承同一个私有摘要。所有现有来源预览／整专辑授权／保存路径经过候选resolve，因而不能继续使用变更前的录音来源。原有歌曲资料指纹及历史回执元组不改，不把来源摘要开放为调用者授权参数。

## 集中MVP及边界

新增Provider/Broker和闭合读取器14项集中检查通过，覆盖无歌名直读、来源ID校验、发行范围、缺失响应、不做静默回退、前后状态变动、派生发行与署名候选约束以及普通文本搜索兼容。实际桌面组合最终53项通过，增加单一录音直读、非法选择拒绝、修改引用淘汰旧候选、多标识显式界面选择、派生发行失效及离线媒体重启后查询。

具体数量、最终命令退出码、源码摘要和界面截图由`docs/validation/v0.203-checkpoint.json`记录。在线为明确fetch夹具，实际生产Main/preload/Service与Electron界面；不作为真实曲目匹配正确率验收。初次署名扩展夹具缺少release响应的失败保留；最后新增重启查询检查一度误排在关闭后，已放回同一存活实例关闭前。

新增重启查询首次遗漏了fetch夹具，曾向真实服务请求虚构录音MBID并得到404，未发送用户曲目或保存资料；失败保留。最终源码重启沿用同一fetch边界，验证媒体文件离线时的已确认录音查询；实际发布程序不注入夹具，该分支仅检查本地引用和暂停联网拒绝，本轮未运行该发布分支。
