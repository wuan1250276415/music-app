# ADR-093：主题、缩放与 DPI 布局

日期：2026-10-02；源码 0.88.0；schema v38、音频 IPC 1.19、媒体协议 6、系统媒体协议 1 不变。

## 范围与接口依据

推进架构 §19 的深浅主题、缩放、高 DPI、多显示器和键盘可达性。侧栏加入“外观与缩放”，提供跟随系统／浅色／深色、75%–200% 的九档缩放和恢复 100%。设置保存后应用，音乐播放、曲库及图像内容不参与主题切换。

[Electron nativeTheme](https://www.electronjs.org/docs/latest/api/native-theme)提供 system／light／dark、实际暗色状态和系统强制颜色状态；其主题选择同步 Chromium 的 prefers-color-scheme。Main 在创建窗口前加载已确认设置，再设置 nativeTheme，CSS 使用媒体查询切换对应颜色，避免 renderer 单独保存另一份主题或等待 IPC 才决定首次配色。

[Electron webContents](https://www.electronjs.org/docs/latest/api/web-contents)的 setZoomFactor 使用百分比除以 100；Electron 44 提供 manual zoom mode，关闭自动缩放但仍提供滚轮缩放请求。本项目锁定的 44.4.5 类型已包含该 API。Main 设置 manual，管理缩放、Ctrl／Command 加减号和 0，以及 zoom-changed 滚轮请求；pinch 限为 1，避免未保存的第二套视觉缩放。范围为 75、80、90、100、110、125、150、175、200%，超出端点保持端点。

[Electron screen](https://www.electronjs.org/docs/latest/api/screen)区分设备无关坐标和物理像素。本批次直接使用工作区 DIP 创建／找回窗口，不再次乘显示器比例；页面 Canvas 则使用 Chromium 已含页面缩放的 devicePixelRatio。

## 保存与恢复

- 新增独立 `appearance_preference` app_setting，版本 1，包含 revision、theme 和 zoomPercent；缺失时为跟随系统／100%。已有窗口关闭、媒体键与音频输出设置保持各自契约。复用现有表，没有新增 schema／迁移；旧版本不会读写此新 key，不能把它写进旧 DesktopPreference 严格字段中。
- Library Service 是唯一写入者，校验字段数／枚举／缩放档位，通过 expected／next 修订 CAS 保存，重复相同 next 回读幂等。Main 校验 UUID 和请求字段，只接受已确认持久化结果，未确认结果不预先应用到页面。
- Main 同时只处理一个设置写入／回读，保留原请求及至多 64 个已完成命令回执。RPC 写入异常时回读：精确 next 为成功，其他已知修订为拒绝；回读也失败则进入 unknown，保留原意图。核对原提交只回读，不再生成写入。界面重载或重新打开设置可重新读取 Main 保留的提交结果；整应用重启后读取数据库中的实际设置，不恢复旧 UI 命令。
- Renderer 草稿保留开始编辑时的 preference revision。期间缩放快捷键更新了设置，旧草稿会提示重新读取，并以原修订提交使冲突被拒绝，避免悄悄覆盖另一项已保存选择。未知结果保留原 UUID、限制新提交；已处理的拒绝恢复编辑。
- 已保存设置应用失败时单独显示 applyError 和实际缩放，允许重新读取／应用，不将原生应用失败描述为数据库未保存。初始化读取错误保留安全默认外观并限制写入，不使音乐库初始化直接失败。
- 快捷键／滚轮目标合并至一个最新档位，150ms 后提交；新显式设置操作淘汰旧待发缩放意图。写入中的新手势留在一个目标槽，未知结果清除该槽并要求核对。退出时移除主题／屏幕监听和所有合并计时器。

## 配色与绘图

- 把现有组件配色移入 `themes/colors.json` 的 378 个深浅颜色对和图表别名；核心页面、侧栏、播放器、对话框、正文、次要文字和强调色有语义 token。细分旧色使用明确的 tone token；旧深色值保持，浅色基底采用中性纸面和深色文字，状态／渐变使用对应浅色值。
- `generate-release` 生成 theme-tokens.css：默认深色定义、系统实际浅色媒体查询、强制颜色的 Canvas／CanvasText／Highlight 图表映射。`check:release` 核对产物，拒绝组件 CSS 再加入裸十六进制颜色或引用未声明 token。颜色对是可直接编辑的源数据，不在运行时做图片反相或色彩猜测。
- 封面图片不应用 CSS 滤镜，不改变嵌入、sidecar、ICC 或 EXIF 处理；内嵌优先次序保持。备用封面文字和阴影颜色单独保留，避免影响已有深色封面渐变。所有现有 CSS 页面／对话框的颜色都使用成对 token，CSS 不负责改写歌曲或元数据。
- 频谱和整曲波形读取统一图表颜色；系统主题、强制颜色、屏幕比例和页面尺寸变化使它们重绘。显示器 DPR 监听重新绑定当前 resolution 媒体查询，跨屏后不会只监测第一次变化；ResizeObserver 继续处理元素大小变化。
- 两个 Canvas 统一计算 backing store，DPR 只应用一次，最大有效比例 4、宽 4096、高 1024，每个至多 2 Mi 像素，尺寸使用向下取整。更高密度允许受预算限制的降采样，未宣称任意 DPR 都保持物理像素一比一。只更新 UI 绘图，不改变音频分析或实时回调。
- 高对比度遵循系统 forced-colors，增加当前条目／焦点边界，图表使用系统颜色。实际颜色、文字对比度和无障碍验收仍待 MVP，不以 token 完整性或构建通过代替视觉／WCAG 证据。

## 缩放与窗口布局

- 移除 body 固定 920 CSS 像素最小宽度；保留桌面默认布局，并在有效宽度 800 以下变为可打开的侧栏导航。窄导航作为对话框，具备焦点恢复、Tab／Escape、关闭按钮和遮罩；打开期间主内容 inert。选取导航、目录或设置后关闭侧栏，其他已开的模态窗口不会自动叠加文件入口。
- 580 以下播放器使用歌曲／播放与进度／输出和音量三行，保留封面详情、停止／切歌／暂停、进度、输出设置、音量入口。播放详情的底部边界与播放器共享变量，不继续假定固定 94 像素。
- 窄布局的歌曲表优先保留曲目与时长，资料仍在详情中；搜索和功能按钮换行。详情的专辑与歌词／列表改为上下布局，窄窗口专辑区可滚动。低高度时整页／对话框采用可滚动布局，避免放大后页脚按钮或详情内容因压缩变为不可达。
- 窗口初始 1320×850 DIP，并裁剪到主屏工作区居中；最小尺寸为 760×480 与当前工作区的较小值。设备增加／移除／工作区／比例变化合并后核对可达的标题区域；不可达时在最接近的工作区找回并缩小，已可达窗口不随比例变化跳动。
- 最大化／全屏／最小化窗口不直接抢改其状态；恢复、取消最大化和退出全屏后再核对可达性。窗口移动／大小的观察事件合并为 100ms，屏幕变化处理合并为 150ms。没有把窗口位置或显示器设备 ID 暴露给 renderer 任意写入。
- 当前尚未持久化窗口位置／最大化状态，混合 DPI 的实际跨屏拖动、托盘图标多分辨率资源、完整多显示器恢复和 macOS／Linux 发行验证仍在完整架构范围中。

## 验证边界与待验收
