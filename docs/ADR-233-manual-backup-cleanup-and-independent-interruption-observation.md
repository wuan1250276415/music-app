# ADR-233：手动备份清理与中断后的独立文件核对

日期：2026-10-17。状态：手动清理集中 MVP 通过；全量备份空间管理和总体架构目标继续。

## 行为与边界

标签写回前生成的来源备份按用户设置保留，默认30天和10GiB空间目标。本阶段在备份空间页提供单份核对、明确确认清理、停止、历史和中断结果核对。任务仍在使用、需要恢复、目录或文件不在线、未达到保留期或来自恢复隔离的旧曲库时保留文件。超过空间目标不绕过保留期。

文件名和固定备份目录由后端任务产生。Renderer只能传入任务或操作UUID，不接收任意删除路径。先在独立原生进程中核对NTFS目录和文件身份、完整文件与FLAC证据，用户另行确认后再启动一次删除操作；删除前重新核对策略、任务修订和原暂存日志。活动批次与其他标签文件操作互斥。

## 持久化与失败处理

schema85新增清理操作、不可变命令和阶段回执，支持原命令幂等查询。文件日志与数据库分别保存相同规范记录和摘要链。原生组件在独占句柄下核对文件，只有收到已持久化的delete_ready确认后才能按句柄删除；删除后再次检查原位置，并等待全部回执和实际正常退出。

删除已经发生但最终确认丢失时，原操作仍保留中断与未确认退出状态。用户可发起新的只读观察，核对原文件当前存在或缺失；观察有自己的日志、进程和退出回执，不修改原操作的成功事实。重启不会自动重发原删除，也不会复活原用户确认。

整库快照纳入tag-backup-cleanup目录及其阶段文件；恢复校验检查原始命令、父子关联、规范记录摘要、回执连续性与操作结果。缺失阶段回执即使SQLite完整性正常也拒绝恢复。
