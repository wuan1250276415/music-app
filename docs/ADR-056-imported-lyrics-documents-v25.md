# ADR-056：用户歌词原文、版本与修订（schema v25）

日期：2026-10-01。状态：0.51.0 源码实现，运行与迁移待 MVP。对应架构 §17.1、FR10、WP03/WP10；保留 FR01–FR14 与 WP01–WP11 全范围，ASIO 实机验证继续暂停。

## 导入与预览

详情和歌词侧栏增加“导入歌词与版本管理”。可由 Windows 原生选择器选择 LRC/TXT 文件，或粘贴文本；导入前明确版本名称、可选语言、编码和时间基，先解析预览，再确认保存。自动编码按 BOM 的 UTF-16LE/BE、严格 UTF-8、严格 GB18030 回退识别，界面提示核对文字；可手动指定编码重新预览。粘贴文本按 UTF-8 保存。预览不写数据库、不自动联网。

Main 只读取选择器返回的具体文件路径，Renderer 和 Service 接口不接受调用方路径。使用一个只读文件句柄，检查普通非空文件、大小与读取前后属性，最多读 1 MiB + 1 字节，拒绝超限／读取中变化；向 Renderer 返回短文件名及原始字节的 base64，不返回完整路径。属性检查不等于文件锁或内容原子快照，UNC 读取仍受操作系统 I/O 行为影响。

Main 对传输字段和大小做检查、白名单提取；Service 再检查目标范围、请求结构、规范 base64、实际字节数、语言和编码。原始字节最多 1 MiB，解码后 UTF-8 文本最多 1 MiB，单份解析 JSON 最多 2 MiB，拒绝空内容、空字符、严格解码失败及超限。JSON 转义放大也在保存前检查，避免保存后无法读取。继续沿用最多 5000 行、1 MiB 展示文字的 LRC 解析限制。版本名称最多 128 字符，语言为可选 BCP 47 形式标签。

普通曲目时间从源起点开始；CUE 必须明确选择“当前曲目时间”或“源音频时间”。后者只接受在当前轨范围有可用行的同步歌词，在应用 LRC offset 后按整数 75 fps 范围裁剪并转换为轨相对时间；整碟纯文本不自动分给单轨。原始字节和完整解码文本保持完整，不把裁剪后的行误称为原文。

文件内容、名称、语言、编码或时间基改变会清除预览，确认使用已经预览的同一输入。所选文件可以将解码文本复制到编辑框，生成新的 UTF-8 版本；不改写原歌词或音乐文件。预览显示前 12 行并可展开完整解码文本，没有伪造逐字同步。

## 文档、范围与存储

schema v25 新增 `lyrics_document_scope`、`lyrics_document`、`lyrics_document_state` 和 `lyrics_document_change`。原文在曲库数据库中以不可变 BLOB 保存，另保存 SHA-256、实际解码编码、完整文本、语言、标签、时间基、解析 JSON、解析器版本与 `local-private-v1` 来源授权引用。这是持久用户内容，不进入图片／波形缓存或自动清理。后续文件形式导出、user-content 目录适配与完整备份恢复仍需开发。

文档范围沿用 ADR-050 的 PlayableItem、媒体身份／路径、普通或 CUE 类型与完整源范围摘要。版本 ID 由范围、原文／解码文本摘要、名称、语言、时间基、实际编码和解析版本生成；相同版本拒绝重复插入，提示恢复或选择已有版本。新内容保存成新版本，不更新旧版本的原始内容或解析结果。不同编码的原始字节不会因解码文字相同而被覆盖。

用户文档和范围中的 item_id 为历史引用，不依赖可删除的 playable_item 外键，防止删除旧 CUE 条目时连带删除原文或阻塞扫描。写操作仍必须通过 Service 读取存在的当前条目，核对范围。CUE 范围／路径变化后旧版本保留，但不自动套用到新范围；当前管理页显示同一条目旧范围版本数量，旧范围查阅／显式重绑定和条目移除后的独立用户内容管理继续开发。

同一范围最多保留 64 个版本／32 MiB 原始字节；达到限制拒绝新导入，不删除用户版本。最多同时启用 16 份导入文档／4 MiB 解析 JSON；可归档已有版本释放启用预算，归档不释放持久原文预算。普通本地来源仍有 ADR-050 的 16 份／2 MiB 文档预算，因此 bundle 最多约 32 份／6 MiB。读取有效来源只取解析内容；版本分页只取摘要，不读入整页原始 BLOB。查看单个原文时核对原始字节 SHA-256。

## 生效、归档与记录

用户导入按最近保存优先，排在自动本地来源之前；既有显式主／辅助选择保持优先。没有音频文件可读时，保存的用户文档仍可展示，点击跳转沿用播放状态限制。库内偏移、双语设置和字体仍通过原有歌词设置保存，不重复应用 LRC offset。

归档将文档从可用来源移出；显式选择缺失时暂用其他来源并提示，旧选择和偏移保留。恢复后同一文档身份可重新生效，原偏移只用于匹配的主来源。每次导入／归档／恢复增加范围修订并记录不可变回执；不称为物理删除或 Provider 数据清除。

管理页分为导入、保存版本和修订记录。版本可查看解码原文／编码／字节数／原文摘要、归档和恢复；修订记录显示动作、文档、范围修订和时间并可查看对应版本。版本、自动来源顺序与修订记录均按范围单调修订排序，采用每页 20 项的范围绑定键集分页，避免同毫秒或系统时间回拨改变先后关系。它们记录文档操作，不替代 ADR-050 的独立歌词显示设置回执。

## 并发与回执

写操作携带 UUID、曲目 ID、scope 与 baseRevision；导入在事务外准备有界解析，在同一单写入进程事务内检查范围／修订／容量，保存不可变文档、状态、范围修订和回执。归档／恢复检查文档确实属于该范围，恢复再次检查启用预算。schema v24 升级前执行 pre-v25 一致备份，表和版本号在事务中提交；v24 安装步骤增加条件保护。迁移 SQL 尚未执行验证。

回执只保存规范请求身份和原文摘要，不重复保存 base64 文本。相同 UUID 只允许相同输入；已提交回执在当前范围判断之前返回历史成功结果，核对不会再次创建文档或重做归档。通知通道失败不把已提交结果改称拒绝。明确拒绝返回 rejected；传输失败／超时保留原输入和 UUID，界面阻止新操作并提供“核对上次保存结果”。重放后重新读取当前版本状态，而非恢复历史状态。

未确认意图仍在此 Renderer 会话内存中；持久结果、文档与回执在数据库中。应用重启后可读取实际版本和修订记录，尚未加入跨 Renderer 重启待确认意图箱。其他歌词或曲库修改让管理页要求刷新；Service 的范围／修订检查仍是提交边界，不依赖界面检测及时性。模态键盘处理加入文本框与可见 summary，忽略关闭 details 内的隐藏控件。
