# ADR-182：历史 CUE 重新解释与曲库引用复审

- 日期：2026-10-10
- 状态：0.176.0 源码接入，类型／构建及静态核对；运行验收留至 MVP
- 对应：FR02、FR04、FR13、WP03、WP04、WP10；沿用 ADR-104、ADR-106、ADR-179–181

## 问题与分阶段流程

现有历史界面可以解码和导出任意版本；现有解释提交仍针对当前来源设置，后台扫描读取磁盘上的最新CUE。把历史版本的编码选择直接送入这个入口，不能实现所选历史原文重新应用，还可能让用户误以为旧范围已经恢复。

补齐历史重新应用必须包含：保存版本及原字节核对、当前解释与引用复审、明确选择的持久记录、实际音乐与目录／权限的新核对、停止受影响播放／预备轨后的检查点提交、失败保护及重启继续。本次实现前两步和曲库引用记录的完整复审分页，不借旧提交入口伪装历史应用；后续持久选择／扫描／提交仍属于完整目标，未验收完成。

## 所选原文与当前设置

新增请求明确绑定来源UUID、所选历史版本SHA、当前来源基础修订与latestVersion、请求编码、间隙政策和128项分页偏移。第一页偏移0；后续页必须携带前一结果的完整复审摘要。无新增写命令、回执或schema迁移。

Library先核对来源修订和latestVersion仍与请求一致，按来源和版本联合读取原资产。原字节SHA／长度、保存时解析JSON SHA及基础结构、v42或v43原版本摘要推导均独立核对。外部导出与本次复审复用 `sourceBundle`，继续保留v42默认previous与v43明确间隙政策，不重写旧摘要、原JSON、BOM、编码或回执。

只有通过原版本核对，才使用当前parser4及用户明确的编码／间隙选择重新解释原字节。保存时轨数来自经摘要核对的旧快照；当前轨数、元数据、原75帧范围、隐藏前导音频与诊断来自本次解析。这里不声称独立运行过所有旧外部parser来证明旧树等价；固定旧文本parser的读取另见ADR-180。

## 曲库引用记录

当前来源目录与保存时位置分别展示。以当前曲库根和当前来源路径作为引用锚点，使用既有 `resolveCueReference` 检查词法目录边界。目录缺失、绝对／上级引用、路径无效不构造外部访问；FILE、CDTEXTFILE和音乐文件都不读取。

按既有NFKC／小写／trim路径键参数化查询当前媒体记录、原属性观察及文件管理状态。引用表示当前解析音轨所使用的名称，不把没有可解析音轨的原FILE行计作成功引用。记录区分：目录外、无曲库记录、离线或缺失、已忽略、已移出、待恢复重扫、解析错误、无属性观察、写回／恢复占用和曲库记录在线。目录来自整库恢复时仍按原恢复策略和目录监听记录判断是否重新授权；这是应用策略记录，不是OS授权或实际文件核对。

范围以CUE原75帧单位判断，起点／INDEX01／子索引须在已记录时长内，已声明结束位置不得越过记录长度；当前来源解析本身无效时明确显示，不能把部分可定位记录当作完整可用编排。没有已知时长时标为未知，末轨未声明终点则保留null／“文件结尾”，不推断精确总采样数或用浮点时长补造原采样依据。前导段保持原条目和身份，不自动重新加入已忽略／移出的文件。

查询依据只是曲库快照：在线标记、size／mtime、属性观察、codec／sampleRate和时长都尚未通过新的真实文件读取。不能据此播放、取得写权限或应用旧编排。

## 完整复审摘要与分页

每页重新解释和查询完整结果，再计算 `aural-cue-catalog-review-v1` 摘要。范围包括请求的来源／版本／基础修订／编码／间隙、当前来源摘要、当前根路径／状态／扫描代次、恢复策略及当前根监听记录摘要、保存位置／时间、原文／当前解析树及parser、所有引用记录／文件管理修订／观察／可读状态和所有范围判断。偏移及期望摘要不进入内容摘要，翻页能核对同一完整结果。

期望摘要不匹配时必须从第一页重新读取，不拼接旧范围和新记录。该摘要是相同查询范围内的分页一致性证据；不覆盖OS文件内容、所有实时资源或未声明权限域，更不是历史应用许可。后续应用必须重新建立实际来源／资源／任务的完整证明，不能直接接纳这个摘要作提交授权。

最多2000项（普通与隐藏音频合计），每页128项；曲目标题／艺人各256字符，引用名512字符，映射相对路径1024字符，专辑／艺人资料各512字符，诊断16条且每条512字符；省略均明确显示。下一页与上一页使用同一完整摘要，源设置或引用变化后拒绝继续。显示原文件结尾而非虚构采样范围。

## 桌面接入与状态保持

历史页新增“复审此版本的当前解释与曲库引用”，可用于任意保存版本，按当前预览编码和间隙政策发起。更换来源／版本／解码／间隙政策清除旧复审；新结果及翻页获取焦点，关闭回到复审按钮。旧待确认解释命令继续阻止新增操作；已有待扫描状态明确显示，但本次复审不修改或清除它。

可信主frame、原documentEpoch、Main维护工作和共享CUE文件占用保持。Main严格读取请求，返回结果必须匹配原请求和偏移；文档变化后不发布旧结果。preload只提供固定复审能力，完整原字节和解析树不作为Renderer可提交的通用播放／写回值。

现有最新来源configure及扫描事务行为保持；没有调用播放停止、扫描提交、历史恢复、音乐写回或来源注册。新的复审方法只读历史与曲库；目录策略load、监听load及标签assertReadable也已在源码确认仅查询，不调用保存方法。
