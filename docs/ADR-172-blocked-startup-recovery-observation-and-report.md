# ADR-172 未决恢复的独立启动核对页面与报告

状态：源码实现，运行验收待 MVP。日期：2026-10-10。版本：0.166.0。

## 问题与决定

恢复启动准入拒绝之后，原程序仅显示初始化错误并退出，用户看不到保留的恢复记录和目录观察。本批把此阶段的错误定义为 `RestoreStartupBlocked`，携带已取得的整体启动核对结果；根目录或登记读取失败也归入该错误并保留“结果未完成”，不能把读取失败当作空目录。

该异常发生在普通 Library fork 之前。Main 只在实际服务不存在、未 ready、桌面未初始化时进入独立启动核对模式，创建安全默认窗口；不绑定未初始化的桌面/位置/设置管理器，不启动曲库、音频设备、系统媒体或旧任务。已经进入 Library 之后的普通初始化错误仍沿用现有错误流程，本批没有冒充所有启动错误都已经可恢复。

Renderer 首先读取启动模式。核对模式按需载入专用页面，跳过普通 App、备份客户端初始化和恢复新文档 seed；普通模式保持既有入口顺序。核对页面不是正在运行的整库恢复维护界面，也不取得上一进程遗留的租约或实例身份。

## 观察与权限

复用原完整只读启动检查：规范全局记录、原生移动回执、实际四个目录槽位、已完成历史关系及第二次规范读回。新增只读摘要包括实际事务版本、来源操作、阶段回执数量、最后阶段、旧用户确认时间和当时的 completed 是否登记；这些摘要不成为恢复成功或重放许可。

公开结果严格版本1、512KiB、64事务、每事务四槽/16移动/48全局记录、四条移动阶段回执及已知观察状态。未知登记名称可显示但不采用；损坏/缺失登记保留原错误。页面每次八条分页，全部记录可查阅，旧移动槽位观察与当前整体准入区分。

恢复模式的业务 IPC 全部拒绝；维护控制仅允许读取核对状态、重新核对、导出报告和退出。外部文件入口、封面资源和系统恢复时的设备/服务启动也暂停。读取和报告保存绑定实际主窗口主 frame/文档 epoch及服务不存在；导航、界面退出、休眠和应用退出使原工作中断，原实际读取/文件保存 Promise 仍负责结束。

主动重新核对使用原检查函数并在每个外层读回检查原授权。列表/目录“通过”只代表当次启动登记准入，不等于已经打开数据库或恢复服务；页面继续保持核对模式，没有自动重启、移动、回滚、删除、SQL、空库创建或旧任务重放。

## 报告保存

报告保存原有观察快照，而不是在选择文件之后偷偷改成新一次核对。报告含格式/版本、当前应用版本、导出时间及规范核对结果，应用数据路径替换为标记；不含音乐内容、凭据、队列/设置或 pending 原文。读取和保存互斥，原窗口和快照变化拒绝保存结果。

只使用 Main 原生保存选择，不接受 Renderer 路径。仅允许新的 JSON，拒绝应用数据目录内目标及同名覆盖。规范普通父目录、目录身份、wx+独占句柄、sync、同一文件完整原字节读回、实际名称/单链接/观察和父目录再核对；中断或未确认的文件不报保存成功。没有替换音乐文件、内部登记或已存在的用户报告。

## 验证与后续

本批做类型、Main/Renderer 构建、原生/既有金样仅编译、脚本语法与发行静态核对。未运行应用、SQL、恢复、报告文件保存、音乐、驱动或测试。真实初始化分支/正常启动/跨文档、损坏记录、移动观察、列表分页和报告选择/盘满/读回/退出交错在 MVP 集中验证。

实际未决事务的继续/回滚操作、新进程重新取得实际所有权、完成决策与当前可变 WAL/数据库核对、已完成恢复后数据库打开失败的诊断，以及原文导出复审、完整领域/迁移校验和和物理工件配额继续开发。没有新增假“继续恢复”或清理按钮；完整 FR/WP/G/AC 目标保持未完成或待验收。
