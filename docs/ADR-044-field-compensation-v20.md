# ADR-044：在线单值字段补偿撤销

状态：0.39.0 源码实现；2026-10-01。对应架构 §11.3、WP03/WP08。schema v20，音频协议 v1.6 不变。当前未通过迁移、桌面、网络或 MVP 运行验收。

## 字段检查与预览

- 单值在线修订的歌名、歌手、专辑按字段判断可撤销、已撤销或冲突。新的修订另记录实际更新字段及更新前后有效展示值，保留原覆盖值与来源快照。旧记录由前后覆盖值差异推导更新字段，不改写旧审计数据。
- 检查当前覆盖值是否仍等于该次 after 值，有效展示值是否改变，以及该字段的来源观察、选择模式、锁与单调字段修订是否一致。另一个字段的修改不再自动阻止本字段撤销；同一字段 A→B→A 的来源修订变化仍判为冲突。
- 歌手字段后续确认的结构化署名、集合锁和人工集合选择会阻止旧单值撤销覆盖。来源快照不足的旧记录使用保守条件；无法证明一致时显示冲突，不猜测来源。
- 预览提供原修订、当前值、拟恢复值、恢复来源权限与冲突原因。用户勾选仍可撤销的字段并再次确认；预览指纹绑定当前覆盖、字段来源、当前本地标签、曲库关联和逐字段状态，提交时重读并检查。
- 原覆盖为 NULL 时，撤销表示取消这次覆盖并回到当前本地来源，已重扫的标签不会被旧标签文本替换。已存在人工覆盖时恢复原覆盖和其来源选择。显示艺人身份的名称仍遵守当前曲库关联，预览标明本地来源恢复语义。

## 来源与补偿记录

- 新 `restoreMetadataField` 只恢复所选字段的来源选择，增加字段与来源策略修订；不重置未选字段、不全量恢复旧集合状态、不改写自动来源历史。恢复的观察必须属于当前实体与字段，并允许保存和展示。
- schema v20 增加不可改写的 `metadata_compensation`、`metadata_undo_member` 及归属检查，保存每次实际恢复字段、补偿前后值、来源快照、有效展示及受影响条目。字段与原修订的唯一键防止重复恢复同一字段。
- 原修订的 before／after 数据不被补偿操作重写。只在全部原更新字段已撤销后设置 `metadata_change.undone_at`，部分撤销保留剩余字段并继续提供预览。补偿记录接入已有“撤销修订”历史类别，不提供递归撤销补偿自身的入口。
- 覆盖更新、来源恢复、关联／索引刷新、补偿日志、字段完成标记及命令回执在同一写事务内保存；失败回滚。命令 ID 与请求摘要持久去重，重放先读回执；同 ID 不同参数拒绝。
- 升级前对已有库保存一致备份，再于独立事务安装 v20。原批次应用回执保持不变，另加 `undo_result_json` 记录撤销结果，避免撤销结果覆盖原应用记录。

## 界面、批次与历史

- 单曲在线匹配面板的“撤销本次修改”先打开字段预览。歌名、歌手和专辑可分别选择；冲突字段保留并列出原因。丢失提交响应后可按原命令重试；新字段选择使用新命令。
- 在线修订及补偿记录加入统一曲库修订列表，在线修订支持字段预览，部分撤销显示标识。完整多人署名、发行整理和其他既有修订继续使用其原撤销流程。
- 批次撤销采用当前可恢复字段，返回已撤销、剩余和冲突字段。部分成功仍记录撤销冲突状态，界面另标“已部分撤销”，逐项显示恢复和保留的字段；其余歌曲继续处理。完全没有可恢复字段时只保存冲突结果，不伪造补偿变更。
- 在批次外通过统一历史恢复某些字段后，批次记录的读取按原修订完成标记与字段补偿日志协调状态，避免继续显示已恢复项为已应用。批次也提供单项字段预览入口，子对话框打开时父对话框不可交互。
- 本轮限定在线单值修订及对应批次。艺人／录音／发行资料、字段来源选择、风格和有序集合的部分冲突撤销尚未实现；整专辑审核、完整署名批量及正式 Provider 保留／撤销／凭据管理仍待开发。
