# ADR-027：用户状态、静态歌单与曲库 v5

状态：已实现原型，2026-09-30。对应架构 §8、§16、FR04/FR07，推进 WP03/05/06。

## 数据与事务

SQLite v5 新增 `item_user_state`、`playlist`、`playlist_item`、`user_command_receipt`。收藏、0–5 星评分和用户状态 revision 独立于文件扫描标签。歌单按独立 entry ID 引用 PlayableItem，同一曲目可出现多次，位置在歌单内唯一且连续。创建、创建并添加、编辑、重排和删除均在本地事务中执行；错误时全部回滚。删除歌单只删除其条目。

用户状态及歌单修改使用命令 UUID 和基础 revision。成功结果与数据一起保存为持久回执；重启后相同命令仍返回同一结果，命令被用于其他参数时拒绝，旧 revision 的新命令也拒绝。Renderer 仅在保存确认后更新界面。回执目前保留全部成功命令；后续需给出兼容重试保证的归档策略。

曲目新增 `added_at`，新导入时记录，重扫不覆盖。旧库没有原始导入时间的条目保留 NULL，排在“最近添加”视图后面，不以迁移时间冒充首次导入时间。

v4→v5 前通过 `VACUUM INTO` 生成一致备份，随后在事务中迁移；发行 manifest 声明 schema 0–5。旧版 0.21.0 支持范围仍为 0–4，不能直接打开升级后的库；恢复需使用旧版的一致备份，升级后产生的用户数据不在旧快照中。

## 文件与 CUE 生命周期

文件缺失、根目录 offline 和已不再可见的 CUE 条目在收藏/歌单中保留，并标记不可用。根目录重新扫描或 CUE 条目返回后，原引用可以恢复可用。删除旧 CUE 条目的行为改为隐藏，以保留队列、元数据修订和用户引用；用户数据 FK 使用 RESTRICT，避免清理时静默连带删除。

现有 CUE 身份仍基于文档和 ordinal；插入或大幅重排 CUE 轨的身份对账尚未完成，不能将本次删除/返回测试扩大解释为任意 CUE 改写已正确对账。

## 播放和界面

导航提供收藏、最近添加和歌单。曲目旁有收藏及加入歌单按钮；详情页可收藏、评分及加入歌单。歌单支持创建、重命名、删除、移动和移除条目。

播放歌单时由 Library Service 在同一读快照中验证歌单 revision 和所选 entry，Main 创建独立的队列 entry，附带来源 playlist entry ID。点击重复歌曲的第二次出现，队列从该次出现开始；播放队列是歌单快照，后续编辑歌单不改动正在使用的队列。相同播放命令的进程内回执重放先于重新查询歌单，避免歌单后续编辑造成已成功命令错误重执行。

当前静态歌单和播放队列最多 500 项；超过容量原子拒绝，不截断。后续需演进有界分页队列，支持更大歌单。智能歌单、导入/导出、完整播放历史及基于呈现时钟的 play_count 尚未实现；完整 Recording/Release 与多艺人模型仍待 WP03。

## 验证

44 项单元测试涵盖用户状态重扫/离线/重启保留、持久回执、修订冲突、静态歌单重复/排序/移除/删除、创建并添加回滚、CUE 条目消失和返回、v4→v5 一致备份及原队列/修订保留。桌面回归从隔离 v4 库启动，验证收藏、评分、重复歌单播放位置、重排/移除/重命名及重启恢复。发行版结果在 README 0.22.0 记录。
