# ADR-108：ASIO PCM 原生模块与驱动生命周期

- 状态：源码、类型及编译检查通过；ASIO 实机验证按用户要求搁置
- 版本：0.102.0
- 日期：2026-10-03
- 关联：架构 §12／§14.2／§26.3、FR09、WP02／WP06／WP07；延续 ADR-021／022

## 当前交付与尚未完成范围

此前 ASIO 仅有官方接口和独立枚举／初始化／短时静音探针。本批新增原生宿主可编译的 `Engine`、完整 PCM 样本打包和生命周期模块。模块包含真实 IASIO 调用、可信环形缓冲消费入口、样本处理和双缓冲写入逻辑。生产宿主编译该模块，新增 `--asio-drivers` 有界注册目录输出；该命令不初始化或播放驱动。

应用的输出设置、持久偏好、私有 IPC 播放路径仍使用 WASAPI，未连接此 Engine。ASIO 没有被加入现有播放能力握手，不宣称现在能从应用选择 ASIO 播放音乐。FR09 未完成：后续必须接入设备能力查询／设置／持久偏好、播放前计划、实际回执验证、进程监督、控制面板入口和切换恢复；呈现时钟／尾部映射、自动 reset／resync、真实驱动矩阵继续。Native DSD／DoP 设备输出也仍在完整目标中。

## 驱动与控制边界

仅从 HKLM 的 64 位 `SOFTWARE\ASIO` 目录读取注册名／CLSID／说明，最多检查 1024 项、返回 256 个驱动及跳过／截断／注册读取状态。CLSID 必须为 GUID 文本，再转为规范值；不接受 ProgID，不通过任意 DLL 路径加载。打开时重新检查注册名与规范 CLSID 同时匹配。描述不是身份；不能把一个同名新驱动当作原驱动。

在明确拥有的 STA 线程初始化 COM、创建自己的隐藏窗口并实例化 IASIO；初始化、采样率、通道、缓冲、控制面板、延迟、消息循环和释放由该线程串行调用。没有桌面窗口回退。控制面板仅能在当前会话准备缓冲之前打开；设置之后重新查实际能力。消息循环每次最多分发 64 条，退出消息记为终止事件。

一个进程仅使用一个驱动生命周期。即使 stop／dispose／Release 成功，下一次 reopen 也要求新进程。ASIO 回调没有 userdata，旧驱动的错误延迟回调不能被重新绑定到新歌曲／驱动。此策略要与 Main 的进程代次、原始位置书签、nonce、有限重启和用户播放意图共同接入，不能由模块自行盲目恢复。

准备时只选择显式且不重复的输出编号，每个源声道对应一个输出，不做隐式重排／混音。核对 PCM 模式（支持 I/O mode 查询时）、实际源采样率、输出范围和格式，再创建双缓冲；准备后再次核对声道数量／身份／启用状态、采样率、模式及缓冲几何，使用实际样本格式形成内部准备报告。未知／DSD 样本类型拒绝作为 PCM。

硬件缓冲遵循固定大小、首选大小或驱动声明的步进／从最小值翻倍规则，且不超过 32768 帧。源率限定 8 kHz 至 1536 kHz、最多 16 声道，匹配源率失败不隐式 SRC。原生整数有效位或浮点位数描述必须完整。检查双半区指针、区间溢出、通道及半区互不重叠、已提交可写内存；这些检查只证明虚拟内存属性，不能证明驱动分配容量或硬件行为。

## PCM 与实时路径

支持有符号 16／24／32 位、float32／float64 交错小端源，以及 ASIO 的大小端整数／浮点输出和 32 位容器内 16／18／20／24 位右对齐整数。扩展整数按官方 SDK 2.3 规范第 33–34 页作符号扩展；此处读取本地官方固定 ZIP 中的规范，仅使用既有未修改接口，不复制 SDK helper／sample 代码。版本与许可仍由 [SOURCE.txt](../native/asio-probe/vendor/SOURCE.txt)、GPLv3 选择及固定哈希清单追溯。

默认拒绝数值转换。整数输出有效位足够时可准确重打包，运行时核对声明的低位 padding 为零；同宽浮点可以原位序重打包。这些只是样本打包候选，不代表上游解码／DSP 或设备链 bit-perfect。用户允许转换时，整数降位确定地向零截断，浮点量化到整数使用最近舍入／半值离零及饱和；跨浮点宽度转换的非有限数置零并计数。同宽浮点复制保持原位模式，包括非有限值。没有 dither、SRC、DSP 或 Native DSD 静音伪装；完整处理计划与对应数值／音质验收仍需接入。

源交错及输出声道暂存各不超过 4 MiB，准备期间分配，回调不分配、不读文件、不解码、不访问数据库／IPC、不等待锁。RenderTarget 只允许可信、有限、非阻塞环形缓冲消费者。这描述 Aural 自身代码，厂商 outputReady 行为与调度性能仍须实测。先转换到私有平面，再复制到驱动半区；短读清零剩余样本，统计有效音乐、补零、饱和、非有限值和丢弃缓冲。错误的读取数量、原始 padding、重入／过期缓冲和 outputReady 错误锁存，停止继续消费新 PCM。

仅预填半区 B，再 start，避免预消费半区 A 后被首个回调覆盖。一次准备只允许一次 start 尝试，暂停／定位／换曲／重配须由传输层以新计划与书签重新打开。尊重 `directProcess`：允许立即处理时直接完成；要求延后时只唤醒预创建的单个音频线程，以单在途半区传递，不排积压音频。线程尝试加入 MMCSS Pro Audio，实际是否加入写入准备报告；若下一次切换仍未完成则锁存故障，留待监督层停止／恢复。暂存和这些护栏不保证调度期限及硬件 DMA 正确，不能替代真实延迟／欠载检查。

outputReady 在驱动明确报告支持时才调用；实际回调返回的 samplePosition／systemTime 通过一致快照读取，后续回调缺少时间信息时失效旧时钟有效标记，不额外在回调内查询时钟。它们不是已经对齐源时间和输出延迟的呈现时钟。填充／音乐／补零计数使用独立一致快照，读取无法确认一致时标记无效；填充帧不是已播放帧，不能用于提前发 ended。旧 bufferSwitch 路径没有时间信息时不捏造硬件时钟。

## 通知、停止与失败

所有回调用进程生命周期的入口栅栏；回调表也保留到进程结束，驱动持有表指针时不引用已销毁的 Engine 成员。render 与延后工作共享单写入保护。采样率／时钟／reset／resync／buffer size 等改变锁存事件，回调不调用控制 API 或主动重开。尚未连接自动恢复协调器，reset／resync／buffer-change 的响应仍明确不承诺接受。延迟变更和 overload 作为观察事件保留，延迟重新查询在控制线程执行；通知修订单调增加，查询记录开始时的修订，查询期间再次通知仍保留为待读取，不能因清除一个布尔标记而丢失后续变更。

停止先撤销消费意图，也撤销尚未启动的准备会话；等待在途回调／音频工作退出，再调用 stop，并再次确认退出。关闭先撤销回调目标；确认音频线程终止后才 stop／dispose／Release／释放窗口及 COM。等待各有 2 秒边界；失败保留未知驱动及缓冲状态，禁止再次打开并要求终止整个原生进程。析构不能干净关闭时终止原生进程，避免释放仍可能被使用的回调上下文。Release 释放当前拥有的引用，返回计数仅是测试用途，不用其数值推断全部驱动对象是否销毁，也不据此误报关闭失败，见 [Microsoft IUnknown::Release 文档](https://learn.microsoft.com/en-us/windows/win32/api/unknwn/nf-unknwn-iunknown-release)。驱动自身控制 API 可以阻塞，不能由这些等待限制解决；Main 外部 watchdog 的 ASIO 接入仍是必要后续工作。
