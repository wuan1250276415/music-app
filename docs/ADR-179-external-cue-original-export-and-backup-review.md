# ADR-179：外部 CUE 原文导出与来源备份复审

- 日期：2026-10-10
- 状态：0.173.0 源码接入，编译检查；原文、文件与界面运行验收留至 MVP
- 对应：FR02、FR04、WP03、WP04、WP10、WP11；沿用 ADR-104、ADR-106 和 ADR-178

## 问题和决策

外部 CUE 的不可变原字节及解析版本此前可以查阅和选择重新解释，但缺少完整原文导出。页面的131072字符解码预览不能代替备份，也不能按当前预览编码重新编码后冒称原始文件。内嵌来源导出已在0.172接入，本次补齐外部来源，并提供保存的来源备份的独立只读复审。

用户选择任意已保存版本，可以导出两种内容：

| 输出 | 内容和限制 |
|---|---|
| `.cue` | 该版本的完整原字节，包含原 BOM、原编码、换行、引用名称以及解码失败内容；最大2MiB |
| `.json` | 完整原字节 base64／SHA、原解析 JSON 字符串／SHA、实际及请求编码、间隙政策、parser标记、原解析错误、保存时间、当时根目录／相对路径及历史来源身份；最大8MiB |

导出只读原版本及资产，并核对长度与SHA。当前预览编码、当前文件、扫描状态和当前版本选择不会转换所选历史字节。来源JSON保存 `parsedJson` 原字符串而不重新归一化旧解析树；原文可解码与否不影响原始字节导出，文件为空时也保留空文件真值。

## 历史版本和备份复审

JSON格式为 `aural-cue-source`／version1，19个严格字段。保留来源版本推导种类：v42历史摘要不包含独立间隙字段，v43摘要包含间隙字段。导出和复审均重算对应摘要；v42只允许原默认previous，不能借复审修改旧版本或回执。根目录／路径等保存资料沿用原记录，它们不是经过数字签名的真实性证明，备份中的身份也不会自动授权当前曲库访问。

Renderer只提交来源UUID、版本SHA及raw／bundle种类；保存位置和读取的JSON位置只能由Main本机对话框选择。没有向Renderer暴露完整原字节或完整解析JSON的通用写文件能力。内嵌与外部CUE文件操作共享一个在途占用；整个IPC异步工作沿用Main维护等待范围和原主窗口身份核对。

打开备份须是8MiB以内的普通独立 `.json` 文件，同一打开句柄读至EOF，前后属性摘要和路径观察一致、严格UTF-8、严格字段与预算。根JSON须与本格式的规范19字段／两空格缩进／末尾换行字节完全一致，拒绝重复键、重排／改写格式、额外BOM及尾随资料；此入口接收Aural原始导出的来源备份，不承诺任意JSON格式兼容。20秒检查是合作预算，不能中断仍阻塞的OS读取。Main把已读取的私有完整来源发送到Library，Library再次核对规范base64、原字节SHA／长度、原解析JSON UTF-8字节数及SHA、版本推导和解析快照基础结构。

通过来源内容核对后，当前解析使用保存时的请求编码与间隙政策；原文显示使用保存时的实际编码。显示保存时parser／曲目数／诊断和当前parser／曲目数／诊断，解码失败和无效编排明确显示。预览限制131072字符、64个引用名称且每名称512字符，并标明省略；两类完整原文仍在原备份中。

新备份复审入口在执行现有解析器之前，使用线性FILE语法预检查，避免不完整引号声明进入旧引用token正则的回溯路径。预检查失败仍显示原文和保存时资料，当前轨道数／编码为空，`currentParsed=false`，界面明确尚未执行当前解析。它不构造假的解析成功结果。普通扫描及内嵌解析器的同类语法实现仍需后续统一改造、明确parser代次和历史兼容，本次只保护新增备份入口。

没有访问 FILE、CDTEXTFILE 或其它来源路径，也没有创建、绑定、重扫或改变曲库记录。声明的音频引用只显示为文字。当前曲库来源映射、音乐本体身份与权利复审、历史解释重新应用、外部／内嵌备份互通和批量恢复是后续独立工作；只读预览不是恢复完成或编排可播放证明。

## 保存行为

内嵌和外部导出复用 `source-export-file.ts`。Main对私有导出值重算规范base64、长度和SHA，并分别保留内嵌2MiB、外部原文2MiB、外部备份8MiB限制。解析实际父目录后排除应用数据目录，只能 `wx+` 新建文件，不能覆盖源CUE、已存在目标或竞态创建的目标。成功必须sync、原句柄回读及EOF、文件和父目录身份／实际位置、原窗口身份全部通过。

失败时保留新创建的文件并提示重新选择文件名；不按可能已被替换的路径删除。此行为不承诺目录fsync、跨平台强目录隔离或崩溃原子发布。原音乐、源CUE和数据库不因导出或打开备份而被修改。
