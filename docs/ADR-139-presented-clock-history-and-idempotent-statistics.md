# ADR-139：按呈现时钟记录播放历史与幂等统计

日期：2026-10-06。状态：0.133.0 源码实现，运行与产品口径验收待 MVP。对应 FR07、架构 §9／§15／§16.2、WP06／WP07。

## 身份与时间依据

播放协调器在每次重新开始曲目时创建逻辑 session UUID，绑定已经持久化的 queue entry 身份和播放时曲目资料。单曲循环、重新选择同一 entry 也产生新 session；暂停、seek、输出重开、系统恢复和 ASIO 重建沿用逻辑 session。相邻 CUE 预排轨使用同一逻辑 session、不同 entry，按已经验证的源帧边界拆分累计值。即使边界时队列推进尚在等待数据库回执，也使用宿主计划中冻结的 next entry，不猜测界面中的当前行。

音频控制器只提供经过现有协议校验的源时钟观察：WASAPI sourceFrame、ASIO PCM sourceFrame、原始 DSD sourceTick。设备／驱动映射时钟记为 presented_us；重采样映射、回调估算另记 estimated_us。源音乐帧映射已经区分缓冲中填入的静音，不能再拿设备总帧或回调次数当听歌时长。不得使用播放按钮次数、系统墙钟、界面进度或歌词计时累计统计。

宿主身份、generation 或采样率变化时重新建立基线，第一点、跳转跨度、暂停书签和缺失观察之间的间隔不计时。恢复的设备时钟落后于先前回调估算时，保留同代际最高水位，避免同一坐标区间再次累计。两个端点均为设备／驱动回报时才计 presented_us，其余可累计间隔记为估算。BigInt 源单位换算微秒并保留每种证据／速率的余数，避免每个事件的取整误差累积。

只有明确完成且由设备／驱动时钟证明的曲尾会补充最终源位置；估算曲尾不补造呈现时间。首次观察、时钟切换、暂停重建及错误前最后一次有效事件之间可能少记一个观察间隔。这是保守下界，不保证每个已听到的采样都被统计，也不证明 DAC 实际输出。ASIO 实机仍搁置。

## 口径与持久化

默认策略版本 1 沿用架构建议：有效回报时长达到 min(曲长 50%, 240 秒) 后，每个 session+entry 只计一次；不足 30 秒需累计达到 95% 并且有接近曲尾的有效回报；未知曲长用 240 秒。估算时长不参与达标次数，所以只有重采样／回调估算证据的播放可能显示估算时长而不增加次数。这里冻结的是本批可追溯的实现版本，产品口径及可配置策略仍须在 MVP 评审确认。

schema63 新增 playback_history、playback_history_checkpoint、playback_item_stats。升级前一致性备份，事务创建表和推进版本。历史保存 title／artist／album／duration／策略版本等播放时显示快照（文字字段最多2048字符，控制字符折为空格）；没有到可重扫或被移除曲目的级联删除外键。统计独立于收藏／评分修订，重扫和在线元数据覆盖不会重置用户统计。每曲累计计数表为后续统计筛选留出接口，本批尚未把统计字段加入智能歌单 DSL。

Library Service 是数据库唯一写入者。检查点带递增序号和累计值；session+entry+checkpoint 的不可变摘要回执用于重复提交核对，身份改变、旧序号未存在、累计回退或同序号异载荷都拒绝。历史累计、每曲增量、第一次达标的 play_count 增量与回执在同一事务提交。回复丢失后重复提交或提交更新的累计值不会重复增加次数。

Main 约每 15 秒持久化待保存检查点，退出／终止观察时也尝试刷新。先写同目录临时文件、同步文件句柄、替换自己的待保存文件，再提交数据库；收到匹配回执后才移除对应待保存版本并再次保存文件。进度在请求期间更新时保留更新的版本。启动回放待保存检查点，失败自动重试，原文件无效时停止记录并保留文件。预算为 512 项／16 MiB；满队列保留旧数据并报告新记录暂停。原始音乐文件不参与此文件操作。

普通退出与窗口位置保存共享既有 1.5 秒等待上限，逾期终止服务，已写入的检查点下次回放。未进入文件的内存进度、意外断电或持续存储失败期间的进度可能丢失；没有目录刷盘或电源故障下“零丢失”的承诺。损坏待保存文件的人工恢复、历史清理／导出／保留期及多窗口管理继续留在计划中。

## 界面与验证边界

侧栏“播放历史与统计”和播放详情“此曲播放记录”按需加载历史对话框。支持播放时资料的文字检索、仅此曲目、分页、已保存记录数／达标次数／设备回报与估算时长、当前资料检索和重新播放。关联歌曲移除、忽略、隐藏或暂不可用时仍保留快照，并禁用播放；重播前再次读取当前曲目并使用既有播放和队列入口。

每次最多 50 行并替换当前显示页，避免历史窗口随翻页无限增长；以插入 ID 做 keyset 分页；游标绑定文字和曲目范围及第一页 ID 上界，防止跨筛选范围继续翻页和混入新记录。旧行累计数值仍可更新，这不是全库一致性快照。收到历史或曲库变化事件提示刷新，不静默重排正在浏览的页面。异步读取用 epoch／alive 校验，操作单飞，关闭和焦点沿用现有对话框机制。聚合检索和名称 LIKE 尚未做十万曲性能验收，不宣称具备通用模糊匹配性能。

Main／Renderer 类型与构建、原生生产组件及既有金样编译通过；41 个 CommonJS 语法、发行生成文件及分发清单（18 个 npm 运行依赖／5 个 vendored 组件）静态核对通过。本批只做类型、编译、语法和发行／分发静态检查。不执行 SQL／迁移、应用、单元／端到端测试、真实媒体、音频／驱动或安装包。MVP 集中验证：初次／循环／seek／暂停／输出重开／休眠、CUE 连续边界、DSD 单位换算、估算回退与恢复、短轨阈值、重扫保留、重复和冲突检查点、未知事务结果、存储失败／损坏文件／强杀与退出恢复、分页筛选切换／更新提示／移除曲目重播及布局与焦点。FR07 及对应 AC 尚未验收。

用户要求的内嵌封面优先、播放栏封面进入歌词＋列表、歌曲资料点击检索、滚动歌词和播放模式源码路径继续保留（ADR-105／114／122）。实际缺图案例尚未复现，界面及真实封面验收仍待 MVP。没有新安装包，最新已验证安装版仍为 0.29.0；全架构其余功能和验收继续推进。
