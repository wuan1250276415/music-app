# ADR-141：独立筛选预设与原请求核对

日期：2026-10-06。状态：0.135.0 源码实现，SQL／迁移、故障恢复和界面运行验收待 MVP。对应 FR04／FR05、WP05 的组合筛选与用户视图；全架构实施范围继续保留。

## 用户行为与规则范围

组合筛选窗口新增“已保存的筛选预设”，展开后读取目录，支持命名保存当前草稿、载入、只重命名、用当前草稿替换、重新读取及确认删除。载入替换完整草稿，不立即修改窗口外的查询；用户检查后点击“应用筛选”。保存预设本身不应用草稿，取消或关闭筛选窗口也不撤销已经确认保存的预设。

预设是 `version:1 + MusicFilters`。艺人角色／任意全部、风格／下级、年份、编码质量、PCM／DSD 参数、收藏／评分／可用性、达标次数、无播放记录、近期／长期未播及近期加入共用严格规范化器。天数保存为相对规则，应用后按 ADR-140 的查询分钟基准计算。载入时同步全部输入和独立选择器状态，避免沿用载入前的数值或艺人条件。

预设不保存当前分类、文件夹范围、检索词、排序、折叠状态或音乐条目集合；它用于当前所在视图，也可在智能歌单的组合条件编辑中复用。保存智能歌单仍采用其完整范围／检索／排序规则，没有把预设定义作为歌单引用。后续更改或删除预设不会隐式改写已经应用的查询、智能歌单定义或提交的播放队列。

只重命名保留所读取的预设条件；“替换此预设”从当前完整草稿取值。每次载入／管理先读取当前定义；修改或删除则使用该定义修订做 CAS，不能覆盖其他窗口或后来修改的新修订。重名允许，身份和修订独立。

## 持久化与有界目录

schema65 增加 `music_filter_preset` 与独立 `music_filter_preset_clock`。每条记录包含 UUID、名称、修订、创建／更新时间和规范化 JSON。名称1–120个字符，禁止控制字符；规则限制规范化 JSON 长度16384个 UTF-16 单位，嵌套条件保留原16项身份与值白名单。最多1024个当前预设，应用层和 INSERT 触发器共同限制数量。空条件可作为“全部条件不限”预设。

目录每页50项，按既有自然名称键及 UUID 稳定排序，返回总数、范围和服务端快照。客户端验证字段、时间、身份唯一、页面对齐及完整范围。独立持久修订由 INSERT／UPDATE／DELETE 触发器在同一事务内更新，回滚也回滚修订；服务进程 epoch 和外部 data_version 一起绑定快照。旧快照返回 stale，界面提示刷新，不跨快照拼接旧页；每页替换显示，目录最多保留当前50项。

预设目录不依赖曲库或播放统计修订，播放进度写入不会令目录持续失效。提交后 `filterPresetsChanged` 只通知打开的预设面板刷新；Main 原有事件转发继续共用，根音乐界面不把它当成资料／歌词／封面或队列变化。目录自然键在 SQL 计算，1024条上限内没有额外后台投影或物化全库 ID。

升级前使用既有一致性备份，事务创建预设表、时钟和触发器并设置 user_version65。原曲库、smart/static 歌单、播放历史、用户状态、队列及原命令回执不迁移内容。旧程序拒绝新 schema，不支持生产库降级。现有旧 schema 夹具辅助函数只在预设为空且目录修订为0、未发生过预设变更时移除新增结构，已更新现有版本断言；未执行辅助函数、迁移或测试。

## 操作一致性与可信边界

Main 校验唯一可信桌面文档，读取严格请求后发送给单写入 Library Service；Service 再次校验。只允许 list/get/create/update/delete；不接受 SQL、文件路径或原生操作。请求含 UUID commandId，修改／删除同时含 UUID id 和 baseRevision。

规范化请求加独立操作域生成 SHA256，与既有共享 `user_command_receipt` 同事务保存结果。相同 UUID 同载荷返回原结果，即使目标后来被修改或删除；相同 UUID 不同载荷拒绝。创建／更新／删除、目录修订和成功回执原子提交。提交异常后仅在数据库不处于未决事务且原回执可读时核对原结果；无法读取回执则保留异常给 Main，不猜测成功或失败。已知拒绝与结果未明分开。

Renderer 在发出 IPC 前先保存完整规范化请求到固定待核对记录，限制读取记录长度32768个 UTF-16 单位；本地记录写入失败则不发送。超时、关闭或断开后重新展开面板可重试原 UUID／原载荷；有未决操作时禁止新写请求。回执校验 commandId、动作对应空结果／定义、名称、身份和修订，再核对本地记录仍属于原请求后清除。只收到明确已保存或已拒绝结果才清除，异常继续保留原请求。

单组件用同步 flight 标记避免连击，并在退场后停止更新界面；本地已存在另一个载荷时拒绝覆盖。该记录机制没有宣称跨窗口原子锁或跨进程租约，多窗口完整协调仍属于后续范围。待核对记录损坏时只能明确清除，不能把无法读取的旧操作自动改成新 UUID。共享回执保留期／清理和应用数据备份继续沿用未完成的总体数据管理计划。
