# ADR-178：不可变内嵌 CUE 历史与原始来源导出

- 日期：2026-10-10
- 状态：0.172.0 源码接入，编译检查；数据库、媒体、界面与导出运行验收留至 MVP
- 对应：FR02、FR04、WP03、WP04、WP10、WP11；沿用 ADR-175–177 的原句柄读取与采样级编排

## 问题

外部文本 CUE 已有原文字节及解析历史。FLAC 内嵌二进制 CUESHEET 和 Vorbis CUESHEET 字段此前只在当前 `cue_document.fields_json` 中保存一次扫描结果，后续扫描可能覆盖旧编排。两类来源需要各自保留原字节、STREAMINFO、文件内位置及解析版本；不能把二进制块冒充外部 UTF-8 CUE，或将音频文件路径交给外部 CUE 重扫入口。

## 存储和扫描

schema69 增加 `embedded_cue_asset`、`embedded_cue_file`、`embedded_cue_version` 和 `embedded_cue_usage`。原始二进制块及完整原名 `CUESHEET=<正文>` 字段以 SHA-256 寻址、BLOB 去重；版本保存规范 JSON、SHA、文件身份及当时根目录／相对位置／文件大小、文件资料基线、来源种类、原 STREAMINFO／块位置／字段序号及完整解析快照。读取版本时重新核对版本摘要、资产摘要、归属和预算，再独立重解析原字节；旧二进制 parser1／2／3 标记保留，按当前严格二进制解析器核对全部字段。

已知来源的后续扫描发现两类编排均不存在时，也保存一个明确的“已无内嵌编排”版本。没有任何内嵌来源、且从未保存过历史的普通 FLAC 不创建空历史。完全相同的版本复用原身份和首次保存时间；版本返回成为当前观察时更新来源指针及修订。该模型保存内容版本，不声称记录每次扫描的完整时间线。

扫描沿用原曲库写入事务：历史观察与当前编排的 `embeddedVersion` 一起提交，原扫描失败／取消保护和外部 CUE 优先保留。容量或校验失败不会只更新当前编排而丢掉旧历史。来源指针和资产不依赖音乐文件或根目录的删除级联；文件移出后仍可在全局历史中查阅。

预算：每资产 ≤512KiB，每解析版本 ≤2MiB；原字节总量 ≤512MiB／32768 个资产，解析快照 ≤512MiB／65536 个版本，来源 ≤65536。触发器禁止更新／删除资产和版本、禁止删除来源历史；不把它们纳入封面或波形缓存淘汰。这里只是逻辑留存预算，完整物理配额和显式治理仍属架构待办。

## schema68 升级与备份兼容

普通曲库迁移前创建 `.pre-v69-*.bak`；迁移事务从仍关联现有音乐文件和根目录的旧当前文档中，校验并登记可保存的内嵌原字节，标记为 `retained-v68`，在原文档上绑定历史版本。旧源没有原字节或已被覆盖的历史无法补造。容量、损坏或外键失败使本次迁移回滚，保留原库和迁移前备份；此流程尚未运行验证。

当前普通／恢复暂停／WAL 准备连接要求 schema69。新备份和播放历史导出据实际连接报告 schema69；schema68 备份清单、预览、兼容性报告和历史导出文件头保留实际旧版本，仍可读取和独立离线核对。服务就绪凭据绑定原 `normal.manifest.schema`，不能把旧凭据改成69。

受控整库应用仍要求与本构建完整结构相同的候选。因此 schema68 备份可核对和保留，但当前暂停恢复流程明确拒绝隐式迁移；独立候选升级、升级审核及故障恢复仍需后续实现。不能声称本次已完成旧备份跨版本恢复，或内嵌历史的完整领域认证。

## 查阅与导出

播放详情的内嵌 CUE 信息、FLAC 文件操作以及扫描任务中的 CUE 历史入口均可进入独立内嵌历史弹窗；外部和内嵌来源分别展示。来源20项、版本20项键集分页，游标由当前 Library 进程 HMAC 签名，并绑定查询、来源修订或全局代次；进程重启／观察变化后需重新读取第一页。

弹窗显示当时位置、采样率／总采样、两类源摘要、采用状态和诊断，区分最近观察、当前编排记录匹配和旧版本。该匹配只证明当前曲库记录关联，不证明扫描后真实文件未变，也不证明它正在播放。文本显示前131072字符；二进制预览前128轨、每轨32个索引及总字符上限，省略数明确展示。原始字节完整保留。

导出通过可信主窗口和本机保存对话框，Renderer 只提交来源／版本身份及导出种类，不能指定路径或原文字节。四种输出：

| 类型 | 内容 |
|---|---|
| `.flaccue` | 原始 FLAC 类型5 CUESHEET payload，不含元数据块头 |
| `.vorbis-cue` | 原始完整 `CUESHEET=<正文>` 字段，保留原大小写和字节 |
| `.cue` | 从原字段移除9字节名称及等号后的正文；不重新编码或改写 FILE 名称 |
| `.json` | 两类原始字节、完整 STREAMINFO／位置／摘要／解析版本／当时来源资料；派生轨道和文本解析树不重复携带 |

JSON 是原始来源备份，不是曲库备份或当前支持的重新导入／应用命令。坏 UTF-8 原字段仍可导出，文本预览明确提示；导出的 FILE 名称可能是原镜像文件名，单独使用前需要核对音频位置。

Main 独立核对字节数、规范 base64 和 SHA；输出 ≤2MiB。保存要求应用数据目录之外的新文件，解析实际父目录后再次排除应用数据目录，`wx+` 独占创建，不覆盖已有文件。完成须 sync、原句柄回读 SHA／EOF、文件和父目录身份及原主窗口确认；全部工作受 Main 原维护请求等待范围约束。失败时保留已创建文件、提示新文件名重试；不按可能已被替换的路径删除。这里不声称跨平台强目录身份隔离、目录 fsync 或崩溃原子发布。

## 后续验收与完整范围

MVP 验收须覆盖 schema68真实升级、损坏／容量失败回滚、二进制与文本组合及来源移除、同内容去重／旧版本返回、原个人状态保留、外部来源优先、脱机／移出查阅、分页变化、保存取消／目标存在／目录替换／回读失败与四种导出逐字节真值。

本次没有执行应用、SQL／内存库／迁移、worker、真实音乐、保存对话框、驱动或测试，没有新安装包。历史复审／显式重新应用旧解释、复杂 CUE／声明静音／去加重／跨文件无缝、未决恢复继续／回滚／新进程所有权／当前 WAL、更多 Provider、标签认证、物理配额、在线／逐字歌词、任务中心、多窗口／插件／跨平台及全部 FR01–FR14、WP01–WP11、G1–G5、AC01–AC19 继续保留。仅 ASIO 实机验证搁置，用户原缺图问题仍未真实复现确认。
