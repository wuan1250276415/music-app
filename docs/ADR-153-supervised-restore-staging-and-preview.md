# ADR-153 独立恢复暂存与内容预览

状态：源码已接入，MVP运行验收待完成。日期：2026-10-09。版本：0.147.0。

## 恢复流程边界

使用可信主窗口原生文件选择打开`.auralbackup`，Renderer仅传操作UUID。Main监督独立恢复进程，接通已有完整容器校验、全新暂存、离线数据库检查及暂存内容重算。界面显示已校验备份的曲目、歌单、歌词文档、播放历史、来源版本、快照时间、资料大小及摘要。恢复预览不构造活动曲库仓储、不执行迁移、不覆盖当前曲库、原音乐或用户凭据，也不自动执行存档中的待核对命令。

准备完成仍不是整库恢复完成。恢复应用前必须再次校验暂存、完整schema/迁移与领域约束、组件/插件版本和来源权限，并捕获当前用户状态及可回滚一致快照；这些步骤继续实施。

## 私有登记与保留预算

`userData/backups/restore-operations/<operation UUID>/`独占创建，记录原生选定的来源、来源父目录身份、普通单链接文件身份/观察/大小、操作及数据父目录身份。`source.json`使用规范JSON、`wx`、完整写入和sync。资料父目录`data/`由Main独占创建，独立进程只在此父目录下新建随机恢复暂存；源备份ID与本次操作UUID分开管理。

保留最多64个操作、声明输入大小总和128GiB，开始前再次核对已有来源登记并计入中断操作。未知目录、缺失或不完整登记阻止新暂存，保留字节供后续显式处理。可用空间须至少输入文件大小加64MiB；属于观察值，不能预留其它进程的写入容量。声明输入大小是保守暂存预算，不等于实际目录字节配额或OS硬限制；暂存物理所有权、实际配额、列表/保留清理仍须继续完成。

这些登记不会出现在普通曲库备份清单中。不会按旧随机目录名自动收编工件，也不会取消后删除有疑问的工件。

## 独立处理与证明

固定utilityProcess入口、256MiB heap、有界逐序消息、最多16KiB诊断及45分钟取消意图。实际进程退出之前Main始终保留owner；kill返回、观察超时、done或ACK都不能替代exit0。取消重试kill直到实际exit，退出/重载/休眠/曲库服务丢失中断原任务；应用退出等待预算不构成通过证明。

进程先核对来源身份、观察和暂存父目录身份；第一遍校验完整容器及每文件/完成摘要，确认后才创建全新恢复子目录；第二遍同来源句柄提取并sync各文件。来源前后必须相同、目录及白名单清单完整。schema68独立DELETE日志快照的只读SQLite检查涵盖头部、页面边界、integrity、FK、来源身份及11项关键计数；不注册仓储、修复或迁移。然后再次逐文件核对暂存清单和摘要。Renderer待核对原文额外以受检查句柄读取、完整原摘要及前后观察验证，只计算条数，不执行原请求。

消息结果由严格共享契约核对，Main在实际exit0后再次核对原来源意图、来源父目录/文件证据、操作/数据父目录和暂存身份。只有此时才以`wx`＋sync生成规范`prepared.json`（绑定原清单、来源、暂存及内容预览和规范摘要），随后公开ready。路径只由Main选择和登记，不能由Renderer指定。

Main互斥阻止备份和恢复预览同时运行；失败的曲库维护占用也阻止恢复开始。预览期间不冻结活动曲库，长文件读负载对音频的影响留到MVP测量。

## 后续及运行验证

离线数据库检查不是完整schema定义、迁移校验和、所有领域不变量或插件权利认证。目录观察不提供OS排他锁，heap不提供完整OS进程资源隔离，文件sync不保证目录项断电持久性。这些证据不得直接开启活动数据替换。
