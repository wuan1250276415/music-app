# ADR-063：CUE 索引、间隙记录与独立进程读取

状态：0.58.0 源码实现；2026-10-01。schema v30，音频 IPC 1.8 不变，内部媒体协议 version 2。完整 FR01–FR14／WP01–WP11 继续保留，ASIO 实机验证仍暂停。

## 播放范围与当前能力

原解析器在下一轨存在 INDEX 00 时用该位置结束前一轨，却仍从下一轨 INDEX 01 开始播放，导致两个索引之间的文件音频没有可播放条目。本次默认把文件内的轨前音频归入前一轨：前一轨结束于下一轨 INDEX 01，下一轨从自己的 INDEX 01 开始，所有位置继续使用每秒 75 帧的整数时间基。文件首个 INDEX 01 大于零时，增加独立的隐藏／前导音频条目，覆盖文件开头到该索引；普通第一轨仍从 INDEX 01 开始。

PREGAP／POSTGAP 是编排中的声明间隙，与文件里已有音频的 INDEX 00 分开记录。本次没有向播放器插入声明静音，也没有实现间隙归属设置。详情明确显示这一限制；FLAGS PRE 只记录并提示未去加重，不把标志保存等同于已处理音频。跨文件无缝、滤波及 sample-wise 连续性仍待实现或验证，AC03 未通过。

解析器补充全部 INDEX 00–99、PREGAP／POSTGAP、FLAGS、SONGWRITER、ISRC、CATALOG、CDTEXTFILE 与 REM 原字段，保存声明顺序、行号和文件类型。CDTEXTFILE 仅记录引用，不另行打开。FILE 切换前先结束当前轨，避免丢失上个文件的最后一轨。重复文件块、重复轨号、非 AUDIO 轨、缺少 INDEX 01、索引次序错误、越过下一轨的子索引与不支持指令产生结构错误；扫描不应用该编排，保留既有记录。

最多读取 2 MiB、50000 行、每行 16384 字符、1000 个声明轨；每轨／全局原字段各限 128 项，警告限 256 条。参考 [libcue 解析语法](https://github.com/lipnitsk/libcue/blob/master/cue_parser.y)核对命令类别，本次没有复制其实现，也没有声称覆盖所有合法 CUE 变体。多文件按各自文件时间解析；重复 FILE、复杂跨文件多段编排仍需专门模型。

## 读取与媒体协议

CUE 的读取、字符解码、摘要和解析接入 ADR-062 的独立适配进程及 Windows 监督。内部媒体协议升级到 version 2，请求显式区分 tags／cue；固定入口按任务种类处理，CUE 回执包含解析结果、原始字节 SHA-256、编码、解析器版本及结束文件观察。父端校验任务身份、形状、字段、集合、数值与大小，不直接信任子进程结果。

worker 从自己持有的同一只读句柄读取，最多多读一字节检测长度变化；结束后复核句柄与授权路径。BOM UTF-16LE／BE 使用严格解码，其余先严格 UTF-8，失败再严格 GB18030。父扫描器持有另一个只读句柄，并在 worker 退出后再次核对句柄、路径与文件属性。沿用 22 秒监督墙钟、25 秒父端取消 watchdog、提交内存／CPU 上限及真实退出后释放槽的规则。未确认监督退出时停止调度，不完成扫描对账。

原始字节只用于当次解码及摘要，本次没有存储不可变 CUE 原文件版本。自动编码不等于用户确认编码；手工编码选择、原文件历史与回滚仍待实现。父端目录枚举、stat、open 与引用文件复核尚未全部硬隔离；两进程各自持有句柄，也不等于跨进程句柄转移、Windows File ID、排它租约或完整 OS 沙箱证明。

正常轨先核对引用在授权范围内、音频在当前扫描 pass 已安全读取、索引未超已知文件时长；隐藏轨只附加到已通过核对的对应普通轨，避免无有效歌曲却隐藏整个文件。既有编排出现引用警告时保留原编排；新编排可导入有效部分但标记不安全，不据此判定缺失。授权边界异常中止整次扫描。

## schema 与条目身份

v30 在 cue_document 增加当前源摘要、编码、解析器版本和全局字段；cue_track 保存可播放条目、编排与媒体文件归属、声明顺序、轨号、索引、声明间隙、隐藏标记、子索引与原字段。整数时间基受安全整数、非负和索引次序约束；触发器保护 playable_item 的 kind／file／cue_key 与记录的归属。更新在原扫描检查点事务内进行，失败一并回滚。

迁移前建立一致备份；旧编排不猜测缺失索引或编码，重扫后才补充。详情中旧记录显示重新扫描提示。旧版应用的 schema 上限保护继续生效，v13–v30 真实迁移尚未验证。

重扫只在同一编排、同一媒体文件 ID、同一轨号及隐藏状态有唯一旧活动条目时复用 ID。新增或歧义条目分配新 ID，历史 ID 不重新分配给另一轨；旧条目隐藏保留，收藏／歌单等用户引用不按新声明顺序随意移转。这改善插入或声明顺序变更的身份处理，但没有解决全部音频替换、文件改名、轨号重写与重复编排。完整内容身份、改写预览和人工确认仍待实现。CUE 范围改变会改变歌词范围身份，旧范围保存的歌词继续留在原范围，不自动套用偏移到新范围。

## 详情与验证

播放详情新增 CUE 编排信息，显示文件、编码、INDEX 00／01、PREGAP／POSTGAP、子索引、FLAGS 和当前来源摘要；隐藏／前导音频有独立提示。现有封面内嵌优先、可点击的歌手／专辑／风格检索、滚动歌词、播放模式与队列编辑保持共用路径。

本批类型检查、Main／Renderer（64 模块）／音频／凭据／媒体监督编译及发行／分发清单静态核对通过；现有相关维护与测试脚本只检查语法。未执行 CUE 解析用例、SQL、迁移、播放、封面、界面、资源或安装包验证。最新已验证安装包仍为 0.29.0，0.58.0 只交付源码。

MVP 验证需覆盖有／无 INDEX 00、首轨前导音频、多文件最后轨、全部编码、结构错误与无效引用保留、子索引越界、摘要变化、取消／超时／父退出、截断或多帧协议、v29 备份迁移／失败回滚、旧应用拒绝、重排与插入后的收藏／歌单／队列引用、范围变化后的歌词，以及真实音频逐样本边界与详情布局。

剩余能力包括声明静音生成／呈现时钟、可选间隙归属、完整多段与跨文件 CUE、FLAC 内嵌 CUESHEET、原文件历史、手工编码与改写审核、每轨文件标签回退、去加重、播放中扫描租约及跨文件无缝。完整 CUE 与 WP04 门槛仍未完成。
