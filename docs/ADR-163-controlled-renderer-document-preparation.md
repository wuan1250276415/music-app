# ADR-163 恢复时受控替换界面文档与冻结准备视图

状态：源码实现，运行验收待 MVP。日期：2026-10-10。版本：0.157.0。

## 决策与目的

在 ADR-162 的 Main 状态重建持久确认后，采用当前 WebContents 的完整本地页面重载。完整替换 JavaScript 文档使旧 React 草稿、查询、封面、歌词缓存、计时器、监听器和未完成回调随旧文档退出。仅组件重新挂载不足以清除模块缓存和旧异步操作。受保护 localStorage 原文继续遵守 ADR-161 的候选清理或原库保留结果。

此阶段仅构造只读准备视图。普通 App 不挂载，业务查询、播放和后台任务仍冻结；准备成功不能当作整库恢复完成。

## 持久顺序与当前所有者

Main 先复核同一恢复曲库实例、实际 PID、构建、维护占用、目录移动结束及 Main 状态摘要。全局 renderer-intent 持久后才调用一次当前窗口重载。意图绑定原事务、激活、hydration 摘要、完整十组状态及摘要、pending 值摘要、随机挑战和文档 token、WebContents 身份、固定本地页面 URL 和下一 documentEpoch。

Main 独立观察 did-start-navigation 的主 frame 跨文档导航、did-start-loading 的下一 epoch，以及 did-finish-load；实际 URL 必须是固定 index.html，无 query/hash。成功回执和实际观察共同写入 renderer-ready。历史记录解析严格核对原意图、状态、构建和导航身份，不能以界面声明替代 Main 的观察。

旧 frame 的授权只覆盖持久意图和受控重载。之后由 Main 验证新文档与原资源所有者；普通 IPC 仍按当前主 frame 授权。仅该一次加载免于普通导航中断；二次加载、未登记导航、超时、取消、崩溃、关闭和应用生命周期变化保留原意图及占用，不猜测重试或释放。

## 新文档协议

新增固定 renderer-seed/reply 通道。种子只返回当前严格版本化界面请求；没有活动恢复返回 null。读取失败时显示只读失败视图，不能回落到普通 App。

新文档先初始化维护客户端，再取得种子。准备视图在实际挂载后用 WebCrypto 核对完整恢复快照与受保护 pending 值，生成新的文档 UUID，并核对本构建、原事务、挑战、token 和请求摘要。下一事件循环再次观察视图连接及 pending 不变，再回复。使用事件循环而非 animation frame，避免最小化窗口无限等待。Main 等待 load 完成、验证回执和当前文档，只接受完全相同的重复回执。

准备视图显示已核对队列数量、循环/随机模式和输出方式。没有普通 App 副作用、数据库业务读取、设备查询或资源释放入口。

## 记录预算

共享全局链记录上限从 32 调整为 48，加载和追加使用同一常量。当前最长路径从 29 增至 31 条，后续终态与分阶段释放需要余量。单帧 3 MiB、累计 64 MiB、保留 64 个事务的既有边界保持；这不代表物理配额清理已经实现。
