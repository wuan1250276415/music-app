# ADR-023：播放队列命令的修订检查与重放

状态：0.18.0 进程内契约和桌面回归通过；跨进程恢复、多窗口界面仍待验收。

## 决策

Renderer 发起会修改队列的播放、跳转、上一首、下一首、循环、随机、移除和重排操作时，附带随机 `commandId` 与所见的 `baseRevision`。Main 在单一串行队列中先比较修订，再执行动作；旧版本命令拒绝，Renderer 重新读取队列，用户可基于新状态重新操作。自动播放结束和 CUE 边界仍在同一串行队列中修改修订，因此客户端不能越过这些变化。

Main 为命令 ID 保存进程内回执。同一 ID、相同操作和参数的并发请求共享同一个 Promise，完成后重放同一成功结果或错误；同一 ID 试图执行另一操作会拒绝。最多保留 512 条记录，优先淘汰已完成记录，不丢弃进行中的命令。每个窗口的命令 ID 由 Renderer 生成，Main 仍负责校验输入。音频 Host 的 command ID 与队列命令 ID 各处在自己的边界，不互相替代。

测试所用的独立 `userData` 必须在申请 Electron 单实例锁之前设置；这样已运行的安装版不会使隔离测试版误判为第二实例。生产模式仍使用原单实例策略。

## 验证与未完成项

单元测试模拟两个客户端持有相同修订：重复“下一首”只前进一次；两个不同 ID 竞争时，后一条旧修订命令在副作用前拒绝；刷新并使用新 ID 可继续；失败命令重放不重复写入。Electron 回归通过真实 preload/Main IPC 验证重复循环模式命令与旧修订拒绝，并在已有安装版进程运行时使用隔离目录启动测试版。

回执只保留在当前 Main 进程内，超过 512 条的历史 ID 可被淘汰；进程崩溃后的重放恢复与完整多窗口界面尚未实施。0.19.0 起数据库写入失败后的状态对账见 [ADR-024](ADR-024-queue-durable-commit.md)；本 ADR 不代表 WP01 全部完成或 WP06 验收。
