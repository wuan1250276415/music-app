# ADR-226：不可变恢复尝试与中断续办 MVP

日期：2026-10-16；源码0.220.0，schema80。完整FR01–14／WP01–11／G1–5／AC01–19继续，FR12／AC12未完成。

## 设计与实现

原恢复表把一次任务限制为一次恢复，恢复在已移走目标、尚未放回来源的阶段中断后无法再执行。现在每次续办创建独立尝试，关联前次尝试、最新六工件核对与原提交。每个任务只有一个根尝试，每次尝试最多一个后继；首次及最多15次接续形成固定上限的链。每次接续保留原读取所有者并递增数据库租约修订，旧请求不能操作新的尝试。

续办冻结绑定使用版本2，保存前次日志的完整摘要、修订、核对身份与租约链；旧版本1绑定继续可读。原提交、音频来源、备份、权限存档及目录授权仍保持原约束。先重读前次完整日志，再独立检查六个现有工件和四个可操作路径，之后才创建新的原生恢复。新副本与被移走目标使用新UUID名称，不重用、覆盖或删除前次名称，因此完整或部分旧副本均可保留。原路径已经恢复时走独立重新解析，不重复移动文件。

Main／preload／Service新增续办及停止调用，Main校验封闭请求并核对可信页面；Library继续校验当前修订、权限、前次记录、工件和静态证书。界面增加明确确认、按来源选择续办、同命令核对重试、停止按钮及有界完整尝试历史。静态恢复目录仍为空，未通过环境变量或普通IPC放行正式恢复。

## 结构升级

schema79→80为恢复父表去除单次恢复限制，增加前次尝试、续办核对和次数字段；保持原表名、原列值及所有子表外键。升级遵循[SQLite官方表结构重建流程](https://www.sqlite.org/lang_altertable.html#making_other_kinds_of_table_schema_changes)：确认已知旧父表结构，保存依赖对象，事务外暂时关闭外键，事务内创建新表、复制原列、重建索引和触发器，再核对完整性、外键及业务计数；失败回滚，finally恢复外键。已有额外索引／触发器也保留，不使用writable_schema。升级前仍生成已同步并独立核对的原库快照。

当前备份及恢复暂停连接、历史导出使用schema80；旧68–79的清单和导出记录继续可读，完整整库应用仍要求明确迁移到当前结构。结构版本变化未变更媒体16或音频IPC1.23。

## 验证

协调链27项包含原0.219的13项，以及：

- 旧文件／备份两种模式各六个阶段实际拒绝SQLite回执，文件日志已同步、数据库回滚；数据库关闭重开后重新核对。前四阶段通过新尝试完成恢复，后两阶段独立重新解析已恢复来源，原音频与曲库可用状态一致。
- 已移走目标、原路径明确缺失时继续恢复，前次目标与副本逐字保留。
- 明确构造16字节部分副本夹具，独立检查发现copy-unconfirmed；使用新名称完成备份恢复并保留部分副本。该夹具不能当作真实复制中途进程终止或满盘证明。
- 连续两次恢复中断、每次数据库重开后第三次完成；三个尝试、递增租约、前次中断状态及全部工件历史保留。

实际旧schema79的已完成恢复数据库副本升级4项通过：全部原列与回执／核对／重新解析／释放记录不变；升级前快照保持原79结构；结构重建并恢复依赖触发器后注入验证失败，完整回滚原表与数据、版本不变且外键重新启用；原旧版夹具字节不变。

当前实际Electron暂存／恢复9项回归通过。识别映射8、定点重试16、工作清单18、后台识别23及历史schema72迁移4项通过，覆盖schema80的独立备份和十一域检查。四个识别／清单套件因记录变量设置错误，只保存了真实终端输出和退出码，摘要从最后的JSON输出提取，不冒充套件的完整结构化报告。历史迁移保留了完整4项报告。

应用构建、Main／Renderer类型检查、发行与分发清单通过。生产原生文件逐项核对与0.219检查点一致，候选编译组件沿用此前专属根限定的事务；本轮没有重编译生产原生或打包。

## 边界与后续

协调链仍使用隔离生成音频、真实监督／原生程序、真实SQLite与候选认证目录。新Main／preload／界面入口为源代码和构建证据，实际认证按钮尚未完成端到端验证；桌面9项验证的是已有暂存恢复流程。数据库关闭重开与SQLite故障不能替代Main硬崩溃、物理断电、满盘及完整权限／并发矩阵。

尚未冻结绑定或日志不可确认的准备阶段中断继续保留工件并拒绝盲目续办；次数上限后的处理、完整保留清理、正式认证激活、MP3／批量及其余架构工作继续。最新试用安装包仍0.215.0，未新增安装、签名或硬件验收；仅ASIO实机验证暂停。
