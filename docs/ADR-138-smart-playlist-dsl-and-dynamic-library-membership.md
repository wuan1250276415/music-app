# ADR-138 智能歌单规则与动态曲库成员

日期：2026-10-06。状态：0.132.0 源码实施，SQL／迁移、真值、故障、性能及界面运行验收留到 MVP。对应架构 §9数据模型／§10浏览检索、FR04／FR05／FR07、WP05／WP06。完整音乐库、检索和播放功能尚未验收。

## 规则与存储

智能歌单保存 version1 SmartPlaylistDefinition，query为现有严格白名单 BrowseQuery，包含浏览范围、实体／文件夹选择、艺人角色、风格交并集与下级、检索词、组合源音频／年份／个人状态条件、排序和版本折叠。拒绝歌单范围，因此没有嵌套引用、递归规则或循环依赖；不保存任意SQL，不保存固定曲目ID清单。

schema62将playlist.kind扩展为static／smart并增加filter_json。静态歌单必须没有规则，智能歌单必须有有效JSON；应用读取时再次严格校验规则版本与字段。歌单类型不可转换，智能歌单不能插入或转入固定playlist_item。静态接口仅读取static，继续使用原有entry UUID、重复条目和position。

创建／更新／删除以UUID命令和基础revision执行，事务冻结规范化请求指纹，沿用user_command_receipt的全局命令身份。相同命令回读原结果，不重复创建；同命令不同请求拒绝。创建修订0，更新／删除推进修订；playlist_smart_history保存不可修改／删除的名称与完整规则历史，删除歌单仍保留历史和原操作回执，不删除音乐、个人资料或已提交播放队列。

## 共用查询计划

原Library.list的参数化范围、直接／中文／拼音／英文错拼、组合条件及折叠逻辑提取为libraryQueryPlan。普通曲库继续使用同一计划与字段；智能歌单先由保存规则生成无分页的成员子查询，再将p.id IN子查询加入当前浏览计划。不把全库结果物化到JavaScript或Renderer，不为成员生成虚构的playlist_entry_id。

智能歌单最终只包含可见、正常收录的曲目。文件离线仍可列出，除非保存了“可用”条件；忽略／隐藏条目不自动进入智能歌单。规则中的收藏范围不会绕过这个要求。保存版本折叠时先在规则范围内选择文件版本；智能歌单内不再擅自改变折叠选择或手工排序。

当前歌单内的搜索与组合筛选是附加约束，与保存规则按AND组合，不能扩大原成员范围。未追加搜索词时沿用规则检索词与匹配理由；追加搜索词时按附加词显示直接／近似匹配。英文纠错沿用现有300词／条目上限，因此这不是无限召回；追加约束在已定义的规则成员中继续筛选。

规则排序决定动态播放次序，recent默认加入时间降序，其他默认专辑／碟轨；显式自然名称、艺人、专辑、部分发行日期和加入时间方向保持。搜索直接命中仍先于近似结果。总数、分页和按当前结果播放均使用同一计划，动态歌单不通过静态条目播放接口，也不伪造重复条目身份。

## 修订与分页

智能歌单目录仅返回名称／身份／revision／时间，每页50项，按自然名称和ID稳定排列；定义单独按ID读取，不为目录逐个计算歌曲数量。目录支持快照、翻页、刷新及迟到响应隔离，无256歌单总量截断。进入智能歌单后曲目列表给出当前匹配总数。

playlist及playlist_smart_history纳入原BrowseClock。全部浏览快照保守包含派生content_revision，以覆盖原请求没有搜索词但智能规则内部使用拼音／错拼的情况。规则修改、收藏评分／资料变化、补建或扫描会使旧分页及旧按位置播放请求失效；Main既有browsePlayContext再核对当前项／全范围及快照，队列保留当次已确认范围，后续成员变化不偷偷改写正在播放的队列。

## 桌面与原操作核对

曲库工具栏增加“保存为智能歌单”；歌单页加入分页智能歌单目录与创建入口。打开歌单读取当前定义，编辑面板支持名称、保持原范围或改全曲库、检索词、复用组合筛选、六种排序／方向和版本折叠。规则编辑按需加载；使用现有焦点进入、Tab循环、Esc及窄窗口规则，危险操作有明确删除按钮。艺人／发行／风格ID是保存范围，不显示为底层文件实现细节。

编辑期间保留读取时的revision，冲突拒绝后可重新读取规则。保存先将规范化原请求存入当前Renderer本地存储，再发送一次操作；单飞闸门避免重复点击生成两个请求。成功或已证明没有提交的拒绝清除待核对记录；通信／回执不明时保留完整原请求，禁止改字段后盲目再次提交，可关闭后或重启再以原UUID重试。恢复请求不能误用于当前另一个歌单；删除回调只清除实际被删除的当前选择。

服务返回saved／rejected的结构化结果：数据库异常时先确认无未结束事务并回读匹配命令回执，已提交则返回原结果；能够读取且无匹配成功回执才报告拒绝，无法核对则仍传播异常。Renderer严格读取分页、资料和操作响应，回执目标不符不宣称成功。无效本地记录需用户在界面核对现有歌单后显式清除；本地记录不是数据库备份或跨窗口协调协议，持久业务证据以数据库历史／回执为准。

## 迁移与边界

旧库先保存pre-v62一致快照，事务复制playlist和playlist_item至新父子表，保留全部静态名称、revision、时间、entry_id、item_id和position；先移除旧子表再父表，重命名新父子表、重建引用索引和约束，foreign_key_check通过后提高user_version62。user_command_receipt保留。这里是迁移源码设计，本批没有执行迁移，不能当作保留数据已实测。

历史测试退回链同步父子表结构，仅允许没有智能歌单及智能历史的fixture退回schema61；拒绝把有业务历史的库悄悄降级或丢掉智能数据。四处当前版本断言同步到62，未新增或运行单元测试。
