# ADR-066：随应用提供 WebP 封面解码与缩略图算法兼容

状态：0.61.0 源码实现；2026-10-01。schema v32；音频 IPC 1.8、内部媒体协议 3 不变。FR01–FR14、WP01–WP11 与未通过的验收门槛继续保留，ASIO 实机验证仍暂停。

## 解码与图片策略

ADR-064 的 WebP 路径依赖系统注册的 WIC codec，无法提供稳定的安装环境兼容性。本次固定 libwebp 1.6.0 官方发布源码，MSVC x64 静态编译 decoder 与 demux，链接到已有媒体监督／图片转换程序；不增加可搜索 DLL、外部解码路径、编码工具或网络能力。WebP RIFF 头在 WIC 创建解码器之前分流，JPEG／PNG／GIF／BMP 继续走系统 WIC。

静态 WebP 用 WebPGetFeatures 先检查尺寸，再通过有界 BGRA 外部缓冲和解码器缩放选项生成最大边 256／1024 的图片。动画 WebP 使用 WebPAnimDecoder 的首个合成画布帧，处理画布背景及帧位置，避免把第一个局部矩形误当整张封面；之后统一进入 WIC 缩略图转换。动画只取首个展示帧，不持续播放；GIF 仍沿用 WIC 第一帧路径，未声称已经补齐 GIF 画布编排。

所有路径将目标尺寸转换为直通 alpha 的 BGRA，用整数公式将透明度合成到固定背景 #10131a，再输出 JPEG。这样透明 PNG／WebP 不依赖隐含黑底行为。背景是该算法版本的固定参数，未来换背景必须更新算法。EXIF 方向、ICC／颜色转换、HDR 与完整多帧格式策略尚未实现；当前不能宣称色彩准确。

原有 16 MiB 压缩图、每边 8192、32 Mi 像素、2 MiB 输出、单任务 CPU／墙钟与 Job 提交内存上限继续生效。静态 WebP 输出缓冲最多 4 MiB；动画合成需要完整画布及解码内部缓冲，极大但尺寸合法的动画可能因进程 384 MiB／Job 512 MiB 预算失败，随后尝试其他候选。尺寸允许不代表所有此尺寸图片都保证解码成功。仍不把 Job、白名单或哈希称作完整 OS 沙箱。

内嵌正面封面优先、其他内嵌图片及同名／目录图片回退、Renderer 拒绝 token、源文件观察复核、可见租约和受控图片 URI 沿用 ADR-061、064、065，WebP 不改变候选优先级。

## 持久缓存与兼容

新生成缩略图记录算法 wic-webp-jpeg-v2。旧 wic-jpeg-v1 JPEG 经原有长度、头部和 SHA-256 校验后仍可被离线／普通失败回退及已授权资源读取使用；文件在线时只有新算法且观察匹配的缓存直接命中，旧图会重新转换。无法转换时保留旧图并提示旧缓存，避免升级即丢失离线图片。未知算法继续失效处理。

资产 ID 仍为规范 JPEG 字节 SHA-256；若新旧转换输出相同，更新算法声明而不重复存储。旧缓存不批量重写，不将旧算法图片谎报为已运行新算法。选择、文件归属与租约仍按原事务模型处理。

schema v32 仅增加版本兼容边界，保持三张表结构和现有资产：v31 应用只接受旧算法，必须拒绝打开新版数据库，避免将 v2 图片当损坏数据删除。迁移先 VACUUM INTO 一致备份，再事务更新 user_version；v31 创建表步骤加入条件分支。Main 初始化等待上限从 15 秒调整为 180 秒，为含缓存的备份留出时间，这不是任何磁盘上的完成时限保证，也没有实际大库时间证据。真实升级失败／备份容量、耗时与恢复仍需 MVP 验证。

历史测试辅助脚本回退 v32 时清空可派生图片缓存再设 v31，不伪造算法；保留曲库领域数据。此辅助脚本仅用于旧 schema 测试构造，不是生产降级工具。本批未执行 SQL、迁移或测试。

## 验证边界

类型、Main／Renderer（64 模块）／原生及 WebP 静态库编译、发行／分发清单与有关脚本语法静态检查通过。未执行任何图片解码、界面、SQLite／迁移、重启／离线、音频、负载或安装包测试，集中到 MVP；最新已验证安装包仍为 0.29.0。

MVP 必须覆盖静态有损／无损 WebP、透明背景／尺寸／纵横比例、动画首帧局部位置与合成背景、损坏／截断／伪头／超大图、预算内回退／取消／退出确认、JPEG／PNG／GIF／BMP 回归、原 metadata 封面优先与详情切歌、v1 离线读取／在线重生成／失败保留、相同字节去重、未知算法／损坏失效、v31 备份升级／旧应用拒绝／恢复、大 BLOB 备份耗时，以及实际安装包中的解码器、源码和许可核对。

FR04 与 WP04 尚未验收；方向／颜色、完整媒体隔离、文件身份／授权撤销、磁盘配额／管理 UI、Provider 封面授权与保留清理、跨平台与多窗口继续开发。
