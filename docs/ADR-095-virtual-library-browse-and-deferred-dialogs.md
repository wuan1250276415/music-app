# ADR-095：虚拟曲目浏览、快照分页与按需弹窗

日期：2026-10-02。状态：0.90.0 源码实现；运行与性能验收待 MVP。

## 问题与范围

架构 §19 和 WP05 要求大库采用虚拟列表。原界面每次读取 50 项并累积到数组，逐项建立 DOM；加载到 500 项以上时还可能超过既有播放上下文的 500 项限制。0.89 界面主脚本约 516 kB，许多管理弹窗即使没有打开也在初始模块中。

本批次接入全结果范围的虚拟曲目列表、有界分页缓存、跨页变化保护和按需管理弹窗。不是十万库性能或 AC01／AC09 通过的证明。封面网格／密度、分类索引的大库分页、完整拼音／排序筛选、全局文案资源化和其余架构范围继续保留。

## 查询快照与服务

新增版本 1 的 `BrowseQuery`／`BrowseRequest`／`BrowseResponse`，旧 `list` 接口供其他现有视图使用。参数严格校验视图、角色、文本长度、风格组合、对齐偏移和摘要；Main 仅接受当前主窗口主 frame。每页 100 项，服务返回总数、偏移和查询绑定的 SHA-256 快照。

`BrowseClock` 在曲库连接中延迟建立 TEMP 计数表及 AFTER INSERT／UPDATE／DELETE 触发器。安装过程用 SAVEPOINT，失败完整回退；只接受受限制的领域表名，并核对必要表。追踪音乐文件／可播放条目／CUE／搜索短字、曲库身份／关联、个人状态／歌单、元数据／来源／外部引用等当前领域表。TEMP 触发器明确附着 `main`；计数与领域事务一起提交或回滚，能观察到扫描写入，即使 UI 的合并通知尚未发送。封面、波形、歌词、窗口／音频设置和队列保存不属于这个浏览计数。新增领域表时必须重新审查匹配清单。

快照还绑定随机连接 epoch、同连接 `PRAGMA main.data_version` 和规范查询。服务重启使旧快照失效，外部连接提交也使其失效；不支持绕过应用直接编辑运行中的数据库。TEMP 数据不改变磁盘 schema，仍为 v38。同步页读取前后核对快照；不同页不是长期持有的数据库读事务或冻结历史，变化时明确返回 `stale`，不能混用前后两套结果。

## Renderer 与虚拟行

`useLibraryBrowse` 最多一个正在读取的请求，查询变化后的旧回执丢弃；最新可见范围替代旧的未读取范围，不无限积累滚动请求。每页 100 项、最多 5 页／500 个曲目对象，按最近使用淘汰；优先保护可见页和聚焦页。点击批量选择仍最多 100 项。队列、当前资料和用户已选条目的既有独立状态不计入分页缓存，完整整窗内存仍需测量。

同一查询的曲库修订重读保留总数估计和当前范围，直到取得新快照；新查询从首屏开始。无法确认的分页错误停止自动读取，可显式刷新。一个查询修订内快照失效 3 次后暂停，避免持续变化时无限重读；用户刷新或新的查询修订重置该预算。没有假定取消 Renderer 等于已终止服务内的同步 SQL。

`VirtualLibrary` 使用 76 DIP 固定行高、5 行超扫、最多 100 个附近行及 1 个额外聚焦行。整个结果提供滚动高度，只创建附近 DOM，远处图片组件卸载，继续沿用封面可见租约。单行内容省略／局部操作横向滚动，避免长文本改变定位。ResizeObserver 与动画帧合并滚动测量；新查询重新定位，缩减结果裁剪滚动位置。提供序号跳转、视口 Home／End／上下／PageUp／PageDown、原生按钮和输入键盘行为、list／listitem、位置和总数描述。聚焦在已加载行时保护其页并保留额外 DOM；修订后控件焦点和屏幕阅读器连续浏览仍待实际验收。超过浏览器滚动尺寸范围的超大库需进一步分段，当前十万目标不能由这份代码推导性能已达标。

## 播放范围

普通浏览点击通过独立 `playBrowse` 读取服务端当前顺序的连续上下文，从所选曲目所在 100 项分组开始，最多 500 项；确认快照和所选绝对位置后才进入既有 Playback API。点击曲目仍是起播位置，前面的分组条目只提供上一首和循环上下文，不自动先播放它们。UI 明示最多 500 首，这保留既有队列预算；没有把所有十万项传入 Renderer 或播放请求。上下文已独立复制，后续缓存淘汰不会改变当前队列。更多曲目的队列延续／持久查询队列仍需另行实现，未缩小完整目标。

Main 在等待上下文期间核对音频操作 token、休眠、退出和回执，再交给队列修订／串行操作处理；停止优先，过期查询不自动起播。歌单继续使用已有 entry ID、歌单修订与重复条目播放接口。显式文件版本选择保持原处理，并裁剪到既有 500 项预算；其查询范围完整重绑定仍是后续项。

## 按需界面组件

20 个管理弹窗使用动态 import，公共焦点／Tab／Escape 从 `catalog-dialog` 抽为轻量 `dialog-focus`，避免其他模块因焦点函数把整个整理页带入初始模块。包装组件在模块级建立稳定类型；加载中的可关闭原生风格页面、独立 Suspense 和局部错误边界不替换整个音乐库／播放器。显式重新尝试才建立新的 lazy 类型；加载或显示失败不会自动重放保存。已提交但未确认的编辑仍需使用现有回读／修订记录核对。

构建产物的初始 JS 主块约 358 kB，20 个组件分在 18 个弹窗模块中；不是整包大小下降，也不是已测启动或内存改善。动态模块／样式在打包的 file 页面和 CSP 下实际载入待 MVP。

## 验证与后续

仅做类型检查、Main／界面构建、全部原生编译、发行／分发清单和 41 个 CommonJS 源文件语法核对。没有执行数据库／TEMP 触发器／迁移、Electron、歌曲／图片解码、音频、Provider、安装器或 gold EXE。IPC 1.19／schema v38／媒体协议 6／系统媒体协议 1 不变；最新已验证安装包仍 0.29.0。

MVP 需集中测一万／十万库首屏和远距跳转，页缓存与 DOM／资源峰值，扫描期间跨页变化、事务回滚和外部提交，搜索快速切换和迟到回执，重复歌单、折叠版本、播放顺序及停止／休眠交错，低高度／缩放／跨屏和键盘／屏幕阅读器焦点，以及弹窗载入失败、样式、关闭、嵌套、保存未知结果和安装包离线模块路径。OFFSET／COUNT 的深页查询开销、快照触发器扫描开销、初始包性能均必须量化，不能用类型或编译成功代替。
