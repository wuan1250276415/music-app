# ADR-096：分类分页、封面浏览与显示设置

日期：2026-10-02。状态：0.91.0 源码实现；运行与性能验收待 MVP。

## 问题与范围

架构 §19／WP05 要求分类视图和可切换密度的封面网格。此前歌手、专辑、专辑概念使用旧 `facets` 接口，其 SQL 最多返回 200 项；界面没有分页入口，数量也只是这一批返回项，不能代表完整收藏。

本次三个主分类入口改为完整结果范围的分页浏览，提供封面／列表、紧凑／舒适／宽松密度、分类内子串搜索、名称／文件版本数量排序，专辑另有发行日期排序。点击分类仍以实体 ID 筛选下方曲目；同名身份不会仅因名字相同而合并。上方全局歌曲搜索和分类内搜索分别保持自己的条件。旧 `facets` 接口保留兼容，主分类入口不再调用它。

此批次不关闭 FR04／FR05、WP05 或十万库性能门槛；完整拼音、首字母、英文错拼、组合检索和排序、智能歌单、查询队列延续及跨平台范围继续。

## 分类数据与计数

新增严格版本 1 的 `CatalogBrowseQuery/Request/Response`，固定视图、署名角色、排序和长度；偏移按 60 项对齐，快照为查询绑定摘要。Main 只接受本应用主窗口的主 frame，库服务再验证参数。SQL 中的实体、联表和排序来自固定分支，搜索与分页值均绑定参数。

歌手沿用人工来源身份绑定、作品署名角色和已确认录音署名的既有规则；专辑按 `release.id`，专辑概念按 `release_group.id`。只统计可见 `playable_item`，来源身份、重复署名、不同文件版本不会使同一发行曲目重复计数。聚合分别返回：

- `trackCount`：不同发行曲目 `release_track.id` 数量。跨发行重复录音仍是不同发行曲目；不是录音身份数量。
- `fileCount`：不同可播放条目／文件版本数量；CUE 每段各为一个可播放版本，不是不同物理媒体文件数量。
- `releaseCount/discCount`：不同发行／介质身份数量，不由最大碟号推算。
- `availableCount`：文件被曲库观察为在线且根目录未标为离线的可播放版本数；不代表设备、格式或音频实机认证。
- `formats`：来源编码去重排序，最多 32 项；界面显示前 4 项。

专辑卡片显示已保存的专辑艺人、日期、版本、国家、厂牌和目录号。日期排序当前按已保存日期文本、未知日期在后；标签中的非规范日期和完整精度排序留待后续与 MVP。名称按现有 SQLite NOCASE／ID 稳定排序，尚未实现完整自然序／中文拼音排序。

分类搜索按 NFKC、大小写及边缘空白归一化后的子串匹配名称、区分说明、专辑艺人、版本和目录号。歌手额外检索同一身份已绑定来源的名称／排序名，不自动把相同名称当作别名关系。连接注册的确定性 SQLite 函数只做文本匹配，不写入数据或访问文件。这不是拼音或错拼检索。

## 封面来源

每个分类选择一个真实代表条目：在线条目优先，再按稳定条目 ID；没有在线条目时保留离线代表。只批量读取本页至多 60 个代表的既有 `LibraryItem`，不把全部成员交给 Renderer，也不拼接不同版本的位深／采样率来声称某个文件的音质。

卡片复用现有 `Artwork`／监督读取、持久缩略图和资源租约。单条目的来源顺序保持内嵌正面封面、其他内嵌图片、同名／目录侧车封面；损坏候选使用既有有限恢复。歌手卡片明确标注来自代表作品的专辑封面，未声称是艺人照片。代表文件没有封面时显示已有占位图，不自动扫描全部成员寻找“最佳”封面。离线缓存、内嵌图片、重读及真实 UI 显示仍需 MVP 验证。

播放栏封面入口、独立当前歌曲资料、可点击专辑／歌手／风格检索、大封面、滚动歌词、播放模式和队列编辑保留；当前歌曲资料不依赖分类缓存。

## 快照、缓存与可见网格

复用 ADR-095 的曲库连接 epoch、TEMP 领域事务计数及外部提交观察，加入规范分类查询和独立命名空间。页读取前后比较快照，变化返回 `stale`。设置／封面缓存不使分类失效；扫描和身份／元数据改变会使旧页失效。没有持有长时冻结读事务，也没有宣称取消 Renderer 已取消同步 SQL。

原曲目浏览引擎抽为泛型 `useSnapshotPages`，曲目保留 100 项页／5 页缓存，分类为 60 项页／5 页即最多 300 个分类对象及各自代表资料。每个浏览器实例只有一个正在读取的页请求，新查询／修订和旧回执隔离；查询 key 也在范围、条目和选择回调中复核。手动刷新替换只读浏览会话，刷新前正在读取的旧回执丢弃，完成后才串行读取新页；组件卸载同时关闭当前会话。可见页与聚焦页受保护，缓存按使用时间淘汰，持续失效 3 次暂停，明确刷新后再读。两个独立浏览器的缓存预算不是整个窗口或库服务内存上限。

网格用固定卡片高度和按视口宽度计算的 1–8 列，只创建最多 120 个附近项及一个额外聚焦项；列表单列。完整结果提供滚动空间，封面仅随附近组件建立可见租约。密度／宽度改变时尽量保留首个可见序号，缩减结果裁剪位置。新分类查询重新定位；同查询修订保留当前范围估计。

提供序号跳转、方向键、Home／End／PageUp／PageDown、list／listitem 的总数和位置、原生按钮名称和选中状态。远距跳转先聚焦视口，页返回后把焦点交给目标卡片；离开网格清除聚焦保护。真实 Tab 顺序、跨页焦点、屏幕阅读器和低高度／缩放／强制颜色需 MVP 验收。超大结果仍受浏览器滚动高度限制。

## 显示设置与未知结果

新增独立 `catalog_view_preference`，使用现有 `app_setting`，不改变 schema v38。内容为版本 1、单调修订、布局和密度；缺失时只读默认封面／舒适，不自动写默认值。三个分类共享偏好。

保存同时携带已观察值与下一修订，库事务做完整 CAS；相同下一值返回已保存结果，冲突要求回读。Renderer 每次只有一个设置操作，收到确认才应用新布局。保存报错只读当前值；无法确认时保留原布局、禁止继续保存，用户重新读取核对。没有根据超时猜测成功或自动重放写入。组件卸载后旧回执不更新新页面，下一次进入重新读持久设置。

## 验证与待办

本批次保留类型／Main／Renderer／原生编译、发行与分发清单以及 CommonJS 源文件语法静态核对；最终结果记入实施状态。未执行 SQL／迁移、Electron、音乐／封面／歌词、Provider、音频、安装器或 gold EXE。IPC 1.19／schema v38／媒体协议 6／系统媒体协议 1 不变；最新已验证安装包仍 0.29.0。

MVP 集中验证超过 200 个分类、同名艺人与角色、来源别名、重复署名／多版本／CUE／多碟／多发行计数、离线根目录、内嵌图片优先、远距跳转和密度保存／冲突／未知结果、扫描更新与服务重启、窄屏／缩放／键盘。COUNT／GROUP BY／OFFSET 及逐分类字符串匹配会遍历聚合结果，深页、持续扫描和一万／十万库开销仍需量化；必要时建立可重建分类索引／后台投影，不能用前端缓存证明性能达标。
