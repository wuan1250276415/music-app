# ADR-109：ASIO 驱动观察与持久配置

日期：2026-10-03；源码版本 0.103.0；状态：源码实现，运行验收集中到 MVP。

## 范围与结果

按架构 FR09／WP06，将 ADR-108 的真实 ASIO 原生模块接入 Main、Library Service、Preload 和输出设置界面，完成驱动选择前的观察与持久配置。实际歌曲播放仍走原 WASAPI 私有 IPC。本批不把保存首选 ASIO 驱动解释为已经切换播放后端。

只有 ASIO 实机验证按用户要求搁置，ASIO 开发、DSD Native／DoP 和其他架构功能仍在目标内。不得以这些配置入口或编译成功宣布 FR09／G2–G4 完成。

## 驱动目录与能力观察

- `--asio-catalog <nonce> <parent>` 只读取 HKLM 64 位 ASIO 注册目录，沿用最多 1024 注册项、256 返回驱动的预算，保留注册读取状态、跳过数及截断标识。不加载驱动 DLL，也不把 32 位注册当作可用 x64 驱动。
- `--asio-info <nonce> <parent> <registryName> <canonicalCLSID>` 在一次性原生进程初始化明确选择的驱动。`Engine::open` 在加载前重新核对完整注册名称与规范 CLSID，不接收任意 DLL 路径或 ProgID。
- `Engine::inspect` 在未准备缓冲的拥有者 STA 上查询驱动名称、版本、输入／输出总数、前 256 个输出声道及 PCM 容器布局、缓冲范围／首选／步长、当前采样率、I/O 模式与可选延迟。输入／输出数上限各 4096；完整输出映射最多 16 源声道，不能保存未观察或非 PCM 的输出。
- 观察不会调用 `setSampleRate`、`setIoFormat`、`createBuffers`、`start`、`outputReady`，没有渲染目标，也不打开音乐文件。初始化驱动本身可能占用设备，因此必须由用户明确点击能力读取，先停止播放，并等应用原有音频进程确认释放。
- 采样率和延迟查询失败分别返回 null；旧驱动不报告 I/O 模式返回 unreported。未知或查询失败的 I/O 模式阻止保存该 PCM 配置；DSD 模式与非 PCM 声道会显式显示，不能推导 Native／DoP 支持。当前采样率并不证明驱动接受其他歌曲的采样率。
- 能力信息只是初始化驱动报告，`buffersCreated/playbackStarted/hardwareVerified` 固定 false。真正播放前仍须重新核对实际源格式、声道映射、I/O 模式及 createBuffers 后的布局，不能将本报告当作正式播放计划。

## 有界查询与输出所有权

查询走独立版本 1 的四字节长度前缀 JSON 回执，而不复用音乐播放会话。Main 核对操作、nonce、当前 native build ID、x64 架构及对象字段／类型／声道连续索引；PCM 类型的大小端、容器、有效位和对齐也须与 SDK 类型枚举一致。单次 stdout 总预算 256 KiB＋4，stderr 16 KiB；只接受一帧。注册目录 10 秒、初始化观察 25 秒观察期限，超时终止子进程，再等待最多 2.5 秒确认退出。

只有驱动 clean close 成功后，原生端才能写出成功能力回执；Main 仍须等待子进程 close 后才发布。旧查询进程未确认退出时，阻止再次查询；若其加载了驱动，还阻止新音乐播放及 WASAPI 能力查询。超时不是退出证明，保留进程句柄直到 close。父进程存活监督沿用 ParentWatch；父进程死亡时原生进程自行终止。

同一驱动的在途观察合并，不同驱动在单项观察结束前拒绝新增，不累积观察队列。查询进入 PlaybackCoordinator 的串行队列，拒绝 playing／paused／preparing 和尚未释放的音频宿主。AudioController 在播放开始及旧宿主释放后再次检查 ASIO 查询进程所有权；WASAPI 能力观察与 ASIO 初始化观察互斥。休眠／退出取消查询、递增本地观察代次并丢弃晚回执；设备通知修订变化也丢弃能力报告。单条能力缓存用单调时钟保存 60 秒，并绑定完整驱动身份和设备修订。

此门禁覆盖当前应用中的查询和播放入口，不证明系统内其他应用释放了声卡，也不是 ASIO 实时调度／驱动稳定性验收。注册身份重新读取不证明相同 CLSID 下的驱动文件或设备没有改变；正式播放仍须重新准备与校验。

## 配置契约与持久化

`AsioOutputPreference` 独立于现有 WASAPI `AudioOutputPreference`，包含：修订、首选注册身份快照、按源声道顺序的唯一输出索引、缓冲帧数、是否明确允许 PCM 数值精度转换。缓冲 0 表示实际准备时选择驱动首选；自选 1–32768 帧必须符合驱动范围、固定大小、首选-only、步长或 minimum 的二次幂倍数规则。不能自动补选／复制／混音；配置声道数量与实际歌曲解码声道数量的匹配属于后续正式播放准备。

允许转换仅授权 PCM 位宽／整数浮点精度转换，不授权 SRC、DSP、混音或 DSD 转换。它不证明 bit-perfect，转换算法与数值边界仍由 ADR-108 定义。清除驱动必须同时清空声道、缓冲和转换授权。

schema v44 在迁移前按原有机制创建 v44 备份，事务内新增 `asio_output_setting` 和 `asio_output_change`；用户原 WASAPI 设置、CUE 策略及媒体记录不改写。旧版最高 v43 会拒绝打开 v44，不能把单改 user_version 当作回退方案。

保存先查持久原 UUID 回执；新操作核对 baseRevision、当前注册身份和 60 秒内的 Main 能力观察，再在 Library Service 单写入事务中 CAS、更新首选值并插入不可变回执。同一 UUID 换内容拒绝；历史回执不可更新／删除，最多 65536 条。Main 单线程串行配置、最多保留 128 个在途／已完成调用引用，未知提交结果保留原操作并阻止其他配置，使用同一 UUID 核对后恢复。已存在的回执可在设备移除或报告过期后核对；不会重复初始化驱动或重复切换输出。

保存注册 description 是可读身份快照；匹配必须同时使用注册名称与 CLSID，不按 description 或列表位置认设备。保存失败／回读错误都不改变当前 WASAPI 会话，因为此版本配置尚未成为活动播放后端。

## 界面

输出设置中按需展开 ASIO 区域，初始只读取注册目录和已保存配置。点击“读取所选驱动能力”才初始化该驱动；所有源声道映射均需明确选择。列表缺失、截断、非 PCM、缓冲范围、过期报告、未知保存结果和播放接入开发状态均显式显示。选择另一驱动清空旧声道及转换授权；不隐式选 ASIO4ALL、MOONRIVER 或另一设备。

配置保存入口与 WASAPI 的“保存并切换”分开。界面不得出现已经切换 ASIO、支持 Native DSD 或硬件已验证的文案。播放器封面、歌曲检索、滚动歌词、播放模式及队列沿用既有实现。

## 后续真实播放接入

继续完成 ASIO 私有音乐 IPC、活动后端选择和适配器路由、源解码／ring 消费／正式计划、增益与可视化、实际 ASIO 采样位置与输出延迟的呈现映射、短文件／EOF 尾部、暂停／seek／恢复时新进程准备、设备错误、reset／resync 重开和外部监督。ASIO 能力缓存只是选择前观察，不跳过任何正式准备或 SourceBinding 核对。DSD Native／DoP 的传输和设备能力另行实现。
