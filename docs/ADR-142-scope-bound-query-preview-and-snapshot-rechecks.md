# ADR-142：按当前范围预览与快照核对

日期：2026-10-06。状态：0.136.0 源码实现；查询真值、时间／事件顺序、界面及性能运行验收待 MVP。对应 FR04／FR05、WP05 的组合筛选、智能规则编辑和用户视图。schema65、音频 IPC1.22及原媒体／写回协议保持。

## 用户流程与完整范围

组合筛选窗口和智能歌单规则编辑页增加“结果预览”。用户手动请求后可查看匹配总数及当前排序的前8首，包括标题、艺人、专辑、时长、CUE标记和暂不可用状态。正式歌曲列表的当前分类／实体身份、角色、风格范围、检索词、组合条件、排序与折叠状态一起传入预览。智能歌单编辑则使用完整草稿查询；组合条件子窗口也沿用该草稿的其他范围字段。

从预设载入完整条件、修改输入或改变检索／范围／排序会形成新草稿身份，旧预览立即退场。无效数字或规则显示具体错误并禁止请求；未选择具体歌单时提示先选择范围。智能歌单名称修改不改变成员查询，允许沿用相同查询的预览。

预览手动触发，编辑输入不持续发送 COUNT。预览不是应用操作或智能歌单固定条目快照，用户仍需点击原“应用筛选”或“保存规则”。预设保存、歌单规则、当前队列和音乐文件均不因预览而改变。样本没有播放入口、资料操作或图片资源请求；完整音乐浏览继续通过正式列表进行。

## 共用正式查询与有界数据

新增可信 Main／preload／Library Service 的 `previewMusicQuery` 和 `checkMusicPreview`。前者使用 `LibraryDatabase.list` 的原参数化计划，limit8／offset0、同一个服务端 UTC 分钟基准和共用 `libraryBrowseSnapshot`。总数和前8项复用原分类、收藏／个人引用、静态歌单重复条目、智能动态成员及额外条件、模糊召回、源参数／统计筛选、自然／部分日期排序和版本折叠语义。

正式 browse 与预览使用同一快照函数，没有第二套客户端筛选 SQL 或猜测数量。读取前后核对曲库／检索派生／相关统计修订及相对分钟；跨快照返回 stale，数量和样本为空。静态歌单重复曲目使用其 entryId 区分，不把重复条目误作重复响应；普通／智能列表使用曲目身份。

响应只返回8项展示资料，不暴露全 `LibraryItem` 路径、CUE原文、来源记录或实体集合。显示文字清理控制字符、限制512个 UTF-16 单位并避免截断到尾部高代理项；不修改原标签。非有限、负数或超出1e9秒的显示时长返回未知。身份最多128字符。请求严格白名单 BrowseQuery，规范化后 JSON 最长16384个 UTF-16 单位；不接受 Renderer 提供服务器时间锚点、任意 SQL、LIMIT或音乐条目全集。

响应含原规范化查询、版本、状态、SHA256快照、分钟基准及 counts／recency／relative依赖。Shared／Renderer严格核验字段、数量、完整前缀范围、样本身份唯一／重复entry语义及查询回显。响应先经过数据库前后核对，再在到达界面时执行一次轻量快照核对，避免排队中的更新把旧数量当当前数据。

`checkMusicPreview` 只获取当前查询修订／分钟和快照，对比原请求SHA，不执行 COUNT 或样本水合。目录式智能规则仍读取当前保存定义，因此其隐含统计或相对依赖包含在服务端响应中。服务重启的新 epoch、定义／曲库修订、相关统计或时间改变均使旧快照失效。必要的连接本地浏览时钟安装及缓存沿用原 browse；预览不写用户数据或申请媒体读取任务。

## 界面失效与异步顺序

组件用规范化查询＋曲库修订作为草稿身份，另有单飞标记和请求代际。旧草稿、已退场组件或被事件失效的请求不得更新当前结果；preview和check共用同一flight，禁止连击产生并发的重复整库查询。输入验证错误也改变身份，不能继续显示此前有效数量。

曲库或检索变化让已显示预览失效，播放统计只按服务端返回的当前查询依赖判断。尚无响应的歌单查询可能隐藏智能统计规则，收到统计变化时保守失效；不尝试从未知规则猜测依赖。相对查询在分钟改变时失效，时钟回退也不能把旧日期窗口当新窗口。时间检查有界重设定时器，避免时钟调整时定时器到期后停止检查。

窗口重新获得焦点或恢复可见时请求轻量check，而不是自动再次计算整库匹配。核对期间及已失效结果不显示当前数量／样本；核对失败提示重新预览。明确失效仍需用户重新请求完整预览。事件通知用于及时撤下结果，服务端快照核对作为判定依据。监听器、定时器与异步显示在组件退场时关闭；关闭对话框不自动发送后续查询。

该机制没有承诺保存规则后的成员固定不变，也不提供任意长查询取消／独立预览进程或 COUNT性能认证。服务单写入同步数据库查询和原超时规则继续沿用，十万曲库耗时需 MVP 实测。客户端边界检查不是 SQL／真实时钟正确性的运行证明。
