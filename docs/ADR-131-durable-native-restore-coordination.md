# ADR-131 原生恢复的持久协调与退出记录

日期：2026-10-04。状态：0.125.0 源码及编译阶段，schema55；恢复协议1、四工件核对2、音频IPC1.22保持。完整 FR01–FR14/WP01–WP11/G1–G5/AC01–AC19 目标继续，FR12/AC12尚未验收。

## 本批次结果和边界

ADR-130 的原生恢复需要逐阶段持久确认，本批次接入内部 TagWriteManager、不可变恢复日志与数据库回执、独立租约epoch、取消/退出/重启状态和只读桌面结果。新增 startRestore/cancelRestore 是协调器内部函数，未注册 Main/服务/preload/Renderer 的实际恢复执行 IPC；独立恢复认证清单保持空，未认证请求在文件占用及原生启动前拒绝。

原生恢复成功仍不使文件可用：保留恢复占用、清除旧扫描观察，等待后续六工件核对、原来源再次解析/曲库事务/读取释放。六工件恢复检查和桌面动作、原来源重新解析与库事务、完整ACL政策/认证、断裂日志、工件保留/清理/批次/MP3/集合来源，以及全架构余项继续。本批次没有执行程序、SQL、迁移、真实文件恢复或测试。

## 原请求与新占用修订

明确确认的请求包含 commandId/jobId/baseRevision/inspectionId/certificateId/mode/confirmed，停止为 commandId/operationId。沿用不可变原命令回执，重复UUID先比对原始请求再返回历史结果，不用新请求替代结果未知的请求。

要求原提交 recovery_required 或 native_verified、标签任务 recovery_required、当前内容和任务审核修订、原提交恢复租约身份/epoch不变、最新四工件核对实际退出且完成、原暂存SHA及完整提交日志证据。matched 对齐已保存数据库最后阶段；FS-ahead必须领先。选择模式的认证独立检查，已知文件布局/原来源/目标的内容与物理身份在申请占用前通过恢复契约验证；未知、busy、unreadable或无法确认来源拒绝。

schema55 保存恢复操作和两个新工件UUID、原提交/任务/文件/最新核对/原请求/审核修订、模式/认证与新epoch。一个原提交和标签任务目前至多一个恢复操作，重复恢复需要先完成后续六工件恢复解释，不能任意建立新副本或丢失已有工件记录。

已有应用读取 owner 使用原提交 leaseId 连续持有，DB leaseRevision严格+1并变为 held，标签任务 running/revision+1；不先释放再取得，避免普通读窗口。后续原提交四工件和重新解析入口因旧epoch失效而被拒绝，桌面同时隐藏旧处理按钮。新owner不是新的UUID：这是同一恢复占用的连续所有者，以新epoch隔离旧动作，所有后续释放必须同时核对当前任务、owner和epoch。

## 文件再核对与冻结

停止此曲目的预览，协调解析/扫描/服务读取及waveform退出，最多35秒；所有tag文件任务全局串行，未知原生退出阻止新任务，关闭会取消恢复。新原生核对再次读取四文件，等待实际close；文件证据与所选报告精确一致，根/父目录只比较物理身份，不因无关目录mtime变化拒绝。

重新读取原暂存完整阶段、原提交SHA链及所有已存DB回执，确认matched/FS-ahead及摘要/阶段仍与所选报告相同。原提交已经有 locked 父目录证明时，当前父目录卷/文件ID/创建时间必须与该证明相同。未有父目录证明的原始日志不能编造历史父目录身份，继续使用已核对的当前授权目录和已知物理来源。

冻结 TagRestoreBinding 包含原请求、原 TagCommitBinding、原提交日志revision/status和严格恢复请求。原三文件基准来自原提交，不重新认证旧已撤销提交证书；实际新恢复仍要求当前独立模式认证。新epoch、所有工件UUID、原来源/目标、授权路径、原暂存/提交SHA逐一绑定。原标签计划/内容不改写，恢复不是重新使用在线值或生成新的标签差异。

## 文件日志与数据库阶段

dataDir/tag-restore/operationId/0000..0006.json 保存初始绑定及 locked/prepared/intent/displaced/restored/verified。单条不可覆盖创建、canonical JSON SHA链、fsync/关闭后完整回读；拒绝序列缺口、不明文件、部分JSON、符号链接、硬链接、路径/打开前后BigInt观察变化和未知摘要。历史读取允许已撤销证书，创建或推进仍要求当前恢复认证。

初始记录1MiB、阶段64KiB，文件日志1024目录/每操作7记录。DB操作4096条/意图及绑定512MiB，阶段回执512MiB，请求4096字节、进度1024字节、最终原生证明64KiB。schema55迁移前保存pre-v55快照；SQL/迁移本轮未运行。维护既有隔离迁移fixture降级链与schema断言，没有新增或运行测试。

每阶段先再次核对任务/当前内容/租约epoch/元数据可用性/授权根，再持久文件日志、回读SHA及证明顺序/来源物理身份/策略链，最后保存不可变FULL-sync DB阶段回执；回调返回持久摘要后才能ACK原生。只能推进一个阶段，重复回执必须完全一致，原生消息序列允许中间进度但关键阶段不能跳跃。文件日志领先DB时保留FS-ahead，不能在旧任务中偷偷补ACK或假装结果已完成。

原生持有排他文件时，上层只核对目录及库内身份，不重新打开歌曲原路径，包括两个移动之间原路径缺失的窗口。阶段日志写入和SQLite不是文件系统交换或掉电原子事务，不宣称目录flush及整个恢复已认证。

## 成功、取消与重启

客户端完成要求六阶段均持久ACK、最终done与verified相同、实际进程退出及所有阶段回调退休。之后重新读恢复日志/DB回执并保存 native_restored/final_json/exit_confirmed=1；标签任务恢复为 recovery_required，保留当前epoch与读取占用，清除扫描观察/标记missing。原 tag_commit_operation/final/退出标记/原回执保持原样，它们是原提交历史，不能用恢复结果伪造原提交成功。

停止保存不可变原请求，再取消当前进程并等待实际退出。取消和失败记录使用当前held租约/任务revision CAS，不因文件策略或目录刚变为无效而无法停止；旧任务失败不能失效后来的占用。失败、部分副本、已移走目标和未知退出均保留证据与恢复占用，不自动重试、删除、回滚或解除普通读。

重启把 reserved/running 置 recovery_required/未知退出；native_restored最终证明不改写。只对当前恢复任务且与恢复操作的owner/epoch完全匹配的文件清观察/标记missing，旧历史不能禁用后来的已恢复/新任务。应用gates在重启时需要后续实际核对重建，但DB恢复占用继续阻止普通读。

只读桌面显示等待恢复、正在恢复、原文件已核对待曲库、恢复中断及退出待确认。原提交另标为历史；恢复后四角色已经不足，旧三/四工件操作不再显示。新的六工件核对/恢复入口和受控原来源重探测是下一步，不能以原目标 replacement-observed分支更新已恢复文件。
