# ADR-100：扫描稳定窗口与文件属性观察

- 状态：源码实现与编译通过；真实文件、SQL／迁移和性能待 MVP
- 版本：0.95.0
- 日期：2026-10-02
- 关联：架构 §9.1–9.2、WP04、FR13；承接 [ADR-099](ADR-099-file-watch-and-durable-reconciliation.md)

## 问题与依据

扫描原先已核对解析前后的大小、mtime、ctime、dev 和 ino，但跨扫描的增量判断只保存大小与截断毫秒的 mtime。外部工具修改标签后保持大小／mtime 不变时，若其他属性已经变化，原增量判断仍可能跳过解析。目录通知合并也不能证明每个文件已经稳定。

使用 Node 的 BigInt 文件属性观察，保留 mtime／ctime／创建时间的纳秒表示与 dev／ino 的完整整数值，不将它们转为浮点数计算摘要。实际时间精度和语义仍依赖文件系统；ctime 表示属性变化时间，不能作为创建时间。依据：[Node.js 24 Stats 与时间属性](https://nodejs.org/docs/latest-v24.x/api/fs.html#stat-time-values)。

## 数据与迁移

schema v40 新增 `media_file_observation`，按 `file_id` 保存 `node-bigint-stat-v1` 算法和固定 64 字符摘要，外键随文件记录删除。`scan_entry` 增加可空的观察摘要与采样时间，保持历史扫描任务、UUID、代次和检查点。

摘要的输入是算法标识、size、mtimeNs、ctimeNs、birthtimeNs、dev、ino、mode 的十进制字符串。排除 atime，避免读取自身改变观察。摘要采用 SHA-256 编码这些属性，**不是文件字节哈希、音频内容指纹、永久资产身份或完整 Windows FileIdentity**。

既有数据库迁移前另存 `.pre-v40-时间.bak`，结构变更与版本标记在同一事务中；未来版本仍拒绝打开。观察表初始为空，不根据旧 mtime 伪造观察，也不在迁移期间打开音乐文件。下次成功扫描为旧文件重读标签并逐步补齐观察，可能增加升级后的首次扫描成本。

## 扫描流程

1. 枚举音频／CUE 时，先沿既有根边界核对目标，再采样 BigInt `lstat`，将摘要和时间与最多 256 项的清单批次一起保存。目录本身无需文件摘要。采样失败仍保留待处理文件条目，由其读取步骤记录异常和保护旧资料；越界继续停止该扫描。
2. 打开音频／CUE 后读取句柄属性，与枚举采样比较。不同则暂不解析，不把正在变化的版本替换为新资料；完成前的新一轮枚举或后续扫描再处理。
3. 两次观察采用 750 ms 窗口，复用枚举到实际读取之间已经过去的时间，只等待不足部分。旧任务尚无观察时保存新的观察后等待；未来时间戳重新采样。等待可响应取消，单次剩余等待上限 750 ms。
4. 服务存活期间用启动时的时间基准加单调时钟生成采样时间，避免运行中调整系统时间使等待突然增长。跨重启检查点使用持久时间表示；跨重启的大幅时钟变化仍不是可靠的持续写入证据。
5. 窗口后再次核对句柄摘要；取得既有媒体 worker 的数值属性后再核对一次。worker 原有同句柄观察和严格回执不变，不把新增扫描摘要当作 worker 授权。
6. 增量跳过标签解析必须同时满足：有效旧标签、已完成分类、大小／mtime 一致、当前算法的完整属性摘要一致。缺少摘要或任何变化都重新读取。ctime、inode、创建时间、模式或细粒度 mtime 变化因此可使“相同大小／mtime”的文件重新解析。
7. 解析完成后沿原路径授权再次检查，比较原有数值属性、句柄 BigInt 摘要与当前路径 BigInt 摘要。成功标签、ReplayGain、分类／检索与新的文件观察在原安全检查点事务内提交；中途失败不覆盖旧观察。
8. 文件仍在变化或读取失败时继续保留旧曲目及任务异常记录。CUE 不稳定时保留旧编排，沿原规则阻止不安全范围的缺失判定。扫描取消、代次、完成前对账和目录自动更新的持久回执继续复用。

直接通过其他内部调用写入 `ParsedFile` 而未提供经扫描核对的观察时，会清除该文件的旧观察，避免旧证据给新标签背书。观察摘要不改变 `LibraryItem.fileStamp` 既有大小／mtime 合约，本批不声称所有播放／媒体请求已使用完整原生内容身份。

## 边界与后续计划

750 ms 的属性安静窗口只是当前版本的稳定判据，不证明下载完毕、写入方关闭文件或其稍后不会继续写入。写入暂停后恢复、完整字节保持所有属性不变、元数据时间精度不足及网络缓存仍可能漏检；需要可选字节／内容哈希、原生文件／卷身份、任务重试策略和完整授权生命周期继续补齐。

检查与入库之间不是原子文件系统事务；无硬隔离的 stat／realpath／目录读取仍可能阻塞。旧检查点缺少采样会分别等待，额外枚举属性读取和首次补齐标签有性能成本，不能把编译成功视为十万曲性能达标。未改变目录自动更新的 64 根／两个后台观察预算。
