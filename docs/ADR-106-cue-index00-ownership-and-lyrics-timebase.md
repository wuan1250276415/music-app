## 归属模型

架构要求保留文件内 INDEX 00 音频，并允许将其归前一轨尾部或本轨前奏。解析器增加 `previous`／`current` 策略，默认仍为前一轨。选择作用于一个外部 CUE 文档内的全部文件与音轨，后续可扩展逐轨策略。

保留原始 INDEX 00、INDEX 01、子索引及原文字节；实际 `startFrame` 与声明的 `index01Frame` 分开保存。前一轨策略的实际起点是 INDEX 01；本轨策略有 INDEX 00 时从 INDEX 00 开始，否则仍从 INDEX 01 开始。同文件前轨的结束位置等于下一轨实际起点，均为半开范围和整数 75 fps 时间。

例如第二轨 INDEX 00 为 00:58:00、INDEX 01 为 01:00:00：前一轨策略让第一轨播放到 01:00:00，第二轨从 01:00:00 开始；本轨策略让第一轨播放到 00:58:00，第二轨从 00:58:00 开始，其正式 INDEX 01 仍是 01:00:00。已有两秒前间隙只播放一次。这是设计示例，未运行音频验证。

每个文件的前导隐藏条目从文件开头到首轨实际起点。本轨策略下首轨 INDEX 00 为零时无需再生成同一段隐藏条目；INDEX 00 为正数时仅将其之前的文件音频作为前导。无 INDEX 00 的首轨继续保留 INDEX 01 之前的文件音频。不同 FILE 之间不根据 INDEX 推断额外静音或跨文件连续性。

非递增／重叠原始边界、原始 INDEX 01 越界及子索引越过新结束位置继续拒绝。数据库及内部回执校验实际起点与策略一致，正常轨的结束必须晚于 INDEX 01。最后一轨未声明结束时仍交给源文件结束边界；声明 PREGAP／POSTGAP、去加重与复杂多段时间线保持后续范围。

## 持久设置、历史与扫描

schema v43 在当前 CUE 来源、不可变解析版本和已提交编排中增加归属列，并为 CUE 曲目身份核对增加部分表达式索引；升级前备份及结构事务延续原迁移流程。既有记录默认 `previous`。历史字节、解析 JSON、摘要、时间及命令回执不改写。

解析器版本升级为 `aural-cue-3`，解析快照及版本标识包含策略。已编排匹配除原文摘要、编码和解析器外，还核对归属；同一原文字节的不同解释不会错误显示为相同编排。来源摘要分别展示当前选择与最近观察的归属。

“CUE 原文与编排解释”入口增加归属选项。编码及策略作为同一命令保存，沿用原 UUID、来源修订和最近版本核对、不可修改回执、未知结果再次核对及持久重扫意图。历史版本只能查阅，当前预览只解码原文，不伪称已完成新范围验证。

旧 v42 五字段命令的规范请求仍可回放，新界面总是发送六字段命令；旧命令的新执行按 `previous` 解释。旧回执的缺省策略只在返回视图中补为 `previous`，原始 ledger JSON 保留；相同 UUID 不允许改变请求形状或策略来执行新操作。

沿用协调器串行停止受影响 CUE 文档、预备轨及恢复书签，保存后待核对编排暂不可播放。扫描读取前捕获策略／修订，原文观察事务及编排检查点再次核对；并发修改、失败、取消或中断保留原编排记录和未完成意图。只有没有警告的安全提交清除意图，不把保存设置或解码预览视作编排成功。

内部媒体协议升级为 9，CUE 请求与完整来源回执明确包含策略；解析文档／实际起点也受校验。音频 IPC 1.19 和系统媒体协议 1 保持，实际播放及同源相邻 CUE 使用既有源范围契约中的新整数起点／终点。

## 曲目标识与个人引用

正常轨继续按文档、源文件、轨号和隐藏类型核对原曲目标识。优先复用唯一可见条目；因前导范围为空而隐藏的历史条目，再次出现时可复用唯一历史标识。原 `cue_track` 已撤去时，从零轨号判断历史隐藏类型；歧义不任意改绑。

核对使用文档表达式索引和单次分组，避免对每个音轨重复扫描全部历史候选；每文档最多核对 262144 项，超限拒绝并保留原编排。收藏、评分、歌单／队列条目及原歌词历史引用继续指向原标识，范围和 source span 随新编排更新。此模型仍不证明任意 CUE 文本编辑后的身份归属已完全解决。

## 歌词时间基

专辑文件内嵌同步歌词仍按源文件绝对时间裁切，并减去当前实际播放起点。本轨前奏包含在播放器零点前段时，其后的歌词自然延后对应时长；前一轨策略结束位置缩短时，范围外歌词不进入前一轨。

曲目同名 LRC 则明确采用 INDEX 01 为零点。读取上下文增加原始 INDEX 01，并按 `(INDEX01 - 实际起点) / 75` 平移同步行；纯文本和整曲文件不平移。音乐观察、原始歌词字节及来源校验延续原路径；包含前奏的解码歌词采用自己的来源摘要，不复用此前相对范围的解码版本。

歌词偏好和用户导入文档本来以曲目标识及实际播放范围构成 scope。范围改变时原偏好／导入版本仍保留在原 scope，不自动改写时间或复制到新范围；可以从历史版本中明确复制并调整时间基。切回完全相同范围且标识不变时可重新使用原 scope。外部同名 LRC 是否实际按 INDEX 01 编写仍需真实语料核对，已有用户偏移可以调整；没有自动推断所有歌词的零点。
