# ADR-186：核心 MVP 导入、封面与播放详情验证

- 日期：2026-10-11
- 版本：0.180.0，schema72／音频 IPC1.23／媒体14
- 对应：FR01、FR04、FR05、FR07、FR08、FR10；WP04、WP05、WP06、WP10
- 状态：隔离曲库的核心流程运行验证通过；完整 MVP 和 V1 未验收

## 本轮修复

媒体解析器构造 catalog 时保留了值为 undefined 的可选署名和发行字段。worker 在 JSON 序列化前进行严格响应检查，因而把没有这些标签的正常文件判为“媒体解析署名集合无效”；扫描终态可以完成，但音乐未入库。现在生产方在校验前省略缺失字段，保留实际空值和空集合，不放宽接收方检查。

浏览快照变化后，旧列表点击播放会在建立队列之前被拒绝。新增稳定的 AURAL_BROWSE_STALE 错误标记，界面据此刷新列表并提示重新选择。保留快照和曲目位置核对，不自动重复播放命令或改用另一个曲目。

## MVP 验证方法

更新既有 tests/electron-detail.smoke.cjs，使用临时音乐根与独立 userData，真实运行 schema 初始化、扫描、Library 进程、媒体读取、Chromium 图片资源和音频宿主。测试窗口可见但不主动抢焦点，结束后关闭并清理自己的临时目录。后台扫描完成后再检查稳定曲库。

封面是惰性加载资源。检查先将目标置于可见区域中央，再等待资源解码并读取实际截图像素；隐藏窗口和自动最小滚动曾造成未绘制或被祖先裁剪的测试失败，不能据此认定生产读取失败。歌手点击限定主歌曲信息区域，区分同名的歌手和专辑艺人。

样本：带红色内嵌封面的 MP3，目录内同时存在蓝色 cover.png；无内嵌封面的六秒 WAV；两个本地 LRC，其中 WAV 有51行。执行默认 WASAPI 共享播放，不调用 ASIO 播放、厂商面板或 ASIO 硬件验证。

## 已观察结果

完整脚本退出0，证据见 [运行日志](validation/v0.180-core-mvp.log) 和 [播放详情截图](validation/v0.180-playback-detail.png)。

- 两个样本扫描入库，重新打开应用后可读取。
- 列表、播放栏和详情的 MP3 内嵌封面像素为红色，优先于蓝色目录图片；无内嵌封面的 WAV 使用蓝色目录图片。
- MP3 和 WAV 实际进入 playing；输出报告为耳机 (MOONRIVER 3)、WASAPI shared、44100 Hz、f32。MP3 为单声道且报告适配转换，WAV 为双声道且未报告适配转换；两者 hardwareVerified 均为 false。
- 失效浏览快照明确拒绝，播放队列前后完全一致。
- 封面打开详情，本地歌词点行定位、当前行高亮与滚动、详情队列切歌、随机与顺序／单曲／列表循环状态、歌手和专辑跳转、Escape 关闭通过。

日志中的浏览快照拒绝是有意的负例。关闭末尾还观察到一次封面租约释放晚于 Library 正常退出0的诊断；测试清理成功，此记录不作为完整退出生命周期验收，仍纳入后续故障与退出验证。

## 构建与范围

Main／Renderer 类型检查和构建、生产原生组件及既有金样编译通过。既有金样此次没有执行。发行生成文件、分发清单及发行脚本语法另行静态核对。主界面199模块，主块465.22kB／gzip143.21kB。

这份结果不证明用户原先缺图歌曲已修复，也不证明 FLAC／WAV-ID3／DSF 所有封面样本、独占输出、位完美、ASIO、DSD、长时音频、大库检索、故障恢复、旧 schema 迁移或安装包通过。已请求原问题的歌曲路径，继续复现。完整 FR01–FR14、WP01–WP11、G1–G5、AC01–AC19 范围保持，只有 ASIO 实机验证暂停。
