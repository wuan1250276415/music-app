# ADR-015：运行时 seek 与音频时间线代次

状态：0.9.0 Windows WASAPI 原型已实施；G1 的数字输出捕获仍未通过。

## 决策

音频协议 1.2 增加 `playback.seek`。Main 发送相对当前曲目的十进制字符串 `positionUs`，Host 验证目标位于当前源片段内，再换算成绝对 PCM 帧。CUE 曲目的绝对起点继续来自整数 75 fps 边界。超出片段或已知文件长度的目标被拒绝，播放保持原状。

Host 接受命令后先回 receipt；实际执行时停止 WASAPI 设备和解码生产线程，等待二者退出，再定位解码器、清空环形缓冲的读写计数、重设片段剩余帧数并预填新样本。原来暂停的会话保持暂停。设备重新启动成功后，Host 递增 generation，并发送带原 commandId 的 `playback.seekCompleted`，其中报告相对曲目时间和绝对源 PCM 帧。Main 只在此事件到达后更新播放位置和完成调用；receipt 本身不能代表 seek 已完成。完成事件缺失或时间线协议异常时关闭宿主，避免把未知位置当作成功。

Main 同时只发送一项 seek；新目标到达时覆盖尚未发出的旧目标，所有被合并的调用以最终目标的结果完成。界面拖动时只显示预览位置，松开、键盘提交或失焦时发出 seek。Stop 能取消等待中的跳转并终止宿主。

## 验证与剩余边界

原生协议测试覆盖暂停时 seek、两次前后跳转、generation 增量、重复 commandId 返回原 receipt、不重复执行、越界拒绝与恢复播放。控制器测试覆盖完成事件前不结算、完成事件丢失时关闭会话、连续目标合并和同一宿主内 seek。Electron UI 测试通过进度条点击跳转 CUE 曲目。原生 WAV/FLAC 金样验证了被 seek 到的软件解码片段的逐样本值。

这些测试未捕获 WASAPI 设备实际输出；回调之后的设备缓冲、共享模式混音器和声卡链路仍需数字捕获验证。0.10.0 增加有条件的整数 PCM 路径，详见 [ADR-016](ADR-016-pcm-output-plan.md)。多窗口并发控制、长驻宿主和连续曲目无缝播放仍待后续工作包。
