# ADR-192：检索覆盖索引与 schema73 升级

日期：2026-10-12。源码版本：0.186.0。状态：实现与聚焦 MVP 验证；十万规模性能未验收。

## 问题和决策

0.185 的十万条合成目录组合检索 p95 约557ms，超过架构200ms预算。查询已经限制本页资料读取，但候选排名和排序键仍反复读取宽表。

schema73 添加 `playable_item_search_cover` 和 `item_sort_release_cover`，分别覆盖候选排名字段和专辑排序前缀。生产查询明确使用这两个索引。没有错拼候选时直接排名，避免重复检测直接候选集合；风格成员的 `IN` 子查询使用 `UNION ALL`，由 `IN` 保持成员去重语义。递归风格集合仍使用原去重策略。

每个数据库连接只保留一个短查询的规范化上下文；艺人文本规范化最多512项、64KiB，按插入顺序淘汰。标题、查询结果和排名不缓存。列表查询复用既有有界SQL语句缓存。保留原排名、精确总数、同分边界次级顺序、旧派生键回退和歌单重复条目。

## 升级与数据保护

已有曲库从schema72升级前，检查普通独立文件和剩余空间，使用 `VACUUM INTO` 保存单独的 `.pre-v73-*.bak`。核对快照身份、fsync、schema72、DELETE日志、全部实际结构、13类表计数、完整性和外键，然后在事务内创建索引、核对原计数和完整性，最后写入schema73。新库不生成无意义的空快照。

原schema68至72备份元数据继续可读取；旧候选不被改标为73，完整恢复仍要求显式兼容升级。恢复只读或暂停连接不会通过普通启动迁移。新增索引不会改变音频IPC1.23和媒体协议14。

真实十万合成目录的首次升级约294.6秒，超过旧Main初始化180秒。正常初始化改为有界45分钟，仍只有实际PID、构建与原准入证明核对后才置为ready，普通请求15秒期限不变。没有放宽3秒冷启动性能门槛。该时间调整尚不能证明完整应用完成十万库升级；长升级的可见进度和完整应用升级验证仍待完成。

## 已有验证和实际限制

880组生产查询与原完整关系查询的有序分页对照通过；风格双来源、交并集、用户状态、质量、年份、艺人和播放统计的独立清单断言通过。

独立schema72定义摘要匹配、升级快照和原歌曲／用户状态／重复歌单保留、重开幂等、生产SQLite备份接口、schema73独立检查及恢复结构审核通过。第一索引后注入异常时事务回滚，原schema72和快照保留。初始夹具误把SQLite可选统计表计入必需定义，原失败保留；修正为生产已有的可选统计规则后通过。此夹具是合成旧结构，不是全部历史用户库迁移认证。

十万同语料正式20次采样两次均exit1，正确性完成但completed=false：第一轮组合检索p95约226.1ms，增加FIFO规范化和语句复用后第二轮约231.7ms。不能声称后两项进一步改善或达到预算。精确／繁简标题、拼音、重音、错拼及有风格范围的错拼在这份报告中通过对应预算；宽短词和深页仍慢。报告包含来源指纹，未同时运行构建或播放，没有修改预算或重建语料以规避失败。

语料为合成目录，未验证十万真实文件扫描、OS冷缓存、完整应用端到端、全进程内存或8小时运行。DSD硬件、元数据完整来源／写回矩阵、恢复重启／历史候选、跨平台、签名与完整发布门槛仍待完成。仅ASIO实机暂停；FR01–FR14、WP01–WP11、G1–G5、AC01–AC19范围保持。

首次打包的静态核对失败：验证脚本用POSIX路径读取多层ASAR目录，Windows版ASAR按宿主分隔符遍历。实际包内拼音依赖存在；现在统一转为宿主路径后读取，保留依赖版本、许可和全部字节SHA核对，原exit1保留。程序或依赖未因这个验证脚本修改而重打包。

最终构建、应用回归和交付工件结果记入 `validation/v0.186-checkpoint.json`；这份记录不将静态核对当作运行或硬件验收。
