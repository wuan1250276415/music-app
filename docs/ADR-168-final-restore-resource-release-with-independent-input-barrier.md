# ADR-168 恢复最终资源释放与独立交互屏障

状态：源码实现，运行验收待 MVP。日期：2026-10-10。版本：0.162.0。

## 决定

ADR-167 确认正常 App 已在原新文档挂载并取得六类实际读取，但仍然保留普通 Main、播放和历史维护。不能先结束普通 Main 占用再等待完成记录，否则托盘、快捷键、外部文件和普通 IPC 可能提前开放。

本批接通 finalization-intent 和 final-resources-held。前者在实际停止显示读取之前持久，绑定同一完成 UUID、原新文档 UUID/token/代次/版本、application-ready 及其成功回执和 pending 值摘要。后者独立确认全部普通维护占用结束及实际停止状态，但保留独立 Main 交互屏障和历史完成屏障。这两个记录都不是 completed，不授权正常重启或用户操作。

## 实际读取停止

同一正常 App 原实际证明核对后，CatalogRestoreApplication 先关闭其固定显示读取入口，再等待 MainCatalogResources 登记的全部读取实际结束。登记覆盖业务方法、结果观察和结束校验，原在途请求仍须通过实际实例/文档/取消核对。拒绝新的读取并不代表旧请求已结束；Promise.allSettled 后集合必须为空才能进入下一步。

安装独立交互屏障时，普通 Main、播放和历史占用仍然冻结，13 组资源释放证明仍须有效。普通 run 和 assertAvailable 额外核对独立屏障；held 同时包含普通维护和该屏障。已有系统入口使用 held，因而普通 Main 占用结束后仍拒绝托盘、快捷键、设置、缩放、窗口保存及外部文件。普通维护释放不能绕过恢复分阶段状态。

## 原文档再次确认

Main 停止显示读取并安装屏障后，才向原实际新文档发送最终挑战。正常 App 包装层在原挂载回执之前安装监听，并保存实际原成功回执。Renderer 核对同一文档 UUID、token、代次、版本、已连接的正常播放栏、实际 inert 和原成功 App 回执摘要；再次计算受保护 pending 值并等待事件轮次后重查文档、播放栏、inert 和原值。

Main 严格核对原当前主 frame、实际曲库/文档及同一挑战摘要，原回执只能精确重复。失败回执、不同内容、30 秒未确认、取消、窗口/曲库退出、休眠或导航都保留占用和原记录。时限只能表示没有获得确认，不能作为结束资源或成功的证据。

## 普通资源结束与历史屏障

释放前，历史记录重新核对原处理 Promise、内存规范字节和真实单链接 pending 文件的完整摘要；所有核对仍受当前操作和普通历史冻结保护。

历史完成屏障先建立，再结束历史普通维护。屏障期间 observe 不累计、flush 不提交、关闭不保存，统计规则不能变更，计时器仍为空；现有 pending 文件及内存保留。播放同样先建立原操作的完成屏障，才结束普通维护；直接队列/切歌命令、暂停和迟到的 CUE 边界或曲尾通知继续拒绝，防止内部通知绕过 Main 交互门禁。随后结束普通 Main 占用，整个同步转换期间独立交互屏障已经存在。

释放后实际断言要求：普通 Main 和播放维护未占用、音频输出实际已释放、播放为 idle/error、没有原未结播放命令、历史未关闭/无计时器/无在途保存/内存摘要仍一致、显示读取集合为空、独立屏障仍属于原操作。只有这些条件实际成立，才持久 final-resources-held 并独立读回。

原 App 和 Renderer 所有者核对在这一转换后继续有效，切换的是资源断言，实际导航/实例/代次检查不放宽。取消监听保留到后续最终完成。

## 余项和验收

后续必须在独立屏障内持久 completed，确认完成启动准入和历史事务关系，然后解除交互及历史屏障、发布真实维护状态、清理原进程恢复归属及所有私有协调器占用。当前没有解除屏障的方法，也没有用户恢复应用入口；未决重启仍阻止普通曲库打开。

原始资料保留、未决事务核对/恢复及原文导出复审、完整领域/迁移校验和、实际配额清理继续。全部 FR01–FR14、WP01–WP11、G1–G5、AC01–AC19 保留。

最长记录链 44/48，单帧 3 MiB、累计 64 MiB 和最多 64 个保留事务不变；schema68/音频IPC1.22/媒体10保持。源码检查不能证明真实恢复、实际界面、文件、SQL、设备或异常效果。按用户要求，运行/故障演练和完整验收集中到 MVP；ASIO 实机验证搁置，真实缺图仍待复现。
