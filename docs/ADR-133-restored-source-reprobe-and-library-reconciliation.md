# ADR-133 恢复原文件重新解析与独立曲库恢复

日期：2026-10-04。状态：0.127.0 源码及编译阶段，schema57；完整FR01–FR14／WP01–WP11／G1–G5／AC01–AC19目标继续，FR12／AC12仍未验收。

## 问题与范围

六文件报告能确认原路径已经是恢复来源，但旧目标重新解析流程要求目标标签和四文件布局，不能用于旧文件放回或备份副本恢复。本批增加独立原来源重新解析、曲库事务和读取协调释放，不移动或删除文件。保留原native提交／恢复状态、最终结果、退出标记及阶段回执，独立证明可以记录已实际恢复的来源，而不补造原ACK或done。

## 请求、模式与历史

schema57一致备份后事务建立`tag_restore_reprobe`及`tag_restore_reprobe_release`。原请求UUID／明确确认／最新核对ID／任务baseRevision、原owner和恢复epoch不可变，模式immutable：

- native-restored：raw恢复为native_restored／exit1，最新已实际退出六文件报告restored-source，日志matched／verified／revision6且原final存在。
- interrupted-source：raw恢复为recovery_required，最新报告restored-source，日志matched或FS-ahead，revision4–6／displaced、restored或verified。实际来源被独立观察到，不推定原恢复退出已知或成功。

触发器限制当前恢复操作／文件／任务／核对身份、模式与raw状态、已完成实际退出报告及当前任务修订／owner／epoch；同一恢复仅一个running和一个completed证明。身份／模式不可改，终态不可修改，不删除取证；4096条／512MiB总预算，4KiB请求、1KiB进度、3MiB证明。后端还检查内容修订、原暂存计划、原恢复base+2、最新报告、文件／目录政策、原提交固定来源路径、完整不可变绑定及所有链接摘要；历史认证撤销不阻止只读证明，不能因此执行移动。

## 原标签及双快照验证

停止其他读取，原owner持续持有，35秒超时不放行；此解析与全部标签文件任务串行。严格执行：

1. 当前任务／目录复核，重新六文件排他核对并要求与选择的完整报告一致，实际close后才解析。
2. 本机源路径／BigInt观察、非链接／单链接、真实路径与stat反复核对。
3. owner内部受监督FLAC raw preview，重现原冻结只读差异，要求完整preview与原证据一致，特别是每一**实际fields.before**仍等于原来源，源元数据SHA／源偏移／字节数、STREAMINFO、保留块SHA及音频范围不变，不接受内嵌CUE。原目标值仅用于重现只读预览，只有实际源tags解析结果进入曲库，不执行文件写入。原来源可含空字符串或超过32个字段值（既有before契约最多256个），不能把before当成限制32项／24KiB的写请求，否则会错误拒绝有效恢复来源。
4. owner内部受监督tags解析，等到实际关闭；再次核对同一观察和当前所有权。
5. 第二次六文件核对，全部文件证据及目录身份与第一快照一致，原路径仍classified restored-source；再核对源观察。
6. 原暂存完整日志与全部库回执、精确原提交revision／SHA及全部回执、完整恢复链和全部回执，对齐选择报告的matched／FS-ahead和SHA。保存两次快照、raw preview、parsed／stat／观察、三层日志SHA、恢复日志revision／模式及原提交与恢复真实退出标记。

证明验证实际源字段、容器、文件大小、采样率、位深、STREAMINFO时长和来源哈希。副本模式必须准备阶段中的独立新物理文件；victim模式必须原来源物理文件。未知工件、变动、缺口、解析错误或撤销目录政策拒绝提交；不会推定备份恢复具有原ACL／SACL。

## 曲库事务与身份保留

在既有FULL-sync单写入事务内，再核对请求／模式／报告／租约／内容及证明，通过受控actor区分原目标解析和恢复来源解析，不能传任意路径或新增文件。沿用原root／规范路径、fileId及原可播放file曲目itemId；缺失／变化身份拒绝，不能回退新建item。更新实际文件技术信息、stream／span、local catalog source、来源信息／搜索／ReplayGain和新观察，沿用既有人工确认、覆盖、集合模式、用户收藏／评分、歌单／队列引用及首次加入时间。

同事务推进内容和租约修订、清空当前文件DB租约，标签任务completed，保存独立恢复曲库证明。**原native提交和恢复的raw状态、退出、final和ACK回执全部保持**；六文件历史也不重写。应用文件读取闸门在此时仍保留，待独立清理回执才放行。

文件系统与SQLite不是原子事务：两次核对的排他句柄均在曲库事务前关闭，随后再次检查观察。提交后变化只在当前精确epoch及所保存观察匹配时使文件不可用、删除旧观察并等待重扫，不撤销已提交证明，也不能禁用后续新任务的文件。

## 读取释放、停止与重启

completed独立证明但无release ACK时，普通读取及新写租约继续拒绝。释放先确认DB当前epoch是原解析epoch+1且state none／owner和job null，再用原owner释放parser与运行服务闸门，保存不可变释放ACK。若已是后续epoch，不释放后续owner；原清理回执单独收尾。失败可按启动和5秒服务重试，不重复曲库事务。当前解析尚未结束提交后观察复核时，后台清理明确延后；同ID异步清理合并，服务清理串行且不重入。每次清理（包括启动）再次核对实际源观察和当前epoch，变化先禁用旧观察，再释放闸门／记录ACK，不允许后台重试抢先放行。

停止请求先持久化原命令回执，再取消；即使来源／目录政策变化也能停止。提交前失败、取消或中断保留原占用及所有工件；重启仅把running解析改interrupted，不自动继续解析。completed任务不再满足旧提交／恢复观测失效条件，历史中断不会禁用新观察或后续任务。

## 桌面与剩余完整目标

Main／服务／preload提供重新解析及停止入口，仍无原生恢复执行入口、独立恢复认证目录空。桌面在最新restored-source报告及当前模式下明确确认恢复原文件资料，开始／停止／原请求重试，显示曲库已恢复、读取释放待确认或文件可用。原恢复标为历史，避免其等待提示覆盖新完成证明。

后续补齐中断恢复继续执行、完整原ACL／SACL权限政策、格式／文件系统／厂商音频认证、断裂日志闭环、工件保留清理、批次、MP3及集合权利；其余架构功能、性能、跨平台和G1–G5／AC01–AC19仍须完成。MVP验证schema56→57及历史版本迁移、触发器／预算、两种mode、原请求重放、前后六文件和源字段／音频不变、目录／身份及取消变动、事务任一阶段故障、原个人状态保留、postDB替换、释放故障／重启及历史隔离。运行测试集中到MVP，ASIO实机继续搁置。
