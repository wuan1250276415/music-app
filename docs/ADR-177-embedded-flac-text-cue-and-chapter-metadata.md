# ADR-177：FLAC 内嵌文本 CUE 与曲目信息

日期：2026-10-10。范围：FR02／FR04／FR10／FR12 源码，延续 ADR-175／176；尚未运行验收。

## 来源与读取

[RFC 9639 §8.6](https://www.rfc-editor.org/rfc/rfc9639.html#section-8.6) 定义 Vorbis 注释的 UTF-8、大小写不敏感字段名及小端长度。`CUESHEET` 字段名属于本应用支持的常用约定，不能称为 RFC 标准字段；其文本也不等于类型 5 的二进制 CUESHEET。

新增独立 `flac-cue-reader.ts`，在既有监督标签进程及原句柄中一次核对整个 FLAC 元数据链，分别提取二进制块与注释字段。注释只允许一个块，最多 32768 字段，vendor 长度 1 MiB、字段名 256 字节、CUESHEET 字段 512 KiB；两个同名 CUESHEET 字段拒绝自动选择。总元数据位置／累计读取各 32 MiB，20 秒合作式取消与原监督进程实际退出确认保持。

新增 `flac-cue-text.ts`，保存完整 `CUESHEET=` 原始 UTF-8 字段、SHA、原注释块位置／字段序号及 STREAMINFO，严格解码并复用现有文本 CUE 解析器。无效文本保留原字节与诊断。媒体协议 13 的接收方重新解析原始文本／STREAMINFO，完整比较回执并检查文件范围／rate／总时长；不依赖 music-metadata 的未知标签规范化结果。二进制解析标记升为 3，旧标记 1／2 仍保留保护并触发一次重新探测。

## 分轨与名称

内嵌文本必须是单文件编排。原 FILE 名用于说明历史整轨镜像；它可以是转码前的 WAV 名，绑定到当前拥有此注释的 FLAC，不打开或解析成另一文件。拒绝多文件、绝对和上级目录引用；外部多文件 CUE 仍使用其独立原流程。

只有文本来源时，原 75 帧 INDEX 用整数乘除映射到采样位置，并以 STREAMINFO 已知总采样数给最后一轨确定结尾；沿用虚拟曲目、前间隙归前轨、首轨隐藏前导、可精确表示的 75 帧与非对齐采样范围模型。文件封面与歌词仍属于当前 FLAC。

二进制与文本同时存在时，先核对 STREAMINFO、轨数、每个轨号及全部 INDEX 的实际采样位置，显式 FLAGS 的 PRE 和双方非空 ISRC 也须一致。只有一致才应用 TITLE／PERFORMER／专辑 TITLE／SONGWRITER／ISRC／原字段。文本缺省 FLAGS 不会清除二进制 PRE；未明确命名的轨继续用编号。缺少文字资料时继承文件标签，人工来源选择和锁仍通过已有资料仓库保护。

冲突或解析错误不改二进制分轨，使用原二进制范围／编号和文件资料，在扫描结果与详情给出文本未采用原因。无二进制且文本不可用时保留整文件播放及诊断，隐藏已不适用的旧分轨。原二进制摘要和原文本摘要分别保存、详情可区分二进制命名补充与文本分轨。

原 REM ReplayGain、轨标志、ISRC、子索引与声明 PREGAP／POSTGAP 保留。声明间隙显示并在扫描提示，当前仍不插入额外静音，不把名称导入当作完整间隙编排实现。

## 曲库、详情与写回

媒体与两类来源、命名信息及分轨在原扫描检查点事务内更新，保持现有轨身份与个人引用；来源重读校验失败仍回滚该检查点。文档仍采用自己的 FLAC 相对路径，外部 CUE 优先。明确 `playable` 标记区分可用二进制加文本诊断与没有可用分轨，使外部文档移除后正确恢复当前有效内嵌编排；旧文档没有此标记时保留原兼容判断。

列表投影移除原二进制／STREAMINFO、原文本／STREAMINFO 与整份文本解析文档，只返回详情所需来源状态／摘要／有界诊断。原字段用于 ReplayGain，名称与署名进入已有资料／检索路径。详情不为内嵌来源展示外部文本重新解释按钮。

FLAC 单曲标签预览现在同时识别类型 5 与 Vorbis CUESHEET 字段，保持内嵌编排的单曲写回限制，避免对整镜像执行普通单曲修改。未增加真实文件提交或解除认证限制。
