# ADR-191：完整排序桶分页与风格成员查询

日期：2026-10-12。源码检查点：0.185.0。schema72、音频 IPC1.23、媒体协议14保持。

## 问题

十万条合成音乐目录已经完成入库并保存一致备份。原查询在分页前展开全目录的媒体、专辑、碟、用户资料和排序资料；风格筛选逐项执行关联成员查询。0.184 同语料诊断中的常用风格与标题组合超过架构 200 ms 核心检索预算，完整浏览和宽召回也慢。

仅减少本页详情读取不够：仍需保证完整顺序、精确总数、版本折叠、旧派生索引回退和重复歌单条目，并避免改变检索召回与排名。

## 决策

`libraryQueryPlan` 保留完整条目投影，新增内部 ID 投影。按实际筛选、排名和排序引用建立关联；计数使用筛选实际需要的关联。静态歌单仍按条目身份、位置排序，保留重复歌曲。

风格身份以绑定参数选取，用递归 UNION 展开所选树，再从风格反向索引找到歌曲与专辑成员。成员 UNION 去重，后代的归档规则保持各原 API 的语义。显式反向索引与连接顺序避免未统计目录选成全表遍历；不会在每首歌曲上重新展开整棵树。

直接检索候选去重，与原有最多300项、已经按实体范围筛选的错拼候选合并，再读取候选条目。直接命中仍排在错拼前；排名只在不可能改善结果的分级上提前返回，繁简等价加0.25的原规则保持。

标题、艺人、专辑和默认专辑顺序先物化轻量候选 ID、搜索分级／距离、第一排序键。在这些键上探查目标页的位置，取得上下边界；随后展开两端完整同分组，才读取专辑、碟、曲序等原有次级排序资料。统计严格早于下边界的候选数，修正本页偏移，再执行完整原顺序。不能只按前100个任意同分候选读取，否则会丢失正确歌曲。

精确总数来自同一候选集合。空目录或超过末页仍返回总数，空结果哨兵不会送入详情读取。旧算法或缺失排序键保持原关联数据与自然排序回退；添加时间、发行日期和默认最近添加保持原查询。只读取本页最多100项详情与版本数量，不缓存查询结果，不修改 SQLite 缓存配置，也不需要迁移、重建索引或重新生成十万语料。

## 验证口径

聚焦查询 MVP 使用实际生产数据库接口和受控合成目录，对照完整关系排序，同时独立按夹具清单检查风格成员和用户状态。覆盖同名／自然数字、升降序、深页／空页、人工曲序、缺失／旧排序键、搜索分级、收藏、可用性、版本折叠、风格交并集／后代／改名别名、专辑与歌曲共同风格及重复歌单条目。

十万规模另从0.184源码包取出原查询，以相同保留目录核对首／末页、标题降序、艺人深页、风格与短中文组合的完整顺序和总数。该对照的混合耗时不作性能验收。

正式性能复测独立运行同一目录20次采样，保留原200／500 ms预算和失败退出状态；物理扫描、OS冷缓存、完整应用端到端、全部进程内存、8小时稳定运行及硬件门槛另行验收。实际标签重扫、28项检索真值、索引升级、缺失／重现和Electron检索界面另作真实文件MVP回归。

## 范围

本检查点推进完整架构的规模查询部分，不代替全部FR01–FR14、WP01–WP11、G1–G5或AC01–AC19。仅ASIO实机验证暂停；DSD、复杂CUE、完整写回／恢复、跨平台、发布等原范围继续。运行结果见本ADR最终证据段与validation记录。


## 最终结果

Main／Renderer构建、两侧类型检查、完整原生编译与分发清单生成／核对通过；880组有序页对照及独立成员／属性／身份／统计检查通过，十万原查询六组顺序与精确总数对照通过。原查询对照在版本号更新前运行，报告中appVersion仍0.184.0，当前逻辑是最终0.185查询；参考代码SHA与该版本来源保留在报告中。

9首真实FLAC的28项检索真值、改标签重扫与旧词撤出、旧派生索引升级、缺失／重现与用户状态、数据库重开及Electron搜索／风格界面回归通过。MP3/WAV封面与播放详情、滚动／点行歌词、播放模式、队列和实体检索回归通过。ASIO和DSD硬件本轮未执行，没有新安装包。

详情首轮正常退出捕捉到封面保留请求竞态，功能检查通过但退出断言失败，原exit1保留。close改变资源代次时，已经发往Library的保留请求仍可能完成；现在先明确补偿释放该租约，退出时结束原请求，避免误报文档变化。普通导航仍拒绝旧文档请求，退出仍拒绝新保留，帧和字段校验保持。最后详情与FLAC/CUE的正常退出断言通过，不能将原失败命令改写为通过。
