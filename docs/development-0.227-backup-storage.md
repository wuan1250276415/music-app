# 0.227.0 备份保留与空间管理开发记录

日期：2026-10-17。本次是研发快照，完整架构目标仍在进行；最近一次已归档的集中 MVP 验证为 0.226。

## 已接通的代码

- 任务中心新增“备份空间与保留设置”，通过受信 Main、preload 和 Library 接口取得保留设置及分页空间清单。
- 默认任务结束后保留 30 天、空间目标 10 GiB；可修改保留天数和空间目标，不设目标以 0 表示。超出空间目标不自动越过保留期或恢复保护。
- schema83→84 新增只追加的保留策略历史。保存带原命令身份与修订检查，重试复用原操作；恢复检查要求历史连续、默认值正确、设置与原命令一致。备份、恢复、历史导出及版本边界同步到 84。
- 备份名称必须对应当前库的实际暂存描述，目录必须位于当前应用的标签备份目录。任务未结束、文件仍有租约或读取协调占用、批次未结束、正在恢复或核对的备份均归为保留。
- 空间清单读取实际文件长度，区分已关联、达到保留期但待核对、需保留、未关联和无法读取。未关联目录不递归遍历，链接或不明文件不作为可清理备份；磁盘可用空间无法获取时显示不可用。
- 清单每页 20 项，单次最多 65536 个目录项，并限制核对时间；过程可取消并在维护／关闭前排空。分页使用当前会话的清单身份，不把分页缓存当作删除授权。目录变化、无法读取或超出预算时显示不完整结果。
- 保留起点取任务结束时间和备份创建时间中较晚者，不用可能沿用原歌曲时间的备份修改时间计算到期。

## 验证边界

本阶段仅执行应用构建、类型和发行清单检查，不为每个小功能单独运行测试。schema84 实际升级／回滚、跨重启设置、真实桌面、真实文件核对及清理故障矩阵留到完整空间管理 MVP 集中验证。0.226 及更早检查点仅证明对应版本。

当前没有手动或自动删除入口，没有执行备份删除、原歌曲写入或用户曲库升级；清单中的到期候选不代表已经取得清理证明。生产标签写入与恢复认证目录继续为空。本次不重编原生组件、不生成新安装包。

## 接续工作

1. 增加固定清理范围及不可变原操作记录，绑定策略修订、任务结束状态和实际备份身份；清理前重新检查恢复依赖。
2. 通过原生组件独立核对备份 hash、物理身份和目录锚点；按已核对的文件句柄执行删除，保留删除前日志和完成回执。
3. 接通手动确认、在途停止／排空、丢回应及进程重启后的原操作核对，再接入按策略执行的后台清理和空间目标提示。
4. 对实际旧 0.226 库升级／回滚、到期与空间边界、未知文件、忙碌／链接／外部替换、崩溃与恢复保护进行一次集中 MVP 验证。

其余 FR01–14、WP01–11、G1–5、AC01–19 继续按架构推进；仅 ASIO 实机验证暂缓。
