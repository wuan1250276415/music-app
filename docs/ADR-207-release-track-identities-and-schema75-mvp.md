# ADR-207：发行曲目身份确认及schema75升级 MVP

日期：2026-10-14；源码0.200.0。媒体协议15、音频IPC1.23不变，曲库schema75；最新已验证试用安装包仍0.198.0。完整架构计划继续，仅ASIO实机验证暂停。

## 用户流程和身份区别

整专辑对应后的“审核音乐身份”增加发行曲目目标。具体发行版的某一轨与它使用的录音分别保存外部标识；同一录音出现在不同发行版本或不同位置时，不把录音ID当成轨目ID。[MusicBrainz标识说明](https://musicbrainz.org/doc/MusicBrainz_Identifier)明确Tracks也有MBID。

每个目标显示本地／来源标题、来源标识、规范Track链接、来源碟号／轨号／印刷编号、本地对应位置、全部本地文件版本数量和当前引用。按本地ReleaseTrack去重，同一轨的多个文件版本只产生一个身份目标。默认不采用，分别确认录音、发行版、发行曲目及专辑概念范围。

Track链接使用`https://musicbrainz.org/track/{MBID}`，Main仅允许规范实体地址。该路径由[官方服务端Track控制器](https://github.com/metabrainz/musicbrainz-server/blob/master/lib/MusicBrainz/Server/Controller/Track.pm)处理，当前轨目会跳转到具体发行介质与轨目锚点；本轮核对官方代码，不声称真实用户轨目链接已逐一运行验收。

已有手工实体引用编辑器也能单独选择“发行曲目”。追加引用或只替换MusicBrainz保留其他来源。一个源ID已有其他本地轨目归属时拒绝保存；关联录音或来源发行存在其他本地归属冲突时，轨目也要求先处理关联，不借轨目确认绕过冲突。普通已验证单轨可单独确认；缺少完整发行审核仍会阻止整体发行／概念身份确认。

## 授权、保存和补偿

默认旧预览请求不增加轨目目标；当前桌面明确请求includeReleaseTracks。目标最多为1000个录音＋1000个轨目＋发行／概念，共2002个；映射1000条、影响条目5000条、4份／16MiB预览预算保留。

请求仍只传服务器审核目标键、确认方式及范围勾选，不能提供新ID或轨目上下文。由验证过的发行上下文生成每个轨目的来源发行／录音／专辑概念、碟号、位置和印刷编号，保存在该实体审计的typed trackContext中；发行轨目MBID进入external_ref，不用作本地主键。

私有快照绑定实体资料、引用单调修订、父发行、介质完整资料、署名及全部PlayableItem成员。介质ID不变但碟号或格式改变也会使旧审核／引用编辑失效。其余轨目、录音和专辑概念分别保留各自修订。

多目标仍在一个事务内先验证再保存，任一轨目审计失败会回滚先前引用、审计和聚合回执。来源历史／计数包含轨目确认，支持单轨独立撤销、MusicBrainz-only替换、后续引用冲突保护、取消／离线／重启后的回执重试。轨目撤销不改录音、其他轨目、成员或音乐文件。

新增可选confirmedReleaseTrackScope。缺少新字段的历史请求保持原有规范JSON元组及回执摘要，不能确认轨目；没有把新字段默认补入旧请求。

## 数据库升级、备份和恢复边界

schema75在external_ref及entity_reference_state的闭合集合加入release_track；补齐实体存在、禁止直接更新、轨目引用身份删除保护。旧schema74声明保持原样，新增独立迁移函数，仅替换两张引用表及其守卫，其他表不改结构。

已有74库正常启动先用一致快照保存和核对完整结构、关键音乐／用户表计数、完整性及外键，再在同一事务内迁移。逐行摘要比较全部已有引用、引用修订、审计原JSON和提交回执，确认值未改变；原快照继续标为74。无事务调用拒绝，末段表／触发器替换失败可完整回滚。75重开不再生成升级快照。

发行manifest与构建核对同步支持75。新备份／历史导出记录75，旧68–74清单、预览和报告仍保留真实schema。暂停恢复连接及当前完整结构兼容核对要求75，禁止隐式迁移旧备份；旧库候选的显式迁移及完整恢复生命周期仍属于待完成范围。

## 集中验证与证据

集中命令仍`npm run test:metadata-identities-mvp`，包含录音／发行／概念仓库、轨目与迁移仓库、实际桌面组合流程。需要先完成当前原生构建。网络仅替换fetch边界，实际Main／preload／Service／图像监督进程／SQLite运行，未注入候选或批准凭据。

- 原身份仓库27项：录音／发行／概念的全局范围、事务、逐实体补偿、来源、回执及备份保持。
- 轨目／迁移仓库14项：完整历史74表结构夹具；升级快照；末段故障回滚；旧引用／审计／回执保留；幂等重开；多文件版本范围；窄请求与单独确认；第二轨目审计失败原子回滚；来源上下文；独立补偿／重试／其他来源保留；外部归属冲突；介质变化失效；75备份检查／重开及完整性。
- 实际桌面组合链33项：三份MP3、两个发行版，确认2录音＋1发行＋2轨目＋1概念；三类基础范围及新增轨目范围分别勾选。先撤销发行／概念，再只撤销一个轨目，保留另一个轨目及两个录音；离线重启保持各自状态及来源审计。此前图片、五发行字段、双曲文本批次流程继续经过生产路径。

首轮轨目快照测试的额外只读连接未登记生产CUE路径函数，完整性检查失败；测试连接补上同一生产函数后通过。第一次原生组合构建在最后的分发核对仍要求schema74，整体exit1；更新核对目标并重新完整构建后通过，未把失败命令作为编译／发行通过证据。失败日志保留。最终通过证据集中到MVP命令、三份报告和最终检查。

这不是实际旧安装版升级、十万物理库性能、完整恢复切换或崩溃矩阵证明。历史schema74来源为完整旧SQL表定义夹具，源上下文及网络为明确夹具；真实轨目匹配正确性、标签写回和新硬件没有新增认证。未修改用户原曲库／音乐。

## 后续工作

缺少本地概念时直接创建／合并、实体关联与多人完整角色、整专辑真值集和召回、隐藏／数据轨、ISRC／指纹、多来源及更多字段、全库批量、完整来源清除／写回／恢复、规模和长时性能以及发布门禁继续。引用接受不自动修改本地归属、录音／轨目文本或标签文件；完整V1未交付。
