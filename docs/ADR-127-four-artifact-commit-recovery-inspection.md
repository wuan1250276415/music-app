# ADR-127 提交后的四工件恢复核对

日期：2026-10-04。状态：0.121.0 源码及编译阶段；schema52。认证提交目录保持空，运行测试集中到 MVP。

## 架构目标与本批次

架构 §12.2 / WP09 / AC12 要求用实际文件和阶段回执解释崩溃结果。ADR-125 的原生非覆盖移动会保留实际旧文件，故仅检查原文件、备份、临时文件不足以恢复；ADR-126 已拒绝对提交任务使用旧三工件入口。本批次接入独立只读四工件核对、持久报告及桌面入口。并未完成原生恢复/重探测/曲库提交/清理策略，FR12/AC12 尚未验收，全架构目标保持。

## 四工件读取协议

复用固定 tag-file-inspector.exe 与既有单进程 Windows Job 监督（128MiB、8小时墙钟、6小时CPU，父进程身份/退出及EOF取消）。v1 inspect 仍限于三个角色；新增 v2 inspect-commit 严格要求原文件 original、备份 backup、临时文件 temporary、旧文件 victim 的固定顺序，严格 nonce/连续消息序列、64KiB帧/128KiB每秒输出、4MiB分块实际 SHA 与每工件64GiB上限。

v2 额外保持从本机驱动器根开始到授权源目录、备份目录、源文件父目录的祖先无删除共享句柄，拒绝重解析/最终路径变化。来源、临时、旧文件必须同一固定父目录，备份直接位于冻结备份目录；路径全部由不可变原执行描述和提交工件身份派生，桌面不能指定文件路径。返回父目录物理身份及两个根的身份。修复共用扩展路径函数对三字符驱动器根 C:\ 的边界判断，以支持祖先句柄从驱动器根开始取得；此改动仍待 MVP 实机验证。

四个现存文件同时保持 share=0 只读句柄直到最终回执；完整/元数据/音频载荷摘要和卷/128位文件ID/时间/字节数实际读取。多硬链接/重解析/路径变化或读取中身份变化拒绝。明确区分 present / missing / busy / unreadable；占用和错误不能解释为缺失。返回前再次检查全部现存句柄的身份和精确路径，重新打开确认缺失名称仍缺失，并检查固定目录身份。

不存在的名字无法像现存文件一样持有排他锁，重新确认只是读取时证据，不证明其后不会创建；快照在实际进程退出后已不持有句柄。核对报告不授权替换、恢复或释放租约。将来的恢复动作必须重新同时取得所有相关句柄并校验当前目录、实际文件和日志。

## 请求、报告和重启

schema52 新增 tag_commit_inspection，冻结原命令、提交操作/任务/审核修订和新提交租约身份。活动核对每操作至多一个，历史最多8192条/256MiB；请求4096字节、进度1024字节、报告64KiB。触发器要求属于该操作的同一租约、请求身份不可修改、最终报告不可修改/删除。旧库迁移前保存 pre-v52 备份；SQL/迁移本轮未运行。

Library 开始前检查 job=recovery_required、operation=recovery_required/native_verified、内容修订未变、新恢复租约属于该操作、原暂存计划未变，保存请求及原命令回执后才启动后台核对。按新租约阻止媒体/扫描/服务读取，等待解析/分析退出；35秒超时保留占用。再次复核授权目录，启动 v2 读取，等待实际退出后复核请求/目录，才保存不可变报告和退出确认。

取消请求同样保存原命令回执，再关闭进程输入，等待实际退出。未知退出禁止继续新文件操作。重启将 running 核对置 interrupted/exit_unknown，保留原任务、全部文件、恢复租约和历史结果；用户可以重新核对。核对不会清除观察、恢复在线、释放读取协调、重扫或把标签任务标成 completed。

## 证据与分类

存在冻结提交绑定时，先检查原暂存日志的完整链和每条 DB 回执，SHA 必须与认证提交绑定链接一致；再核对提交日志完整链、所有关键阶段证据及每条不可变 DB receipt，并区分 matched / fs-ahead。已保存 native_verified 的 done / 实际退出证据必须等于 verified 日志。没有冻结绑定时报告 binding-unavailable；日志缺失、部分写入、链/DB不符则 journal-unconfirmed，不把旧暂存证据当作提交证明。

分类逐项比较实际完整FLAC/元数据/音频摘要、物理卷/文件ID/字节数、根及可用的父目录基准，结合日志阶段的最小/最大可能进度。来源备份必须同时满足内容和物理身份基准。现存的未知工件、占用/不可读取、目录变化及阶段与布局矛盾进入 recovery-required。核对没有读取完整 ACL/SACL 政策，分类只解释文件内容/身份/布局，不能称为完整权限保留认证。

| 分类 | 证据与含义 |
| --- | --- |
| unchanged-staged | 原路径是冻结来源，备份及临时目标符合基准，旧文件明确缺失，日志最多 intent；尚无文件替换证明 |
| victim-moved | 原路径明确缺失，旧文件是实际来源，备份和临时目标符合基准，日志为 intent/victim_moved；可能处于两次移动间缺口 |
| replacement-observed | 原路径是实际目标，旧文件/备份是来源，临时路径明确缺失，日志至少 victim_moved；仍需重探测/曲库提交 |
| restore-available | 原路径明确缺失且来源备份可验证，其他现存工件无未知内容，未与已持久阶段矛盾；只表示恢复候选，需后续显式原生动作 |
| recovery-required | 工件状态/身份/摘要/目录/阶段无法证明可解释布局；保留全部文件及占用 |
| binding-unavailable / journal-unconfirmed | 实际认证绑定或日志证据未确认；不提供自动恢复结论 |

报告冻结最终核对文件快照、分类、已核对提交阶段/SHA、原暂存 SHA 和 matched/fs-ahead 状态。DB 保存前再次核验这些指针不落后于操作的持久阶段。
