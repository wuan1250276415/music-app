# ADR-085：音量调整触发 PCM 路径重规划

日期：2026-10-02；源码 0.80.0；音频 IPC 1.19／schema v38／媒体协议 6 不变。

## 问题与范围

允许转换的独占模式在零音量增益／无 ReplayGain 时可能选整数输出；此前播放栏可以保存衰减／静音，却因当前输出不是 f32 而拒绝本次会话调整。用户看到保存成功，但当前音乐仍按旧路径播放。架构 §13.3 要求启用数字处理时采用明确浮点处理路径，不能在整数直通标签下暗中改变样本。

本批在现有播放 coordinator 内选择音量应用方式：活跃 f32 会话继续 callback 20ms 包络，活跃整数会话发生不同音量／静音目标时通过原有停止、保存、重新规划和恢复流程切换处理路径。原始格式独占模式仍拒绝软件音量。Native／DoP／ASIO 和完整 PlaybackPlanner 仍在后续范围；ASIO 实机验证继续搁置。

## 串行选择与保存

AudioController.volumeNeedsReopen 观察当前状态、实际格式／applicationIntegerPath 和目标差异； preparing 阶段在保存前拒绝。选择在 coordinator 串行操作执行时作出，避免请求到达时的旧状态决定后续行为。音量请求仍只能修改本配置 volumeDb／muted；device、mode、DSD 策略与其他处理字段必须完全一致，修订 CAS 与完整请求回执保持。

configureOutput 抽取私有 reopenOutput，configureVolume 在同一个串行操作中复用它，避免嵌套等待自己的队列。先取消／对账相邻 CUE 预排，取当前 item／位置／暂停状态并核对队列当前项，再释放旧宿主并确认退出。保存后 applyOutputPreference，按新处理设置重新走解码、设备协商、prepared／start 独立计划核对；不向旧整数会话发送浮点音量命令。

恢复使用既有最近呈现位置书签，而不是精确音频帧接续保证；重新打开会有短暂中断，不属于 gapless。曲目和暂停意图保留，输出设备／模式不因音量改变而自动改选。停止的 operation token 继续优先：保存期间用户停止后仍可保留已提交偏好，但不自动恢复。旧宿主退出失败、CUE 对账失败和保存修订冲突不冒充成功恢复。

目标与当前音量／静音完全相同时，不重新打开、不发多余 callback 命令。f32 路径恢复到 0 dB／取消静音后可继续 f32，会话不会为了切回整数再重开；下一次播放根据保存设置重新协商。空闲／尾部阶段保存供后续播放使用；准备阶段禁用提交并在 Main 再校验。

保存失败继续原有持久回执核对；结果未知阻止播放并释放宿主，核对只确认保存、不自动重启。保存已提交但恢复失败返回 saved 和明确错误，保持配置与当前播放失败的区别。既有 live-volume 目标回执仍只证明接受目标，不证明 DAC 已呈现。

## 界面与验证

播放栏使用当前 PlaybackState，在允许转换的整数会话提示“调整时启用数字处理”，控件说明重新打开与状态保留； preparing 阶段禁用控件。原始模式与未知保存禁用逻辑保留。重开后的现有管线详情显示实际浮点解码／处理和样本变化，不保留旧整数输出描述。

内嵌封面优先、点击播放栏封面进入详情、专辑／歌手／风格检索、滚动歌词、模式和队列保留。本批没有新增数据或音频 IPC 格式；仍需要重编译版本身份一致的宿主。发行摘要记录重规划行为。

仅做类型、Main／Renderer／Native 编译、发行／分发清单、维护脚本语法与源码归档 CRC 核对；最终结果见实施状态。按用户要求未运行单元、音频、进程、UI、SQL／迁移、网络、硬件或安装验证，集中到 MVP；最新已验证安装包仍 0.29.0。完整 FR／WP／G／AC 不因本批而视作完成。

MVP 验收覆盖整数 s16／s32 衰减和静音重规划、同目标不重开、原始模式拒绝、paused／playing 恢复、书签误差／可听中断、原输出设备保留、CUE 跨界／队列修订、stop 在释放／保存／恢复各阶段的优先性、尾部与 preparing、持久回执 unknown／丢回执、恢复失败与退出失败、拖动合并后后续 f32 平滑目标，以及详情实际管线变化。完整数字音量／SRC／dither／limiter／跨文件 gapless／硬件认证继续开发。
