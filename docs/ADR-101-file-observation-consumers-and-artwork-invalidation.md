# ADR-101：文件观察在媒体读取与播放前核对中的使用

- 状态：源码实现与编译通过；真实文件、数据库、界面与播放待 MVP
- 版本：0.96.0
- 日期：2026-10-02
- 关联：WP04、WP06、WP10、FR04、FR10、FR13；承接 [ADR-100](ADR-100-scan-stability-and-file-observations.md)

## 问题与依据

上一批已持久保存完整整数属性观察，并用于扫描增量判断。但 `LibraryItem` 仍只携带旧大小／mtime 标记，歌词在途请求和读完后发布、播放前 ReplayGain 核对尚未使用新观察。封面指纹也只包含音乐和目录的浮点属性，在目录时间未变、同名图片原地改写时可能返回旧选择。

BigInt 时间表示及其平台精度限制仍遵循 [Node.js 24 Stats 时间说明](https://nodejs.org/docs/latest-v24.x/api/fs.html#stat-time-values)。本批继续使用属性证据，不将其声明为字节哈希或原生授权身份。

## 分层与曲目投影

将属性摘要及严格核对放入 `platform/file-observation.ts`，曲库层保留 schema／稳定窗口定义并重导出原符号，Main 不依赖曲库 schema。算法和摘要输入不变，已有 v40 观察仍可使用。

`LibraryItem` 新增可选 `fileObservation`；列表、单条与按 ID 批量读取均投影当前算法的摘要，并严格验证。没有观察的旧文件不伪造字段，下次成功扫描继续补齐。原 `fileStamp` 大小／mtime 合约保留，Native 的旧回执核对继续使用它。schema v40、音频 IPC 1.19、媒体协议 6、系统媒体协议 1 不变，无新运行依赖。

元数据审核指纹加入大小／mtime 和新观察。扫描观察更新后，既有待审核批次会重新面对来源变化校验；它只核对数据库已保存的观察，不声称已经完成磁盘内容的实时授权或标签写回。

## 歌词请求与发布

歌词在途合并键加入新观察，文件观察不同的请求不合并。读取开始核对扫描摘要与打开的句柄，再核对原有数值属性；完成后比较句柄与当前路径的完整整数摘要。扫描资料已经过时或读取中变化时，保留已有导入歌词，返回明确的本地读取提示。

曲库服务在读取结束、保存原文历史／设置之前重新取得曲目，新旧观察不同则拒绝发布这次来源结果，即使标题、大小和 mtime 未变。原有 item／范围、来源集合、偏好修订和持久回执仍保留；`lyricsScope` 不加入文件属性，避免每次扫描都丢失同一歌曲范围的歌词偏好。

## 封面失效与读取

1. 保持内嵌正面、其他内嵌、歌曲同名图片、目录常规封面的顺序。指纹改为音乐文件完整整数摘要、目录整数属性以及最多 18 个常规图片候选的观察；候选名称生成由指纹与 worker 共用。
2. 候选按顺序做 `lstat`，不读取图片字节或跟随该候选的符号链接。不存在、权限不可用、链接／其他类型分别进入失效键；不能查看目录或候选时仍允许继续探测音乐内嵌封面。实际图片读取仍在原监督 worker 中，保留授权边界和尺寸／字节限制。
3. 选择策略标识改为 `embedded-first-bigint-sidecars-v3`，在线旧引用重新核对；离线时继续读取既有图片缓存。对于能够按这些路径观察到的候选，原地替换／改写所改变的 ctime／inode 等会产生新指纹，不等待旧 sidecar 引用的 30 秒期限。
4. 本地图片 worker 加入句柄／路径的 BigInt 摘要前后核对。音乐内嵌图片在服务读取过程也加入完整观察，随后重新计算整个封面指纹，变化时不保存新选择。
5. 服务的在途键加入扫描观察，读取前、保存／返回前核对曲目来源仍一致。Renderer 的封面上下文也加入新观察；同一文件的不同条目授权、图片资源租约、有限重试和独立重读继续复用。

指纹使用常规名称直接观察；Windows 默认名称解析与大小写敏感文件系统的别名查找并不等价。worker 既有目录别名搜索保留，大小写敏感目录／跨平台的完整候选身份对应仍需补齐。权限错误无法提供完整候选属性证据，仍依赖显式重读、目录失效和旧选择的有限复查。

这些探测增加每次指纹的最多 18 个顺序属性读取，不扩大图片字节预算；原有请求与缓存预算保留。但底层文件 I/O 没有硬取消，不能据此证明 NAS 响应时间或全库封面性能达标。

## 桌面文件入口与播放前核对

文件拖放／外部打开的私有绑定加入完整属性摘要，绑定前后核对，完整重查比较摘要；CUE 字节哈希读取前后也核对绑定摘要。播放所选曲目时，若已有扫描观察则必须与文件请求绑定一致，原目录／CUE／修订与播放意图校验继续执行。

普通播放在启动 Native 之前核对已保存的扫描观察；相邻同源 CUE 轨的观察也必须与实际文件匹配。ReplayGain 保留原大小／mtime 检查。已有观察不匹配时提示重扫，未经补齐观察的旧条目保留原规则，不凭空认证。

核对最多等待 5 秒，超时或旧操作结果不继续打开宿主。5 秒是等待期限，不会硬取消尚未返回的 stat；它与 Native 打开之间也不是原子事务。Native 同句柄文件绑定／只读共享及其既有回执继续保留，本批没有将 Node 的 dev／ino 直接映射成 Windows 卷／文件 ID，也没有完成扫描观察与 Native 句柄回执的全部字段对应。这些身份、竞态、硬 I/O 隔离及 MediaSource 授权生命周期仍在完整计划内。
