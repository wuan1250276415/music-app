# 内置数据源适配示例

示例使用 API 1.0，目标是证明内置适配器能够通过版本化请求契约接入统一 Broker。`.invalid` 地址没有真实服务，MVP 验证只注入模拟响应，不访问外网。

宿主单独维护 `host-grant.cjs` 的允许能力、域名和凭据槽；不能把外部 manifest 直接转换成授权。`ProviderExtensionHost` 在整个登记批次验证成功后才注册接口，然后只把 `host.client('example-metadata')` 交给适配器。适配器返回带来源、获取时间、期限和权利的候选，不能自行更新曲库。

在工程目录先执行 `npm run build`，再运行 `node tests/provider-extension-mvp.smoke.cjs`，验证真实宿主／Broker和本示例。独立演示入口不注册到正式用户界面，不创建真实网络来源或凭据。

新增正式内置来源还需实现对应领域查询、私有候选身份、明确审核／应用／撤销、来源权利及保留策略，登记可信宿主授权和备份组件，并验证所用服务的访问条件。这份示例不是完整公共 Provider SDK。

内置适配器与应用同属可信代码，接口限制不是 JavaScript 或操作系统沙箱。V1不加载用户脚本、第三方 DLL 或外部插件包；公开 SDK、签名安装、独立 worker 和完整插件生命周期另按架构计划推进。
